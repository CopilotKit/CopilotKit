**Short answer: use the sort that comes with your language.** Python, JavaScript, Java, C++, Rust and Go all ship heavily tuned hybrid algorithms, and they'll beat anything you write yourself for everyday data. Picking an algorithm by hand only matters when you implement one, or when your data has a special shape.

The rule of thumb behind it, checked in order:

1. **Keys are small integers or fixed-width?** Counting or radix sort, which skip comparisons entirely.
2. **Tiny or nearly sorted?** Insertion sort for a few items, Timsort for larger arrays.
3. **Need stability?** Merge sort or Timsort.
4. **Memory tight and worst case critical?** Heapsort.
5. **Anything else?** Introsort or a modern quicksort variant, which is what the standard libraries already give you.

### Why stability matters

A stable sort keeps equal items in the order they arrived. That lets you sort in several passes. Say you have employees already sorted by name and then sort them by department:

| Input (sorted by name) | Stable sort by department | Unstable sort may give |
|---|---|---|
| Alice · Sales | Bob · Engineering | Dan · Engineering |
| Bob · Engineering | Dan · Engineering | Bob · Engineering |
| Carol · Sales | Alice · Sales | Carol · Sales |
| Dan · Engineering | Carol · Sales | Alice · Sales |

With the stable sort, names stay alphabetical inside each department for free.

### What the standard libraries actually use

| Language | Default sort | Stable? |
|---|---|---|
| Python | Timsort (Powersort merging since 3.11) | Yes |
| JavaScript | Stable by spec since ES2019; V8 uses Timsort | Yes |
| Java | Dual-pivot quicksort for primitives, Timsort for objects | Objects only |
| C++ | `std::sort` is usually introsort; `std::stable_sort` merges | `stable_sort` only |
| Rust | `sort` is driftsort, `sort_unstable` is ipnsort (since 1.81) | `sort` only |
| Go | Pattern-defeating quicksort (since 1.19) | `sort.Stable` only |

Sources: [Python sorting HOWTO](https://docs.python.org/3/howto/sorting.html), [MDN: Array.prototype.sort](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort), [Rust slice docs](https://doc.rust-lang.org/std/primitive.slice.html).

Notice the pattern: every serious implementation is a hybrid, using quicksort or merging for the bulk, insertion sort for small pieces, and a fallback for bad cases. If sorting really is your bottleneck, benchmark the built-in sort on your own data before replacing it.
