<Steps>
  <Step>
    ### Own the A2UI tool and pin its attempt cap

    `get_a2ui_tool` from `ag_ui_adk` builds the `generate_a2ui` tool. It
    drives a forced `render_a2ui` call on the model you pass, validates each
    attempt, and retries an invalid one. Recovery is on by default.
    `"recovery": {"maxAttempts": 3}` pins the cap so the renderer's
    "Retrying… (N/M attempts)" label matches it, and `on_a2ui_attempt` is
    called for every attempt, rejected ones included. When no attempt is
    valid, the tool returns the `a2ui_recovery_exhausted` envelope and the
    renderer shows the failure card.

    <DemoCode file="src/agents/recovery_agent.py" region="a2ui-recovery-agent" />

    The tool calls its model directly, so it needs a model object rather than
    a model name. `get_a2ui_model()` returns a `Gemini` instance for that,
    while `get_model()` serves the `LlmAgent` itself. Both come from this
    Showcase's `agents/shared_chat.py`, as does `stop_on_terminal_text`.
    `default_catalog_id` names the catalog the page registers, which this
    demo shares with the dynamic-schema demo.
  </Step>

  <Step>
    ### Serve the agent at its own path

    The agent server wraps every entry in `AGENT_REGISTRY` in an `ADKAgent`
    and mounts it with `add_adk_fastapi_endpoint`. The registry maps
    `a2ui_recovery` to this agent, so it is served at `/a2ui_recovery`.

    <DemoCode file="src/agent_server.py" region="adk-agent-endpoints" />
  </Step>

  <Step>
    ### Point a runtime at it without a second A2UI tool

    The demo has its own runtime endpoint, `/api/copilotkit-a2ui-recovery`,
    which proxies to the ADK server with an `HttpAgent`. The page passes a
    catalog to the provider, which would otherwise turn tool injection on, so
    `injectA2UITool: false` keeps the runtime from adding a second
    `generate_a2ui` next to the agent's. The A2UI middleware still runs and
    reports building, retrying, painted, and failed states to the renderer.

    <DemoCode
      file="src/app/api/copilotkit-a2ui-recovery/route.ts"
      region="a2ui-recovery-runtime"
    />

    `extractForwardedHeaders` copies the request's `x-*` headers onto the
    agent call so the Showcase's recorded-response tests can match; your
    runtime can build the `HttpAgent` without it.
  </Step>
</Steps>
