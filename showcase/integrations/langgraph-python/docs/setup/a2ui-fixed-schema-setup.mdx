<Steps>
  <Step>
    ### Give the graph the tool

    The reference graph is a `create_agent` agent whose only tool is
    `display_flight`. `CopilotKitMiddleware` adds CopilotKit's frontend tools
    and the frontend's agent context to each model call. It doesn't put agent
    state in the prompt unless you opt in with `expose_state`, and this graph
    doesn't need to. The system prompt tells the model to call `display_flight`
    once and stop, because the tool result is the rendered card.

    <DemoCode file="src/agents/a2ui_fixed.py" region="a2ui-fixed-schema-agent" />

    Register the graph with the LangGraph server under the `a2ui_fixed` key in
    `langgraph.json`. The runtime in the next step asks for it by that
    `graphId`.
  </Step>

  <Step>
    ### Serve it from a runtime that does not inject the A2UI tool

    The cell has its own runtime endpoint, `/api/copilotkit-a2ui-fixed-schema`.
    With `injectA2UITool: false` the A2UI middleware still runs, so it finds
    the `a2ui_operations` container in the `display_flight` result and paints
    the surface. It just doesn't add a `generate_a2ui` tool next to the
    agent's own.

    <DemoCode
      file="src/app/api/copilotkit-a2ui-fixed-schema/route.ts"
      region="a2ui-fixed-schema-runtime"
    />

    The demo page points the provider at this endpoint with
    `runtimeUrl="/api/copilotkit-a2ui-fixed-schema"` and
    `agent="a2ui-fixed-schema"`, and passes the flight catalog as
    `a2ui={{ catalog }}`.
  </Step>

  <Step>
    ### Try it

    Ask "Find me a flight from SFO to JFK on United for $289." The agent calls
    `display_flight` once, and the flight card renders in the chat with those
    four values, followed by a one-sentence confirmation.
  </Step>
</Steps>
