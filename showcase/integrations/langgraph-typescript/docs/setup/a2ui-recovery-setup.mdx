  <Step>
    ### Own the A2UI tool and pin its attempt cap

    `getA2UITools` from `@ag-ui/langgraph` builds the `generate_a2ui` tool.
    Its body runs the `render_a2ui` sub-agent with the model you pass,
    validates each attempt, and retries an invalid one. Recovery is on by
    default. `recovery: { maxAttempts: 3 }` pins the cap so the renderer's
    "Retrying… (N/M attempts)" label matches it, and `onA2UIAttempt` receives
    an `A2UIAttemptRecord` for every attempt, rejected ones included. When no
    attempt is valid, the tool returns the `a2ui_recovery_exhausted` envelope
    and the renderer shows the failure card.

    <DemoCode file="src/agent/recovery-agent.ts" region="a2ui-recovery-agent" />

    `defaultCatalogId` names the catalog the page registers, which this demo
    shares with the dynamic-schema demo. `forwardingFetch` and
    `headerForwardingMiddleware` are defined earlier in the same file. They
    carry the request's `x-*` headers into the inner render call so the
    Showcase's recorded-response tests can match. In your agent, construct
    the models with `new ChatOpenAI({ model: "gpt-5-mini" })` and pass
    `middleware: [copilotkitMiddleware]`.

    Register the graph under the `a2ui_recovery` key in `langgraph.json`.
  </Step>

  <Step>
    ### Serve it without a second A2UI tool

    The demo has its own runtime endpoint, `/api/copilotkit-a2ui-recovery`.
    The page passes a catalog to the provider, which would otherwise turn
    tool injection on, so `injectA2UITool: false` keeps the runtime from
    adding a second `generate_a2ui` next to the agent's. The A2UI middleware
    still runs and reports building, retrying, painted, and failed states to
    the renderer.
