Your existing Hermes installation already owns the model, provider credentials,
and tools. Channels only needs Hermes to expose that agent over AG-UI.

Start the adapter from your Hermes environment:

```bash title="Agent application"
hermes agui
```

By default, it listens on `127.0.0.1:8000` and reuses the configuration selected
with `hermes model`. Verify the server before continuing:

```bash title="Terminal"
curl http://127.0.0.1:8000/health
# {"status":"ok"}
```

Keep that process running. The AG-UI run endpoint is mounted at the server root:

```dotenv title=".env"
AGENT_URL=http://127.0.0.1:8000/
```

Hermes speaks AG-UI directly, so the standard HTTP client is sufficient; you do
not need a Hermes-specific Channels adapter. Install it in the Channels runner:

```bash title="Channels runner"
npm install @ag-ui/client@0.0.57
```

Export the `makeAgent` function expected by the surrounding Channels guide:

```ts title="agent.ts"
import { HttpAgent } from "@ag-ui/client";

export function makeAgent() {
  return new HttpAgent({ url: process.env.AGENT_URL! });
}
```

Channels clones the returned client for each run and assigns the conversation's
stable thread ID itself, so you do not need to manage agent instances or IDs in
this file. Hermes keeps executing its configured tools server-side while
Channels delivers messages and streams the response back to Slack or Teams.

The URL above is intentionally local and requires no session token. If the
Channels runner and Hermes do not share a host or network namespace, follow the
[Hermes AG-UI security guidance](https://github.com/NousResearch/hermes-agent/blob/b036d8be6d9786a7117777c8c3c2b40a84d2ca3b/agui_adapter/README.md#security)
for a network bind and `HERMES_AGUI_SESSION_TOKEN`; changing only `AGENT_URL` is
not sufficient.
