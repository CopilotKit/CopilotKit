# ShellDocs test-removal catalog

The first reduction removed useful functional coverage as well as brittle copy and presentation checks. It should not merge unchanged. This audit recommends retaining a smaller set of behavioral and compatibility guards while removing wording, CSS, icon, ordering and broad content-inventory locks.

This is a catalog of the existing draft [PR #7682](https://github.com/CopilotKit/CopilotKit/pull/7682), not a restoration commit. All deletions described below are still present. **Restore** and **Trim** identify coverage to bring back or consolidate before merging; **Optional** records useful coverage that can intentionally sit outside the lean baseline.

## Scope and evidence

- Original tree: `146c03e5bee889b2b64e307fda9328c818e6e2fb`; reduction: `eb965eda37`.
- Original suite: **144 files**. Draft suite: **13 files**, comprising **7 modified** and **6 unchanged** files.
- This catalog covers **all 131 deleted files and all 7 modified files**, using the original test declarations, assertion chains and test bodies to identify behavior versus copy/presentation checks.
- [Machine-readable inventory](./test-removal-inventory.json) includes every original declaration's title and line, each file's assessment, and the declarations remaining in modified files. Table links open the original committed source.
- Declaration counts are static: parameterized tests and loops expand at runtime. They are not executed-case counts, cost measurements or a promise that every assertion in a mixed suite should return.
- The reduced suite passed locally with **96 executed cases** in roughly **4 seconds**. The original suite was not rerun or timed file by file for this audit. A file importing real generated MDX/content can cost more than a small pure fixture, but there is no measured per-file cost ranking here.
- The reduced [ShellDocs CI job](https://github.com/CopilotKit/CopilotKit/actions/runs/37524126506/job/112476674796) passed in **83 seconds** (20:08:05–20:09:28 UTC on October 6, 2026). This is one job sample, not a measured savings comparison. The cause of the reported Depot spinning and actual CI-minute savings have not been established.

## Functional coverage the first cut missed

1. **Authentication and deployment configuration:** server-safe signup links, missing Clerk keys, correct environment origins, browser config injection and Edge-safe configuration handling. The retained serializer does not cover these.
2. **Working controls:** wizard forward/back/resume and fixed-backend selection, video play/pause/reduced-motion behavior, partner demo switching, menu opening and search recommendation destinations. Ordinary search result tests do not cover recommendation controls.
3. **Copy reliability and command validity:** rejected clipboard writes, pending-click deduplication, retry, analytics failures, CLI identifier mapping and feature intent URLs. Shared PromptPill happy paths are insufficient for wrapper/context assembly and the global clipboard tracker.
4. **Documentation machinery:** code-region extraction, recursive snippet/import handling, actual LLM rendering, hidden/default routes, authored override precedence and search reachability/index generation failures. The retained Markdown route suite mocks the LLM renderer.
5. **Guidance compatibility:** Microsoft .NET obsolete API and starter-version checks, AG-UI package relationships, and a few selected credential/API/example guards. Source checks protect guidance accuracy; they do not prove a real SDK/service integration works.

A lean replacement should consolidate these behaviors into shared fixture-based cases, keep a small generated-content/link smoke check, and avoid reintroducing exhaustive per-framework copy matrices. Optional framework guidance checks can run only when their source/example dependencies change. Measure the resulting CI job before claiming savings.

## The Microsoft guidance job

The removed job was **Microsoft Agent Framework .NET guidance** (`ms-agent-dotnet-guidance`) inside [test / integration / docs](https://github.com/CopilotKit/CopilotKit/blob/146c03e5bee889b2b64e307fda9328c818e6e2fb/.github/workflows/test_integration-docs.yml). It installed ShellDocs dependencies and ran:

- `ms-agent-dotnet-provider.test.ts`: five declarations covering obsolete .NET API guidance, package versions matching the working starter, adapter/state wiring and workflow-source checks.
- `ag-ui-install-pin.test.ts`: one declaration scanning documentation install versions against runtime dependencies to prevent incompatible duplicate client/core packages.

Keep the API/version relationship checks. Remove the test of the workflow's literal source structure, and run the retained cases once in the shared docs job rather than a separate install/runner. If the checks move, that job must also trigger on **`examples/integrations/ms-agent-framework-dotnet/**`and`packages/runtime/package.json`\*\*; the current reduced docs workflow does not include those dependencies.

This is different from `prompt-guidance.test.ts`, which pins two exact sentences and does not compare other products or exercise controls. That deletion is reasonable.

## CI and supporting changes, separate from test deletions

- The old ShellDocs job in `test_unit-showcase.yml` was replaced by the path-filtered `test_unit-shell-docs.yml`. It installs only scripts/docs dependencies, reuses them for the harness generator, generates content once, typechecks and runs tests with a ten-minute timeout.
- Three jobs were removed from `test_integration-docs.yml`: Microsoft .NET guidance/AG-UI pins, framework setup-concept coverage, and feature prompt intents. Their relevant guidance assertions are cataloged above. Their duplicate install/generation overhead can be removed without deleting all their coverage.
- Model-name validation, the deprecated-import validator and executable documentation snippet checks remain. They are not proof that every deleted example, language or behavior is covered; in particular, no replacement .NET guidance coverage was established.
- `test:ci` now runs Vitest directly, worker count dropped from eight to two, and the custom CI config/empty quarantine file/ratchet script were deleted. This is infrastructure simplification, not an individual-test usefulness judgment.
- README and internal Intelligence skill instructions were updated to describe the reduced scope; two implementation comments referencing deleted tests were removed. Application behavior was otherwise unchanged by the reduction.

## Decision before merging

Keep the removal of clear copy/presentation/source-shape locks. Correct the over-removal by preserving the focused behaviors identified above, especially the Microsoft/AG-UI compatibility guards and deployment/auth, routing, rendering, copying and control tests. Optional guidance checks should be an explicit scope choice, not described as worthless or already covered without evidence.
