## Add Intelligence to your existing app

Give users reconnection, catch-up, and delivery across devices around your Claude Agent SDK agent. Follow the [Intelligence quickstart](/intelligence/quickstart) to connect your existing CopilotKit app and Runtime, then verify that a new conversation is saved. This enables AG-UI streams for runs through CopilotKit; no historical import is required.

Keep your agent and its native session storage connected so you can continue the same conversations. See [how streams work with framework storage](/intelligence/threads-explained#how-threads-work-with-framework-storage).

## Include earlier conversations (optional)

The importer reads saved Claude Agent SDK conversations from a project transcript directory or a custom SessionStore export, for Python or TypeScript. It brings over saved messages, tool calls and results, available attachments, child histories, and saved state where available. Child histories appear within the parent conversation; they do not become independent conversations.

Import can only restore what the source saved. Missing MCP App views or media cannot be reconstructed, and external attachment references still need to be accessible. Historical permission callbacks that existed only in a running process cannot be recovered.

## Prerequisites

- A CopilotKit app with CopilotKit Intelligence enabled.
- Node.js 20.9 or later to run the CopilotKit CLI.
- Read access to the selected native session history and the SDK version that wrote it.

## Confirm the target project

Choose the Intelligence project that will receive the history. Its app-api URL and project-scoped runtime key select the destination. You will export those values before importing.

For a CLI-created app, you can select a cloud-hosted project:

```bash title="Terminal"
npx copilotkit@latest project select
```

The command updates the project selected for the current directory and writes its project-scoped runtime key to the app's generated `.env`.

## Configure the source

Select a project transcript directory containing only the conversations you want to import:

```bash title="Terminal"
export CLAUDE_SDK_TRANSCRIPT_DIR="/absolute/path/to/project-transcripts"
export CLAUDE_SDK_VERSION="your-producing-sdk-version"
export CLAUDE_SDK_PROJECT_KEY="-original-working-directory"
export CLAUDE_SDK_SOURCE_ID="my-claude-app"
export CLAUDE_SDK_AGENT_KEY="support"
export CLAUDE_SDK_END_USER_ID="user-123"
```

Set `CLAUDE_SDK_END_USER_ID` to the application user ID your Runtime returns from `identifyUser`. All selected conversations are assigned to that user. Select only their history and repeat for each user.

Use the actual SDK version that wrote the history in `CLAUDE_SDK_VERSION`. For local transcripts, `CLAUDE_SDK_PROJECT_KEY` is the original project directory name beneath `~/.claude/projects/`, such as `-srv-my-agent`. If you copied the directory, retain its original key. For a custom store, use the exact project key passed by the native SDK. Keep the original project key and your chosen source ID stable across repeat imports. `CLAUDE_SDK_AGENT_KEY` identifies the source agent for the mapping below.

Run the import while the selected conversations are idle, or read a stable copy of their transcripts. Local history import does not require an Anthropic API key; continuing the agent uses its normal provider authentication.

### Custom SessionStore exports

If your app uses a custom SessionStore, export the selected sessions with the helper bundled in the CopilotKit CLI. Run it in the app that already has access to your store, while writers are stopped or against a stable read snapshot.

```bash title="Terminal"
npm install --save-dev copilotkit@latest
```

<Tabs groupId="language_claude_sdk_import" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
    Copy the Python helper into your app:

    ```bash title="Terminal"
    cp node_modules/copilotkit/exporters/claude-sdk/export_session_store.py ./export_session_store.py
    ```

    In your async export routine, pass your existing store, its original project key, and the session IDs to export:

    ```python
    import json
    from pathlib import Path
    from export_session_store import export_session_store

    exported = await export_session_store(store, original_project_key, session_ids)
    Path("claude-sessions.json").write_text(json.dumps(exported))
    ```
  </Tab>
  <Tab value="TypeScript">
    In your export routine, pass your existing store, the producing SDK version, its original project key, and the session IDs to export:

    ```typescript
    import { writeFile } from "node:fs/promises";
    import { exportSessionStore } from "copilotkit/exporters/claude-sdk/store-export.ts";

    const exported = await exportSessionStore(
      store,
      {
        language: "typescript",
        sdkVersion: actualProducingSdkVersion,
        projectKey: originalProjectKey,
      },
      sessionIds,
    );
    await writeFile("claude-sessions.json", JSON.stringify(exported));
    ```

    Run this with your app's TypeScript runner.
  </Tab>
</Tabs>

Point the importer at that file instead of a transcript directory:

```bash title="Terminal"
unset CLAUDE_SDK_TRANSCRIPT_DIR
export CLAUDE_SDK_SESSION_STORE_EXPORT="/absolute/path/to/claude-sessions.json"
```

Keep the source, agent, and user settings above. The configured SDK version and project key must match the export. Use exactly one source; do not change the version label to make an incompatible export pass.

## Map Claude agents to CopilotKit agent IDs

Map the agent key you set in `CLAUDE_SDK_AGENT_KEY` to the `agentId` your live CopilotKit Runtime uses:

```json title="agent-map.json"
{
  "support": "support-agent"
}
```

Using the same `agentId` as live traffic keeps imported history and future conversations grouped together.

## Prepare the CopilotKit Intelligence destination

A real import needs the destination app-api URL and project-scoped runtime key. A CLI-created starter writes them to `.env`, but the importer reads the current process environment and does not load `.env` or `.copilotkit/project.json` automatically.

Copy the generated values into your shell before importing:

```bash title="Terminal"
export INTELLIGENCE_API_URL="https://..."
export CPK_INTELLIGENCE_API_KEY="cpk-..."
```

`COPILOTKIT_API_KEY` is also accepted for the key. You can also pass the destination directly with `--api-url` and `--api-key` instead.

## Continue using Claude Agent SDK persistence

Keep a durable, authorized mapping from each app thread to its original native session and execution configuration. In TypeScript, configure `sessionRecovery`; in Python, configure `session_binding_store`, `resolve_profile`, and `execution_profile`. Keep access to the same working directory, native session store, tools, and provider credentials. Default in-memory mappings do not survive a backend restart.

See the adapter’s session-recovery setup for [TypeScript](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/claude-agent-sdk/typescript) or [Python](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/claude-agent-sdk/python). An unavailable imported session should return an error rather than start a new conversation.

Keep your frontend tools and UI renderers configured to display saved interactions. Supported saved native deferrals can be resumed; pending parallel or child calls are not guaranteed to recover after a backend restart.

Importing copies supported history; it does not establish ongoing database replication. Intelligence rename, archive, and delete operations affect only Intelligence records. Future runs through CopilotKit are saved to Intelligence while your SDK keeps its native session.

- **Threads Drawer:** already included in CLI-created starters. Use the [Threads Drawer guide](/prebuilt-components/copilot-threads-drawer) to customize its ready-made thread UI.
- **Headless Threads:** use the [Headless Threads guide](/headless-threads) only when you need a custom UI. Select a thread with `useThreads`, store its `thread.id`, and pass that value to your chat component as `threadId`.

Open an imported conversation and send a follow-up to continue it.
