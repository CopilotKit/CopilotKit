# How to Debug Errors

When a chat request fails, you need to see the error. In development, the Inspector shows it. In production, send it to your error tracker with `onError`.

## Quick Setup

In development builds, `CopilotKitProvider` shows the Inspector by default, so you do not need to configure it. To turn it off, set `enableInspector` to `false`:

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="<your-runtime-url>"
      enableInspector={false} // [!code highlight]
    >
      {children}
    </CopilotKitProvider>
  );
}
```

The Inspector shows only in development builds on localhost. It never shows in production, on remote hosts, or during server rendering, so end users do not see the error details.

## Programmatic Error Handling

`CopilotKitProvider` and `CopilotChat` both take an `onError` callback for programmatic error handling. No `publicApiKey` is required.

### Provider-Level Error Handling

Catches all errors across the entire application:

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";
import { errorTracker } from "./error-tracker";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        // event.code — error type (e.g. "runtime_info_fetch_failed", "agent_run_failed")
        // event.error — the Error object
        // event.context — additional context (agentId, toolName, etc.)
        console.error(`[CopilotKit ${event.code}]`, event.error.message);
        errorTracker.capture(event);
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

### Chat-Level Error Handling

This handler is scoped to a specific chat's agent and fires in addition to the provider-level handler:

```tsx
import { CopilotChat } from "@copilotkit/react-core";
import { showToast } from "./toast";

export function Chat() {
  return (
    <CopilotChat
      agentId="my-agent"
      onError={(event) => {
        showToast(`Agent error: ${event.error.message}`);
      }}
    />
  );
}
```

### Errors Replayed From Thread History

Connecting to an existing thread replays its history, including a `RUN_ERROR` from an earlier run. `onError` receives that error with the code `agent_run_error_event`, like a live failure. `event.context.phase` tells them apart: `"live"` for a run happening now, `"replay"` for thread history, and `"unknown"` when the connection can't tell.

If your handler shows a banner, skip only `"replay"`. Keep `"unknown"` visible, so a live failure is never hidden:

```tsx
import {
  CopilotKitProvider,
  CopilotKitCoreErrorCode,
} from "@copilotkit/react-core";

<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  onError={(event) => {
    errorTracker.capture(event); // Still record every error.
    if (
      event.code === CopilotKitCoreErrorCode.AGENT_RUN_ERROR_EVENT &&
      event.context.phase === "replay"
    ) {
      return; // An earlier run's failure, replayed on connect.
    }
    showErrorBanner(event.error.message);
  }}
>
  <App />
</CopilotKitProvider>
```

### Error Codes

| Code | Description |
|------|-------------|
| `runtime_info_fetch_failed` | Could not reach the runtime `/info` endpoint |
| `agent_connect_failed` | Agent connection (thread setup) failed |
| `agent_run_failed` | Agent run rejected (e.g. network error) |
| `agent_run_failed_event` | Agent's `onRunFailed` subscriber fired |
| `agent_run_error_event` | Agent sent a `RUN_ERROR` event |
| `tool_argument_parse_failed` | Tool call arguments were not valid JSON |
| `tool_handler_failed` | A frontend tool handler threw an error |

## Troubleshooting

### Development Debugging Issues

- **Inspector not showing:**
  - Confirm that the app runs as a development build on localhost
  - Confirm that `enableInspector` is not `false`
  - Check for JavaScript errors in the browser console
  - Make sure that no CSS is hiding the Inspector launcher
