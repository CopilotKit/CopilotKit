Your frontend needs a server endpoint that reaches your agents and keeps API keys off the client. The Copilot Runtime is that endpoint. You set it up during the [quickstart](/quickstart).

## Setting Up the Runtime

The runtime is a lightweight server endpoint that you add to your backend:

```npm
npm install @copilotkit/runtime @tanstack/ai-openai
```

Here's a minimal example using Next.js. `createCopilotKitRuntimeHandler` returns a
plain fetch handler. It lives at a **catch-all**
path and exports **GET, POST, PATCH, and DELETE**, so the runtime can serve its sub-routes (`/info`,
agent runs, threads) rather than a single URL:

```ts title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
import {
  CopilotRuntime,
  createCopilotKitRuntimeHandler,
  InMemoryAgentRunner,
} from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: {
    // your agents go here
  },
  runner: new InMemoryAgentRunner(),
});

const handler = createCopilotKitRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
```

With the route in place, `GET /api/copilotkit/info` returns a JSON description of the
runtime and the agents it has registered. Tooling and the frontend read this route to
discover your runtime. Open it to confirm that the endpoint works.

Then point your frontend at the endpoint:

<FrontendOnly frontend="react">
```tsx title="app/providers.tsx"
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">
      {children}
    </CopilotKitProvider>
  );
}
```

<Callout type="info">
  When you omit `useSingleEndpoint`, `<CopilotKitProvider>` negotiates the
  transport from `GET /info` and uses the REST transport that
  `createCopilotKitRuntimeHandler` serves. See [Provider and handler
  pairs](/backend/runtime-endpoints#provider-and-handler-pairs).

  To keep a single POST-only URL instead, create the handler with
  `mode: "single-route"` at a plain `route.ts`.
</Callout>
</FrontendOnly>

<FrontendOnly frontend="angular">
```ts title="src/app/app.config.ts"
import { provideCopilotKit } from "@copilotkit/angular";

provideCopilotKit({
  runtimeUrl: "/api/copilotkit",
})
```
</FrontendOnly>

For setup with other backend frameworks (Express, NestJS, Node.js HTTP), see the [quickstart](/quickstart).

## The Default Agent

If you register an agent with the name `"default"`, CopilotKit's prebuilt UI components will use it automatically without any additional configuration on the frontend. This is useful when you have one primary agent and don't want to specify an `agentId` everywhere.

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
import { HttpAgent } from "@ag-ui/client";
import { CopilotRuntime } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: {
    // Frontend APIs use this agent when no other agent id is selected.
    default: new HttpAgent({ url: "https://my-agent.example.com" }),
  },
});
```

When you register multiple agents, the `"default"` agent powers the chat unless a specific agent is selected. Other agents remain addressable through the frontend agent API.

## What the Runtime Provides

### Authentication and Security

The runtime runs on your server, which means agent communication stays server-side. This gives you a trusted environment to enforce authentication, validate requests, and keep API keys secure. The runtime does not authenticate requests by default. Add your check in the `onRequest` hook of `createCopilotKitRuntimeHandler`.

### AG-UI Middleware

The [AG-UI protocol](/agentic-protocols/ag-ui) supports a middleware layer (`agent.use`) for logging, guardrails, request transformation, and more. Because the runtime runs server-side, this middleware executes in a trusted environment where it cannot be tampered with by the client.

### Agent Routing

When you register multiple agents with the runtime, it handles discovery and routing automatically. Your frontend doesn't need to know the details of where each agent lives or how to reach it.

### CopilotKit Intelligence

Features like [threads](/AG-UI-Streams) and the [inspector](/inspector) are provided through the runtime and CopilotKit Intelligence. These give you conversation persistence and debugging capabilities with no extra setup.

## Built-in Middleware

The runtime has built-in middleware options that you can enable directly on `CopilotRuntime`, without a call to `.use()` on each agent. This section covers two of them.

### Generative UI

The `generativeUI` option gives the agent the `render_ui` tool and its guide, so it can render components in the chat. By default, it is on for each run where the client sends a catalog:

- Omitted: on for runs where the client sends a catalog. In React and Vue, the provider sends the [standard catalog](/generative-ui/components/standard-catalog) by default.
- `true`: on for every run.
- `{ agents: [...] }`: on only for these agents.
- `false`: off.

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
import { CopilotRuntime } from "@copilotkit/runtime";
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const runtime = new CopilotRuntime({
  agents: { "my-agent": new BuiltInAgent({ model: openaiText("gpt-6-luna") }) },
  generativeUI: { agents: ["my-agent"] },
});
```

An agent that writes A2UI v0.9 (for example, with the Python `copilotkit.a2ui` helpers) needs `a2uiVersion: "0.9"`. The runtime then converts its surfaces to A2UI 1.0:

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
import { HttpAgent } from "@ag-ui/client";
import { CopilotRuntime } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: { default: new HttpAgent({ url: "http://localhost:8000/" }) },
  generativeUI: { a2uiVersion: "0.9" },
});
```

See [Keep a v0.9 agent](/generative-ui/components/from-a2ui#keep-a-v09-agent).

An agent that sends A2UI 1.0 operations on the A2UI path, for example a Google ADK agent, needs no option. The runtime passes them through as they are. See [Keep an agent that sends A2UI 1.0](/generative-ui/components/from-a2ui#keep-an-agent-that-sends-a2ui-10).

<FrontendOnly frontend="angular">
Angular has no default catalog. Add `provideGenerativeUI` to the root providers:

```ts title="src/app/app.config.ts"
import type { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import {
  provideGenerativeUI,
  standardUI,
} from "@copilotkit/angular/generative-ui";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({ runtimeUrl: "/api/copilotkit" }),
    provideGenerativeUI({ ui: standardUI }),
  ],
};
```
</FrontendOnly>

To use your own components or colors, see [Components and surfaces](/generative-ui/components) and [Theme the components](/generative-ui/components/theming).

### mcpApps

Pass `mcpApps` to configure MCP servers for all agents from a single place:

```ts title="app/api/copilotkit/[[...slug]]/route.ts"
import { CopilotRuntime } from "@copilotkit/runtime";
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const runtime = new CopilotRuntime({
  agents: { default: new BuiltInAgent({ model: openaiText("gpt-6-luna") }) },
  mcpApps: {
    servers: [
      { type: "http", url: "http://localhost:3108/mcp", serverId: "my-server" },
    ],
  },
});
```

Each server entry optionally accepts an `agentId` field to scope that server to a single agent. Without it, the server is available to all agents.
