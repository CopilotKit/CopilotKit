When your agent builds UI on the fly, you want it to use only components you
approve. A2UI renders the agent's UI in Angular chat from a catalog that you
define. The renderer creates only components that the catalog defines.

## Install zod 3

A2UI catalogs use zod 3 schemas. A new Angular 22 app resolves `zod` to
version 4, so install version 3 explicitly:

```bash
npm install zod@^3.25.75
```

## Define a catalog

A catalog lists the components the agent may use. Each entry has a zod schema
for its props and an implementation. The implementation is an Angular
component, or a Custom Element such as a component from an existing design
system.

Create `src/app/a2ui-catalog.ts`:

```ts title="src/app/a2ui-catalog.ts"
import { Component, input } from "@angular/core";
import {
  ChildListSchema,
  CopilotA2UIChild,
  createAngularCatalog,
  type A2UICatalogDefinitions,
  type A2UIProps,
} from "@copilotkit/angular/a2ui";
import { z } from "zod";

const definitions = {
  Badge: { props: z.object({ label: z.string() }) },
  Panel: { props: z.object({ children: ChildListSchema }) },
} satisfies A2UICatalogDefinitions;

// An Angular component gets its props through a required `props` input.
@Component({
  selector: "app-panel",
  imports: [CopilotA2UIChild],
  template: `
    <section class="a2ui-column">
      @for (child of props().children; track $index) {
        <copilot-a2ui-child [child]="child" />
      }
    </section>
  `,
})
export class PanelComponent {
  readonly props = input.required<A2UIProps<typeof definitions, "Panel">>();
}

// A Custom Element gets the node's context on every update.
export class AcmeBadge extends HTMLElement {
  set context(
    ctx: { componentModel: { properties: Record<string, unknown> } } | undefined,
  ) {
    this.textContent = String(ctx?.componentModel.properties["label"] ?? "");
  }
}

export const productCatalog = createAngularCatalog(
  definitions,
  {
    Badge: { tagName: "acme-badge", element: AcmeBadge },
    Panel: PanelComponent,
  },
  { catalogId: "product-catalog", includeBasicCatalog: true },
);
```

How the two kinds of entry work:

- **Angular component**: reads its typed props from the `props` input.
  `<copilot-a2ui-child>` renders each child node from the catalog.
- **Custom Element**: pass `{ tagName, element }`. CopilotKit registers the
  element, renders it in place of the node, and assigns the node's A2UI
  `ComponentContext` to its `context` property on every update. The example
  reads static props. To resolve data bindings and write to the data model,
  use web_core's `GenericBinder`. Elements render in the browser only, not
  during server rendering.

`includeBasicCatalog: true` adds the basic components (`Text`, `Row`,
`Column`, `Button`, and others). Give each catalog a stable `catalogId`.

## Turn on A2UI in the app

Pass the catalog through the `a2ui` option of `provideCopilotKit`. Keep the
`runtimeUrl` from the [Angular quickstart](/angular):

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { productCatalog } from "./a2ui-catalog"; // [!code highlight]

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "http://localhost:8200/api/copilotkit",
      // [!code highlight:4]
      a2ui: {
        catalog: productCatalog,
        recovery: { showAfterMs: 2_000, showAfterAttempts: 2 },
      },
    }),
  ],
};
```

A catalog is required: without one, A2UI stays off even when the runtime
enables it, and CopilotKit logs a warning.

## Check the result

Ask the agent: "Show my order status in a panel with a badge." The chat renders
a `Panel` from your catalog, with the agent's text and a `Badge` inside it.

## Choose a schema strategy

A broad catalog lets the agent compose several application primitives. A fixed
catalog narrows the generated interface to a specific domain and set of
shapes. The flight example keeps its component vocabulary deliberately small.
Its `dynamicString` helper accepts a literal or a data-model path:
`z.union([z.string(), z.object({ path: z.string() })])`.

<AngularSnippet region="a2ui-fixed-schema" />

By default, CopilotKit includes the catalog schema in agent context. Set
`includeSchema: false` only when the server already supplies equivalent schema
and generation instructions. Otherwise the agent cannot reliably know which
components and props are valid. With `includeSchema: false`, the agent context
lists only the catalog ID and the custom component names. A LangGraph A2UI
subagent then gets only the component names. To give it more, pass a
composition guide through the A2UI guidelines of the CopilotKit middleware.

## Style rendered components

Catalog components are Angular components with application-owned class
names. Style those classes in the global stylesheet so generated surfaces and
their nested elements receive the same rules:

<AngularSnippet region="a2ui-styling" />

These rules come from the Showcase. They use two color variables. Define them,
or replace them with your own colors:

```css title="src/styles.css"
:root {
  --line: #e2e8f0;
  --muted: #64748b;
}
```

Keep semantic state in explicit classes such as `a2ui-status-success` rather
than asking the model to invent colors. You can also pass an A2UI `theme`
through `provideCopilotKit` for renderer-level theme values. Catalog CSS
remains the right place for product-specific layout and visual states.

## Recover incomplete streams

An interrupted stream can leave an A2UI surface without a terminal lifecycle
event. Configure `recovery.showAfterMs` to avoid flashing recovery UI during a
normal pause and `recovery.showAfterAttempts` to wait through transient retry
attempts. The provider sample above uses two seconds and two attempts.

Use `recovery.debugExposure` only when users should see protocol diagnostics.
Keep it hidden in consumer-facing chat, or choose a collapsed or verbose mode
for internal debugging. Recovery thresholds affect client display. The server
still owns activity lifecycle status and retry behavior.

## Angular support boundaries

- **Hashbrown is unsupported.** The stable Hashbrown Angular package does not support the Angular 22 policy.
  Use A2UI with a typed catalog instead.
- **JSON Renderer is not applicable.** JSON Renderer does not provide an Angular renderer. Use A2UI for declarative Angular interfaces.
