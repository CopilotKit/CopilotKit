## What is this?

By default, agent state only updates *between* backend checkpoints, so a long tool call (writing a full document, drafting an email) reaches the UI as one burst at the end. In an agent-native app, that feels broken: users expect to watch the output appear.

**State streaming** copies one tool argument into an agent state key while the model writes the argument. Your screen, subscribed with `useAgent`, re-renders on every token.

## When should I use this?

Use state streaming when a tool's output is long-form text or a growing structured value, and you want the user to see it build up in real time. Common shapes:

- A writing agent that produces a document
- A research agent that collects a list of findings
- A planning agent that builds a step-by-step plan

## The backend: one streaming state mapping

<FrameworkSetup concept="state-streaming-setup" />

On LangGraph Python, the example also imports `langchain_openai`. Install it too: `uv add langchain-openai`. If the folder has no `pyproject.toml` yet, run `uv init` before the first `uv add`.

The backend pattern is always the same: map one streaming tool argument to one shared-state key. Each framework does this in its own way:

- LangGraph Python: `StateStreamingMiddleware` with `StateItem(...)` entries.
- LangGraph TypeScript: `copilotkitCustomizeConfig` with an `emitIntermediateState` mapping.
- Direct SDK adapters: parse partial tool arguments in the streaming loop, and emit `STATE_SNAPSHOT` whenever the mapped value changes.
- LlamaIndex and Pydantic AI: there is no per-token mapping. A backend tool sends a state snapshot after each step or tool call instead (see [Shared State](/shared-state) for those frameworks).

When the model streams that argument, CopilotKit writes every partial value into shared state before the tool finishes.

A few things to note:

- The state key must exist in your agent state (`document` in this example).
- The tool and argument names must match the exact tool call the model makes (`write_document.document` here).
- Streamed values are previews. When the step ends, the state the agent saves replaces them, so save the final value when the tool finishes. On CrewAI, LlamaIndex, and Pydantic AI, write the final value to the agent state yourself, or it is overwritten when the step returns.

## Serve the agent

Serve the agent and register it in Copilot Runtime as `default`, the id the frontend below uses. For LangGraph Python, add a `langgraph.json` next to the agent file:

```json title="langgraph.json"
{
  "dependencies": ["."],
  "graphs": {
    "default": "./shared_state_streaming.py:graph"
  }
}
```

Start the LangGraph server with your model key in the environment:

```bash
uv add "langgraph-cli[inmem]"
export OPENAI_API_KEY=sk-...
uv run langgraph dev --port 8123 --no-browser
```

Then register the graph in the `server.ts` from the [quickstart](/quickstart), in place of the `default` agent there:

```ts title="server.ts"
import { LangGraphAgent } from "@copilotkit/runtime/langgraph";

const runtime = new CopilotRuntime({
  agents: {
    default: new LangGraphAgent({ // [!code highlight:4]
      deploymentUrl: "http://localhost:8123",
      graphId: "default",
    }),
  },
});
```

Restart the runtime with `npx tsx server.ts`. For other frameworks, follow the quickstart of your framework.

## The frontend: useAgent and OnStateChanged

The app side is the same as any other [shared-state](/shared-state) subscription: `useAgent` with `OnStateChanged` gives you a live `agent.state`. Add `OnRunStatusChanged` for a "writing" indicator.

<Callout type="warn" title="Read the partial tool argument on React Native">
  When the backend maps the argument with a predict-state mapping (for example LangGraph Python `StateStreamingMiddleware`), `@copilotkit/react-native` does not copy the streamed argument into `agent.state` yet. `agent.state.document` then changes only when the tool call ends. Until then, the view below reads the partial `document` argument of `write_document` from the agent's events. This also works when the backend sends state snapshots itself.
</Callout>

```tsx title="src/DocumentView.tsx"
import { useEffect, useState } from "react";
import { ActivityIndicator, ScrollView, Text, View } from "react-native";
import { useAgent, UseAgentUpdate } from "@copilotkit/react-native/headless";

export function DocumentView() {
  const { agent } = useAgent({ // [!code highlight:4]
    agentId: "default",
    updates: [UseAgentUpdate.OnStateChanged, UseAgentUpdate.OnRunStatusChanged],
  });
  const [preview, setPreview] = useState("");

  useEffect(() => { // [!code highlight:14]
    const { unsubscribe } = agent.subscribe({
      onRunStartedEvent: () => setPreview(""),
      onToolCallArgsEvent: ({ toolCallName, partialToolCallArgs }) => {
        if (toolCallName !== "write_document") return;
        const args = readArgs(partialToolCallArgs);
        if (typeof args.document === "string") setPreview(args.document);
      },
    });
    return unsubscribe;
  }, [agent]);

  const saved = (agent.state as { document?: string } | undefined)?.document ?? "";
  const document = agent.isRunning && preview ? preview : saved;

  return (
    <View style={{ padding: 16, gap: 8 }}>
      {agent.isRunning ? <ActivityIndicator /> : null}
      <ScrollView style={{ maxHeight: 320 }}>
        <Text>{document}</Text>
      </ScrollView>
    </View>
  );
}

// The partial arguments can arrive as a JSON string, or as an empty string at first.
function readArgs(args: unknown): { document?: unknown } {
  if (typeof args !== "string") return (args ?? {}) as { document?: unknown };
  try {
    return JSON.parse(args);
  } catch {
    return {};
  }
}
```

While the run is active, `preview` grows on every token. When the run ends, the view shows the saved `agent.state.document`. `agent.isRunning` also tells you whether to show the indicator. The `ScrollView` with a `maxHeight` keeps a long document from pushing the rest of the screen away.

Render `<DocumentView />` above your chat, inside `CopilotKitProvider`, as in [Render agent state in your app](/shared-state/rendering-in-app).

If a fast stream re-renders a heavy screen too often, pass `throttleMs` to `useAgent` to batch the updates.

## Try it

Ask the agent to write a short poem. The `document` text grows on your screen while the agent writes. When the run ends, `agent.isRunning` is `false`, so the indicator goes away.
