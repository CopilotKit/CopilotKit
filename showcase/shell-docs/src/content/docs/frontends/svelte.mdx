`@copilotkit/svelte` is the initial Svelte 5 frontend for CopilotKit. It provides
a context provider, rune-based state factories, lifecycle-managed tool
registrations, and chat components backed by [Copilot Runtime](/backend/copilot-runtime).

<Callout type="warn" title="Initial compatibility release">
  The package covers the basic chat and agent interaction path. Check the
  compatibility table below before replacing a React, Angular, or Vue frontend
  that depends on advanced renderers or developer tooling.
</Callout>

## Requirements

- Svelte 5
- Node.js 20 or later
- A Copilot Runtime endpoint

## Add the provider and styles

Place the provider above every component that uses a CopilotKit factory or
registration. Import the public stylesheet once at the application root.

```svelte title="src/routes/+layout.svelte"
<script lang="ts">
  import "@copilotkit/svelte/styles.css";
  import { CopilotKitProvider } from "@copilotkit/svelte";

  let { children } = $props();
</script>

<CopilotKitProvider runtimeUrl="/api/copilotkit">
  {@render children()}
</CopilotKitProvider>
```

## Render chat

```svelte title="src/routes/+page.svelte"
<script lang="ts">
  import { CopilotChat } from "@copilotkit/svelte";
</script>

<div class="chat-shell">
  <CopilotChat agentId="default" />
</div>

<style>
  .chat-shell {
    height: 700px;
  }
</style>
```

The runtime must expose the selected agent ID. If `agentId` is omitted, the
chat uses the runtime's `default` agent.

## Compatibility

| Area | Initial Svelte support | Notes |
| --- | --- | --- |
| Runtime connection and AG-UI streaming | Supported | Includes message updates, run state, and agent state invalidation. |
| Inline chat | Supported | Use `CopilotChat`; lower-level chat and message components are also exported. |
| Popup and sidebar chat | Partial | The surfaces render, but closing an instance without an explicit `threadId` currently resets its generated chat state. |
| Frontend tools | Supported | Register with `registerFrontendTool`; registrations clean up with their component. |
| Agent context | Supported | Connect reactive application data with `connectAgentContext`. |
| Suggestions | Observation only | `createSuggestions` observes suggestions already present in core; Svelte does not yet register suggestion-generation configuration. |
| Threads | Experimental headless API | `createThreads` is available, but runtime-transport and store-lifecycle parity still need follow-up work; a prebuilt threads drawer is not included. |
| Interrupts | Headless | Observe and resolve AG-UI interrupts with `createInterrupt`. |
| Attachments | Experimental headless API | Direct validation/upload helpers exist, but DOM refs and chat-composer wiring are not production-ready. |
| Tool-call rendering | Registration only | Renderer registration exists, but the prebuilt chat currently shows generic tool status unless the host supplies a custom tool-call slot. |
| Human approval | Custom UI required | `registerHumanInTheLoop` matches concurrent calls by tool-call ID, but the prebuilt chat does not yet mount its renderer; the provider-level `humanInTheLoop` prop is not ready. |
| A2UI and Open Generative UI | Not yet supported | Built-in catalogs, renderers, and sandbox helpers are planned. |
| CoAgent/LangGraph state renderers | Not yet supported | Use the lower-level agent binding for state today. |
| Memories and learning APIs | Not yet supported | No Svelte-specific bindings are included in this release. |
| Modal, threads drawer, audio input | Not yet supported | Build these surfaces from the exported state factories where possible. |
| Inspector and developer console | Not yet supported | Use Runtime and browser diagnostics while developing. |

## Reactive agent state

Stateful APIs use `create*` names because they create rune-backed state and
subscriptions. Keep the returned object intact and read its live getters in
markup; plain destructuring snapshots a getter and loses reactivity.

```svelte
<script lang="ts">
  import { createAgent, useCopilotKit } from "@copilotkit/svelte";

  const agentHandle = createAgent({ agentId: "default" });
  const { copilotkit } = useCopilotKit();

  async function send(content: string) {
    const agent = agentHandle.agent;
    if (!agent) return;

    agent.addMessage({
      id: crypto.randomUUID(),
      role: "user",
      content,
    });
    await copilotkit.runAgent({ agent });
  }
</script>

{#if agentHandle.isRunning}
  <p>Agent is thinking…</p>
{/if}
```

Use `$derived` only when you want a local alias or computed value:

```svelte
<script lang="ts">
  const { messages, isRunning } = $derived(agentHandle);
</script>
```

## Register a frontend tool

Registration APIs use `register*` names. They register during component setup
and unregister when the component is destroyed.

```svelte
<script lang="ts">
  import { registerFrontendTool } from "@copilotkit/svelte";
  import { z } from "zod";

  registerFrontendTool({
    name: "showToast",
    description: "Show a notification in the browser",
    parameters: z.object({ message: z.string() }),
    handler: async ({ message }) => {
      alert(message);
      return "Notification shown";
    },
  });
</script>
```

Set `agentId` to scope a registration to one agent. Omit it to make the tool
available to every agent connected through the provider.

## API naming

| React concept | Svelte 5 API |
| --- | --- |
| `useAgent` | `createAgent` |
| `useFrontendTool` | `registerFrontendTool` |
| `useAgentContext` | `connectAgentContext` |
| `useRenderTool` | `registerRenderToolCall` |
| Provider accessor | `useCopilotKit` |

React V1 names such as `useCopilotAction`, `useCopilotReadable`, and
`useCopilotChat` are not part of the Svelte API. Prefer the Svelte `create*`,
`register*`, and `connect*` functions.
