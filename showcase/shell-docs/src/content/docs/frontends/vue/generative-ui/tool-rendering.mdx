## What is this?

Tools are named functions an agent can call. Tool rendering turns their arguments, execution state, and result into purposeful UI rather than a generic transcript entry.

## When should I use this?

Use a renderer when users should see what a backend tool is doing: a progress card, preview, structured result, or domain-specific explanation. The renderer observes a tool; it does not implement that tool's server-side behavior.

Handle partial parameters while arguments stream, an executing state while the tool runs, and the completed result. An explicit schema and render-prop type keep the intended payload visible.

<Callout type="info">
Current renderer/schema inference is permissive in some paths. Prefer an explicit schema and explicit render-prop type when the UI depends on a precise payload. Positive compilation alone does not prove every incompatible renderer or typo would be rejected.
</Callout>

## Default tool rendering

Call [`useDefaultRenderTool`](/reference/vue/hooks/useDefaultRenderTool) with no configuration to register CopilotKit's expandable default card for otherwise unhandled tools. Supply its `render` option for one wildcard fallback. A specifically named `useRenderTool` renderer takes precedence for that tool.

For a component that itself becomes a frontend tool, use [Display-only](/vue/generative-ui/your-components/display-only). A `tool-call-{name}` chat slot is another Vue-specific option when customization belongs directly to one chat instance.
