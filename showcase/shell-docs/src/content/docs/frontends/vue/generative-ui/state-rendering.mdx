## What is this?

State rendering lets you build UI that reflects your agent's state in real-time. As your agent progresses through nodes and emits state updates, your frontend renders those changes, showing progress, drafts, or intermediate results.

## When should I use this?

Use state rendering when you want to:

- Show real-time progress (for example, "Researching... 2/5 complete")
- Display drafts that update as the agent works
- Build dashboards that reflect agent state
- Render structured output outside of the chat

## How it works in code

On the frontend, subscribe to the agent's state. Each time the backend sends a new state, your component re-renders. `useAgent` returns an `agent` ref. Read `agent.value?.state` in script, or let templates unwrap the ref. Keep the provider in an ancestor SFC.

The component reads the `document` key that the backend example below writes:

```vue title="src/components/ResearchProgress.vue"
<script setup lang="ts">
import { computed } from "vue";
import { useAgent, UseAgentUpdate } from "@copilotkit/vue/v2";

type DocumentState = { document?: string };

const { agent } = useAgent({
  agentId: "researcher",
  updates: [UseAgentUpdate.OnStateChanged, UseAgentUpdate.OnRunStatusChanged],
});

const state = computed(() => (agent.value?.state ?? {}) as DocumentState);
const isRunning = computed(() => agent.value?.isRunning ?? false);
</script>

<template>
  <section aria-live="polite">
    <p>{{ isRunning ? "Writing…" : "Idle" }}</p>
    <article v-if="state.document">{{ state.document }}</article>
  </section>
</template>
```

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
import ResearchProgress from "./components/ResearchProgress.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="http://localhost:8200/api/copilotkit">
    <ResearchProgress />
    <CopilotChat agent-id="researcher" />
  </CopilotKitProvider>
</template>
```

On the backend, the agent writes the `document` key of its state. The example below maps the `document` argument of a `write_document` tool into that key.

<Callout type="info" title="When the state updates in Vue">
  Some backends, such as LangGraph and CrewAI, send a `PredictState` mapping and
  let the client build the state from the tool argument token by token.
  `@copilotkit/vue` does not apply that mapping yet, so with these backends
  `state.document` updates when the tool call finishes. Backends that send
  `STATE_SNAPSHOT` or `STATE_DELTA` events while the model writes update the
  component as each event arrives.
</Callout>

Then connect the agent to the Vue app:

1. Install what the agent file imports. For the LangGraph Python example, also run `uv add langchain-openai`.
2. Serve the agent the way your framework quickstart shows. If you serve a LangGraph graph yourself with FastAPI, compile it with a checkpointer: pass `checkpointer=MemorySaver()` (from `langgraph.checkpoint.memory`) to `create_agent`. Without it, every run fails with `No checkpointer set`. `langgraph dev` and LangGraph Platform add one for you.
3. Register the agent in the [Vue quickstart](/vue) `server.ts` under the id `researcher`. For an agent served over AG-UI HTTP, install `@ag-ui/client` and add it next to `default`:

   ```ts title="server.ts"
   import { HttpAgent } from "@ag-ui/client";

   const runtime = new CopilotRuntime({
     agents: {
       // ...the `default` agent from the quickstart
       researcher: new HttpAgent({ url: "http://localhost:8000/" }), // your agent's URL
     },
   });
   ```

Ask the researcher agent to write a short report. "Writing…" shows while the agent runs, and the document text appears above the chat (when the tool call finishes, or as it streams, depending on your backend).

Treat agent state as untrusted external data. Validate it before using it for privileged actions, and avoid putting secrets in state that is streamed to the browser.
