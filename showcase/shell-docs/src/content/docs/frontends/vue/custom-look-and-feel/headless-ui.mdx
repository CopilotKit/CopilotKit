## What is this?

A headless UI gives your Vue application full control of layout, message rendering, input, and controls while CopilotKit continues to manage the agent connection and run lifecycle. It uses the same `useAgent` and `useCopilotKit` primitives as [Programmatic Control](/vue/programmatic-control).

## When should I use this?

Choose headless UI when slots are not enough: a substantially different chat layout, an assistant embedded into an existing workflow, or a non-chat interface that still sends messages and runs an agent. If only one supplied region needs changing, [Slots](/vue/custom-look-and-feel/slots) is less work.

## Implementation

### Access the agent and CopilotKit

`useAgent` returns a reactive agent ref. `useCopilotKit` returns the orchestration client. Request message and run-status updates so the custom view remains reactive.

### Display messages and status

Read `agent.value?.messages` defensively while the Runtime connection is resolving. Render messages using stable IDs and reflect `agent.value?.isRunning` so users understand when work is in progress.

### Send a message and run the agent

Create a user message with a browser-generated UUID, add it to the resolved agent, then call `copilotkit.value.runAgent({ agent })`. The orchestration method streams the run, executes frontend tools, handles follow-ups, and reports errors through CopilotKit.

### Stop a run

While the same agent is running, call `copilotkit.value.stopAgent({ agent })`. A custom interface should disable duplicate submission and keep cancellation reachable.
