## What is this?

Some approvals belong outside the chat, such as a dashboard button, a modal, or a test fixture. This page shows how to render the pending request anywhere in your Vue tree. The UI can be a button grid, a form, a modal, or a keyboard shortcut.

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

Set `renderInChat: false` on `useInterrupt` and render the pending interrupt anywhere. No chat needs to be mounted. On a native interrupt runtime, the backend pauses the run and sends the interrupt to the client. The Vue composable exposes it through `slotProps`, then `resolve(...)` or `cancel(...)` resumes the run using the AG-UI standard flow. The composable also supports custom `on_interrupt` events, which the LangGraph adapter sends by default. The differences between the two flows are below.

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" equals="promise-based">

For promise-based integrations there is no native interrupt primitive. Build the same headless experience with [`useHumanInTheLoop`](/vue/human-in-the-loop):

- The frontend-tool handler holds a Promise open.
- Your application state renders the picker outside the chat.
- The user's answer resolves the tool call.

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" absent>

> **Use `useHumanInTheLoop` on this framework.** Headless interrupts need an agent that emits an AG-UI interrupt or an `on_interrupt` custom event, and a working resume path. On the Built-in Agent, interrupts are temporarily unavailable. [`useHumanInTheLoop`](/vue/human-in-the-loop) pauses on a tool call instead.

</WhenFrameworkHas>

## When should I use this?

- **Testing / Playwright fixtures**: a deterministic, chat-less button grid is easier to drive than a picker that appears after an LLM call.
- **Non-chat UIs**: dashboards, side panels, inspector surfaces, or any place where you want the agent's interrupt without the transcript.
- **Custom flow control**: when you need to know exactly when the interrupt arrived and when it was resolved.
- **Research / debugging**: when you want to observe raw interrupt state without the chat abstraction.

If you just want a picker in chat, use [`useInterrupt`](./useInterrupt) with the default `renderInChat: true` and the `#interrupt` slot.

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

## The primitives

<FrameworkSetup concept="programmatic-control-setup" />

The simplest headless pattern uses `useInterrupt({ renderInChat: false })`. Instead of publishing the state into `<CopilotChat>`, the composable returns reactive refs that you place anywhere:

```vue title="src/components/ApprovalPanel.vue"
<script setup lang="ts">
import { useInterrupt } from "@copilotkit/vue/v2";

const { slotProps } = useInterrupt({
  agentId: "interrupt-headless",
  renderInChat: false,
});
</script>

<template>
  <section v-if="slotProps" class="approval-panel">
    <p>{{ slotProps.interrupt?.message ?? "Approve this action?" }}</p>
    <button @click="slotProps.resolve({ approved: true })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
</template>
```

`interrupt` carries the primary AG-UI `Interrupt` object (`{ id, reason, message?, responseSchema?, expiresAt?, ... }`). `resolve(payload)` submits the user's response; `cancel()` submits a cancelled response. Both return a `Promise<RunAgentResult | void>`. The result is `void` while waiting on further interrupts when more than one is open.

Internally, `useInterrupt` composes two public APIs:

1. **`agent.subscribe({ onCustomEvent, onRunStartedEvent, onRunFinishedEvent, onRunFinalized, onRunFailed })`**: standard interrupts arrive on `onRunFinishedEvent` with `{ outcome: "interrupt", interrupts: [...] }`. Custom-event interrupts (the LangGraph adapter default) arrive as a custom event named `on_interrupt`.
2. **`copilotkit.runAgent({ agent, resume })`** for the standard transport, or **`copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })`** for the custom-event transport. These are the same calls that `resolve()` and `cancel()` make.

The composable is careful to:

- Surface a standard interrupt only after the run finalizes, so the picker does not flash while the run is still streaming.
- Clear stale pending state when a new run starts.
- Drop staged state after a failed run so a transport error does not leave the UI stuck.

</WhenFrameworkHas>

## The primitives

Register a `useHumanInTheLoop` tool with a Vue render component that reflects the pending request into application state. The tool's handler remains pending until something calls `respond(...)`. No runtime interrupt is involved.

Keep the pending request in a shared ref:

```ts title="src/approval-store.ts"
import { ref } from "vue";

export const pendingApproval = ref<{
  toolCallId: string;
  reason: string;
  respond: (result: unknown) => Promise<void>;
} | null>(null);
```

The render component receives `respond` only while the tool call is executing. It hands the request to the store and renders nothing in the chat:

```vue title="src/components/ApprovalBridge.vue"
<script setup lang="ts">
import { watchEffect } from "vue";
import { pendingApproval } from "../approval-store";

const props = defineProps<{
  toolCallId: string;
  args: { reason?: string };
  respond?: (result: unknown) => Promise<void>;
}>();

watchEffect(() => {
  if (props.respond) {
    pendingApproval.value = {
      toolCallId: props.toolCallId,
      reason: props.args.reason ?? "",
      respond: props.respond,
    };
  }
});
</script>

<template></template>
```

Register the tool, and render the picker from the store anywhere in your app:

```vue title="src/components/HeadlessApprovalPanel.vue"
<script setup lang="ts">
import { z } from "zod";
import { useHumanInTheLoop } from "@copilotkit/vue/v2";
import ApprovalBridge from "./ApprovalBridge.vue";
import { pendingApproval } from "../approval-store";

useHumanInTheLoop({
  name: "request_approval",
  description: "Ask the user to approve an action before it runs.",
  parameters: z.object({ reason: z.string() }),
  render: ApprovalBridge,
});

async function answer(approved: boolean) {
  const pending = pendingApproval.value;
  if (!pending) return;
  pendingApproval.value = null;
  await pending.respond({ approved });
}
</script>

<template>
  <section v-if="pendingApproval">
    <p>{{ pendingApproval.reason }}</p>
    <button @click="answer(true)">Approve</button>
    <button @click="answer(false)">Reject</button>
  </section>
</template>
```

Keep these rules:

- If the agent can call the tool several times at once, key pending requests by tool-call id.
- Clear the pending state after the user responds.
- If the picker lives elsewhere, render nothing from the render component.

## Provider setup

The chat renders tool calls, so it mounts the render component. Keep `<CopilotChat>` mounted, even if the picker lives elsewhere:

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotChat, CopilotKitProvider } from "@copilotkit/vue/v2";
import HeadlessApprovalPanel from "./components/HeadlessApprovalPanel.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <HeadlessApprovalPanel />
    <CopilotChat />
  </CopilotKitProvider>
</template>
```

Ask the agent to do something that needs approval. The panel shows the reason with Approve and Reject. Click **Approve**, and the agent continues with `{ approved: true }`.

</WhenFrameworkHas>

## Driving it from plain UI

Combine `useAgent`, `useCopilotKit`, and the headless interrupt state when the same page needs to start the run and resolve its pause:

```vue title="src/components/HeadlessInterruptPanel.vue"
<script setup lang="ts">
import { toRaw } from "vue";
import { useAgent, useCopilotKit, useInterrupt } from "@copilotkit/vue/v2";

const { agent } = useAgent({ agentId: "interrupt-headless" });
const { copilotkit } = useCopilotKit();
const { slotProps } = useInterrupt({
  agentId: "interrupt-headless",
  renderInChat: false,
});

async function kickOff(prompt: string) {
  const current = agent.value;
  if (!current || current.isRunning) return;

  current.addMessage({
    id: crypto.randomUUID(),
    role: "user",
    content: prompt,
  });
  await copilotkit.value.runAgent({ agent: toRaw(current) });
}
</script>

<template>
  <section v-if="slotProps">
    <p>{{ slotProps.interrupt?.message ?? "Pick an option" }}</p>
    <button @click="slotProps.resolve({ choice: 'approve' })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
  <button v-else @click="kickOff('Prepare the governed action.')">
    Start
  </button>
</template>
```

If you need custom accumulation logic or a deterministic test fixture, subscribe to the agent directly. For ordinary product UI, the public `useInterrupt` composable already handles standard and custom-event transports, multiple interrupts, cleanup, and resume submission.

## Provider setup

The component calling these composables must be below `CopilotKitProvider`:

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
import HeadlessInterruptPanel from "./components/HeadlessInterruptPanel.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <HeadlessInterruptPanel />
  </CopilotKitProvider>
</template>
```

Click **Start**. The agent pauses, and the panel shows **Approve** and **Cancel**. Click **Approve**, and the run continues.
