## What is this?

The `#interrupt` slot is the 80% path: it keeps the UI attached to a `<CopilotChat>` transcript and handles when to show the picker. This page covers the escape hatch: set `renderInChat: false` and render the reactive interrupt state anywhere in your Vue tree. The UI can take any shape — button grid, form, modal, keyboard shortcut — and no chat needs to be mounted.

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

On a native interrupt runtime, the backend pauses the run and sends the interrupt to the client. The Vue composable exposes it through `slotProps`, then `resolve(...)` or `cancel(...)` resumes the run using the current AG-UI standard flow. Legacy `on_interrupt` events are also supported, with the transport differences described below.

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" equals="promise-based">

For promise-based integrations there is no native interrupt primitive. Build the same headless experience with `useHumanInTheLoop`: its frontend-tool handler holds a Promise open, application state renders the picker outside chat, and the user's answer resolves the tool call.

</WhenFrameworkHas>

<WhenFrameworkHas flag="interrupt_pattern" absent>

> **Not available on this framework.** Headless runtime interrupts require a native interrupt transport. For other integrations, use [`useHumanInTheLoop`](../human-in-the-loop) for a tool-call-based pause/resume flow.

</WhenFrameworkHas>

## When should I use this?

- **Testing / Playwright fixtures** — a deterministic, chat-less button grid is easier to drive than a picker that appears after an LLM call.
- **Non-chat UIs** — dashboards, side panels, inspector surfaces, or any place where you want the agent's interrupt without the transcript.
- **Custom flow control** — when you need to know exactly when the interrupt arrived and when it was resolved.
- **Research / debugging** — when you want to observe raw interrupt state without the chat abstraction.

If you just want a picker in chat, use [`useInterrupt`](./useInterrupt) with the default `renderInChat: true` and the `#interrupt` slot.

<WhenFrameworkHas flag="interrupt_pattern" equals="native">

## The primitives

<FrameworkSetup concept="programmatic-control-setup" />

The simplest headless pattern uses `useInterrupt({ renderInChat: false })`. Instead of publishing the state into `<CopilotChat>`, the composable returns reactive refs that you place anywhere:

```vue title="src/components/ApprovalPanel.vue"
<script setup lang="ts">
import { useInterrupt } from "@copilotkit/vue/v2";

const { slotProps } = useInterrupt({
  agentId: "interrupt-headless",
  renderInChat: false,
});
</script>

<template>
  <section v-if="slotProps" class="approval-panel">
    <p>{{ slotProps.interrupt?.message ?? "Approve this action?" }}</p>
    <button @click="slotProps.resolve({ approved: true })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
</template>
```

`interrupt` carries the primary AG-UI `Interrupt` object (`{ id, reason, message?, responseSchema?, expiresAt?, ... }`). `resolve(payload)` submits the user's response; `cancel()` submits a cancelled response. Both return a `Promise<RunAgentResult | void>` — `void` while waiting on further interrupts when more than one is open.

Under the hood, `useInterrupt` composes two public APIs:

1. **`agent.subscribe({ onCustomEvent, onRunStartedEvent, onRunFinishedEvent, onRunFinalized, onRunFailed })`** — standard interrupts arrive on `onRunFinishedEvent` with `{ outcome: "interrupt", interrupts: [...] }`; legacy interrupts arrive as a custom event named `on_interrupt`.
2. **`copilotkit.runAgent({ agent, resume })`** for the standard transport, or **`copilotkit.runAgent({ agent, forwardedProps: { command: { resume, interruptEvent } } })`** for the legacy transport — the same calls `resolve()` and `cancel()` make.

The composable is careful to:

- Surface a standard interrupt only after the run finalizes, so the picker does not flash while the run is still streaming.
- Clear stale pending state when a new run starts.
- Drop staged state after a failed run so a transport error does not leave the UI stuck.

</WhenFrameworkHas>

## The primitives

Register a `useHumanInTheLoop` tool with a Vue render component that reflects the pending request into application state. The tool's handler remains pending until the component calls `respond(...)`; no runtime interrupt or chat slot is involved.

Keep concurrent calls separate by tool-call id, clear pending state after the user responds, and make the render component visually empty if the actual picker lives elsewhere in the app.

</WhenFrameworkHas>

## Driving it from plain UI

Combine `useAgent`, `useCopilotKit`, and the headless interrupt state when the same page needs to start the run and resolve its pause:

```vue title="src/components/HeadlessInterruptPanel.vue"
<script setup lang="ts">
import { toRaw } from "vue";
import { useAgent, useCopilotKit, useInterrupt } from "@copilotkit/vue/v2";

const { agent } = useAgent({ agentId: "interrupt-headless" });
const { copilotkit } = useCopilotKit();
const { slotProps } = useInterrupt({
  agentId: "interrupt-headless",
  renderInChat: false,
});

async function kickOff(prompt: string) {
  const current = agent.value;
  if (!current || current.isRunning) return;

  current.addMessage({
    id: crypto.randomUUID(),
    role: "user",
    content: prompt,
  });
  await copilotkit.value.runAgent({ agent: toRaw(current) });
}
</script>

<template>
  <section v-if="slotProps">
    <p>{{ slotProps.interrupt?.message ?? "Pick an option" }}</p>
    <button @click="slotProps.resolve({ choice: 'approve' })">Approve</button>
    <button @click="slotProps.cancel()">Cancel</button>
  </section>
  <button v-else @click="kickOff('Prepare the governed action.')">
    Start
  </button>
</template>
```

If you need custom accumulation logic or a deterministic test fixture, subscribe to the agent directly. For ordinary product UI, the public `useInterrupt` composable already handles standard and legacy transports, multiple interrupts, cleanup, and resume submission.

</WhenFrameworkHas>

## Provider setup

The component calling these composables must be below `CopilotKitProvider`:

```vue title="src/App.vue"
<script setup lang="ts">
import { CopilotKitProvider } from "@copilotkit/vue/v2";
import HeadlessInterruptPanel from "./components/HeadlessInterruptPanel.vue";
</script>

<template>
  <CopilotKitProvider runtime-url="/api/copilotkit">
    <HeadlessInterruptPanel />
  </CopilotKitProvider>
</template>
```
