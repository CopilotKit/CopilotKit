Rich Threads give users durable conversations rather than page-local chat sessions. A user can leave, return on another device, reopen a conversation, and continue from the same AG-UI event history. Messages, tool activity, state, generative UI, multimodal inputs, and an active run can all participate in that restored experience.

## Get started

Rich Threads run on CopilotKit Enterprise Intelligence. Create or select an Intelligence project through the CopilotKit CLI, keep its project credential on the Runtime, and verify persistence by creating a conversation, reloading, and reopening it. Threads-capable starters include the prebuilt drawer.

### Production self-hosting

Cloud hosting is the shortest path for development. Organizations that need infrastructure and data-residency control can deploy Enterprise Intelligence in their own Kubernetes environment with CopilotKit Engineering. The Vue client API and thread model stay the same.

## Why use CopilotKit Rich Threads?

Without Rich Threads, an application must design storage, replay historical events and generative UI, retain multimodal inputs, reconnect live streams, synchronize conversation lists, coordinate concurrent runs, and implement lifecycle APIs.

CopilotKit provides:

- durable event history across reloads, sessions, and devices
- replay followed by seamless reconnection to an active run
- restored generative UI, tool activity, state, and multimodal inputs
- realtime thread-list updates without polling
- automatic names plus rename, archive, unarchive, delete, and pagination
- thread-level locking so concurrent runs cannot interleave
- one user-facing persistence model across agent frameworks

## How Threads work

A stable `threadId` connects the visible conversation, Copilot Runtime, and its durable event history:

1. The Vue UI opens or starts a conversation under a `threadId`.
2. Copilot Runtime executes the agent and records conversation events through Enterprise Intelligence.
3. Returning clients replay stored events, reconnect an active stream, and receive synchronized thread metadata.

Your application still owns agent behavior, which lifecycle controls users may access, authorization, and any mapping to a framework-native session or checkpoint.

## Sync existing conversations

Rich Threads capture new CopilotKit conversations after Intelligence is connected. If you already persist supported framework conversations, [Import & Synchronize Thread History](/vue/threads-import) explains how they relate to the same user-facing thread store. Keep native framework storage when you still need its checkpoints and analytics; the two layers are correlated by `threadId`, not automatically treated as one database.
