Rich Threads persist a conversation independently of the page that renders it. When a user reopens a thread, CopilotKit restores its history and the chat reconnects to that conversation. A threads-enabled project also synchronizes thread changes for the signed-in user.

The provider supplies the runtime connection; the configuration provider owns the selected thread and agent context shared by the drawer and chat.

## Choose the right surface

- Use [Threads Drawer](/vue/prebuilt-components/copilot-threads-drawer) for a supplied switcher.
- Use [Headless Threads](/vue/headless-threads) when you need your own list and controls.
- See [Thread lifecycle](/vue/threads-lifecycle) for creation, restoration, and deletion semantics.

Rich Threads require a configured Enterprise Intelligence project and its appropriate license/runtime settings. They are not a replacement for an agent framework's internal checkpointing; use them for the user-facing conversation lifecycle.
