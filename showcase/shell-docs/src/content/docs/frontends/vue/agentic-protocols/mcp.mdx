## Introduction

The Model Context Protocol (MCP) is an open standard for secure, two-way connections between AI applications and external data sources or tools. It lets you connect an agent to data, make those tools available securely, and build AI features with application context.

For protocol background, see the [Model Context Protocol introduction](https://modelcontextprotocol.io/introduction).

<Callout type="info" title="Looking for MCP Apps?">
  When an MCP server returns interactive UI that should render in chat, see [MCP Apps](/vue/generative-ui/mcp-apps). MCP Apps is a distinct server-hosted UI path; it does not establish the MCP tool connection described on this page.
</Callout>

MCP is one of the agentic protocols CopilotKit uses to connect agents to user-facing frontends.

## How the responsibilities divide

- **MCP server:** exposes data and tools over an MCP transport and owns any server-side authentication requirements.
- **CopilotKit runtime:** creates the MCP client, discovers tools, invokes them, and relays their activity through the agent run.
- **Vue frontend:** connects to the CopilotKit runtime and may render tool-call events. It should not own private MCP credentials or create the server-side MCP client.

This separation keeps external credentials and data access on the trusted server side while AG-UI carries agent activity to the browser.

## Quickstart with CopilotKit

### Get an MCP server

Start with an MCP endpoint you control or have configured, such as an SSE endpoint from a provider or your own MCP server. Keep server authentication and credentials on the trusted side of your deployment.

### CLI setup

The React quickstart offers `npx copilotkit@latest init -m MCP` for a Next.js application. Repository evidence does not establish a corresponding Vue initializer or generated Vue configuration, so this guide does not present that command as a Vue setup path.

### Dynamic server configuration

There is currently no supported, verified Vue frontend configuration path for selecting MCP servers.

`CopilotKitProvider` can forward generic request properties, but the current runtime invocation of its MCP tool resolver does not pass those request properties into the resolver. Consequently, setting `properties.mcpServers` in Vue does not establish the MCP tools. The React page's dynamic `setMcpServers` journey also lacks a verified current Vue counterpart.

<Callout type="warning" title="Current Vue limitation">
  No end-to-end MCP setup is shown because repository evidence does not support a working Vue frontend configuration path. Configure and validate MCP at the runtime/agent boundary appropriate to your deployment; do not treat provider properties as an MCP API.
</Callout>

### Add the chat interface

Once an independently configured agent exposes MCP-backed tools through the runtime, a normal Vue chat surface can display their AG-UI events. The [Vue Quickstart](/vue) documents the supported provider, runtime URL, agent ID, and chat composition. That connection alone does not configure MCP.

### Visualize MCP tool calls

MCP tools are ordinary backend tool calls once the runtime resolves them. Use [`useRenderTool`](/reference/vue/hooks/useRenderTool) for a named tool, [`useDefaultRenderTool`](/reference/vue/hooks/useDefaultRenderTool) as a wildcard fallback, or a `tool-call-{name}`/`tool-call` slot on the chat. A renderer should handle partial arguments, `inProgress`/`executing` work, and the completed result.

## Advanced Usage

### Implementing an MCP tool-call component

For a custom card, display the tool name, parameters, lifecycle status, and result. Keep the rendering separate from the tool implementation: the backend or MCP server owns execution; the Vue renderer only observes its events. A named renderer has priority over the wildcard fallback, so use a named card for important tools and one default renderer for the rest.

### Self-hosting option

Self-hosting does not move MCP connection logic to the browser. The trusted runtime or agent layer must own the MCP client, outbound transport, credentials, authorization, and tool discovery. The Vue app may render resulting tool-call events, but this guide does not claim a complete static runtime configuration path without verified end-to-end evidence. See [Architecture](/vue/concepts/architecture) for the layer boundary.
