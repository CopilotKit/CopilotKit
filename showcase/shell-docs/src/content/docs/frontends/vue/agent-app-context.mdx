## What is this?

`useAgentContext` registers JSON-serializable application information that helps an agent understand the current user, page, selection, cart, project, or product state. Context is included with agent runs; it does not give the agent a mutation API for that data.

## When should I use this?

- the agent should understand the current screen or selection
- responses depend on user role, preferences, or application domain
- component-local data should inform the agent without hardcoding it into a system prompt
- multiple product areas should contribute their own descriptions

Use [Shared State](/vue/shared-state) when the agent should also update the data.

## No backend setup needed

The Built-in Agent receives registered context through CopilotKit automatically. Keep values serializable and limited to the data required for the task; do not put browser secrets or unrestricted sensitive records into prompt context.

## Multiple contexts

Call `useAgentContext` from multiple descendant components. CopilotKit combines the active entries, and each registration is removed when its Vue scope is disposed. This allows a user-profile component, page component, and selected-item component to contribute independently.

## Dynamic and reactive context

The description and value accept plain values, refs, computeds, or getters. Prefer a getter or computed when context depends on reactive state. CopilotKit refreshes the entry when its resolved value changes, so manual re-registration is unnecessary.

## Context versus shared state

| Need | Use |
| --- | --- |
| Give the agent read-only background about the app or user | `useAgentContext` |
| Let the agent and Vue UI read and update the same application state | `useAgent` shared state |

See [`useAgentContext`](/reference/vue/hooks/useAgentContext) for serialization, reactivity, and lifecycle details.
