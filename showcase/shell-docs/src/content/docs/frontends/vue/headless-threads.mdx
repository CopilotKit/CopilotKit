## What is this?

`useThreads` is the headless Vue data and action layer for Enterprise Intelligence threads. It lists and paginates conversations, exposes loading and failure state, performs lifecycle mutations, and keeps metadata synchronized in realtime. Your component owns layout, permissions, confirmation, and feedback.

Use it when users need saved conversations across sessions or devices but the supplied [Threads Drawer](/vue/prebuilt-components/copilot-threads-drawer) does not fit your workflow.

## Prerequisites

- A Vue application connected to an Intelligence-enabled Copilot Runtime
- A stable agent ID
- A server-verified signed-in user in multi-user applications

If you are importing existing framework history, first read [Import & Synchronize Thread History](/vue/threads-import).

The fixture demonstrates:

- pagination with separate progress and fetch-more failure feedback
- deliberate rename, archive, and permanent delete controls
- waiting for mutation confirmation and surfacing rejected promises

Thread rows are ordered by recent activity and synchronized from other connected clients. Rename, archive, and delete are pessimistic: the visible list changes only after the server confirms the operation.

<Callout type="warn" title="Archive and delete differ">
Archive is recoverable and hidden from the default list; `includeArchived: true` can include archived rows and `unarchiveThread` restores them. Delete permanently removes the thread and history. `useThreads` does not provide confirmation dialogs, so your UI must ask before destructive actions.
</Callout>

## Switching and restoration

Selecting an existing row marks its ID explicit. `CopilotChat` clears the previous view, connects that thread, replays stored events, and rejoins an active run when one exists. Starting a new conversation creates a non-explicit ID and skips replay because no history exists yet.

Thread metadata belongs to Enterprise Intelligence. A native framework session or checkpoint store is separate unless your backend maps the shared `threadId`.
