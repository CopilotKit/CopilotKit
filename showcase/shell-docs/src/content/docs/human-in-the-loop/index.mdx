## What is this?

Human-in-the-loop (HITL) lets an agent ask for input, confirmation, or a
choice before it continues. The agent requests a choice, the UI renders it, and
the answer returns as the tool result.

## When should I use this?

Use HITL when you need:

- **Quality control** — a human gate at high-stakes decision points
- **Edge cases** — graceful fallbacks when the agent's confidence is low
- **Expert input** — lean on the user for domain knowledge the model lacks
- **Reliability** — a more robust loop for real-world, production traffic

## Start with the supported tool-based pattern

On a framework route that declares frontend-tool support, the model decides
when to ask, the chat renders the choice, and the selected answer resumes the
same run.

## Tool-based approval — `useHumanInTheLoop`

The agent registers a HITL tool on the client with
[`useHumanInTheLoop`](/reference/hooks/useHumanInTheLoop).
When the LLM calls that tool, CopilotKit routes the call through your
`render` function, which shows a custom component and calls `respond`
with the user's answer. The agent sees the answer as the tool result and
continues from there.

## Approval outside the chat — async `useFrontendTool`

<InlineDemo demo="hitl-in-app" />

Some decisions belong in your app rather than in the transcript: a modal, a
side panel, or a review queue. Register the tool with
[`useFrontendTool`](/reference/hooks/useFrontendTool) and give it an async
handler. The handler returns a Promise and stores that Promise's `resolve`
function in React state, which opens the app's approval dialog. The agent's
tool call stays pending until your UI calls `resolve`; the value you pass
becomes the tool result.

<Snippet cell="hitl-in-app" region="frontend-tool-registration" title="frontend/src/app/page.tsx — useFrontendTool with an async handler" />

The dialog is ordinary app UI rendered outside `<CopilotPopup>`. Its Approve
and Reject buttons call the page's `handleResolve`, which passes
`{ approved, reason }` to the stored `resolve` and closes the dialog.

The agent needs no wiring beyond the tool-based setup above. The tool's
`description` tells the model when to ask for approval. For actions that must
never skip the gate, also require the tool in the agent's system prompt.

Try it: pick the **Approve refund for #12345** suggestion. The approval dialog
opens over the ticket list; approve or reject it, and the agent replies with
the outcome.

## Native graph interrupts are a different capability

LangGraph can enforce a graph checkpoint with `interrupt(...)`, and AWS Strands
can pause a tool with `tool_context.interrupt(...)`; both render that AG-UI
interrupt through `useInterrupt`. Google ADK has no equivalent native
interrupt primitive, so `useInterrupt` and the [headless interrupts
guide](/human-in-the-loop/headless) do not apply to the ADK route. Use the
tool-based approval above for the same in-chat decision experience.
