You want a chart in the thread: signups this week, MRR over time, traffic by source. The usual libraries do not help here. Recharts, Chart.js, and friends paint the live DOM, and a channel process has no browser to paint into.

`@copilotkit/channels/charts` ships a set of presentational chart components that render straight to an image through the same [Takumi image path](/channels/posting-jsx-as-images) your own cards use. You pass data, you `post` it, you get a PNG.

<Callout type="warn" title="Install react first">
  The chart components render through React, an **optional peer dependency** of `@copilotkit/channels` (your app owns its React version). Takumi, the rasterizer, ships with the package, so you do not install it. Add React before importing `@copilotkit/channels/charts`:

  ```bash
  pnpm add react
  ```

  Fonts and styling are configured once on `createChannel({ render })`. See [Posting JSX as images](/channels/posting-jsx-as-images) for that setup.
</Callout>

## Post a chart

Import the chart, pass it data, post it. It uploads as an image like any file.

```tsx
import { BarChart } from "@copilotkit/channels/charts";

await thread.post(
  <BarChart
    title="Signups / day"
    data={[
      { label: "Mon", value: 120 },
      { label: "Tue", value: 240 },
      { label: "Wed", value: 180 },
    ]}
  />,
);
```

Charts default to the CopilotKit brand data-viz palette: `#5a3cd1` (purple), `#85ecce` (mint), `#3d92e8` (blue), `#ffac4d` (orange), `#189370` (deep mint), `#bec2ff` (periwinkle). Pass a `colors` prop to override.

## The chart components

Seven components, two rendering styles:

- **Box-model** (fill their container): `BarChart`, `StackedBar`, `Meter`
- **SVG** (`width`/`height` set the canvas): `LineChart`, `PieChart`, `Scatter`, `Sparkline`

```tsx
import { LineChart, PieChart, Sparkline } from "@copilotkit/channels/charts";

// Styled with an explicit line color and a dark card background. LineChart is
// single-color, so colors takes exactly one entry.
await thread.post(
  <LineChart
    title="MRR trend"
    data={mrrSeries}
    colors={["#2563eb"]}
    gridColor="#334155"
    style={{ backgroundColor: "#0f172a" }}
    labelClassName="text-muted-foreground text-xs"
    showGrid
  />,
);

// BarChart and PieChart cycle the palette per bar or slice, so a multi-entry
// colors array produces multiple colors.
await thread.post(
  <PieChart
    title="Traffic by source"
    data={[
      { label: "Organic", value: 55 },
      { label: "Referral", value: 25 },
      { label: "Direct", value: 20 },
    ]}
    colors={["#2563eb", "#16a34a", "#f59e0b"]}
  />,
);

// A sparkline dropped inline inside your own card
await thread.post(
  <div className="p-4 flex items-center gap-3">
    <span>Latency</span>
    <Sparkline data={p95} width={120} height={28} colors={["#dc2626"]} />
  </div>,
);
```

Every chart shares the same `ChartStyleProps` (`className`, `style`, `width`, `height`, `colors`, `gridColor`, `labelClassName`, `title`, `showGrid`), but which fields do something is per chart:

| Chart | Color model | Default background | Size | Title |
| --- | --- | --- | --- | --- |
| `BarChart` | palette cycles per bar, `colors[i]` | white, via `style` | box model, fills container (`width`/`height` ignored) | yes |
| `StackedBar` | palette cycles per **series** (segment), `colors[s]`, every bar shares the same segment colors | white, via `style` | box model, fills container (`width`/`height` ignored) | yes |
| `PieChart` | palette cycles per slice, `colors[i]` | white, via `style` | SVG, `width`/`height` set the canvas | yes, a heading above the `<svg>`, so the image runs a little taller than `height` |
| `LineChart` | single color, `colors[0]` | white, via `style` | SVG plot plus HTML axes, `width`/`height` set the total image | yes, an HTML heading plus HTML y-axis and x-axis, so the plotted area is smaller than the full size |
| `Scatter` | single color, `colors[0]` | white, via `style` | SVG, `width`/`height` set the canvas | yes, a heading above the `<svg>` |
| `Sparkline` | single color, `colors[0]` | transparent | SVG, `width`/`height` set the canvas | no |
| `Meter` | single color, `colors[0]` | transparent | box model, `width` ignored, `height` sets bar thickness | no |

A few things worth knowing before you theme one:

- **Colors are fixed hex, not CSS tokens.** Takumi does not resolve CSS `var()` or theme tokens for SVG `stroke`/`fill` (or for `backgroundColor` on box-model charts), so the default palette is a fixed set of hex values, not your shadcn `--chart-1..5`. Pass a `colors` prop to theme a chart. `StackedBar`'s `colors[n]` indexes the *n*th series, so a multi-entry array gives one color per stack segment, repeated across every bar.
- **Background comes from `style`, not `className`.** `BarChart`, `StackedBar`, `LineChart`, `PieChart`, and `Scatter` set a white background via inline `style.backgroundColor`, and inline `style` beats a CSS class. Theming their background with a utility class like `bg-card` has no effect. Override with `style={{ backgroundColor: "#0f172a" }}`. `Meter` and `Sparkline` have no hardcoded background, so a `className`/`style` background shows through (though `Meter`'s unfilled track stays a fixed gray).
- **All chart text is HTML, not SVG.** Takumi rasterizes HTML text but not text drawn inside an `<svg>`, so value labels, titles, and axes are HTML laid out around the SVG plot, and they honor `labelClassName`. `BarChart` and `StackedBar` print each bar's value compacted (for example `1.2k`); `LineChart` draws a 5-tick y-axis and per-point x-axis labels.
- **`gridColor` and `showGrid` apply only to `LineChart` and `Scatter`.**
- **Scaling is data-relative, not zero-anchored.** `LineChart` and `Sparkline` scale the y-axis to the data's own min and max; `Scatter` scales both axes to the point extent. Include a zero-valued datum if you need a zero baseline.
- **Pass non-negative values.** `BarChart` clamps a negative value to a zero-height bar. `StackedBar` clamps a negative segment to zero and distorts the remaining segments in that bar.

## Flow diagrams

`FlowDiagram` takes nodes and edges and renders them as layered boxes joined by arrows, for a pipeline, a state machine, or a request path.

```tsx
import { FlowDiagram, diagramCanvasSize } from "@copilotkit/channels/charts";

const nodes = [
  { id: "hook", label: "Webhook" },
  { id: "queue", label: "Queue" },
  { id: "agent", label: "Agent run" },
  { id: "post", label: "Post to Slack" },
];
const edges = [
  { from: "hook", to: "queue", label: "enqueue" },
  { from: "queue", to: "agent" },
  { from: "agent", to: "post" },
];

// The canvas is fixed-size and the diagram fills it, so size it to the layout.
await thread.post(
  <FlowDiagram nodes={nodes} edges={edges} title="Request path" />,
  diagramCanvasSize(nodes, edges, "down"),
);
```

How the edges are drawn:

- Nodes are layered by longest path from a root, so a linear process renders as a clean top-to-bottom chain (`direction="right"` lays it out left-to-right instead).
- **Every declared edge appears.** A gap between adjacent layers gets one arrow *per edge* crossing it, captioned with that edge's `label`. When a gap carries more than one edge, each arrow is also captioned `from -> to`, because position alone cannot say which boxes an arrow joins.
- Edges a layered layout cannot route, skip-level, backward, and self edges, are listed as `from -> to` text under the flow rather than dropped. So two graphs that differ only in their edges never render identically.
- Edges referencing an unknown node id are ignored.
- `diagramCanvasSize(nodes, edges, direction)` returns a `{ width, height }` sized to the layout's depth, breadth, and edge count. Spread it into the post options (as above) so a long or wide flow is not clipped by the default 720x480 canvas.

Layout is deliberately simple, there is no graph auto-routing engine here (that would need a browser). For a hand-tuned picture, author your own JSX and post it as an [image](/channels/posting-jsx-as-images).

These are separate from the native [`<Chart>` component](/channels/rich-messages), which renders as a real Block Kit or Adaptive Card chart where the platform supports it. The `charts` components are for image output styled with your own CSS.

## Let the agent chart on its own

Sometimes you do not want to write chart code per request. A user drops a CSV and says "chart this," and the agent should handle it. Wrap a chart component in a [channel tool](/channels/tools): give it a parameters schema and post the chart from the handler.

```tsx
import { z } from "zod";
import { defineChannelTool } from "@copilotkit/channels";
import { BarChart } from "@copilotkit/channels/charts";

const chartTool = defineChannelTool({
  name: "render_chart",
  description: "Render a bar chart from {label, value} data and post it as an image.",
  parameters: z.object({
    title: z.string().optional(),
    data: z.array(z.object({ label: z.string(), value: z.number() })),
  }),
  async handler({ title, data }, { thread }) {
    await thread.post(<BarChart data={data} title={title} />, {
      filename: "chart.png",
      title,
      width: 760,
      height: 440,
    });
    return "Rendered a chart to the thread.";
  },
});

createChannel({ tools: [chartTool /* , ...your tools */] });
```

The [`examples/slack`](https://github.com/CopilotKit/CopilotKit/tree/main/examples/slack/app/tools/render-visuals.tsx) app ships a fuller version of this: a `render_chart` that handles bar, line, pie, stacked, and scatter, plus a `render_diagram` that posts a layered flow diagram of boxes and arrows. Copy it as a starting point.
