## What is this?

A headless UI gives you **full control** over the chat experience. You bring your own components, layout, and styling while CopilotKit handles agent communication, message management, tool-call rendering, and streaming. No `<CopilotChat>` and no slot overrides: only your components, composed on top of the low-level hooks.

## When should I use this?

Use headless UI when:

- The [slot system](/custom-look-and-feel/slots) isn't enough: you need a completely different layout.
- You're embedding chat into an existing UI with its own patterns.
- You're building a **non-chat surface** that still talks to an agent (a dashboard, a canvas, an inspector) and want `useRenderToolCall` / `useRenderActivityMessage` on their own.
- You want to render generative UI primitives outside of a chat entirely.

## The core hooks

These hooks are the same ones `<CopilotChat>` uses internally. The minimal example needs the first two. The complete example adds the third.

- `useAgent({ agentId })`: returns `{ agent }`. The conversation is on that object: `agent.messages` and `agent.isRunning`. With no `agentId`, it uses the agent registered as `default`.
- `useCopilotKit()`: returns the runtime handle you call `runAgent({ agent })` on.
- `useRenderToolCall()`: returns a function that renders any registered tool call inline.

## Minimal example

Start with a hand-rolled message list and composer built from `useAgent` + `useCopilotKit`. This file needs no packages beyond `@copilotkit/react-core`:

```tsx title="components/headless-chat.tsx"
"use client";

import { useState } from "react";
import { useAgent, useCopilotKit } from "@copilotkit/react-core/v2";

export function HeadlessChat() {
  // No agentId: uses the agent registered as `default` in CopilotRuntime.
  // Pass useAgent({ agentId: "my-agent" }) to talk to another agent.
  const { agent } = useAgent();
  const { copilotkit } = useCopilotKit();
  const [input, setInput] = useState("");

  const send = () => {
    const text = input.trim();
    if (!text || agent.isRunning) return;
    agent.addMessage({ id: crypto.randomUUID(), role: "user", content: text });
    setInput("");
    void copilotkit.runAgent({ agent }).catch((err) => {
      console.error("runAgent failed", err);
    });
  };

  // Show only the user and assistant text.
  const visible = agent.messages.filter(
    (m) => m.role === "user" || m.role === "assistant",
  );

  return (
    <div>
      {visible.map((m) => (
        <p key={m.id} data-role={m.role}>
          <b>{m.role === "user" ? "You" : "Agent"}:</b>{" "}
          {typeof m.content === "string" ? m.content : ""}
        </p>
      ))}
      <input
        value={input}
        onChange={(e) => setInput(e.target.value)}
        onKeyDown={(e) => e.key === "Enter" && send()}
      />
      <button onClick={send} disabled={agent.isRunning}>
        Send
      </button>
    </div>
  );
}
```

Render `<HeadlessChat />` from a page inside your `CopilotKitProvider`. Type a message and press **Send**: your message appears, then the agent's reply streams in below it.

This example does not use `<CopilotChat />` or slots. The trade-off: you only get text. Tool calls, activity messages, reasoning messages, and custom before/after slots do not show up unless you wire them in yourself. The complete example wires in tool calls and activity messages.

## Complete example

The complete example rebuilds the generative-UI composition from the low-level hooks directly, without importing `<CopilotChatMessageView>`: text, tool calls with their results, and A2UI and MCP Apps activity messages.

### The `MessageList` component

The example's central piece is a `MessageList` component. It is a **manual recreation of what `<CopilotChatMessageView>` does**. `MessageList` calls `useRenderToolCall` and `useRenderActivityMessage`, and indexes tool results by `toolCallId`:

<Snippet region="use-rendered-messages-hook" title="chat/message-list.tsx: hooks and tool-result index" />

Two low-level hooks feed it:

- `useRenderToolCall()`: returns the renderer for any registered tool call (per-tool via `useRenderTool` / `useComponent`, plus the wildcard from `useDefaultRenderTool`).
- `useRenderActivityMessage()`: renders A2UI + MCP Apps activity messages for the current agent scope.

To add custom before/after slots, also call `useRenderCustomMessages()`. It returns `null` unless two things are true: you are inside a `CopilotChatConfigurationProvider`, and you passed `renderCustomMessages` to the CopilotKit provider. When it returns a function, call it with `{ message, position: "before" }` or `{ message, position: "after" }` for each message.

To check it, give the agent a tool with a renderer. The demo's agent has a `get_weather` tool. On your own agent, install `zod` (`npm install zod`) and register a frontend tool in any component inside the provider. Render `<WeatherTool />` next to your chat:

```tsx title="components/weather-tool.tsx"
"use client";

import { z } from "zod";
import { useFrontendTool } from "@copilotkit/react-core/v2";

export function WeatherTool() {
  useFrontendTool({
    name: "get_weather",
    description: "Get the weather for a city.",
    parameters: z.object({ city: z.string() }),
    handler: async ({ city }) => `Sunny and 22 degrees in ${city}.`,
    render: ({ args, status }) => (
      <div>
        Weather for {args.city} ({status})
      </div>
    ),
  });
  return null;
}
```

Then ask the agent for the weather in Tokyo, so that it calls the tool. Your own bubble shows the reply, and the tool card renders inside it. See [`useFrontendTool`](/reference/hooks/useFrontendTool) for the full options.
