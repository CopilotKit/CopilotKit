Assistant replies arrive as markdown. CopilotKit renders them through the
`markdownRenderer` slot on `CopilotChatAssistantMessage`. Its default is the
built-in streaming renderer from
[`@copilotkit/markdown-renderer`](/reference/packages/markdown-renderer), which
is built for text that is still streaming in. It renders GFM, tables, autolinks,
and citations. It does not do syntax highlighting, math, or diagrams.

You reach the slot by drilling down from the chat component:

```tsx title="page.tsx"
import { CopilotChat } from "@copilotkit/react-core";

export function Chat() {
  return (
    <CopilotChat
      messageView={{
        assistantMessage: {
          // A class string, a config object, or a component.
          markdownRenderer: {},
        },
      }}
    />
  );
}
```

Everything on this page works the same way on `CopilotSidebar` and
`CopilotPopup`, and on `CopilotChatMessageView` (where the path starts one level
in, at `assistantMessage`). To set the renderer for the whole app instead of one
chat, pass the same value to the `markdownRenderer` prop of
`CopilotKitProvider`. See [Markdown Rendering](/markdown-rendering).

## Restyle individual nodes

This is the route to reach for first. A config object for the built-in renderer
can set `nodeRenderers`, which swaps the output for one node type. The keys are
node types, not HTML tags: `link`, `heading`, `codeBlock`, `inlineCode`,
`image`, `table`, `listItem`, and so on.

```tsx title="page.tsx"
import {
  CopilotChat,
  type DefaultMarkdownRendererProps,
} from "@copilotkit/react-core";

// Module scope, so the value keeps its identity between renders.
const markdownRenderer: DefaultMarkdownRendererProps = {
  nodeRenderers: {
    link: ({ defaultNode }) => <span className="my-link">{defaultNode}</span>,
    heading: ({ node, children, defaultNode }) =>
      node.level === 2 ? (
        <h2 className="my-heading">{children}</h2>
      ) : (
        defaultNode
      ),
  },
};

export function Chat() {
  return (
    <CopilotChat messageView={{ assistantMessage: { markdownRenderer } }} />
  );
}
```

Three things are worth knowing about the props a node renderer receives.

**`defaultNode` is the built-in output.** Wrap it to restyle a node and keep
everything the renderer already does. A default link has
`target="_blank" rel="noopener noreferrer"`, and its URL has already passed the
built-in URL check.

**`children` is the rendered content of the node.** Use it when you render the
element yourself, as the `heading` renderer above does for level-2 headings.

**`node` is the parsed node.** It carries the fields for its type, for example
`node.level` on a heading and `node.info` and `node.text` on a code block. If you
render `node.url` yourself, it is the raw model output, and the built-in URL
check does not run on it.

## Restyle the whole markdown block

To change the block as a whole rather than one node, pass a class string. It is
merged onto the markdown container:

```tsx title="page.tsx"
import { CopilotChat } from "@copilotkit/react-core";

export function Chat() {
  return (
    <CopilotChat
      messageView={{
        assistantMessage: { markdownRenderer: "text-sm leading-7" },
      }}
    />
  );
}
```

## Replace the renderer

Passing a component instead of an object replaces the renderer outright. It
receives `MarkdownRendererProps`: `content`, which holds the assistant message's
raw markdown, and the optional `isStreaming` and `className`:

```tsx title="page.tsx"
import {
  CopilotChat,
  type MarkdownRendererProps,
} from "@copilotkit/react-core";

function PlainText({ content }: MarkdownRendererProps) {
  return <pre className="whitespace-pre-wrap">{content}</pre>;
}

export function Chat() {
  return (
    <CopilotChat
      messageView={{ assistantMessage: { markdownRenderer: PlainText } }}
    />
  );
}
```

Reach for this only when you want a different markdown engine, for example for
syntax highlighting or math. The built-in renderer does real work that you take
over with it: it parses markdown that is still half-written without flashing
broken output, escapes raw HTML, and allows only safe link and image URLs. That
last one matters. `content` is raw model output, so anything you render it with
has to be safe against it.

## Custom tags are not supported

You cannot teach the renderer a tag of your own, such as `<reference-chip>`.

The `nodeRenderers` keys are a fixed set of node types, so a custom key is a
compile error. And the built-in renderer has no HTML node: raw HTML in a reply,
such as `Hi <reference-chip id="42">Doc 42</reference-chip>.`, renders as
literal text.

If you need a richer, non-textual surface in the conversation, that is what
[generative UI](/generative-ui/tool-rendering) is for: the agent calls a tool and
you render a React component for that tool call.

## Other frontends

This page describes the React API. The other frontends expose the same idea
under different names:

- **Vue** takes the same config object or component through the provider's
  `markdown-renderer` prop, and has a `message-renderer` scoped slot. See
  [Markdown Rendering](/markdown-rendering) and the
  [Vue `CopilotChatAssistantMessage` reference](/reference/vue/components/CopilotChatAssistantMessage).
- **Angular** uses a `#markdownRenderer` `ng-template` (or `markdownRendererComponent`)
  over `marked`, so there is no `nodeRenderers` prop. See the
  [Angular `CopilotChatAssistantMessage` reference](/reference/angular/components/CopilotChatAssistantMessage).
