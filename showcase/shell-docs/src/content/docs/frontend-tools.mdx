## What is this?

Frontend tools are browser functions that you register for the agent to call.
Their handlers run in the user's browser, so they can update component state,
use browser APIs, or call the UI libraries already used by the page. For
example, an agent can update React state, trigger an animation, read
`localStorage`, show a toast, or move the user's view.

This page covers the "agent drives the UI" shape of frontend tools. The same primitive also powers Generative UI and Human-in-the-loop; see those pages for interaction patterns.

## When should I use this?

Use a frontend tool when an agent needs the user's current browser context:
for example, to update React state, call a browser API, or show an app-owned
UI element such as a toast or chart. Keep server-side work in a backend tool.

## How it works in code

<FrameworkSetup concept="frontend-tools-setup" />

Register a frontend tool with [`useFrontendTool`](/reference/hooks/useFrontendTool).
Give it a name, a Zod schema for parameters, and a handler. The agent can then
call it like any other tool and the browser runs the handler.

<Snippet region="frontend-tool-registration" title="frontend/src/app/page.tsx — useFrontendTool" />

The handler receives the parsed, type-safe parameters and can do anything
the browser can: update state, call an API, touch the DOM. Its return value
is sent back to the agent as the tool result so the model can reason about
what happened.
