Your agent system has more than one connection. The agent calls tools, it can give work to other agents, and people must see and steer what it does. Each of these connections has its own open protocol. Choose the protocol by the connection, not by the vendor.

## The 30-second version

| Connection | Protocol | What it carries | How CopilotKit uses it |
| --- | --- | --- | --- |
| Agent to user | [AG-UI](/agentic-protocols/ag-ui) | Streamed messages, tool calls, state, and interrupts between an agent and an app | Every CopilotKit frontend talks AG-UI to the runtime and the agent. |
| Agent to tools and data | [MCP](/agentic-protocols/mcp) | Tools, resources, and prompts from external systems | Your agent calls MCP servers. [MCP Apps](/generative-ui/mcp-apps) render the UI of a server in the chat. |
| Agent to agent | [A2A](/agentic-protocols/a2a) | Tasks, messages, and artifacts between agents that are deployed separately | `A2AMiddlewareAgent` lets an orchestrator agent send tasks to A2A agents. |
| Agent to generated UI | [A2UI](/generative-ui/a2ui) | A declarative UI description that the app renders from its own component catalog | The runtime option `generativeUI` turns it on. The frontend renders the surfaces. |

The four protocols work together. No protocol replaces another.

## How to choose

Start with the connection that you build:

- **People must see, approve, or steer the agent.** Use AG-UI. It streams each step of a run to the app and carries the answers of the user back to the agent.
- **The agent needs a tool or data from another system.** Use MCP. If the server also returns its own interactive UI, use [MCP Apps](/generative-ui/mcp-apps).
- **The agent gives a task to an agent that another team deploys.** Use A2A. The CopilotKit A2A middleware supports A2A versions before 1.0.
- **The agent describes UI, and the app must control what renders.** Use A2UI. The agent sends a description. The app renders only the components in its catalog, so model output never runs as code.

## Where CopilotKit fits

CopilotKit is the layer between your agent and the people who use it. It implements AG-UI in the frontend and in the runtime:

- **Frontend:** chat, [generative UI](/generative-ui/tool-based), [shared state](/shared-state), and [human-in-the-loop](/human-in-the-loop), all built on AG-UI events.
- **Runtime:** sends each request to the correct agent, applies [AG-UI middleware](/agentic-protocols/ag-ui-middleware), and serves MCP Apps and A2UI.
- **Your agent framework:** keeps the plan, the tool calls, and its own persistence.

CopilotKit does not replace your agent framework, your MCP servers, or the A2A transport between agents. To decide if CopilotKit fits your project, see [When to Use CopilotKit](/concepts/when-to-use).

## Use the protocols together

A typical system uses all four protocols. The app talks to a host agent over AG-UI. The host agent calls tools over MCP and gives tasks to other agents over A2A. The UI that those agents generate reaches the app as A2UI surfaces or MCP Apps.
