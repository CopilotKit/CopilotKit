Set up the CopilotKit monorepo, test a change, and open a pull request.

## Step 1: Install Prerequisites

- [Node.js](https://nodejs.org/en/) 20.x or later
- [pnpm](https://pnpm.io/) v10.x installed globally (`npm i -g pnpm@^10`)
- [Git LFS](https://git-lfs.com/). Run `git lfs install` once before you clone. The repository stores images in Git LFS.

## Step 2: Repository Setup

<Steps>
  <Step>
  ### Fork The Repository
  Go to the [CopilotKit repository](https://github.com/CopilotKit/CopilotKit) and create a fork.

Then, clone your fork to your local machine:

```bash
git clone https://github.com/<your-username>/CopilotKit
cd CopilotKit
```

  </Step>
  <Step>
  ### Install Dependencies
  <Callout type="info">
    The CopilotKit repository is a monorepo using a [pnpm](https://pnpm.io/) workspace. Tasks across packages are orchestrated with [Nx](https://nx.dev/).
  </Callout>

Install the dependencies using pnpm:

```bash
pnpm install
```

  </Step>
  <Step>
  ### Build Packages
  To make sure that everything works, build all packages once:
  ```bash
  pnpm run build
  ```
  </Step>
</Steps>

## Step 3: Development Mode

Start the packages in development mode:

```bash
# Start all packages in development mode
pnpm run dev

# Rebuild only one package when its files change (example: react-ui)
pnpm exec nx watch --projects=@copilotkit/react-ui -- pnpm exec nx run \$NX_PROJECT_NAME:build
```

Now you can start making changes to the code.

<Callout type="info">
  You can find all `@copilotkit/*` packages under the `packages` folder of the
  monorepo.
</Callout>

## Step 4: Test Changes in Real-Time

Run an example from the `examples` folder. The examples use the monorepo packages, so they show your changes.

<FrontendOnly frontend="react">
The steps below use the `next-openai` example, specifically the Presentation Demo (`/presentation`).

In a separate terminal, run the following command to start the example:

```bash
cd examples/v1/next-openai
export OPENAI_API_KEY=<your-openai-api-key>
pnpm run example-dev
```

<Callout type="info">
  Examples run with `pnpm run example-dev`. This is different from
  `pnpm run dev`, which you use to work on the individual packages.
</Callout>

Open http://localhost:3000/presentation to see the example running. The first load compiles the page and can take a minute or two. After that, changes you make to the CopilotKit packages show up here when you reload.
</FrontendOnly>

<FrontendOnly frontend="angular">
For Angular changes, validate the Angular package and Showcase host through Nx:

```bash
pnpm exec nx run @copilotkit/angular:test
pnpm exec nx run @copilotkit/showcase-angular-host:test
```

The Angular Showcase under `showcase/angular` is the frontend-native test host
for components, signals, tools, generative UI, interrupts, threads, and
lifecycle behavior.
</FrontendOnly>

## Step 5: Formatting and Linting

The pre-commit hook formats and lints the files you stage, so most of the time you do not run anything by hand.

To format the files you changed before you stage them, pass their paths to `oxfmt`:

```bash
pnpm exec oxfmt --write packages/react-ui/src/components/chat/Input.tsx
```

Do not run `pnpm run format` from the root for a pull request. It formats the whole monorepo and can change files you did not touch. Do not commit format changes to files you did not edit.

Make sure that you have no linting errors:

```bash
pnpm run lint
```

## Step 6: Submit a Pull Request

Commit and push your changes. Write the commit message as a [Conventional Commit](https://www.conventionalcommits.org/), for example `fix(react-ui): keep chat scroll position`. The commit-msg hook rejects other formats.

Then go to the [Pull Requests page](https://github.com/CopilotKit/CopilotKit/pulls) and create a pull request.

## Debugging

When you run CopilotKit on localhost, the CopilotKit Inspector is on by default. Use it to see agent state, context, and the tools the agent can call. See [Inspector and dev console](/troubleshooting/inspector-dev-console).

<FrontendOnly frontend="react">
To hide the Inspector locally, set `enableInspector={false}` on your `<CopilotKit />` provider.
</FrontendOnly>

<FrontendOnly frontend="angular">
For Angular debugging workflows, use the [Angular troubleshooting guide](/angular/troubleshooting) and the AG-UI Event Inspector.
</FrontendOnly>

## (Advanced) Package Linking

In some cases, you want to test your CopilotKit changes in your own project. For example, you tried to integrate CopilotKit into your own codebase and encountered a bug you want to fix.

Link your local CopilotKit packages to your own project to test your changes. See the [Advanced: Package Linking](/contributing/code-contributions/package-linking) guide for the steps.
