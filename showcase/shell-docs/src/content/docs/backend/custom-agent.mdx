Sometimes `tanstackAIAgent` and `aiSdkAgent` do not set what you need:

- An API key that you read from a vault on each run.
- A router that picks the model per request.
- An option of `chat()` or `streamText()` that the agent sets itself.
- Your own LLM backend.

In factory mode, you write the model call. CopilotKit converts the stream to AG-UI events, runs the agent lifecycle, and connects the agent to the runtime.

You do not have to build the rest of the call. `tanstackAI(ctx)` and `aiSdk(ctx)` give you the messages, the system prompt with context and state, and every tool the run needs. Spread the result into your call and add the adapter or the model.

To write the whole agent yourself, extend AG-UI's `AbstractAgent`. See [Write your own AG-UI agent](/backend/custom-ag-ui-agent).

## Quick Start

Pick your backend:

<Tabs groupId="agent-sdk" items={["TanStack AI", "AI SDK", "Custom"]}>
<Tab value="TanStack AI">
```typescript title="src/copilotkit.ts"
import {
  CopilotRuntime,
  createCopilotRuntimeHandler,
  InMemoryAgentRunner,
  BuiltInAgent,
} from "@copilotkit/runtime";
import { tanstackAI } from "@copilotkit/runtime/tanstack-ai";
import { chat } from "@tanstack/ai";
import { openaiText } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({
  type: "tanstack",
  factory: async (ctx) => {
    const base = await tanstackAI(ctx, { prompt: "You are a helpful assistant." });
    return chat({ ...base, adapter: openaiText("gpt-5.5") });
  },
});

const runtime = new CopilotRuntime({
  agents: { default: agent },
  runner: new InMemoryAgentRunner(),
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});
export default handler;
```
</Tab>

<Tab value="Custom">
```typescript title="src/copilotkit.ts"
import {
  CopilotRuntime,
  createCopilotRuntimeHandler,
  InMemoryAgentRunner,
  BuiltInAgent,
} from "@copilotkit/runtime";
import { EventType } from "@ag-ui/client";

const agent = new BuiltInAgent({
  type: "custom",
  factory: async function* ({ input, abortSignal }) {
    const response = await fetch("https://your-llm-api.com/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ messages: input.messages }),
      signal: abortSignal,
    });

    const reader = response.body!.getReader();
    const decoder = new TextDecoder();
    const messageId = crypto.randomUUID();

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      yield {
        type: EventType.TEXT_MESSAGE_CHUNK,
        role: "assistant",
        messageId,
        delta: decoder.decode(value),
      };
    }
  },
});

const runtime = new CopilotRuntime({
  agents: { default: agent },
  runner: new InMemoryAgentRunner(),
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});
export default handler;
```

With `type: "custom"`, you yield AG-UI events directly, so no SDK helper is involved.
</Tab>
</Tabs>

The frontend setup is the same as in the [quickstart](/quickstart): configure the CopilotKit provider and add a chat component. Send a message, and the reply streams from your own model call.

## How It Works

A factory config has two fields:

- **`type`**: your backend, `"tanstack"`, `"aisdk"`, or `"custom"`.
- **`factory`**: a function that gets the run context and returns the stream of that backend.

The factory gets a `BuiltInAgentFactoryContext` (from `@copilotkit/runtime`). These are its fields:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime";

const agent = new BuiltInAgent({
  type: "custom",
  factory: async function* ({
    input,                 // RunAgentInput: messages, tools, state, context, threadId, runId, forwardedProps
    abortSignal,           // for the AI SDK, fetch, and custom backends
    abortController,       // for TanStack AI, which needs an AbortController
    learnedSkills,         // { catalog, definitions }, empty when learned skills are off
    interrupt,             // pauses the run for human input (AG-UI interrupt)
    onRunEnd,              // registers cleanup that runs once when the run ends
    describeInterruptTool, // sets the reason and message of a tool's approval interrupt
  }) {
    // Yield AG-UI events here.
  },
});
```

CopilotKit does the rest: the `RUN_STARTED` and `RUN_FINISHED` events, the conversion of the stream to AG-UI events, errors, and cancellation. Your factory does not emit lifecycle events.

<Callout type="warn" title="Do not call `.abort()` on the controller you get">
TanStack AI needs a full `AbortController`, so the context gives you `abortController`. Give it to TanStack AI and do not abort it yourself. If you abort it inside the factory, the stream stops without the teardown of the run. To cancel a run, call `abortRun()` on the agent. For the AI SDK, `fetch`, or a custom backend, pass `abortSignal`.
</Callout>

The `runner: new InMemoryAgentRunner()` in the examples above keeps threads in process memory. To change to durable storage, see [AgentRunner & persistence](/backend/agent-runner).

<Callout type="info" title="Using CopilotKit Intelligence? Replace runner with intelligence">
  Intelligence stores the threads and runs for you, so remove `runner` and pass
  `intelligence` (and `identifyUser`) to `CopilotRuntime`. The custom
  agent and its `factory` do not change. See
  [An existing runtime that already has a runner](/intelligence/quickstart#an-existing-runtime-that-already-has-a-runner).
</Callout>

## What the helpers add

`tanstackAI(ctx, options)` and `aiSdk(ctx, options)` return the arguments for `chat()` and `streamText()`:

- **Messages**: the conversation, converted to the format of the SDK.
- **System prompt**: the learned-skills catalog, then your `prompt`, then the context and the application state from the frontend.
- **Tools**: frontend tools, the shared-state tools, MCP tools, learned-skills tools, and your `tools`.
- **Cancellation**: `abortController` (TanStack AI) or `abortSignal` (AI SDK).
- **URL downloads (AI SDK)**: a safe downloader for URL attachments. See [URL attachments](/advanced-configuration#url-attachments-ai-sdk).

Both helpers take `prompt`, `tools`, and `mcpServers`. `aiSdk` also takes `forwardSystemMessages`, `forwardDeveloperMessages`, and `urlDownload`. The helpers close MCP connections when the run ends.

`tanstackAI` also adds system and developer messages from the conversation to the system prompts.

## Async setup

The factory can be async. Do your setup before you return the stream:

<Tabs groupId="agent-sdk" items={["TanStack AI", "AI SDK"]}>
<Tab value="TanStack AI">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { tanstackAI } from "@copilotkit/runtime/tanstack-ai";
import { chat } from "@tanstack/ai";
import { createOpenaiChat } from "@tanstack/ai-openai";
import { getApiKeyFromVault } from "./vault";

const agent = new BuiltInAgent({
  type: "tanstack",
  factory: async (ctx) => {
    const apiKey = await getApiKeyFromVault(); // [!code highlight]
    const base = await tanstackAI(ctx);
    return chat({ ...base, adapter: createOpenaiChat("gpt-5.5", apiKey) });
  },
});
```
</Tab>
<Tab value="AI SDK">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { aiSdk } from "@copilotkit/runtime/ai-sdk";
import { streamText } from "ai";
import { createOpenAI } from "@ai-sdk/openai";
import { getApiKeyFromVault } from "./vault";

const agent = new BuiltInAgent({
  type: "aisdk",
  factory: async (ctx) => {
    const apiKey = await getApiKeyFromVault(); // [!code highlight]
    const openai = createOpenAI({ apiKey });
    const base = await aiSdk(ctx);
    return streamText({ ...base, model: openai("gpt-5.5") });
  },
});
```

## Examples

### With Tools

<Tabs groupId="agent-sdk" items={["TanStack AI", "AI SDK", "Custom"]}>
<Tab value="TanStack AI">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { tanstackAI } from "@copilotkit/runtime/tanstack-ai";
import { chat, toolDefinition } from "@tanstack/ai";
import { openaiText } from "@tanstack/ai-openai";
import { webSearchTool } from "@tanstack/ai-openai/tools";
import { z } from "zod";

const getWeather = toolDefinition({
  name: "getWeather",
  description: "Get the weather for a city",
  inputSchema: z.object({ city: z.string() }),
}).server(async ({ city }) => ({ temp: 72, city }));

const agent = new BuiltInAgent({
  type: "tanstack",
  factory: async (ctx) => {
    const base = await tanstackAI(ctx, {
      tools: [getWeather, webSearchTool({ type: "web_search" })], // [!code highlight]
    });
    return chat({ ...base, adapter: openaiText("gpt-5.5") });
  },
});
```

`tools` takes TanStack AI tools and `defineTool` tools in one array. The model also gets the frontend tools of the run.
</Tab>
<Tab value="AI SDK">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { aiSdk } from "@copilotkit/runtime/ai-sdk";
import { stepCountIs, streamText, tool } from "ai";
import { openai } from "@ai-sdk/openai";
import { z } from "zod";

const getWeather = tool({
  description: "Get the weather for a city",
  inputSchema: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ temp: 72, city }),
});

const agent = new BuiltInAgent({
  type: "aisdk",
  factory: async (ctx) => {
    const base = await aiSdk(ctx, { tools: { getWeather } }); // [!code highlight]
    return streamText({
      ...base,
      model: openai("gpt-5.5"),
      stopWhen: stepCountIs(5), // [!code highlight]
    });
  },
});
```

`tools` takes an AI SDK `ToolSet` or a `defineTool` array. The model also gets the frontend tools of the run. `stopWhen` lets the model answer after a tool result.
</Tab>
<Tab value="Custom">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { EventType } from "@ag-ui/client";

const agent = new BuiltInAgent({
  type: "custom",
  factory: async function* ({ input }) {
    const messageId = crypto.randomUUID();
    const toolCallId = crypto.randomUUID();

    // The LLM decides to call a tool
    yield {
      type: EventType.TOOL_CALL_START,
      parentMessageId: messageId,
      toolCallId,
      toolCallName: "getWeather",
    };

    yield {
      type: EventType.TOOL_CALL_ARGS,
      toolCallId,
      delta: JSON.stringify({ city: "San Francisco" }),
    };

    yield {
      type: EventType.TOOL_CALL_END,
      toolCallId,
    };

    // Execute the tool and return the result
    yield {
      type: EventType.TOOL_CALL_RESULT,
      role: "tool",
      messageId: crypto.randomUUID(),
      toolCallId,
      content: JSON.stringify({ temp: 72, city: "San Francisco" }),
    };

    // Text response after the tool call
    yield {
      type: EventType.TEXT_MESSAGE_CHUNK,
      role: "assistant",
      messageId,
      delta: "The weather in San Francisco is 72°F.",
    };
  },
});
```

With `type: "custom"`, you yield AG-UI events directly. See the [AG-UI event reference](/backend/ag-ui) for all event types.
</Tab>
</Tabs>

### With Reasoning (Thinking Models)

<Tabs groupId="agent-sdk" items={["TanStack AI", "AI SDK"]}>
<Tab value="TanStack AI">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { tanstackAI } from "@copilotkit/runtime/tanstack-ai";
import { chat } from "@tanstack/ai";
import { anthropicText } from "@tanstack/ai-anthropic";

const agent = new BuiltInAgent({
  type: "tanstack",
  factory: async (ctx) => {
    const base = await tanstackAI(ctx);
    return chat({
      ...base,
      adapter: anthropicText("claude-sonnet-4-6"),
      // Stream the thinking text back, so the reasoning is visible
      reasoning: { level: "high", summary: true }, // [!code highlight]
    });
  },
});
```
</Tab>
<Tab value="AI SDK">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { aiSdk } from "@copilotkit/runtime/ai-sdk";
import { streamText } from "ai";
import { anthropic } from "@ai-sdk/anthropic";

const agent = new BuiltInAgent({
  type: "aisdk",
  factory: async (ctx) => {
    const base = await aiSdk(ctx);
    return streamText({
      ...base,
      model: anthropic("claude-sonnet-4-6"),
      providerOptions: { // [!code highlight:3]
        anthropic: { thinking: { type: "adaptive" }, effort: "high" },
      },
    });
  },
});
```

<Callout type="info">
Pick the model with reasoning **visibility** in mind. From Claude Opus 4.7 onward (including Sonnet 5 and Opus 5), Anthropic sets the thinking `display` to `"omitted"` by default. The model still reasons, but no reasoning text comes back, so the reasoning events arrive empty. `@ai-sdk/anthropic` does not expose `display`, so to see the reasoning, choose a model that summarizes its thinking by default, such as `claude-sonnet-4-6`.
</Callout>
</Tab>
</Tabs>

The agent converts the reasoning in the stream to `REASONING_START`, `REASONING_MESSAGE_CONTENT`, and `REASONING_END` events for the frontend. With `tanstackAIAgent` or `aiSdkAgent`, set the same options on the agent. See [Advanced Configuration](/advanced-configuration#provider-specific-options).

### With forwardedProps

Use `forwardedProps` only for preferences that are not secret and that the browser can control. Validate each value against limits on your backend before it changes the run. Do not use these properties for credentials, tenant identity, authorization, or a free choice of model and provider.

<Tabs groupId="agent-sdk" items={["TanStack AI", "AI SDK"]}>
<Tab value="TanStack AI">
```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime";
import { tanstackAI } from "@copilotkit/runtime/tanstack-ai";
import { chat } from "@tanstack/ai";
import { openaiText } from "@tanstack/ai-openai";
import { anthropicText } from "@tanstack/ai-anthropic";

const agent = new BuiltInAgent({
  type: "tanstack",
  factory: async (ctx) => {
    const props: Record<string, unknown> = ctx.input.forwardedProps ?? {};
    const base = await tanstackAI(ctx);

    const adapter =
      props.model === "claude"
        ? anthropicText("claude-sonnet-4-6")
        : openaiText("gpt-5.5");

    const requested = props.temperature;
    const isValidTemperature =
      typeof requested === "number" && requested >= 0 && requested <= 1;
    const temperature = isValidTemperature ? requested : 0.7;

    return chat({ ...base, adapter, modelOptions: { temperature } });
  },
});
```
</Tab>

## Helper Utilities

The helpers that build a full call:

| Utility | Import from | Description |
|---|---|---|
| `tanstackAI(ctx, options)` | `@copilotkit/runtime/tanstack-ai` | Returns `messages`, `systemPrompts`, `tools`, `abortController`, `threadId`, and `runId` for `chat()`. |
| `aiSdk(ctx, options)` | `@copilotkit/runtime/ai-sdk` | Returns `system`, `messages`, `tools`, `experimental_download`, and `abortSignal` for `streamText()`. |

Lower-level converters, if you build the call part by part:

| Utility | Import from | Description |
|---|---|---|
| `convertInputToTanStackAI(input)` | `@copilotkit/runtime` | Converts `RunAgentInput` to `messages`, `systemPrompts`, and frontend `tools` for TanStack AI. |
| `convertMessagesToVercelAISDKMessages(messages)` | `@copilotkit/runtime/ai-sdk` | Converts AG-UI messages to AI SDK `ModelMessage[]`. |
| `convertToolsToVercelAITools(tools)` | `@copilotkit/runtime/ai-sdk` | Converts frontend tools (JSON Schema) to an AI SDK `ToolSet`. |
| `convertToolDefinitionsToVercelAITools(tools)` | `@copilotkit/runtime/ai-sdk` | Converts `defineTool()` tools to an AI SDK `ToolSet`. |
| `createSafeUrlDownload({ signal })` | `@copilotkit/runtime/ai-sdk` | Creates the safe URL downloader for `experimental_download`. |
