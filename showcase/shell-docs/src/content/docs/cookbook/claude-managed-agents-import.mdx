## Add Intelligence to your existing app

If you have not connected your agent to CopilotKit yet, start with the [Claude Managed Agents recipe](/cookbook/claude-managed-agents).

Give users reconnection, catch-up, and delivery across devices around your Claude agent. Follow the [Intelligence quickstart](/intelligence/quickstart) to connect your existing CopilotKit app and Runtime, then verify that a new conversation is saved. This enables AG-UI streams for runs through CopilotKit; no historical import is required.

Keep your Claude agent and its durable storage connected so you can continue the same conversations after importing them. See [how streams work with framework storage](/intelligence/threads-explained#how-threads-work-with-framework-storage).

## Include earlier conversations (optional)

To let users reopen conversations recorded before Intelligence was connected, use the importer below to copy supported historical content. Importing does not enable live delivery or establish ongoing database replication, and it cannot recover history the source no longer exposes.

The importer reads saved sessions directly from Anthropic. The same import works for sessions used through the TypeScript, Python, or .NET adapters. It brings over saved messages, tool calls and results, available attachments, child histories, and persisted shared state where available. Child histories appear within the parent conversation.

Import can only restore what the source retained. Missing MCP App views, reasoning text, or state cannot be reconstructed. Files are included when the source API can read them; unavailable files and external URLs remain references.

The following prerequisites and commands apply only to that historical import. Use Threads Drawer or [Headless Threads](/headless-threads) to open imported and new conversations through the same UI.

## Prerequisites

- A CopilotKit app with CopilotKit Intelligence enabled.
- Node.js 20.9 or later to run the CopilotKit CLI.
- An Anthropic API key with access to the saved sessions you want to import.

## Confirm the target project

Choose the Intelligence project that will receive the history. Its app-api URL and project-scoped runtime key select the destination. You will export those values before importing.

For a CLI-created app, you can select a cloud-hosted project:

```bash title="Terminal"
npx copilotkit@latest project select
```

The command updates the project selected for the current directory and writes its project-scoped runtime key to the app's generated `.env`.

## Configure the source

Select the original sessions and their application user:

```bash title="Terminal"
export ANTHROPIC_API_KEY="your-source-api-key"
export MANAGED_AGENTS_SESSION_IDS="sesn_example"
export MANAGED_AGENTS_AGENT_ID="agent_example"
export MANAGED_AGENTS_USER_ID="user-123"
```

Set `MANAGED_AGENTS_USER_ID` to the application user ID your Runtime returns from `identifyUser`. All selected sessions are assigned to that user; select only their session IDs and repeat for each user. Use comma-separated IDs to select several sessions. Explicit user assignment requires explicit session IDs.

Use your native Managed agent ID in `MANAGED_AGENTS_AGENT_ID`. To select a workspace, also set `MANAGED_AGENTS_WORKSPACE_ID`. Your Anthropic credential must have access to that workspace. This source credential is separate from the destination Intelligence project key.

Run the import while these sessions are idle.

## Run a dry run

Preview the import before writing anything.

```bash title="Terminal"
npx copilotkit@latest import --source claude-managed-agents --dry-run
```

The dry run counts conversations, reports conversations that cannot be imported, and estimates upload size. It does not need a CopilotKit Intelligence URL or API key.

## Map native agents to CopilotKit agent IDs

Map the native agent ID you set in `MANAGED_AGENTS_AGENT_ID` to the `agentId` your live CopilotKit runtime uses.

```json title="agent-map.json"
{
  "agent_example": "support-agent"
}
```

Using the same `agentId` as live traffic keeps imported history and future conversations grouped together.

## Prepare the CopilotKit Intelligence destination

A real import needs the destination app-api URL and project-scoped runtime key. A CLI-created starter writes them to `.env`, but the importer reads the current process environment and does not load `.env` or `.copilotkit/project.json` automatically.

Copy the generated values into your shell before importing:

```bash title="Terminal"
export INTELLIGENCE_API_URL="https://..."
export CPK_INTELLIGENCE_API_KEY="cpk-..."
```

`COPILOTKIT_API_KEY` is also accepted for the key. You can also pass the destination directly with `--api-url` and `--api-key` instead.

## Import the conversations

Run the import after the dry run and agent map look right.

```bash title="Terminal"
npx copilotkit@latest import \
  --source claude-managed-agents \
  --agent-map ./agent-map.json
```

For self-hosted CopilotKit Intelligence, pass the target connection explicitly:

```bash title="Terminal"
npx copilotkit@latest import \
  --source claude-managed-agents \
  --api-url "$INTELLIGENCE_API_URL" \
  --api-key "$CPK_INTELLIGENCE_API_KEY" \
  --agent-map ./agent-map.json \
  --yes
```

Conversations without an end-user ID are omitted by default. Set `MANAGED_AGENTS_USER_ID` before importing.

## Verify the imported conversations

Sign in as the application user whose ID you imported. Open the Threads Drawer, select an imported Claude Managed Agents conversation, and confirm that its history appears in the chat.

## Re-run or replace

Already-imported conversations are skipped by default.

Use `--replace` to refresh them; running or continued conversations are left unchanged:

```bash title="Terminal"
npx copilotkit@latest import \
  --source claude-managed-agents \
  --agent-map ./agent-map.json \
  --replace
```

## Continue using Claude Managed Agents persistence

Importing copies supported history; it does not establish ongoing database replication. Intelligence rename, archive, and delete operations affect only Intelligence records, leaving the native Claude Managed Agents records unchanged.

Keep a persistent session store and an authorized server-side mapping to the original Managed session. Preserve its imported user-message and event positions so reconnecting does not replay old work as a new request. Keep the same workspace access and tool configuration; default in-memory mappings do not survive a backend restart. Configure the resolver for your adapter: [`resolveSession` in TypeScript](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/claude-managed-agents/typescript), [`resolve_session` in Python](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/claude-managed-agents/python), or [`ResolveSession` in .NET](https://github.com/ag-ui-protocol/ag-ui/tree/main/integrations/claude-managed-agents/dotnet).

Reopen the imported conversation to continue its original session, including supported pending approvals and tool requests. Keep your frontend tools and UI renderers configured. Follow-up messages go to the primary session; child histories do not become independent conversations. An unavailable or terminated native session returns an error rather than silently creating a replacement.

Your app sends future conversations through CopilotKit to CopilotKit Intelligence. Activity sent directly to Claude is not automatically synchronized by the importer.

- **Threads Drawer:** already included in CLI-created starters. Use the [Threads Drawer guide](/prebuilt-components/copilot-threads-drawer) to customize its ready-made thread UI.
- **Headless Threads:** use the [Headless Threads guide](/headless-threads) only when you need a custom UI. Select a thread with `useThreads`, store its `thread.id`, and pass that value to your chat component as `threadId`.

Open an imported conversation and send a follow-up to continue it.
