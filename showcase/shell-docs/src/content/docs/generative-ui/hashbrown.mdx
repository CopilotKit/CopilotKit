Hashbrown renders a dashboard while the assistant streams JSON. The examples below come from the selected framework's showcase demo, so the page, chat, renderer, and Code tab stay in sync with runnable source. The bundled demos pin `@hashbrownai/core` and `@hashbrownai/react` to `0.5.0-beta.4`; the chart components also need `recharts` and `zod`. Use the versions in your selected integration's `package.json` when copying the files.

## When to use this

- **Streaming dashboards** that should appear before the full response arrives.
- **Agent-authored UI** constrained to components you expose in a UI kit.
- **Apps already using Hashbrown** for progressive JSON rendering.

For a validated `{ root, elements }` spec that renders as one tree, see [JSON Render](/generative-ui/json-render). Its agent output and React API are different from Hashbrown's.

The renderer exposes `metric`, `pieChart`, `barChart`, `dealCard`, and Markdown with their prop schemas. It passes `kit.schema` to `useJsonParser`, reads the parser's `value`, and calls `kit.render(value)`. ## Backend

The agent sends **one JSON object** as the assistant message, without a Markdown fence or prose before it. Its top-level `ui` array contains component names from the kit. Each component has a `props` object matching its schema. For example:

```json title="example assistant message"
{
  "ui": [
    { "metric": { "props": { "label": "Total Revenue", "value": "$1.2M" } } },
    {
      "pieChart": {
        "props": {
          "title": "Revenue by Segment",
          "data": "[{\"label\":\"Enterprise\",\"value\":600000},{\"label\":\"SMB\",\"value\":400000},{\"label\":\"Startup\",\"value\":200000}]"
        }
      }
    }
  ]
}
```

The selected integration's agent uses this envelope and the same component names. The parser can render finished parts of `ui` while the rest of the JSON is still streaming.
