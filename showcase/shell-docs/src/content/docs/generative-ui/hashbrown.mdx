Use Hashbrown when you already have a component library and want an agent's
structured JSON response to render as a dashboard in chat. The selected
Showcase demo sends one schema-valid JSON object; Hashbrown parses it as the
response streams and renders the pieces that are ready.

## When to use this

- **Streaming dashboards** where partial state should render before the full payload arrives.
- **Agents authoring structured UI** where the output is JSON-shaped, not free text.
- **Cases where you already use Hashbrown** for UI generation elsewhere in your stack.

If you'd rather work with an explicit catalog of registered components rather than streaming a JSON tree, see the sibling page [BYOC — JSON Render](/generative-ui/json-render) for the same scenario implemented with `@json-render/react`.

## Try it

Open the demo above and ask: **“Show a Q4 sales dashboard with revenue by
segment and a monthly trend.”** The selected agent must return one JSON object
whose `ui` array uses the component names registered in the kit.

## Backend

The agent streams one JSON object that matches the `useUiKit` schema. In the
selected demo, its top-level `ui` array contains single-key nodes such as
`metric`, `pieChart`, `barChart`, `dealCard`, and `Markdown`; their props must
match the component declarations above. The agent must emit JSON with no prose
prefix because the parser receives its assistant content directly.

## Comparing the two BYOC patterns

Both patterns let an agent produce structured UI from an allowlisted component
set, but their wire contracts differ. Hashbrown consumes a `ui` array of
single-key component nodes and can progressively render the stream. JSON
Render consumes a `{ root, elements }` element map validated against its
catalog. Pick the library you already use and keep its wire format intact.
