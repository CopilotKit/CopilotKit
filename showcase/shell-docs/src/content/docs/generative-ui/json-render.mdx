You have a chat surface and you want the agent to draw a dashboard from a typed JSON spec. By the end of this guide, the agent will emit a `{ root, elements }` object, and [`@json-render/react`](https://www.npmjs.com/package/@json-render/react) will render it through your React component registry:

- The **catalog** (`catalog.ts`) names the components the agent may use, with a Zod schema for the props of each.
- The **registry** (`registry.tsx`) maps each catalog name to a React component.
- The **spec** is the `{ root, elements }` object that the agent sends.

The demo below has all the frontend files. Copy them into `app/demos/declarative-json-render/`, then add the runtime from [Backend](#backend).

## When to use this

- **Structured UI with a typed contract** where the renderer accepts known component types.
- **Tolerance for prose preamble + code fences** in the agent's output (the demo's parser handles them).
- **Cases where you already use json-render** elsewhere or prefer a Zod-described catalog.

If you'd rather have a streaming progressive render than a one-shot JSON render, see the sibling page [Hashbrown](/generative-ui/hashbrown) for the same scenario with `@hashbrownai/react`.

## Frontend

The demos use `@json-render/react` and `@json-render/core` 0.18.0, with Zod 4 for the catalog. `catalog.ts` imports Zod 4 from `"zod"`:

```bash
npm install @json-render/core@0.18.0 @json-render/react@0.18.0 zod@^4.3.6
```

If your app must keep Zod 3 as `zod`, install Zod 4 under an alias, `zod4@npm:zod@^4.3.6`, and change the import in `catalog.ts` to `from "zod4"`. Use the latest Zod 4. If your Zod 4 is older than the one json-render installs, the catalog does not type-check.

1. Copy `catalog.ts` and `registry.tsx`. `catalog.ts` defines component names and Zod prop schemas with `defineCatalog`. `registry.tsx` uses `defineRegistry(catalog, ...)` to bind those names to React components.
2. Copy `json-render-renderer.tsx`. It parses the assistant content and falls back to the normal assistant message until it can parse a spec:

   ```tsx title="json-render-renderer.tsx (excerpt)"
   export function JsonRenderAssistantMessage(
     props: CopilotChatAssistantMessageProps,
   ) {
     const content =
       typeof props.message.content === "string" ? props.message.content : "";
     const spec = useMemo(() => parseSpec(content), [content]);

     if (!spec) return <CopilotChatAssistantMessage {...props} />;

     return (
       <JSONUIProvider registry={registry}>
         <Renderer
           spec={spec as unknown as Parameters<typeof Renderer>[0]["spec"]}
           registry={registry}
         />
       </JSONUIProvider>
     );
   }
   ```

3. Install the renderer in the `assistantMessage` slot of `CopilotChat`:

   ```tsx title="chat.tsx"
   <CopilotChat
     messageView={{
       assistantMessage:
         JsonRenderAssistantMessage as unknown as typeof CopilotChatAssistantMessage,
     }}
   />
   ```

4. Tell the agent to answer with one `{ root, elements }` object, as shown in [Backend](#backend).

The demo's `parseSpec` allowlists component types and checks the basic object shape, but does **not** validate emitted props against the Zod schemas at runtime. Validate props before rendering if you rely on that guarantee.

## Backend

The agent emits a `{ root, elements }` JSON object as the assistant message content. `root` references a top-level element id; `elements` maps each id to a `{ type, props, children }` triple matching the catalog.

```json title="example agent output"
{
  "root": "revenue-card",
  "elements": {
    "revenue-card": {
      "type": "MetricCard",
      "props": { "label": "Total revenue", "value": "$184,302", "trend": "+12%" },
      "children": ["by-region"]
    },
    "by-region": {
      "type": "BarChart",
      "props": {
        "title": "Revenue by region",
        "description": null,
        "data": [
          { "label": "North America", "value": 112000 },
          { "label": "EMEA", "value": 72302 }
        ]
      }
    }
  }
}
```

The example uses a `MetricCard` root and its registered `BarChart` child. The renderer tolerates a prose preamble or code fence around the JSON, but the agent prompts ask for plain JSON.

`page.tsx` connects to `/api/copilotkit-declarative-json-render`, and `chat.tsx` to the agent `byoc_json_render`. Add that runtime, with a Built-in Agent whose prompt asks for the spec:

```ts title="app/api/copilotkit-declarative-json-render/[[...slug]]/route.ts"
import {
  BuiltInAgent,
  CopilotRuntime,
  createCopilotRuntimeHandler,
} from "@copilotkit/runtime/v2";

const JSON_RENDER_PROMPT = `You are a sales dashboard UI generator.
Reply with ONE JSON object and nothing else: no code fence, no text before or after it.
The object is { "root": "<id>", "elements": { "<id>": { "type", "props", "children" } } }.
Every id in root or in a children array must be a key of elements.
Components (use the name as "type"):
- MetricCard: { "label": string, "value": string, "trend": string | null }
- BarChart: { "title": string, "description": string | null, "data": [{ "label": string, "value": number }] }
- PieChart: { "title": string, "description": string | null, "data": [{ "label": string, "value": number }] }
For a dashboard, use a MetricCard as root and list the charts in its children.
Use plausible sample data when the user gives none.`;

const runtime = new CopilotRuntime({
  agents: {
    byoc_json_render: new BuiltInAgent({
      model: "openai:gpt-6-luna",
      prompt: JSON_RENDER_PROMPT,
    }),
  },
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit-declarative-json-render",
});

export const GET = handler;
export const POST = handler;
```

Open `/demos/declarative-json-render` and ask for a dashboard, for example `Show me a revenue dashboard`. The metric card and its charts render in the chat.
