Use JSON Render when you want an agent's structured response checked against a
Zod-described component catalog before it renders in chat. The selected
Showcase demo accepts a `{ root, elements }` spec and turns it into one React
tree with [`@json-render/react`](https://www.npmjs.com/package/@json-render/react).

## When to use this

- **Structured UI with a typed contract** where the agent's output is validated against a known schema before it touches the DOM.
- **Tolerance for prose preamble + code fences** in the agent's output (json-render's parser handles them).
- **Cases where you already use json-render** elsewhere or prefer Zod-validated catalogs.

If you'd rather have a streaming progressive render rather than a one-shot validated render, see the sibling page [BYOC — Hashbrown](/generative-ui/hashbrown) for the same scenario with `@hashbrownai/react`.

## Backend

The agent emits a `{ root, elements }` JSON object. `root` must name an
element in `elements`; every element uses one of the catalog's component names,
an object of matching props, and optional child IDs. The renderer accepts a
balanced JSON object inside a code fence or prose, but the selected Showcase
agent is instructed to send only the JSON object.

## Comparing the two patterns

Both patterns let an agent produce structured UI from an allowlisted component
set, but their wire contracts differ. JSON Render consumes a `{ root,
elements }` element map validated against its catalog. Hashbrown consumes a
`ui` array of single-key component nodes and can progressively render the
stream. Pick the library you already use and keep its wire format intact.
