## What is this?

[A2UI](https://a2ui.org) (Agent-to-UI) is a declarative Generative UI
specification. Your agent sends a JSON schema in place of plain text.
The frontend renders that schema as cards, rows, columns, badges, and
price tags from a catalog of components that you (or the platform)
define.

You can design and preview A2UI schemas visually using the
[A2UI Composer](https://a2ui-composer.ag-ui.com/).

## The two approaches

CopilotKit ships two complementary A2UI approaches:

- **[Dynamic Schema](./a2ui/dynamic-schema)**: a secondary LLM
  generates both the schema *and* the data. Maximum flexibility, so
  the agent can produce any UI for any prompt.

- **[Fixed Schema](./a2ui/fixed-schema)**: the component tree is
  authored ahead of time as JSON. The agent only streams *data* into
  the data model at runtime. Fastest, with no LLM schema generation.

Both approaches share the same A2UI wire protocol and the same
frontend renderer. The difference is *where the schema comes from* and
*how data reaches the client*.

The agent on this page writes A2UI v0.9. The runtime converts it to
A2UI 1.0, and the browser renders it with
[Components and surfaces](/generative-ui/components). An agent that
sends A2UI 1.0 operations, for example a Google ADK agent, needs no
conversion: the runtime passes them through. For a new agent, use
Components and surfaces directly: the agent writes A2UI 1.0 with the
`render_ui` tool.

## How it works

Every A2UI surface is assembled from three operations emitted by the
agent and consumed by the frontend renderer:

1. **`createSurface`** initializes the surface with its catalog and must
   come first.
2. **`updateComponents`** defines the component tree (the schema) for
   the surface.
3. **`updateDataModel`** supplies the data that populates the
   components via JSON Pointer paths.

The CopilotKit Python SDK provides helpers for each:

```python
from copilotkit import a2ui

a2ui.create_surface(surface_id, catalog_id=...)
a2ui.update_components(surface_id, components)
a2ui.update_data_model(surface_id, {"items": data})
a2ui.render(operations=[...])  # wraps in a2ui_operations and serializes
```

## Setup

<Steps>
<Step>
### Set the A2UI version on the runtime

Tell the runtime that the agent writes A2UI v0.9 with
`generativeUI: { a2uiVersion: "0.9" }`:

```typescript title="app/api/copilotkit/[[...slug]]/route.ts"
import { LangGraphAgent } from "@ag-ui/langgraph";
import { CopilotRuntime, InMemoryAgentRunner } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: {
    default: new LangGraphAgent({
      deploymentUrl: process.env.LANGGRAPH_DEPLOYMENT_URL ?? "http://localhost:8123",
      graphId: "sample_agent",
    }),
  },
  generativeUI: { a2uiVersion: "0.9" },
  runner: new InMemoryAgentRunner(),
});
```

The runtime converts the A2UI operations in the agent's tool results
and tool calls to A2UI 1.0. To set the version per agent, pass a
record: `a2uiVersion: { default: "0.9" }`.
</Step>

<Step>
### Give the client a catalog

The client catalog lists the components that the agent can draw.

- **React and Vue:** nothing to add. The provider uses the
  [standard catalog](/generative-ui/components/standard-catalog), which
  has the 18 basic A2UI components.
- **Angular:** add `provideGenerativeUI({ ui: standardUI })` to the root
  providers. See [A2UI in Angular](/angular/generative-ui/a2ui).

To add your own components, pass `generativeUI={{ ui }}` to the
provider. A component renders only when its name is the name that the
agent writes. See [Convert a custom catalog](/generative-ui/components/from-a2ui#convert-a-custom-catalog).
</Step>
</Steps>

### What gets injected

When the client sends a catalog, the runtime adds a tool named
`render_a2ui` to the agent. It also adds a v0.9 component schema of the
client catalog to the agent's context, so the model knows which
components it can use. See [Dynamic Schema](./a2ui/dynamic-schema) for
the full flow.

### Use your own tool

To use your own tool, set `injectA2UITool: false` on the runtime
(`generativeUI: { a2uiVersion: "0.9", injectA2UITool: false }`). Then
provide the tool yourself with the AG-UI factory (`get_a2ui_tools()` in
Python, `getA2UITools()` in TypeScript), where you set the model, the
default catalog id, and more. This is also how the
[Fixed Schema](./a2ui/fixed-schema) approach works: your agent owns a
data-only tool, and the runtime adds no tool.

LangGraph agents that use the CopilotKit middleware (`CopilotKitMiddleware`
in Python, `copilotkitMiddleware` in TypeScript) get `generate_a2ui` in place
of `render_a2ui`. It runs a secondary LLM, a subagent, that designs the full
surface from the client catalog. You do not write this tool yourself.
