In the dynamic-schema approach, a secondary LLM generates the entire
UI (schema, data, and layout) based on the conversation context.
It's the most flexible A2UI flavor; the agent can render any UI for
any request without pre-defined schemas.

## How it works

1. The runtime adds the `render_a2ui` tool to the agent, because the
   runtime has `a2uiVersion: "0.9"` and the client sends a catalog.
2. The runtime turns the client catalog (component names, props and
   descriptions) into a v0.9 component schema in the agent's context,
   so the LLM knows which components it can use.
3. The tool call streams through the agent as `TOOL_CALL_ARGS` events.
4. The A2UI middleware turns the stream into v0.9 operations, and the
   runtime converts them to A2UI 1.0. The browser renders the cards
   as data items arrive.

<Steps>
<Step>
### Declare your components

Each component has a description and a Zod prop schema. The LLM reads
the description to decide which component to use. `extends: [standardUI]`
adds the standard components (Column, Row, Text, Image, Card, Button,
List, Tabs, and more), so the LLM can mix them with your own:

```tsx title="app/dashboard-ui.tsx"
"use client";
import { z } from "zod";
import {
  createGenerativeUI,
  standardUI,
} from "@copilotkit/react-core/generative-ui";

function StatusBadge({ label, status }: { label: string; status: "ok" | "warn" | "down" }) {
  return <span data-status={status}>{label}</span>;
}

function Metric({ label, value }: { label: string; value: string }) {
  return (
    <div>
      <small>{label}</small>
      <strong>{value}</strong>
    </div>
  );
}

export const dashboardUI = createGenerativeUI({
  id: "acme/dashboard@1",
  extends: [standardUI],
  components: {
    StatusBadge: {
      component: StatusBadge,
      description: "A short colored status label for a service.",
      props: z.object({ label: z.string(), status: z.enum(["ok", "warn", "down"]) }),
    },
    Metric: {
      component: Metric,
      description: "One number with its label, for example latency or uptime.",
      props: z.object({ label: z.string(), value: z.string() }),
    },
  },
});
```

A bound prop arrives resolved, so the component gets a plain string.
See [Catalogs](/generative-ui/components/catalogs) for children,
slots and more prop types.
</Step>

<Step>
### Pass the UI to the provider

```tsx title="app/providers.tsx"
"use client";
import { CopilotKitProvider } from "@copilotkit/react-core";
import { dashboardUI } from "./dashboard-ui";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" generativeUI={{ ui: dashboardUI }}>
      {children}
    </CopilotKitProvider>
  );
}
```

With no `generativeUI`, the provider uses the standard catalog. In
Angular, use `provideGenerativeUI({ ui })`. See
[Components and surfaces](/generative-ui/components).
</Step>

<Step>
### Set the A2UI version on the runtime

```typescript title="app/api/copilotkit/[[...slug]]/route.ts"
import { LangGraphAgent } from "@ag-ui/langgraph";
import { CopilotRuntime } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: {
    default: new LangGraphAgent({
      deploymentUrl: process.env.LANGGRAPH_DEPLOYMENT_URL ?? "http://localhost:8123",
      graphId: "a2ui_dynamic_schema",
    }),
  },
  generativeUI: { a2uiVersion: "0.9" },
});
```

The runtime adds the `render_a2ui` tool to the agent.
</Step>
</Steps>

## Use your own tool

To set the model of the tool yourself, turn off the injected tool with
`injectA2UITool: false`:

```typescript title="app/api/copilotkit/[[...slug]]/route.ts"
import { LangGraphAgent } from "@ag-ui/langgraph";
import { CopilotRuntime } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: {
    default: new LangGraphAgent({
      deploymentUrl: process.env.LANGGRAPH_DEPLOYMENT_URL ?? "http://localhost:8123",
      graphId: "a2ui_dynamic_schema",
    }),
  },
  generativeUI: { a2uiVersion: "0.9", injectA2UITool: false },
});
```

Then build the `generate_a2ui` tool with the AG-UI factory and add it to
your agent's tools. It runs a secondary LLM (a subagent) that designs
the surface, which is why you give it a model:

```python title="agent.py"
from ag_ui_langgraph import get_a2ui_tools
from langchain_openai import ChatOpenAI

generate_a2ui = get_a2ui_tools({
    "model": ChatOpenAI(model="gpt-6-luna", reasoning_effort="none"),
    "default_catalog_id": "acme/dashboard@1",
})

tools = [my_other_tool, generate_a2ui]
```

Use the `id` of your UI as `default_catalog_id`. The runtime still
converts the surfaces of the tool to A2UI 1.0.

## Progressive streaming

The secondary LLM's `render_a2ui` tool call streams through the agent
as `TOOL_CALL_ARGS` events. The A2UI middleware:

1. Waits for the full `components` array before emitting anything;
   the schema must be complete before rendering starts.
2. Extracts `surfaceId` + `root` from the partial JSON.
3. Emits `createSurface` + `updateComponents` once the schema is
   complete.
4. Extracts complete `items` objects progressively and emits an
   `updateDataModel` for each, so cards appear one by one as data
   streams in.

## When should I use dynamic schemas?

- You don't know the UI shape ahead of time; the agent decides what
  to show based on the user's request.
- You want to prototype A2UI without committing to a schema file yet.
- You're building a conversational dashboard where the layout varies
  per turn.

If the surface is well-known (e.g. a product card, a flight result),
use a **[fixed schema](./fixed-schema)**. It is faster and cheaper,
and the UI is deterministic.
