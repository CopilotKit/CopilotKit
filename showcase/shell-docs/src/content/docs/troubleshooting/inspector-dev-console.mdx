`enableInspector` controls the built-in Inspector in browser applications:

- `true`: show it on every browser host, including production.
- `false`: never show it.
- omitted: show it only on `localhost`, `127.0.0.1`, or `0.0.0.0`.

The Inspector is not loaded or rendered during server-side rendering.

## React v2

```tsx
import { CopilotKit } from "@copilotkit/react-core/v2";

<CopilotKit runtimeUrl="/api/copilotkit" enableInspector={false}>
  {children}
</CopilotKit>;
```

React v2 still accepts `showDevConsole?: boolean | "auto"` as a deprecated
compatibility alias. When both props are supplied, `enableInspector` wins.
Otherwise, an explicit `showDevConsole` value keeps its existing behavior;
`"auto"` uses the same local-host rule as an omitted `enableInspector`.

## Vue

```vue
<CopilotKitProvider
  runtime-url="/api/copilotkit"
  :enable-inspector="false"
>
  <App />
</CopilotKitProvider>
```

Vue also retains `showDevConsole` as a deprecated compatibility alias, with
the same precedence rules as React v2.

## Angular

```ts
provideCopilotKit({
  runtimeUrl: "/api/copilotkit",
  enableInspector: false,
});
```

Angular has no `showDevConsole` alias. Configure the Inspector through
`enableInspector` on `CopilotKitConfig`.

## React v1

React v1 keeps its existing behavior. `enableInspector` uses the same
localhost-gated default. Its deprecated `showDevConsole?: boolean` prop controls
error toasts and banners, not the Inspector.

<Callout type="warn">
  Setting `enableInspector` to `true` exposes debugging and event details on
  production hosts. Leave it omitted for the development-only default.
</Callout>

## React Native

Native iOS and Android applications do not have a built-in Inspector yet. The
current Inspector is a DOM web component and is not included in the React
Native dependency graph.
