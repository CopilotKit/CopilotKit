This page lists the error strings CopilotKit surfaces in your console, network
responses, and error UI. If you hit an error, search this page with Cmd/Ctrl-F
for a distinctive phrase from the message.

For the programmatic `onError` **codes** (`runtime_info_fetch_failed`,
`tool_handler_failed`, ...) rather than these human-readable strings, see
[Error Debugging](/troubleshooting/error-debugging).

## Missing runtime configuration

Error string:

```txt
Missing required prop: 'runtimeUrl' or 'publicApiKey' or 'publicLicenseKey'
```

**Where:** the provider, `<CopilotKitProvider>`, imported from
`@copilotkit/react-core`. In production
(`NODE_ENV === "production"`) it's a thrown `Error`; in development it's a
`console.warn` so local-agent and test setups still run.

<Callout type="info" title="Local agents satisfy the check">
  Registering `selfManagedAgents` or `agents__unsafe_dev_only` satisfies the
  check. No `runtimeUrl` or Copilot Cloud key is required.
</Callout>

**Cause:** the provider has no way to reach an agent. You didn't pass a
`runtimeUrl`, a Copilot Cloud key (`publicApiKey` / `publicLicenseKey`), **and** you
didn't register any local agents.

**Fix:** provide one of these values to `CopilotKitProvider`, imported from
`@copilotkit/react-core`:

```tsx
import { CopilotKitProvider, HttpAgent } from "@copilotkit/react-core";

// Runtime-backed (recommended)
export function RuntimeProvider({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">{children}</CopilotKitProvider>
  );
}

// Copilot Cloud
export function CloudProvider({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider publicApiKey="ck_pub_...">{children}</CopilotKitProvider>
  );
}

// Agents you manage yourself
const myAgent = new HttpAgent({ url: "http://localhost:8000/agent" });

export function SelfManagedProvider({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider selfManagedAgents={{ "my-agent": myAgent }}>
      {children}
    </CopilotKitProvider>
  );
}
```

See [Self-managed agents](/backend/self-managed-agents) for the local-agent path.

## Agent discovery failed

Error string:

```txt
useAgent: Agent '<id>' not found after runtime sync (runtimeUrl=<url>). Known agents: [<list>] Verify your runtime /info and/or agents__unsafe_dev_only.
```

**Where:** a thrown `Error` from `useAgent` (and the prebuilt components that
call it), imported from `@copilotkit/react-core`. When no agents are
registered, the message shows `No agents registered.` in place of the
known-agents list.

In v1, the hooks and the GraphQL runtime reported this cause as a
`CopilotKitAgentDiscoveryError`. CopilotKit 2.0 removed those APIs.

**Cause:** the frontend asked for an `agentId` that the runtime didn't return from
its `/info` discovery. This is usually a typo, a missing registration, or a runtime that has no
agents at all. The prebuilt components default to the agent named `"default"`.

**Fix:**

- Register the agent under the id you're requesting (or under `"default"` if you
  pass no `agentId`):
  ```ts
  import { CopilotKitRuntime } from "@copilotkit/runtime";
  import { BuiltInAgent } from "@copilotkit/runtime/agent";
  import { openaiText } from "@tanstack/ai-openai";

  const runtime = new CopilotKitRuntime({
    agents: { default: new BuiltInAgent({ model: openaiText("gpt-6-luna") }) },
  });
  ```
- Confirm the id matches the "Known agents" list in the message.
- Verify the runtime is reachable by hitting `GET {runtimeUrl}/info` directly (see
  [Runtime HTTP endpoints](/backend/runtime-endpoints)). A discovery failure here
  cascades into this error.

`useAgent` throws this error while it renders, so your nearest React error
boundary catches it. It does not go to `onError`. `useAgent` throws only after
`/info` loads. If `/info` itself fails, `useAgent` waits instead, `onError`
gets the code `runtime_info_fetch_failed`, and the Inspector shows a
**Runtime error**.

## Agent route returned 404

Error strings:

```txt
Agent not found
Agent '<id>' does not exist
```

**Where:** an HTTP `404` JSON body from the runtime's agent routes:

```json
{ "error": "Agent not found", "message": "Agent 'my-agent' does not exist" }
```

**Cause:** a `POST /agent/:agentId/run`, `/connect`, or `/stop/:threadId` request
named an `agentId` that isn't registered on the runtime. This is the server-side
counterpart to the client-side errors in [Agent discovery failed](#agent-discovery-failed).

**Fix:** register the agent under that key in `new CopilotKitRuntime({ agents: { ... } })`.
If you see this on the `/connect` route **before sending any message**, also read
[the `/connect` 404 entry](/troubleshooting/common-issues#connect-route-returns-404-on-a-fresh-thread).

## Agent run failed

Error string:

```txt
Failed to run agent
```

**Where:** a `500` JSON body from the runtime's run/connect routes, with a
`message` field carrying the underlying error.

**Cause:** the agent threw while executing. Common causes include a bad model id, a missing API key
on the server, a provider error, or an exception inside the agent itself.

**Fix:** read the `message` field and check your server logs (the runtime logs the
error name, message, and stack). Common culprits: an unset `OPENAI_API_KEY` (or
equivalent) on the server, or a model id the provider doesn't recognize.

## Capability discovery failed

Error string:

```txt
Failed to fetch capabilities for agent "<name>"
```

**Where:** a `console.warn` in the runtime's server logs, from the `/info` handler.

**Cause:** the `getCapabilities()` call of the named agent threw. The `/info`
response still lists the agent, without capabilities.

**Fix:** read the error after the colon, and correct the `getCapabilities()`
method of the agent.
