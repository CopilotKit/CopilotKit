When a run fails, you need to see the error while you develop and send it to your error tracker in production. Turn on the dev console for development. The dev console shows error banners and toasts in your app. Then add an `onError` handler for production.

## Quick setup

```tsx
import { CopilotKit } from "@copilotkit/react-core/v2";

export default function App() {
  return (
    <CopilotKit
      runtimeUrl="/api/copilotkit"
      showDevConsole={true} // [!code highlight]
    >
      {/* your app */}
    </CopilotKit>
  );
}
```

`showDevConsole` is deprecated. It still turns on the error banners and toasts of the dev console. For the Inspector, use `enableInspector`.

The banners come from the `<CopilotKit>` component. `<CopilotKitProvider>` accepts `showDevConsole` but ignores it. If your app uses `<CopilotKitProvider>` (as the quickstart does), replace it with `<CopilotKit>` while you debug, or use [`onError`](#programmatic-error-handling) to show your own message.

To check the setup, set `runtimeUrl` to a route that does not exist, for example `/api/copilotkit-off`, and reload the page. An error banner appears. Click **Show Details** to see the code `runtime_info_fetch_failed`.

<Callout type="warn">
Do not show the dev console in production. It exposes internal error details to end users.
</Callout>

## Programmatic error handling

Pass `onError` to the provider to catch every error, or to `CopilotChat` to catch the errors of one chat.

### Provider-level error handling

Catches every error across the entire application:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core/v2";

<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  onError={(event) => {
    // event.code    — error type (e.g. "runtime_info_fetch_failed", "agent_run_failed")
    // event.error   — the Error object
    // event.context — additional context (agentId, toolName, etc.)
    console.error(`[CopilotKit ${event.code}]`, event.error.message);
    errorTracker.capture(event); // replace with your error tracker
  }}
>
  <App />
</CopilotKitProvider>;
```

### Chat-level error handling

Scoped to a specific chat's agent. It fires **in addition to** the provider-level handler. It also receives errors that have no agent, such as `runtime_info_fetch_failed`:

```tsx
import { CopilotChat } from "@copilotkit/react-core/v2";

<CopilotChat
  onError={(event) => {
    // The prop type also allows a DOM error event, so check for `code` first.
    if ("code" in event) {
      showToast(`Agent error: ${event.error.message}`); // your toast function
    }
  }}
/>;
```

### Errors replayed from thread history

<Callout type="info">
Requires `@copilotkit/react-core` 1.89.0 or later. In earlier versions `event.context.phase` is not set.
</Callout>

Connecting to an existing thread replays its history, including a `RUN_ERROR` from an earlier run. `onError` receives that error with the code `agent_run_error_event`, like a live failure. `event.context.phase` tells them apart:

- `"live"`: a run happening now.
- `"replay"`: thread history. Only threads stored in [CopilotKit Intelligence](/intelligence/overview) report this value.
- `"unknown"`: the connection can't tell. A self-hosted Copilot Runtime (for example the default in-memory runner) sends replayed errors as `"unknown"`, so they still reach your banner.

If your handler shows a banner, skip only `"replay"`. Keep `"unknown"` visible, so a live failure is never hidden:

```tsx
import {
  CopilotKitProvider,
  CopilotKitCoreErrorCode,
} from "@copilotkit/react-core/v2";

<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  onError={(event) => {
    errorTracker.capture(event); // Still record every error.
    if (
      event.code === CopilotKitCoreErrorCode.AGENT_RUN_ERROR_EVENT &&
      event.context.phase === "replay"
    ) {
      return; // An earlier run's failure, replayed on connect.
    }
    showErrorBanner(event.error.message); // your banner function
  }}
>
  <App />
</CopilotKitProvider>;
```

### Common error codes

The full list is the `CopilotKitCoreErrorCode` enum, exported from `@copilotkit/react-core/v2`.

| Code | Description |
|------|-------------|
| `runtime_info_fetch_failed` | Could not reach the runtime's `/info` endpoint |
| `agent_connect_failed` | Agent connection (thread setup) failed |
| `agent_run_failed` | Agent run rejected (for example, a network error) |
| `agent_run_failed_event` | The agent's `onRunFailed` subscriber fired |
| `agent_run_error_event` | Agent emitted a `RUN_ERROR` event |
| `tool_argument_parse_failed` | Tool call arguments were not valid JSON |
| `tool_handler_failed` | A frontend tool handler threw |
| `tool_not_found` | A tool call or `runTool()` named a tool that is not registered |
| `agent_not_found` | `runTool()` named an `agentId` that is not registered |
| `agent_thread_locked` | Another run is active on the same thread |
| `header_resolution_failed` | Your `headers` function threw or returned something other than an object. The request was not sent |
| `subscriber_callback_failed` | A subscriber callback threw |

<Callout type="info">
To see every event your agent emits and where events drop, open the [Inspector](../inspector). When a run fails, the launcher turns red. Click the launcher to open the pane for the failure. The pane shows the agent, the tool if one failed, and the error.
</Callout>

## Troubleshooting

### Dev console not showing

- Confirm `showDevConsole={true}`
- Check for JavaScript errors in the browser console
- Make sure that no CSS hides the error banners of the dev console

### Production error pipeline checklist

- Provider-level `onError` is wired and forwards to your error tracker
- `showDevConsole` is **false** in production builds
- Agent IDs in errors match the agents registered on your runtime
- Critical error codes (`agent_run_failed`, `tool_handler_failed`) are alerted on, not only logged
