# How to debug errors

When a run fails, you need to see the error while you develop and send it to your error tracker in production. Use the Inspector for development. It shows errors in your app, is on by default in development builds, and needs no API key. Then add an `onError` handler for production.

## Quick setup

The Inspector is on by default in development builds on localhost. `enableInspector` controls it:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";

export default function App({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      enableInspector={true} // [!code highlight]
    >
      {children}
    </CopilotKitProvider>
  );
}
```

To check the setup, stop your runtime and reload the page. The Inspector launcher shows a **Runtime error** pill. Open the Inspector to see the details. An `onError` handler gets the code `runtime_info_fetch_failed`.

<Callout type="info">
The Inspector never loads in production builds, so it does not expose internal error details to end users. See [Inspector and dev console](/troubleshooting/inspector-dev-console).
</Callout>

## When to use development debugging

- **Local development**: errors appear immediately in your UI
- **Quick debugging**: no setup required, works by default
- **Testing**: verify error handling during development

## Programmatic error handling

Pass `onError` to `CopilotKitProvider` to catch every error, or to `CopilotChat` to catch the errors of one chat. No `publicApiKey` is required.

### Provider-level error handling

Catches every error across the entire application:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";
import { errorTracker } from "./error-tracker";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        // event.code    — error type (e.g. "runtime_info_fetch_failed", "agent_run_failed")
        // event.error   — the Error object
        // event.context — additional context (agentId, toolName, etc.)
        console.error(`[CopilotKit ${event.code}]`, event.error.message);
        errorTracker.capture(event);
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

### Chat-level error handling

Scoped to a specific chat's agent. It fires **in addition to** the provider-level handler:

```tsx
import { CopilotChat } from "@copilotkit/react-core";
import { showToast } from "./toast";

export function Chat() {
  return (
    <CopilotChat
      agentId="my-agent"
      onError={(event) => {
        showToast(`Agent error: ${event.error.message}`);
      }}
    />
  );
}
```

### Error codes

| Code | Description |
|------|-------------|
| `runtime_info_fetch_failed` | Could not reach the runtime's `/info` endpoint |
| `agent_connect_failed` | Agent connection (thread setup) failed |
| `agent_run_failed` | Agent run rejected (e.g. network error) |
| `agent_run_failed_event` | The agent's `onRunFailed` subscriber fired |
| `agent_run_error_event` | Agent emitted a `RUN_ERROR` event |
| `tool_argument_parse_failed` | Tool call arguments were not valid JSON |
| `tool_handler_failed` | A frontend tool handler threw |

<Callout type="info">
To see every event your agent emits and where events drop, open the [Inspector](../inspector). When a run fails, the launcher turns red. Click the launcher to open the pane for the failure. The pane shows the agent, the tool if one failed, and the error.
</Callout>

## Troubleshooting

### Inspector not showing

- Confirm that `enableInspector` is not `false`
- Confirm that you run a development build, not a production build
- Check for JavaScript errors in the browser console
- Make sure that no CSS hides the Inspector launcher

### Production error pipeline checklist

- Provider-level `onError` is wired and forwards to your error tracker
- Agent IDs in errors match the agents registered on your runtime
- Critical error codes (`agent_run_failed`, `tool_handler_failed`) are alerted on, not just logged
