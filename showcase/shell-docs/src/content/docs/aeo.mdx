---
title: Public AEO surface contract
description: Ownership, compatibility, and verification policy for CopilotKit's public machine-readable surfaces.
---

Use this policy when you change a public surface that search engines, answer
engines, coding agents, or other machine clients use to discover and verify
CopilotKit.

The [machine-readable v1 contract](https://docs.copilotkit.ai/.well-known/copilotkit-capabilities/v1.json)
contains the exact endpoint inventory, owners, media types, and verification
commands. This page defines how maintainers interpret and change that contract.

## Canonical hosts

| Surface | Canonical origin |
| --- | --- |
| Website | `https://www.copilotkit.ai` |
| Documentation | `https://docs.copilotkit.ai` |
| Documentation MCP | `https://mcp.copilotkit.ai` |

Machine endpoints must return their declared content type. An HTML not-found
page served with a successful status is a failure unless `text/html` is the
declared response type.

## Requirement classes

Every contract entry belongs to one of these classes:

| Class | Meaning |
| --- | --- |
| Published standard | A requirement defined by a standards body or established web protocol, such as robots, sitemaps, and canonical links. |
| Community convention | An interoperable ecosystem convention without a governing web standard, such as `llms.txt`. |
| CopilotKit convention | A versioned guarantee that CopilotKit publishes for machine consumers. |

The JSON contract cites the external authority for standards and community
conventions. CopilotKit conventions are governed by the compatibility rules
below.

## Ownership and verification

Repository-owned documentation surfaces must name an automated command that
executes their behavioral checks. Website and documentation MCP requirements
must name the external owner and a concrete follow-up instead of implying that
this repository enforces them.

| Owner | Scope |
| --- | --- |
| CopilotKit docs maintainers | Documentation pages and machine routes in `CopilotKit/CopilotKit`. |
| CopilotKit website maintainers | Website discovery and LLM surfaces in `CopilotKit/website`. |
| Pathfinder/docs MCP maintainers | Documentation MCP transport and future discovery surfaces. |

The currently published documentation MCP transport is `/sse`. Machine-readable
MCP discovery is not yet specified by this contract and remains Pathfinder-owned
follow-up work.

## Compatibility

- Additive fields and surfaces may be introduced within v1. Consumers must
  ignore fields they do not recognize.
- Breaking schema or semantic changes require a new versioned endpoint.
- Keep the previous endpoint available until migration guidance is published
  and its retirement is communicated.
- Do not silently change an endpoint's media type or replace a machine response
  with an HTML fallback.
- Review the contract in the same pull request as a public-surface change and
  at least once per quarter.

## Review checklist

Before merging a public-surface change:

1. Classify the requirement as a standard, community convention, or CopilotKit
   convention.
2. Confirm the canonical host, path or path template, status behavior, and
   content type.
3. Update the versioned JSON contract in the same pull request.
4. Add or update a fail-loud behavioral check for repository-owned behavior.
5. Name the external owner and concrete follow-up for behavior owned elsewhere.
6. Verify deployed output. HTML fallback pages must not pass machine-surface
   checks.
7. Publish a new endpoint version and migration guidance before a breaking
   change.
