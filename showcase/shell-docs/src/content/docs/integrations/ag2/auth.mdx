## What this demonstrates

The AG2 Authentication demo keeps the authorization boundary in the CopilotKit
runtime. The frontend sends an `Authorization` request header, and the runtime
rejects a missing or invalid header before it forwards work to the AG2 agent.

<Callout type="warn" title="Demo token only">
  The Showcase uses a fixed token so you can see both the signed-out and
  signed-in states. Do not use a browser-shipped token or this comparison in a
  production app. Validate your application's session or token on the server,
  then scope every agent tool and data query to that verified identity.
</Callout>

## Troubleshooting

If every request is rejected, inspect the header object passed to
`<CopilotKit>` and verify that your server accepts the same credential format.
If a request reaches an agent without a verified identity, move the validation
to the runtime request hook and make tool and data authorization depend on the
verified server-side identity.
