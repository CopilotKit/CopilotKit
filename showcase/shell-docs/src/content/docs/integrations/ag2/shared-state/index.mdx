## What is shared state?

Your agent and your UI share one state object. With shared state, you can:

- Display the agent's current progress and intermediate results. See [Reading agent state](/ag2/shared-state/read).
- Update the agent's state through UI interactions. See [Writing agent state](/ag2/shared-state/write).
- React to state changes in real-time across your application

AG2 keeps shared state in **conversation variables** (`Context.variables`). `AGUIStream` sends them to the UI as an AG-UI `StateSnapshotEvent`:

- At the start of a run, when the agent or `dispatch()` defines initial variables.
- At the end of a run, when a tool changed the variables.

<Callout type="info">
  CopilotKit consumes AG-UI protocol events streamed by AG2 over <code>/chat</code>. See the <a href="https://docs.ag2.ai/docs/user-guide/ag-ui/" target="_blank">AG2 AG-UI integration docs</a>.
</Callout>

## When should I use this?

Use shared state when the agent and the user work on the same data. Any state that your AG2 backend
emits in snapshot events will be automatically shared by the UI. Similarly, any state that the user updates in the UI will be automatically reflected.

This allows for a consistent experience where both the agent and the user are on the same page.
