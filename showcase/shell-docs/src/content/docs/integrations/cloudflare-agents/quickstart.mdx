## Start with your coding agent

Use this prompt to connect your Cloudflare agent to CopilotKit and verify a working conversation. Your coding agent will follow this guide in your project, or you can work through the manual steps below.

<PageAgentPrompt />

This quickstart serves an agent built with the Cloudflare Agents SDK over AG-UI from a Worker, runs it locally with wrangler, and connects it to a React app.

## Prerequisites

Before you begin, you'll need the following:

- Node.js 22.12 or later (wrangler refuses to run on older versions)
- An OpenAI API key, as `OPENAI_API_KEY`

Running the Worker locally needs no Cloudflare account: `wrangler dev` runs it on workerd with a local Durable Object store.

## Getting started

<Steps>
  <Step>
    ### Create the Worker project

    Create a project for the agent and install the Agents SDK, its AG-UI adapter and the AI SDK with its OpenAI provider, then wrangler and TypeScript:

    ```bash
    mkdir agent && cd agent
    npm init -y
    npm install agents @ag-ui/cloudflare-agents ai @ai-sdk/openai
    npm install -D wrangler typescript
    ```
  </Step>

  <Step>
    ### Configure the Worker

    Each agent class is a Durable Object. Declare it in `wrangler.jsonc`, with the migration that creates its storage:

    ```jsonc title="wrangler.jsonc"
    {
      "name": "agent",
      "main": "src/index.ts",
      "compatibility_date": "2026-09-01",
      "compatibility_flags": ["nodejs_compat"],
      "durable_objects": {
        "bindings": [{ "name": "Assistant", "class_name": "Assistant" }]
      },
      "migrations": [{ "tag": "v1", "new_sqlite_classes": ["Assistant"] }]
    }
    ```

    `wrangler dev` reads local secrets from `.dev.vars`:

    ```plaintext title=".dev.vars"
    OPENAI_API_KEY=your_openai_api_key
    ```

    Add a `tsconfig.json`, then generate the `Env` type of your bindings and secrets:

    ```json title="tsconfig.json"
    {
      "compilerOptions": {
        "target": "es2024",
        "lib": ["es2024"],
        "module": "es2022",
        "moduleResolution": "bundler",
        "strict": true,
        "skipLibCheck": true,
        "noEmit": true
      },
      "include": ["worker-configuration.d.ts", "src/**/*.ts"]
    }
    ```

    ```bash
    npx wrangler types
    ```
  </Step>

  <Step>
    ### Expose the agent over AG-UI

    CopilotKit talks to agents over AG-UI. Make your agent class AG-UI-capable with the adapter's `withAGUI`, and return `streamText` from its `onAGUIRun` handler. `run.streamTextOptions()` supplies everything the client sent: the instructions with the application's context and the shared state, the conversation, the frontend's tools and the signal that stops the model when the user stops the run. The adapter streams the result back as AG-UI events, so you don't write the event loop yourself.

    ```ts title="src/index.ts"
    import { Agent, routeAgentRequest } from "agents";
    import {
      toThreadRequest,
      withAGUI,
      type AGUIRun,
    } from "@ag-ui/cloudflare-agents";
    import { createOpenAI } from "@ai-sdk/openai";
    import { streamText } from "ai";

    type State = Record<string, unknown>;

    export class Assistant extends withAGUI(Agent<Env, State>) {
      initialState: State = {};

      onAGUIRun(run: AGUIRun<State>) {
        const openai = createOpenAI({ apiKey: this.env.OPENAI_API_KEY });
        return streamText({
          model: openai("gpt-6-luna"),
          ...run.streamTextOptions({
            instructions: "You are a helpful assistant embedded in a CopilotKit app.",
          }),
        });
      }
    }

    export default {
      async fetch(request, env): Promise<Response> {
        return (
          (await routeAgentRequest(await toThreadRequest(request), env)) ??
          new Response("Not found", { status: 404 })
        );
      },
    } satisfies ExportedHandler<Env>;
    ```

    The agent's `state` is the thread's shared state, kept in its Durable Object; `initialState` is where it starts. `routeAgentRequest` serves the `Assistant` binding at `/agents/assistant/<thread id>`, one Durable Object per thread. Copilot Runtime posts every run to one URL, `/agents/assistant`, so `toThreadRequest` first moves the run's thread id from the request body into the path.

    Start the Worker:

    ```bash
    npx wrangler dev --port 8000
    ```

    Leave it running, and send it a run from a second terminal:

    ```bash
    curl -N http://localhost:8000/agents/assistant \
      -H "Content-Type: application/json" \
      -H "Accept: text/event-stream" \
      -d '{"threadId":"t1","runId":"r1","messages":[{"id":"m1","role":"user","content":"Hello"}],"tools":[],"context":[],"state":{},"forwardedProps":{}}'
    ```

    The reply streams back as AG-UI events, from `RUN_STARTED` through `TEXT_MESSAGE_CONTENT` to `RUN_FINISHED`.
  </Step>

  <Step>
    ### Create your frontend

    CopilotKit works with any React app. This example uses Next.js App Router. In the second terminal, go to the folder that contains `agent`, so the app sits next to the Worker rather than inside it:

    ```bash
    npx create-next-app@latest frontend
    cd frontend
    npm install @copilotkit/runtime @copilotkit/react-core @ag-ui/client@1.0.5
    ```
  </Step>

  <Step>
    ### Add the CopilotKit runtime route

    Create `app/api/copilotkit/route.ts` in your Next.js app. It registers your agent as an AG-UI `HttpAgent`.

    ```ts title="app/api/copilotkit/route.ts"
    import { HttpAgent } from "@ag-ui/client";
    import {
      CopilotRuntime,
      createCopilotRuntimeHandler,
    } from "@copilotkit/runtime/v2";
    import type { NextRequest } from "next/server";

    const runtime = new CopilotRuntime({
      agents: {
        assistant: new HttpAgent({
          url: process.env.AGENT_URL ?? "http://localhost:8000/agents/assistant",
        }),
      },
    });

    const handler = createCopilotRuntimeHandler({
      runtime,
      basePath: "/api/copilotkit",
      mode: "single-route",
    });

    export const POST = (req: NextRequest) => handler(req);
    ```

    <Callout type="info" title="A client that puts the thread id in the URL">
      `@ag-ui/cloudflare-agents/client` exports `CloudflareAgentsHttpAgent`, an `HttpAgent`
      that adds the run's thread id to the URL itself. Install `@ag-ui/cloudflare-agents` in the
      frontend to use it; the Worker can then pass requests to `routeAgentRequest` without
      `toThreadRequest`. Keep `toThreadRequest` when a plain `HttpAgent` posts to the Worker.
    </Callout>
  </Step>

  <Step>
    ### Mount CopilotKit in React

    Wrap your app with `CopilotKit` and target the agent name you registered in the runtime route.

    ```tsx title="app/layout.tsx"
    import { CopilotKit } from "@copilotkit/react-core/v2";
    import "@copilotkit/react-core/v2/styles.css";
    import "./globals.css";

    export default function RootLayout({ children }: { children: React.ReactNode }) {
      return (
        <html lang="en">
          <body>
            <CopilotKit runtimeUrl="/api/copilotkit" agent="assistant">
              {children}
            </CopilotKit>
          </body>
        </html>
      );
    }
    ```

    <Callout type="info" title="This relative runtimeUrl assumes Next.js serves the runtime">
      `/api/copilotkit` resolves only because Next.js serves your app and the runtime from the
      same origin. A client-only frontend has no shared origin, so it needs a standalone runtime
      server of its own and an absolute `runtimeUrl` such as
      `http://localhost:8200/api/copilotkit`. The per-frontend guides at `/react-spa`, `/vue`,
      `/angular` and `/react-native` each show that setup.
    </Callout>

    Add a chat surface:

    ```tsx title="app/page.tsx"
    "use client";

    import { CopilotSidebar } from "@copilotkit/react-core/v2";

    export default function Page() {
      return (
        <main>
          <CopilotSidebar />
        </main>
      );
    }
    ```
  </Step>

  <Step>
    ### Start the UI

    Keep `wrangler dev` running, then start the frontend from the `frontend` folder:

    ```bash
    npm run dev
    ```
  </Step>

  <Step>
    ### Verify the integration

    Open `http://localhost:3000` and ask:

    ```plaintext
    Tell me in one sentence what this app can do.
    ```

    If the chat streams a response, CopilotKit is connected to your Cloudflare agent.

    <Accordions className="mb-4">
      <Accordion title="Troubleshooting">
        - If the runtime cannot reach the agent, check that `wrangler dev` is running and that `AGENT_URL` names the agent's path, `http://localhost:8000/agents/assistant` in this example: `/agents/` followed by the Durable Object binding's name in kebab case.
        - If the Worker answers `Not found`, the request reached it without a thread id in its path. Route it through `toThreadRequest`, which handles the AG-UI POST that `HttpAgent` sends.
        - If every chat turn fails with an authentication error, set `OPENAI_API_KEY` in the Worker's `.dev.vars`, not only in the frontend, and restart `wrangler dev`.
        - If a run ends with `put() called with undefined value`, the agent class has no `initialState`. Give it one, even `{}`.
        - If a run stops right after a tool call, check whether the tool is a frontend tool. Those end the run until the browser answers, and the next request carries the result back to the model.
      </Accordion>
    </Accordions>
  </Step>

  </Step>

</Steps>
