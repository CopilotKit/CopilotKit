## Start with your coding agent

Use this prompt to connect your Mastra agent to CopilotKit and verify a working conversation. Your coding agent will follow this guide in your project, or you can work through the manual steps below.

<PageAgentPrompt />

## Prerequisites

Before you begin, you'll need the following:

- An OpenAI API key, or an Anthropic API key if you run the agent on Claude
- Node.js 22.13+ (the `create-mastra` template requires it)
- Your favorite package manager

            <Step>
                ### Initialize your Mastra project

                If you don't already have a Mastra project set up, create one. `--llm openai` picks the model provider, so the command does not ask (use `--llm anthropic` for Claude):

                ```bash
                npx create-mastra@latest my-agent --llm openai
                cd my-agent
                ```
            </Step>
            <Step>
                ### Create your Mastra agent

                Create a new agent file in your Mastra project:

                ```ts title="src/mastra/agents/index.ts"
                import { Agent } from "@mastra/core/agent";

                export const myAgent = new Agent({
                  id: "my-agent",
                  name: "My Agent",
                  instructions: "You are a helpful assistant!",
                  model: "openai/gpt-6-luna",
                });
                ```

                Then register it in your Mastra instance. Replace the generated `src/mastra/index.ts` with this file. The template's own agent in `agents/agent.ts` is then not registered:

                ```ts title="src/mastra/index.ts"
                import { Mastra } from "@mastra/core";
                import { myAgent } from "./agents";

                export const mastra = new Mastra({
                  agents: { myAgent },
                });
                ```

                <Callout type="warn" title="Use the agent's `id` in the frontend">
                  With `MastraAgent.getRemoteAgents` (the setup on this page), CopilotKit names each
                  agent by the `id` that the Mastra server reports in `/api/agents`, here `my-agent`.
                  With `MastraAgent.getLocalAgents`, it uses the key you register the agent under in
                  `new Mastra({ agents })`, here `myAgent`.
                </Callout>

                <Callout type="info" title="Running this agent on Anthropic instead">
                  This example uses OpenAI's `gpt-6-luna`. For Claude, change the `model`
                  string. Mastra's model router needs no extra package:

                  ```ts title="src/mastra/agents/index.ts"
                  export const myAgent = new Agent({
                    // ...
                    model: "anthropic/claude-sonnet-4-6",
                  });
                  ```

                  The credential variable changes with the vendor. For Anthropic models,
                  Mastra reads `ANTHROPIC_API_KEY`, so export that instead of
                  `OPENAI_API_KEY` in the next step.

                  <ApiKeyHint provider="anthropic" />
                </Callout>
            </Step>
            <Step>
                ### Configure your environment

                Set your OpenAI API key as an environment variable:

                ```bash
                export OPENAI_API_KEY=your_openai_api_key
                ```

                <ApiKeyHint provider="openai" />
            </Step>
            <Step>
                ### Start your agent

                Leave the Mastra server running in its own terminal:

                ```bash
                npx mastra dev
                ```

                Note the port it prints. `mastra dev` takes 4111 when it is free and walks
                up to 4131 when it is not, and the frontend you build next reaches this
                agent over HTTP at that address.

                Confirm it is serving your agent before you wire the frontend to it:

                ```bash
                curl http://127.0.0.1:4111/api/agents
                ```

                The response lists your agent under its `id`, `my-agent`.

                <Callout type="warn" title="A bare `GET /` is not a liveness check">
                  `GET /` returns `200` even when no agent is registered. Look for your agent in `/api/agents`.
                </Callout>
            </Step>
            <Step>
                ### Create your frontend

                CopilotKit works with any React-based frontend. This example uses Next.js.

                Create it *beside* your Mastra project, not inside it:

                `--yes` accepts the recommended defaults (TypeScript, Tailwind, App Router):

                ```bash
                cd ..
                npx create-next-app@latest my-copilot-app --yes
                cd my-copilot-app
                ```

                <Callout type="warn" title="Keep `next dev` out of your Mastra project root">
                  On its first run, Next.js rewrites the `tsconfig.json` in its root. A sibling folder keeps the build config of your agent as it is.
                </Callout>
            </Step>
            <Step>
                ### Install CopilotKit packages

                ```npm
                npm install @copilotkit/react-core @copilotkit/runtime @ag-ui/mastra @mastra/client-js
                ```
            </Step>
            <Step>
                ### Setup Copilot Runtime

                Create an API route that connects CopilotKit to the Mastra server you
                started above. `MastraAgent.getRemoteAgents` asks that server which agents
                it has and bridges each one over HTTP, so your agent keeps running as its
                own process:

                ```ts title="app/api/copilotkit/[[...slug]]/route.ts" doctest="component"
                import {
                  CopilotRuntime,
                  createCopilotRuntimeHandler,
                } from "@copilotkit/runtime/v2";
                import { MastraAgent } from "@ag-ui/mastra";
                import { MastraClient } from "@mastra/client-js";

                const mastraClient = new MastraClient({
                  baseUrl: process.env.MASTRA_BASE_URL ?? "http://127.0.0.1:4111",
                });

                const runtime = new CopilotRuntime({
                  // A factory, so the agent list is fetched per request rather than at
                  // module load — the route survives an agent server that is not up yet.
                  agents: ({ request }) =>
                    MastraAgent.getRemoteAgents({
                      mastraClient,
                      // Scopes Mastra's own memory to one user. Pass your signed-in user's id here.
                      resourceId: request.headers.get("x-user-id") ?? "anonymous",
                    }),
                });

                const handler = createCopilotRuntimeHandler({
                  runtime,
                  basePath: "/api/copilotkit",
                });

                export const GET = handler;
                export const POST = handler;
                export const PATCH = handler;
                export const DELETE = handler;
                ```

                The runtime reads the address of the agent server from `MASTRA_BASE_URL` in this
                frontend app's `.env`, not in the Mastra project:

                ```plaintext title=".env"
                MASTRA_BASE_URL=http://127.0.0.1:4111
                ```

                `MASTRA_BASE_URL` defaults to `http://127.0.0.1:4111`, so you only need it
                if your agent server took a different port or you are pointing at a
                deployed Mastra service.

                <Callout type="info" title="Embedding Mastra instead">
                  If your Mastra instance lives inside this Next.js app rather than in its
                  own process, swap `getRemoteAgents` for
                  `MastraAgent.getLocalAgents({ mastra, resourceId })` and drop the client.
                  See [local vs remote agents](/mastra/backend/copilot-runtime#local-vs-remote-agents)
                  for which one to choose.
                </Callout>

                This route runs with an in-memory runner. Chat and the Inspector work without any key.

                <Accordions className="mb-4">
                    <Accordion title="Optional: connect CopilotKit Intelligence">
                        From this frontend app directory, sign in and select an Intelligence project:

                        ```bash title="Terminal"
                        npx copilotkit@latest login
                        npx copilotkit@latest project select
                        ```

                        `login` opens a browser sign-in. `project select` writes the server-side project API key to `.env`:

                        ```plaintext title=".env"
                        CPK_INTELLIGENCE_API_KEY=cpk-...
                        ```

                        Then add `CopilotKitIntelligence` to the imports and these two options to `new CopilotRuntime({ ... })`:

                        ```ts
                        intelligence: new CopilotKitIntelligence({
                          apiKey: process.env.CPK_INTELLIGENCE_API_KEY!,
                        }),
                        // Threads are per-user. Without this, every visitor shares one history.
                        identifyUser: (request) => ({
                          id: request.headers.get("x-user-id") ?? "anonymous",
                          name: request.headers.get("x-user-name") ?? "Anonymous",
                        }),
                        ```

                        Without the key, the route fails when it loads, with an error that the `CopilotKitIntelligence` `apiKey` is required. See [Connect your runtime to Intelligence](/intelligence/quickstart) to confirm the key is in use.
                    </Accordion>
                </Accordions>
            </Step>
            <Step>
                ### Configure CopilotKit Provider

                Put the provider in a client file of your own:

                ```tsx title="app/providers.tsx"
                "use client";

                import { CopilotKit } from "@copilotkit/react-core/v2";

                export function Providers({ children }: { children: React.ReactNode }) {
                  return (
                    <CopilotKit runtimeUrl="/api/copilotkit" agent="my-agent" useSingleEndpoint={false}>
                      {children}
                    </CopilotKit>
                  );
                }
                ```

                Then wrap your application with that file. Keep the generated `app/layout.tsx` (fonts and metadata). Add the highlighted imports and wrap `{children}` in `<Providers>`:

                ```tsx title="app/layout.tsx"
                import { Suspense } from "react"; // [!code highlight]
                import { Providers } from "./providers"; // [!code highlight]
                import "@copilotkit/react-core/v2/styles.css"; // [!code highlight]
                import './globals.css';

                // ...

                export default function RootLayout({ children }: {children: React.ReactNode}) {
                  return (
                    <html lang="en">
                      <body>
                        {/* [!code highlight:5] */}
                        <Suspense>
                          <Providers>
                            {children}
                          </Providers>
                        </Suspense>
                      </body>
                    </html>
                  );
                }
                ```

                `<Suspense>` keeps `npm run build` working when `next.config.ts` sets `cacheComponents: true`, the `create-next-app` default in Next.js 16. Without it, the build fails with `encountered the unstable value require('node:crypto').randomUUID()`.

                <Callout type="info" title="This relative runtimeUrl assumes Next.js serves the runtime">
                  For a client-only frontend, see the guides at `/react-spa`, `/vue`, `/angular`, and `/react-native`.
                </Callout>
            </Step>

              ```tsx title="app/page.tsx"
              "use client"; // [!code highlight]

              import { CopilotSidebar } from "@copilotkit/react-core/v2"; // [!code highlight:1]

                return (
                  <main>
                    <h1>Your App</h1>
                    {/* [!code highlight:1] */}
                    <CopilotSidebar />
                  </main>
                );
              }
              ```

## Next steps

Mastra runs your agents, tools and workflows. CopilotKit puts them in your app, where your users can see the run, interrupt it and steer it.

Add a capability:

- [Generative UI](/mastra/generative-ui/state-rendering): show the agent's working memory as your own components while the agent works.
- [Human-in-the-loop](/mastra/human-in-the-loop/useInterrupt): when a tool calls `suspend()`, show your own UI for the decision, then resume the run with the answer.
- [Shared state](/mastra/shared-state): keep the agent's working memory and your app's state in sync, in both directions.
- [Frontend tools](/mastra/frontend-tools): let the agent call tools that update your app directly.
- [And more](/mastra/build-with-agents): chat surfaces, headless UI and background tasks work with Mastra too. Give your AI coding agent current CopilotKit knowledge, so it can help you build them.

Go further:

- [Live demos](/examples?framework=mastra): try each capability with a Mastra agent.
- Using Vue, Angular, or React Native? Pick it in the sidebar's **Frontend** menu. Its quickstart connects this agent.
