---
title: "Dynamic Schema A2UI"
description: "LLM-generated A2UI: a secondary LLM creates both the schema and data from any prompt."
---
Use this approach when your agent must draw a different UI for each request, such as a dashboard for any question. A secondary LLM writes the layout and the data. You supply the components it can use.

It is the most flexible A2UI approach: the agent can render any UI for any request without pre-defined schemas.

## How it works

1. The primary LLM decides to call `generate_a2ui`
2. Inside the tool, a secondary LLM generates a `render_a2ui` tool call with components, data, and layout
3. The tool call arguments stream through the agent as `TOOL_CALL_ARGS` events
4. The A2UI middleware intercepts these events and renders cards progressively as they stream in

## Frontend / runtime

Enable A2UI on your `CopilotRuntime` with `injectA2UITool: true`:

```typescript title="app/api/copilotkit/route.ts"
const runtime = new CopilotRuntime({
  agents: { default: myAgent },
  a2ui: {
    injectA2UITool: true,
  },
});
```

`injectA2UITool: true` forwards the decision to the agent, so the agent gets the A2UI tool. With `injectA2UITool: false`, no tool is injected, but surfaces from your own tools still render. To turn A2UI off, set `a2ui: { enabled: false }`.

Register your component catalog on the provider so the LLM knows what it can draw (see [Bring Your Own Catalog](../../../../generative-ui/a2ui/dynamic-schema) for the catalog `definitions` / `renderers` / `createCatalog` split):

```tsx title="frontend/src/app/page.tsx"
<CopilotKit a2ui={{ catalog: myCatalog }}>
  {/* ... */}
</CopilotKit>
```

## Backend: auto-injected tool

<Callout type="info" title="Using .NET?">
  The backend steps below are for a Python agent. A .NET agent binds its own `generate_a2ui` tool, so set `injectA2UITool: false` on the runtime.
  For a working .NET agent, see [`DeclarativeGenUiAgent.cs`](https://github.com/CopilotKit/CopilotKit/blob/main/showcase/integrations/ms-agent-dotnet/agent/DeclarativeGenUiAgent.cs).
</Callout>

The agent binds no A2UI tool of its own. When `injectA2UITool` is on, the `agent-framework-ag-ui` adapter auto-injects `generate_a2ui` (built from your agent's own model) and executes it:

```python title="src/agents/a2ui_dynamic.py"
from agent_framework import Agent
from agent_framework_ag_ui import AgentFrameworkAgent

base_agent = Agent(
    client=chat_client,
    name="declarative_gen_ui_agent",
    instructions=(
        "Whenever a response would benefit from a rich visual — a dashboard, "
        "KPI summary, card layout, or chart — call `generate_a2ui` to draw it. "
        "Keep chat replies to one short sentence and let the UI do the talking."
    ),
)

# No A2UI tool here — the adapter auto-injects `generate_a2ui` when
# `injectA2UITool` is on. Binding one yourself would suppress auto-injection.
agent = AgentFrameworkAgent(agent=base_agent)
```

Use the system prompt to tell the model *when* to draw. The adapter supplies and runs the tool.

## Backend: recovery and other policy

The auto-inject path takes an optional `a2ui_config` on the endpoint. The adapter
reads this policy dict when it injects the tool. Use `a2ui_config` to set the retry
limit and the catalog for the injected tool. The agent stays a plain agent, and only
the endpoint config changes:

```python title="src/agents/agent_server.py"
add_agent_framework_fastapi_endpoint(
    app=app,
    agent=a2ui_recovery_agent,
    path="/a2ui_recovery",
    a2ui_config={
        "recovery": {"maxAttempts": 3},
        "default_catalog_id": "declarative-gen-ui-catalog",
    },
)
```

`a2ui_config` accepts the same params the adapter uses internally:

- **`recovery`**: the validate-and-retry loop config, e.g. `{"maxAttempts": 3}`. When every attempt is invalid the tool returns a graceful `a2ui_recovery_exhausted` fallback.
- **`default_catalog_id`**: binds generated surfaces to your catalog (BYOC). Catalog ownership stays with the host; the model never picks it.
- **`guidelines`**: optional prompt knobs for the render sub-agent (which components exist and how to compose them).

## Progressive streaming

The secondary LLM's `render_a2ui` tool call streams through the agent as `TOOL_CALL_ARGS` events. The A2UI middleware draws the surface when the component list is complete, then adds list items as they stream in.

Ask the agent for a sales dashboard. A skeleton shows first. Then cards appear as the data streams in.

## Built-in progress indicator

CopilotKit includes a built-in progress indicator that shows while the schema is being generated. It appears automatically and hides once data items start streaming.

To replace it with a custom component, pass the component as `loadingComponent` in the provider's `a2ui` prop. See [Custom A2UI Progress Renderer](./advanced#custom-a2ui-progress-renderer).
