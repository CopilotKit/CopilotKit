Dynamic Schema A2UI uses a second model call to create a UI from the conversation. Register your components in a catalog, then let the agent generate the layout and data.

## Frontend catalog

Register the catalog with `CopilotKit`. The .NET and Python agents use the same frontend setup. See [Bring Your Own Catalog](../../../../generative-ui/a2ui/dynamic-schema) for the `definitions`, `renderers`, and `createCatalog` setup.

```tsx title="frontend/src/app/page.tsx"
<CopilotKit a2ui={{ catalog: myCatalog }}>
  {/* ... */}
</CopilotKit>
```

## Runtime and backend

The .NET and Python agents use different `generate_a2ui` paths. Select your language to see the matching runtime and backend code.

  <Tab value=".NET">

The .NET agent owns `generate_a2ui`. Keep the A2UI middleware enabled, but do not inject a second tool. The tool calls a secondary model and returns `a2ui_operations`. Each `createSurface` operation must name the frontend catalog's ID.

```typescript title="src/app/api/copilotkit-declarative-gen-ui/route.ts"
const runtime = new CopilotRuntime({
  agents: { "declarative-gen-ui": myAgent },
  a2ui: {
    injectA2UITool: false,
  },
});
```

This C# excerpt shows the agent's tool and its call to a secondary model. `A2uiSecondaryToolCaller`, `BeautifulChatA2ui`, and `SalesAgentFactory` are helpers in the showcase, not public library APIs. See the [complete .NET agent](https://github.com/CopilotKit/CopilotKit/blob/main/showcase/integrations/ms-agent-dotnet/agent/DeclarativeGenUiAgent.cs) for their use and for error handling.

```csharp title="agent/DeclarativeGenUiAgent.cs"
public AIAgent Create()
{
    var chatClient = _openAiClient.GetChatClient("gpt-5-mini").AsIChatClient();
    return new ChatClientAgent(
        chatClient,
        instructions: "Call generate_a2ui when a visual answer helps.",
        tools: [
            AIFunctionFactory.Create(
                GenerateA2ui,
                options: new() { Name = "generate_a2ui", SerializerOptions = _jsonSerializerOptions })
        ]);
}

[Description("Generate dynamic A2UI components using a secondary LLM call")]
private async Task<object> GenerateA2ui(
    [Description("Conversation context to generate UI from.")] string context = "",
    CancellationToken cancellationToken = default)
{
    var content = await A2uiSecondaryToolCaller.GetDesignToolArgumentsAsync(
        _configuration,
        BeautifulChatA2ui.DeclarativeGenUiDesignSystemPrompt(),
        context,
        cancellationToken);

    return SalesAgentFactory.BuildA2uiResponseFromContent(
        content,
        Guid.NewGuid().ToString("n")[..16],
        _logger,
        forcedCatalogId: BeautifulChatA2ui.DeclarativeGenUiCatalogId);
}
```

The agent endpoint is `/declarative-gen-ui`. The showcase helper returns a result like this. Your own tool must return the same `a2ui_operations` envelope with A2UI v0.9 operations. Set `createSurface.catalogId` to the ID of the catalog registered in `CopilotKit`; `defaultCatalogId` in the runtime does not fill it in for backend tool results.

```json
{
  "a2ui_operations": [
    { "version": "v0.9", "createSurface": { "surfaceId": "sales", "catalogId": "declarative-gen-ui-catalog" } },
    { "version": "v0.9", "updateComponents": { "surfaceId": "sales", "components": [] } },
    { "version": "v0.9", "updateDataModel": { "surfaceId": "sales", "path": "/", "value": {} } }
  ]
}
```

The middleware reads these operations from the tool result and renders the surface.

The Python agent binds no A2UI tool. Set `injectA2UITool: true` so `agent-framework-ag-ui` injects and runs `generate_a2ui` with the agent's model.

```typescript title="src/app/api/copilotkit-declarative-gen-ui/route.ts"
const runtime = new CopilotRuntime({
  agents: { "declarative-gen-ui": myAgent },
  a2ui: {
    injectA2UITool: true,
  },
});
```

```python title="src/agents/a2ui_dynamic.py"
from agent_framework import Agent
from agent_framework_ag_ui import AgentFrameworkAgent

base_agent = Agent(
    client=chat_client,
    name="declarative_gen_ui_agent",
    instructions=(
        "Call generate_a2ui when a visual answer helps. "
        "Keep chat replies short and let the UI show the result."
    ),
)

# Do not bind generate_a2ui here. The adapter injects it.
agent = AgentFrameworkAgent(agent=base_agent)
```

The adapter calls a secondary model to create `render_a2ui` arguments. It streams those arguments to the A2UI middleware, which renders the surface.

## Recovery and streaming (Python)

The Python auto-injection path accepts an optional `a2ui_config` on its endpoint. Use it to set the recovery attempt limit and the default catalog ID. Pass a raw `Agent` to this endpoint: if you pass an existing `AgentFrameworkAgent`, the endpoint does not apply `a2ui_config`. The recovery agent below is a separate raw agent, unlike the wrapped agent in the basic example above.

```python title="src/agent_server.py"
add_agent_framework_fastapi_endpoint(
    app=app,
    agent=a2ui_recovery_agent,
    path="/a2ui_recovery",
    a2ui_config={
        "recovery": {"maxAttempts": 3},
        "default_catalog_id": "declarative-gen-ui-catalog",
    },
)
```

- `recovery` sets the validate-and-retry attempt limit. If all attempts fail, the tool returns `a2ui_recovery_exhausted`.
- `default_catalog_id` binds the generated surface to your catalog. The host selects this catalog, not the model.
- `guidelines` can tell the render model which components to use and how to arrange them.

The Python adapter streams `render_a2ui` arguments as `TOOL_CALL_ARGS` events. The middleware waits for a complete component schema before it creates the surface. It then sends complete data items as they arrive, so cards can appear one by one. The built-in progress indicator hides when data starts to stream. For a custom indicator, see [Advanced — Custom A2UI Progress Renderer](./advanced#custom-a2ui-progress-renderer).
