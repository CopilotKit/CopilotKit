## What are MCP Servers?

MCP (Model Context Protocol) servers give your agent more tools. You connect to
a server with an MCP client from `@tanstack/ai-mcp`, over **HTTP** or **SSE**.
Then you give the client to the Built-in Agent in `mcpClients`.

## When should I use this?

- You want to connect your agent to existing MCP-compatible tool servers
- You need to add capabilities from third-party MCP providers
- You want to share tools across multiple agents or applications

## Install the MCP package

```npm
npm install @tanstack/ai-mcp
```

## Connect a server

Create the client once, when your server starts. Then pass it in `mcpClients`:

```typescript title="src/copilotkit.ts"
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp"; // [!code highlight]

const client = await createMCPClient({ // [!code highlight:3]
  transport: { type: "http", url: "https://my-mcp-server.example.com/mcp" },
});

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcpClients: [client], // [!code highlight]
});
```

At the start of each run, the agent calls `client.tools()` and gives the tools
to the model. If `tools()` throws, the run ends with that error.

The agent never creates or closes the client. You control the lifecycle. Call
`await client.close()` when your server shuts down.

### SSE transport

For a server that uses Server-Sent Events, set `type: "sse"`:

```typescript
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: { type: "sse", url: "https://my-mcp-server.example.com/sse" }, // [!code highlight]
});
```

### Authentication headers

Pass custom headers for authentication:

```typescript
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: {
    type: "http",
    url: "https://my-mcp-server.example.com/mcp",
    headers: { // [!code highlight:3]
      Authorization: `Bearer ${process.env.MCP_API_KEY}`,
    },
  },
});
```

The SSE transport takes `headers` the same way.

## Multiple servers

Create one client for each server. The agent gets the tools from all of them:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";

const search = await createMCPClient({
  transport: { type: "sse", url: "https://search-mcp.example.com/sse" },
});
const db = await createMCPClient({
  transport: {
    type: "sse",
    url: "https://db-mcp.example.com/sse",
    headers: { Authorization: `Bearer ${process.env.DB_MCP_KEY}` },
  },
});
const analytics = await createMCPClient({
  transport: { type: "http", url: "https://analytics-mcp.example.com/mcp" },
});

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcpClients: [search, db, analytics], // [!code highlight]
});
```

### Tool name collisions

Two servers can expose tools with the same name. For example, a staging server
and a production server expose the same tools. The agent keeps every copy. When
a name collides, each MCP copy gets the prefix `mcp<N>_`, and the agent logs a
warning. N is the position of the client in `mcpClients`, from 1:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";

const staging = await createMCPClient({
  transport: { type: "http", url: "https://staging.example.com/mcp" },
});
const production = await createMCPClient({
  transport: { type: "http", url: "https://prod.example.com/mcp" },
});

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcpClients: [staging, production],
});
// Both servers expose `search`, so the model sees `mcp1_search` and `mcp2_search`.
```

- Only names that collide get a prefix. Other tools keep their names.
- If an MCP tool has the same name as one of your own tools, your tool keeps the
  name, and the MCP tool gets the prefix.
- A tool renderer that you register in the frontend matches only the exposed
  name. If `search` becomes `mcp2_search`, register the renderer for
  `mcp2_search`.

To choose the names yourself, set `prefix` on the client. Every tool of that
client then has the prefix, so no name collides:

```typescript
import { createMCPClient } from "@tanstack/ai-mcp";

const production = await createMCPClient({
  transport: { type: "http", url: "https://prod.example.com/mcp" },
  prefix: "production", // [!code highlight]
});
// The model sees `production_search`.
```

## Combining with server tools

MCP clients work together with `defineTool` server tools. The agent sees the
tools from both:

```typescript
import { BuiltInAgent, defineTool } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";
import { z } from "zod";

const customTool = defineTool({
  name: "getUser",
  description: "Get the current user",
  parameters: z.object({}),
  execute: async () => {
    return { name: "Jane", role: "Admin" };
  },
});

const search = await createMCPClient({
  transport: { type: "sse", url: "https://search-mcp.example.com/sse" },
});

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  tools: [customTool], // Your custom tools
  mcpClients: [search], // Plus tools from MCP servers
});
```

## Custom tool providers

`mcpClients` accepts any object with a `tools()` method that returns a promise
of TanStack AI tools. Use this to cache tools or to refresh auth.

### Tool caching

By default, `client.tools()` asks the MCP server on every agent run. To ask once
at startup, keep the promise and return it on each run:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: { type: "http", url: "https://my-mcp-server.example.com/mcp" },
});

const cachedTools = client.tools(); // [!code highlight]

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcpClients: [{ tools: () => cachedTools }], // [!code highlight]
});
```

Tool discovery starts at once. If it is not done, the first run waits for it.
Later runs get the tools from the cache.

### Dynamic authentication

The auth token can expire between runs. Make a new client inside your provider
when that happens:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";
import { getFreshToken, isTokenExpired } from "./auth";

async function connect() {
  return createMCPClient({
    transport: {
      type: "http",
      url: "https://my-mcp-server.example.com/mcp",
      headers: { Authorization: `Bearer ${await getFreshToken()}` },
    },
  });
}

let currentClient = await connect();

const provider = {
  async tools() {
    if (isTokenExpired()) {
      await currentClient.close();
      currentClient = await connect();
    }
    return currentClient.tools();
  },
};

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcpClients: [provider],
});
```

The provider reconnects only when the token expires, not on every run.

## Client reference

`createMCPClient` takes these fields:

| Property | Type | Description |
|----------|------|-------------|
| `transport.type` | `"http" \| "sse"` | Transport type |
| `transport.url` | `string` | MCP server URL |
| `transport.headers` | `Record<string, string>` | Optional HTTP headers, for example for auth |
| `transport.fetch` | `typeof fetch` | Optional `fetch` to use for each request |
| `prefix` | `string` | Optional prefix for every tool name of this client |

For all client options, see the `@tanstack/ai-mcp` package.
