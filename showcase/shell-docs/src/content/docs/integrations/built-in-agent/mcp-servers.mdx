Your agent needs tools that live on an MCP server: a search index, a database,
a third-party API. Connect to each server once, then give the clients to the
Built-in Agent in `mcp`. The agent gets the tools on every run. You do not
open or close a connection for each run.

## When should I use this?

- You want to connect your agent to existing MCP-compatible tool servers.
- You need to add capabilities from third-party MCP providers.
- You want to share tools across multiple agents or applications.

## Connect a server

1. Install the MCP client:

   ```npm
   npm install @tanstack/ai-mcp
   ```

2. Create the client once, when your server starts. Then pass it in
   `mcp.clients`:

   ```typescript title="src/copilotkit.ts" group=mcp-setup
   import { BuiltInAgent } from "@copilotkit/runtime/agent";
   import { openaiText } from "@tanstack/ai-openai";
   import { createMCPClient } from "@tanstack/ai-mcp"; // [!code highlight]

   const client = await createMCPClient({ // [!code highlight:3]
     transport: { type: "http", url: "https://my-mcp-server.example.com/mcp" },
   });

   const builtInAgent = new BuiltInAgent({
     model: openaiText("gpt-5.4-mini"),
     mcp: { clients: [client] }, // [!code highlight]
     maxSteps: 3, // [!code highlight]
   });
   ```

At the start of each run, the agent gets the tools from each client and gives
them to the model. The model can now call the tools of your MCP server.

Set `maxSteps` to 2 or more. The model needs one step to call a tool, and one
more step to answer with the result. With the default of 1, the run stops after
the tool call.

## Close the clients at shutdown

The agent keeps the clients open between runs. It never closes them. Close them
yourself when your server stops:

```typescript group=mcp-setup
process.on("SIGTERM", async () => {
  await client.close();
});
```

To close the clients when a run ends, set `connection: "close"`. A closed
client cannot serve the next run. Use `"close"` only for clients that you
create for one run.

## Transports and auth

### SSE transport

If the server uses Server-Sent Events, set `type: "sse"`:

```typescript
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: { type: "sse", url: "https://my-mcp-server.example.com/sse" }, // [!code highlight]
});
```

### Authentication headers

Pass custom headers for authentication:

```typescript
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: {
    type: "http",
    url: "https://my-mcp-server.example.com/mcp",
    headers: { // [!code highlight:3]
      Authorization: `Bearer ${process.env.MCP_API_KEY}`,
    },
  },
});
```

The SSE transport takes `headers` the same way.

## Multiple servers

Create one client for each server. The agent gets the tools from all of them:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";

const search = await createMCPClient({
  transport: { type: "sse", url: "https://search-mcp.example.com/sse" },
});
const db = await createMCPClient({
  transport: {
    type: "sse",
    url: "https://db-mcp.example.com/sse",
    headers: { Authorization: `Bearer ${process.env.DB_MCP_KEY}` },
  },
});
const analytics = await createMCPClient({
  transport: { type: "http", url: "https://analytics-mcp.example.com/mcp" },
});

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcp: { clients: [search, db, analytics] }, // [!code highlight]
});
```

### Keep tool names unique

Each tool name must be unique in a run. This covers:

- the tools of all your MCP servers,
- your server tools in `tools`,
- the frontend tools of your app.

If two of these tools have the same name, the run fails with a duplicate tool
name error.

Two servers often expose the same tools. For example, a staging server and a
production server both expose `search`. Set `prefix` on each client. Every tool
of that client then gets the prefix:

```typescript
import { createMCPClient } from "@tanstack/ai-mcp";

const staging = await createMCPClient({
  transport: { type: "http", url: "https://staging.example.com/mcp" },
  prefix: "staging", // [!code highlight]
});
const production = await createMCPClient({
  transport: { type: "http", url: "https://prod.example.com/mcp" },
  prefix: "production", // [!code highlight]
});
// The model sees `staging_search` and `production_search`.
```

If an MCP tool has the same name as one of your own tools, use the same fix.
Set `prefix` on that client, or rename your own tool.

A tool renderer in the frontend matches the name that the model sees. With
`prefix: "production"`, register the renderer for `production_search`.

## Combining with server tools

MCP tools work together with `defineTool` server tools. The agent sees the
tools from both:

```typescript
import { BuiltInAgent, defineTool } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";
import { z } from "zod";

const getUser = defineTool({
  name: "getUser",
  description: "Get the current user",
  parameters: z.object({}),
  execute: async () => {
    return { name: "Jane", role: "Admin" };
  },
});

const search = await createMCPClient({
  transport: { type: "sse", url: "https://search-mcp.example.com/sse" },
});

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  tools: [getUser], // Your server tools
  mcp: { clients: [search] }, // Plus tools from MCP servers
});
```

## Lazy tools

An MCP server can expose dozens of tools. The full schema of each tool goes to
the model on every call, and that costs tokens. Set `lazyTools: true`:

```typescript ignore
const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcp: {
    clients: [search, db, analytics],
    lazyTools: true, // [!code highlight]
  },
});
```

The model then gets one discovery tool in place of the MCP tools. When the
model needs a tool, it asks for that tool by name. Then it gets the schema of
that tool and can call it.

## When a server is down

By default, if one server cannot list its tools, the run fails with that error.
To skip the failed server and keep the tools of the other servers, pass
`onDiscoveryError`:

```typescript ignore
const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcp: {
    clients: [search, db, analytics],
    onDiscoveryError: (error) => { // [!code highlight:3]
      console.warn("Skipped an MCP server for this run", error);
    },
  },
});
```

If you throw from `onDiscoveryError`, the run fails with your error.

## Custom tool sources

`mcp.clients` accepts any object with two methods:

- `tools()`: returns a promise of TanStack AI tools.
- `close()`: closes the connection.

Use a custom source to cache tools or to refresh auth.

### Tool caching

By default, the agent asks the MCP server for its tools on every run. To ask
once at startup, keep the promise and return it on each run:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: { type: "http", url: "https://my-mcp-server.example.com/mcp" },
});

const cachedTools = client.tools(); // [!code highlight]

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcp: {
    clients: [{ tools: () => cachedTools, close: () => client.close() }], // [!code highlight]
  },
});
```

Tool discovery starts at once. If it is not done, the first run waits for it.
Later runs get the tools from the cache.

### Dynamic authentication

The auth token can expire between runs. When it expires, make a new client in
your source:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";
import { getFreshToken, isTokenExpired } from "./auth";

async function connect() {
  return createMCPClient({
    transport: {
      type: "http",
      url: "https://my-mcp-server.example.com/mcp",
      headers: { Authorization: `Bearer ${await getFreshToken()}` },
    },
  });
}

let currentClient = await connect();

const source = {
  async tools() {
    if (isTokenExpired()) {
      await currentClient.close();
      currentClient = await connect();
    }
    return currentClient.tools();
  },
  close: () => currentClient.close(),
};

const builtInAgent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"),
  mcp: { clients: [source] },
});
```

The source connects again only when the token expires, not on every run.

## Reference

### The `mcp` option

| Property | Type | Description |
|----------|------|-------------|
| `clients` | `MCPToolSource[]` | The clients to get tools from. Required. |
| `connection` | `"keep-alive" \| "close"` | `"keep-alive"` (default): the agent never closes the clients. `"close"`: the agent closes them when each run ends. |
| `lazyTools` | `boolean` | If `true`, the model gets each tool schema only when it asks for that tool. Default: `false`. |
| `onDiscoveryError` | `(error, source) => void \| Promise<void>` | Runs when one client cannot list its tools. Return to skip that client. Throw to fail the run. If you do not set it, the run fails. |

`MCPToolSource` and `ChatMCPOptions` are types from `@tanstack/ai`.

### `createMCPClient`

| Property | Type | Description |
|----------|------|-------------|
| `transport.type` | `"http" \| "sse"` | Transport type |
| `transport.url` | `string` | MCP server URL |
| `transport.headers` | `Record<string, string>` | Optional HTTP headers, for example for auth |
| `transport.fetch` | `typeof fetch` | Optional `fetch` to use for each request |
| `prefix` | `string` | Optional prefix for every tool name of this client |
| `toolName` | `(tool) => string` | Optional function that sets the name the model sees. It overrides `prefix`. |

For all client options, see the `@tanstack/ai-mcp` package.
