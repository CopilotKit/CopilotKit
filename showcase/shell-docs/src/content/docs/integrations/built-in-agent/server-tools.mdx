icon: "lucide/Wrench"
description: "Define backend tools for your Built-in Agent."
---

Your agent needs to read a database, call an internal API, or use a secret that must stay on the server. Give it a server tool: a function on your backend that the model can call.

Use a server tool when:

- The agent must reach databases, APIs, or other backend services.
- The tool needs server-side secrets or resources.
- You want the tool input validated against a schema.

<Callout type="warn" title="The tool runs on the server. The UI still runs in the browser.">
`execute` runs on your server, so it can reach secrets, a database, or an internal service. It cannot touch the DOM, component state, or anything else in the page. When the *action* itself belongs in the browser, register it as a [frontend tool](/frontend-tools).

Rendering is separate from execution. The call of a server tool still streams to the browser. To show UI for it, register a render-only tool under the same name. `execute` keeps running on the server.

<FrontendOnly frontend="react">
Use [`useFrontendTool`](/frontend-tools) for the browser-side action and `useRenderTool` for
the render-only registration.
</FrontendOnly>
<FrontendOnly frontend="angular">
Use [`registerFrontendTool`](/reference/angular/functions/registerFrontendTool) for the
browser-side action and
[`registerRenderToolCall`](/reference/angular/functions/registerRenderToolCall) for the
render-only registration.
</FrontendOnly>
</Callout>

## Define a tool

Write the tool with `defineTool` from `@copilotkit/runtime`, then pass it in `tools`:

```typescript title="src/tools.ts"
import { defineTool } from "@copilotkit/runtime";
import { z } from "zod";

export const getWeather = defineTool({
  name: "getWeather",
  description: "Get the current weather for a location",
  parameters: z.object({
    location: z.string().describe("The location's name"),
  }),
  execute: async ({ location }) => {
    return { temperature: 72, condition: "sunny", location };
  },
});
```

```typescript title="src/copilotkit.ts"
import { tanstackAIAgent } from "@copilotkit/runtime/tanstack-ai";
```

<Tab value="AI SDK">

```typescript title="src/copilotkit.ts"
import { aiSdkAgent } from "@copilotkit/runtime/ai-sdk";
import { openai } from "@ai-sdk/openai";
import { getWeather } from "./tools";

const agent = aiSdkAgent({

});
```

The AI SDK stops after one model step by default. Set `maxSteps` so that the model can answer after the tool result comes back.
</Tab>

Ask the agent "What is the weather in Paris?". It calls `getWeather` on your server and answers with the result.

<Callout type="warn" title="`parameters` takes a schema validator, not JSON Schema">
`parameters` must be a Standard Schema v1 validator, such as Zod, Valibot, or ArkType. A plain JSON Schema object throws when the agent converts the tool. The validator also gives `execute` its argument type.
</Callout>

## Several tools

Pass all of them in the array. The model picks the tool that fits the request:

```typescript title="src/copilotkit.ts"
import { defineTool } from "@copilotkit/runtime";
import { tanstackAIAgent } from "@copilotkit/runtime/tanstack-ai";
import { openaiText } from "@tanstack/ai-openai";
import { z } from "zod";
import { db } from "./db";
import { search } from "./search";

const searchDocs = defineTool({
  name: "searchDocs",
  description: "Search the documentation for relevant articles",
  parameters: z.object({
    query: z.string().describe("The search query"),
  }),
  execute: async ({ query }) => {
    const results = await search(query);
    return { results, count: results.length };
  },
});

const createTicket = defineTool({
  name: "createTicket",
  description: "Create a support ticket",
  parameters: z.object({
    title: z.string().describe("Ticket title"),
    priority: z.enum(["low", "medium", "high"]).describe("Ticket priority"),
    description: z.string().describe("Detailed description of the issue"),
  }),
  execute: async ({ title, priority, description }) => {
    const ticket = await db.tickets.create({ title, priority, description });
    return { ticketId: ticket.id, status: "created" };
  },
});

const agent = tanstackAIAgent({
  adapter: () => openaiText("gpt-5.5"),
  tools: [searchDocs, createTicket], // [!code highlight]
});
```

The agent can chain calls: search first, then create a ticket from the result. TanStack AI allows 5 model turns per run by default. With the AI SDK, set `maxSteps`. See [Advanced Configuration](/advanced-configuration#tool-calling-limit).

<Callout type="warn" title="Two names to avoid">
The agent adds `AGUISendStateSnapshot` and `AGUISendStateDelta` to every run for shared state. A tool of your own with one of these names replaces the built-in tool and breaks shared state.

A server tool also replaces a frontend tool with the same name. If you define `getWeather` on both sides, the model sees only the server tool, and the frontend handler never runs. Give each side a different name.
</Callout>

## Native SDK tools

You can also pass tools in the native format of your SDK, including provider tools such as web search.

<Tabs groupId="agent-sdk" items={['TanStack AI', 'AI SDK']}>
<Tab value="TanStack AI">
TanStack AI tools and `defineTool` tools can share one array:

```typescript title="src/copilotkit.ts"
import { tanstackAIAgent } from "@copilotkit/runtime/tanstack-ai";
import { toolDefinition } from "@tanstack/ai";
import { openaiText } from "@tanstack/ai-openai";
import { webSearchTool } from "@tanstack/ai-openai/tools";
import { z } from "zod";
import { getWeather } from "./tools";

const getStock = toolDefinition({
  name: "getStock",
  description: "Get the stock level of a product",
  inputSchema: z.object({ sku: z.string() }),
}).server(async ({ sku }) => ({ sku, inStock: 12 }));

const agent = tanstackAIAgent({
  adapter: () => openaiText("gpt-5.5"),
  tools: [getWeather, getStock, webSearchTool({ type: "web_search" })], // [!code highlight]
});
```
</Tab>
<Tab value="AI SDK">
Pass an AI SDK `ToolSet` in place of the array:

```typescript title="src/copilotkit.ts"
import { aiSdkAgent } from "@copilotkit/runtime/ai-sdk";
import { openai } from "@ai-sdk/openai";
import { tool } from "ai";
import { z } from "zod";

const getStock = tool({
  description: "Get the stock level of a product",
  inputSchema: z.object({ sku: z.string() }),
  execute: async ({ sku }) => ({ sku, inStock: 12 }),
});

const agent = aiSdkAgent({
  model: openai("gpt-5.5"),
  tools: { getStock, web_search: openai.tools.webSearch({}) }, // [!code highlight]
  maxSteps: 5,
});
```

`tools` takes a `ToolSet` or a `defineTool` array, not both. To use `defineTool` tools in a `ToolSet`, write them with `tool()` from `ai`.
</Tab>
</Tabs>

## Tools for each run

To build the tools from the request, pass a function. It gets the run context and returns the tools for that run:

```typescript title="src/copilotkit.ts"
import { tanstackAIAgent } from "@copilotkit/runtime/tanstack-ai";
import { openaiText } from "@tanstack/ai-openai";
import { adminTools, userTools } from "./tools";

const agent = tanstackAIAgent({
  adapter: () => openaiText("gpt-5.5"),
  tools: ({ input }) => // [!code highlight:2]
    input.forwardedProps?.role === "admin" ? adminTools : userTools,
});
```

`forwardedProps` comes from the browser. Use it only to pick between tool sets that are safe for any user. Do not use it for authorization.

## Errors

If a tool throws, the model sees the error. It can tell the user or try a different approach:

```typescript
import { defineTool } from "@copilotkit/runtime";
import { z } from "zod";
import { db } from "./db";

const getUser = defineTool({
  name: "getUser",
  description: "Look up a user by email",
  parameters: z.object({
    email: z.string().email().describe("The user's email address"),
  }),
  execute: async ({ email }) => {
    const user = await db.users.findByEmail(email);
    if (!user) {
      throw new Error(`No user found with email: ${email}`); // [!code highlight]
    }
    return { id: user.id, name: user.name, role: user.role };
  },
});
```

<Callout type="warn" title="Return plain data">
The agent serializes the return value of a tool before the model sees it. If `JSON.stringify` cannot serialize the value (a class instance or a circular reference), the model gets a placeholder string with the name of the tool. Return plain objects, arrays, and primitives, also for errors.
</Callout>

<Callout type="info" title="Writing the model call yourself?">
  In a [Custom Agent](/backend/custom-agent) factory, pass your tools to `tanstackAI(ctx, { tools })` or `aiSdk(ctx, { tools })`.
</Callout>
