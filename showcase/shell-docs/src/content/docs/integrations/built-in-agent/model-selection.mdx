Your agent needs a model. Give `model` a model string, such as
`"openai:gpt-5.4-mini"`, and the Built-in Agent connects to that provider for you.
If you need to configure the provider yourself, give `model` a
[TanStack AI](https://tanstack.com/ai) adapter instead.

## Install the provider package

The Built-in Agent runs on TanStack AI. Install `@tanstack/ai` and the adapter
package for each provider that you use:

```npm
npm install @tanstack/ai @tanstack/ai-openai
```

| Model string prefix                 | Package                  |
| ----------------------------------- | ------------------------ |
| `openai`, `minimax`                 | `@tanstack/ai-openai`    |
| `anthropic`                         | `@tanstack/ai-anthropic` |
| `google`, `gemini`, `google-gemini` | `@tanstack/ai-gemini`    |
| `vertex`                            | `@tanstack/ai-vertex`    |

If a package is missing, the run fails with an error that names the package to
install.

## Supported Models

Specify a model using the `"provider:model"` format. `"provider/model"` also works.

The tables list the models these docs use. The quickstart uses `openai:gpt-5.4-mini`.
The Built-in Agent sends the model id to the provider unchanged, so other model ids
from the same provider also work.

## Environment Variables

Set the API key for your chosen provider. If the key is missing, the run fails
when the agent resolves the model, and the error names the variable to set.

```bash
# OpenAI
OPENAI_API_KEY=sk-...

# Anthropic
ANTHROPIC_API_KEY=sk-ant-...

# Google
GOOGLE_API_KEY=...

# MiniMax
MINIMAX_API_KEY=...
```

Each provider also reads an optional base URL:

- `OPENAI_BASE_URL`: an OpenAI-compatible endpoint. See the next section.
- `ANTHROPIC_BASE_URL`: an Anthropic proxy, for example `https://my-proxy.example.com/v1`.
- `GOOGLE_GENERATIVE_AI_BASE_URL`: a Gemini proxy, with the API version at the end.
- `MINIMAX_BASE_URL`: for example `https://api.minimaxi.com/v1` for the China endpoint.

### OpenAI-compatible endpoints

To send `openai:` model strings to another OpenAI-compatible endpoint, set
`OPENAI_BASE_URL`:

```bash
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_API_KEY=gsk_...
```

The Built-in Agent picks the OpenAI API from that host:

- OpenAI (`api.openai.com`, `*.api.openai.com`) and Azure OpenAI hosts use the
  Responses API.
- Any other host uses the Chat Completions API, because most OpenAI-compatible
  servers serve only `/chat/completions`. The runtime logs this on the first run.

To choose the API yourself, set `COPILOTKIT_OPENAI_API` to `responses` or
`chat`. For example, a proxy in front of OpenAI (such as LiteLLM or Portkey)
needs `responses` to keep Responses-only features, such as reasoning summaries:

```bash
OPENAI_BASE_URL=https://my-gateway.example.com/v1
COPILOTKIT_OPENAI_API=responses
```

You can also pass the API key in your configuration:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";

const agent = new BuiltInAgent({
  model: "openai:gpt-5.4-mini",
  apiKey: process.env.MY_OPENAI_KEY, // [!code highlight]
});
```

## Configure the provider yourself

A model string covers the common setup. To set the client options yourself,
build a TanStack AI adapter and pass it as `model`:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { createOpenaiChat } from "@tanstack/ai-openai"; // [!code highlight]

const agent = new BuiltInAgent({
  model: createOpenaiChat("gpt-5.4-mini", process.env.MY_OPENAI_KEY!, { // [!code highlight:3]
    organization: "org-my-team",
  }),
});
```

Each adapter package has a helper that reads the API key from the environment:

- `openaiText("gpt-5.4-mini")` from `@tanstack/ai-openai`
- `anthropicText("claude-sonnet-4-6")` from `@tanstack/ai-anthropic`
- `geminiText("gemini-3.8-flash")` from `@tanstack/ai-gemini`
- `vertexText("gemini-3.8-flash")` from `@tanstack/ai-vertex`

## OpenRouter, proxies, and bring-your-own LLM

Use `openaiCompatibleText` for anything that serves an OpenAI-compatible API, such as
[OpenRouter](https://openrouter.ai), [Together](https://together.ai),
[Groq](https://groq.com), [Novita](https://novita.ai), a self-hosted gateway, or your
own fine-tuned endpoint. It sends requests to the Chat Completions API:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiCompatibleText } from "@tanstack/ai-openai/compatible"; // [!code highlight]

const agent = new BuiltInAgent({
  model: openaiCompatibleText("anthropic/claude-sonnet-4-6", { // [!code highlight:4]
    baseURL: "https://openrouter.ai/api/v1",
    apiKey: process.env.OPENROUTER_API_KEY!,
  }),
});
```

If the endpoint serves the Responses API, add `api: "responses"`.

<Callout type="warn" title="The model is set on the agent">
  CopilotKit does **not** expose a cloud-hosted endpoint for choosing or
  switching the model at request time. You configure the model **on the agent**,
  as a model string or a TanStack AI adapter:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { anthropicText } from "@tanstack/ai-anthropic";

new BuiltInAgent({ model: "openai:gpt-5.4-mini" }); // model string
new BuiltInAgent({ model: anthropicText("claude-sonnet-4-6") }); // adapter
```

To switch models per user, request, or feature flag, create the agent with the
`model` you want on your own backend. To let the frontend pick a model string,
see [Overridable properties](/advanced-configuration#overridable-properties).

</Callout>

## Deploy to Vercel or Cloudflare Workers

A model string loads its adapter package by name when the run starts. Next.js
output tracing on Vercel and the Cloudflare Workers bundler cannot see that
import, so they leave the package out. The deployed run then fails with an
"Install @tanstack/ai-openai" error, even though the package is installed.

On these platforms, import the adapter and pass it as `model`. Your import makes
the bundler include the package:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai"; // [!code highlight]

const agent = new BuiltInAgent({
  model: openaiText("gpt-5.4-mini"), // [!code highlight]
});
```

## Use an AI SDK model

To run a Vercel AI SDK model, such as `openai("gpt-5.4-mini")` from
`@ai-sdk/openai`, use an AI SDK factory. You write the `streamText()` call, and
the Built-in Agent streams it to the frontend. See
[Use any model router](/backend/custom-agent).

## How it works

The Built-in Agent resolves each model string to a TanStack AI adapter:

| Model string                    | Package                  | Adapter                                     |
| ------------------------------- | ------------------------ | ------------------------------------------- |
| `"openai:gpt-5.4-mini"`         | `@tanstack/ai-openai`    | `createOpenaiChat("gpt-5.4-mini", key)`     |
| `"anthropic:claude-sonnet-4-6"` | `@tanstack/ai-anthropic` | `createAnthropicChat("claude-sonnet-4-6", key)` |
| `"google:gemini-3.8-flash"`     | `@tanstack/ai-gemini`    | `createGeminiChat("gemini-3.8-flash", key)` |
| `"vertex:gemini-3.8-flash"`     | `@tanstack/ai-vertex`    | `vertexText("gemini-3.8-flash")`            |

The `"provider:model"` and `"provider/model"` separators work the same way.

<Callout type="info" title="Need full control of the model call?">
  The [Custom Agent](/backend/custom-agent) lets you write the AI SDK, TanStack
  AI, or custom LLM call yourself, while CopilotKit handles the rest.
</Callout>
