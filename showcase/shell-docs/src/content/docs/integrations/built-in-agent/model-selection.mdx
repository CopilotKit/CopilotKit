Your agent needs a model. Pass a [TanStack AI](https://tanstack.com/ai) text
adapter as `model`. The adapter holds the provider settings: the API key, the
base URL, and the client options.

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({
  model: openaiText("gpt-6-luna"),
});
```

## Install the packages

Install `@tanstack/ai` and the adapter package for your provider:

```npm
npm install @tanstack/ai @tanstack/ai-openai
```

| Provider          | Package                  | Adapter                | API key from                                   |
| ----------------- | ------------------------ | ---------------------- | ---------------------------------------------- |
| OpenAI            | `@tanstack/ai-openai`    | `openaiText`           | `OPENAI_API_KEY`                               |
| Anthropic         | `@tanstack/ai-anthropic` | `anthropicText`        | `ANTHROPIC_API_KEY`                            |
| Google Gemini     | `@tanstack/ai-gemini`    | `geminiText`           | `GOOGLE_API_KEY`, then `GEMINI_API_KEY`        |
| Google Vertex AI  | `@tanstack/ai-vertex`    | `vertexText`           | Google Cloud project, or `GOOGLE_VERTEX_API_KEY` |
| OpenAI-compatible | `@tanstack/ai-openai`    | `openaiCompatibleText` | The config that you pass                       |

The adapter is a normal import, so the agent also works in a bundled server, on
Vercel, and on Cloudflare Workers.

## Supported Models

Give the adapter the provider's model id. The adapter types list the model ids
that each package knows, so your editor completes them. The tables list the
models that these docs use.

Use `gemini-3.5-flash-lite` for lower cost and latency. Google no longer gives
new API keys access to the Gemini 2.5 models. A key that used them before can

import { BuiltInAgent } from "@copilotkit/runtime/agent";

### MiniMax

Install `@tanstack/ai-openai`. MiniMax serves an OpenAI-compatible API, so use
`openaiCompatibleText` with the MiniMax base URL:

| Model        | Model id         |
| ------------ | ---------------- |
| MiniMax M3   | `"MiniMax-M3"`   |
| MiniMax M2.7 | `"MiniMax-M2.7"` |

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiCompatibleText } from "@tanstack/ai-openai/compatible";

const agent = new BuiltInAgent({
  model: openaiCompatibleText("MiniMax-M3", {
    baseURL: "https://api.minimax.io/v1",
    apiKey: process.env.MINIMAX_API_KEY!,
  }),
});
```

For the China endpoint, use `https://api.minimaxi.com/v1` as `baseURL`.

## Environment Variables

Set the API key for your provider:

```bash
# OpenAI
OPENAI_API_KEY=sk-...

# Anthropic
ANTHROPIC_API_KEY=sk-ant-...

# Google Gemini
GOOGLE_API_KEY=...
```

If the variable is missing, the adapter throws an error when you create it. The
error names the variable to set.

## Configure the provider

Each adapter takes a config object as its second argument. Put the provider
settings there.

To pass the API key yourself, use the `create*` helper of the package. It takes
the key as its second argument:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { createOpenaiChat } from "@tanstack/ai-openai"; // [!code highlight]

const agent = new BuiltInAgent({
  model: createOpenaiChat("gpt-6-luna", process.env.MY_OPENAI_KEY!, { // [!code highlight:3]
    organization: "org-my-team",
  }),
});
```

The other packages have the same helper: `createAnthropicChat` and
`createGeminiChat`.

To send requests through a proxy, set `baseURL`:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { anthropicText } from "@tanstack/ai-anthropic";

const agent = new BuiltInAgent({
  model: anthropicText("claude-sonnet-4-6", {
    baseURL: "https://my-proxy.example.com", // [!code highlight]
  }),
});
```

## Reasoning

Some tasks need the model to think longer before it answers. Set `reasoning` to
a level:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({
  model: openaiText("gpt-6-luna"),
  reasoning: "high", // [!code highlight]
});
```

Only the levels of your model type-check. For example, `gpt-6-luna` has `"off"`,
`"low"`, `"medium"`, `"high"`, `"xhigh"`, and `"max"`. If you do not set `reasoning`, the
provider default applies. `"off"` turns thinking off.

For more control, pass an object:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { anthropicText } from "@tanstack/ai-anthropic";

const agent = new BuiltInAgent({
  model: anthropicText("claude-sonnet-4-6"),
  reasoning: { level: "high", summary: false, budgetTokens: 8000 }, // [!code highlight]
});
```

- `level`: one of the levels of the model.
- `summary`: stream the thinking text to the frontend. Default `true`.
- `budgetTokens`: an exact thinking budget. It type-checks only on models that
  take a budget, such as Claude Sonnet 4.6.

## OpenRouter, proxies, and bring-your-own LLM

Use `openaiCompatibleText` for any server with an OpenAI-compatible API. For
example: [OpenRouter](https://openrouter.ai), [Together](https://together.ai),
[Groq](https://groq.com), [Novita](https://novita.ai), a self-hosted gateway, or
your own fine-tuned endpoint. It sends requests to the Chat Completions API:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiCompatibleText } from "@tanstack/ai-openai/compatible"; // [!code highlight]

const agent = new BuiltInAgent({
  model: openaiCompatibleText("anthropic/claude-sonnet-4-6", { // [!code highlight:4]
    baseURL: "https://openrouter.ai/api/v1",
    apiKey: process.env.OPENROUTER_API_KEY!,
  }),
});
```

If the endpoint serves the Responses API, add `api: "responses"`.

## Switch models from the frontend

Sometimes the user picks the model, for example "fast" or "smart" in a menu. The
frontend sends a model name, and your `resolveModel` function turns that name
into a model.

1. On the agent, list `"model"` in `overridableProperties` and add
   `resolveModel`:

   ```typescript
   import { BuiltInAgent } from "@copilotkit/runtime/agent";
   import { openaiText } from "@tanstack/ai-openai";

   const agent = new BuiltInAgent({
     model: openaiText("gpt-5.4-mini"),
     overridableProperties: ["model"], // [!code highlight:11]
     resolveModel: (name) => {
       switch (name) {
         case "fast":
           return openaiText("gpt-5.4-mini");
         case "smart":
           return openaiText("gpt-6-luna");
         default:
           return undefined;
       }
     },
   });
   ```

2. On the frontend, send the name as the `model` property:

   ```tsx
   import { CopilotChat, CopilotKitProvider } from "@copilotkit/react-core";

   export default function Page() {
     return (
       <CopilotKitProvider runtimeUrl="/api/copilotkit" properties={{ model: "smart" }}>
         <CopilotChat />
       </CopilotKitProvider>
     );
   }
   ```

The run now uses GPT-6 Luna. `resolveModel` can return three things:

- An adapter: the run uses it with the configured `modelOptions` and
  `reasoning`.
- The result of `createChatOptions(...)`: the run uses its adapter, and its
  `modelOptions` and `reasoning` replace the configured ones.
- `undefined`: the run uses the configured `model`. The agent logs one warning.
  The same happens when the agent has no `resolveModel`.

### Give each model its own options

The configured `modelOptions` and `reasoning` are typed for the configured
model. When a name picks a model from another provider, give that model its own
options. Build them with `createChatOptions` from `@tanstack/ai`, so that the
new adapter types them:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { createChatOptions } from "@tanstack/ai"; // [!code highlight]
import { openaiText } from "@tanstack/ai-openai";
import { anthropicText } from "@tanstack/ai-anthropic";

const agent = new BuiltInAgent({
  model: openaiText("gpt-6-luna"),
  modelOptions: { verbosity: "low" },
  overridableProperties: ["model"],
  resolveModel: (name) => {
    switch (name) {
      case "fast":
        return openaiText("gpt-5.4-mini");
      case "smart":
        return createChatOptions({ // [!code highlight:5]
          adapter: anthropicText("claude-sonnet-4-6"),
          modelOptions: { max_tokens: 8000 },
          reasoning: { level: "high", budgetTokens: 4000 },
        });
      default:
        return undefined;
    }
  },
});
```

The "smart" run now uses Claude Sonnet 4.6 with its own options. It does not
get `verbosity`, which is an OpenAI option. The tools stay as configured,
provider tools too.

Only the names that `resolveModel` accepts can change the model. The frontend
cannot send an API key or a base URL.

## Use an AI SDK model

To run a Vercel AI SDK model, such as `openai("gpt-6-luna")` from
`@ai-sdk/openai`, use an AI SDK factory. You write the `streamText()` call, and
the Built-in Agent streams it to the frontend. See
[Use any model router](/backend/custom-agent).

<Callout type="info" title="Need full control of the model call?">
  The [Custom Agent](/backend/custom-agent) lets you write the AI SDK, TanStack
  AI, or custom LLM call yourself, while CopilotKit handles the rest.
</Callout>
