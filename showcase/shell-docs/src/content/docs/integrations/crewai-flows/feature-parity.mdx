The CrewAI showcase implements the complete CopilotKit D6 feature matrix for both regular Flows and native Conversational Flows. The two columns exercise the same shared browser probes and user-visible assertions as the LangGraph Python showcase, with CrewAI-specific agent code and deterministic fixtures behind the common frontend surface.

| Showcase column | D6 result |
| --- | --- |
| CrewAI Flows | 41/41 |
| CrewAI Conversational Flows | 41/41 |

The manifest also includes the `cli-start` capability. It is documented and connected to the [CrewAI quickstart](/crewai-flows/quickstart), but it is not included in the 41 browser-run demos because it is a terminal command rather than a web route.

## Supported capabilities

| Area | D6-verified capabilities |
| --- | --- |
| Chat and presentation | Agentic chat, chat slots, CSS customization, sidebar, popup, simple and complete headless chat, default reasoning, and custom reasoning |
| Human approval and interrupts | Original HITL, in-chat approval, booking approval, in-app approval, generative UI interrupts, and headless interrupts |
| Tools and generative UI | Custom tool rendering, default and custom catch-alls, reasoning chains, agentic and tool-based generative UI, open generative UI, advanced open generative UI, declarative UI, fixed-schema A2UI, A2UI recovery, Hashbrown and JSON Render BYOC, Beautiful Chat, and MCP Apps |
| App and agent integration | Synchronous and asynchronous frontend tools, read/write shared state, read-only agent context, agent-readable state, streaming state, subagents, agent configuration, authentication, voice, and multimodal input |

## What D6 verifies

Each runnable capability is exercised through its real CrewAI integration route and the shared showcase frontend. The D6 probes verify observable behavior such as streamed assistant text and reasoning, tool-call and tool-result lifecycles, rendered UI surfaces, state synchronization, interrupt suspension and resume, frontend-owned actions, authentication boundaries, and multimodal request handling.

The CrewAI Flows implementation enters each graph through `kickoff` or `astream`. The CrewAI Conversational Flows implementation enters the same feature logic through CrewAI's public `stream_turn` API, using the AG-UI `threadId` as its session ID. Framework-specific behavior remains in the CrewAI backend and fixtures; the test probes and feature presentation stay aligned with the LangGraph Python north star.
