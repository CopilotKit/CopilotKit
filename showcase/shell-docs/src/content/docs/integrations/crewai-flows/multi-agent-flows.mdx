## What are Multi-Agent Flows?

When building agentic applications, you often want to orchestrate complex flows together that require the coordination of multiple
agents. This is traditionally called multi-agent orchestration.

## When should I use this?

Multi-agent flows are useful when you want to orchestrate complex flows together that require the coordination of multiple agents. As
your agentic application grows, delegation of sub-tasks to other agents can help you scale key pieces of your application.

- Divide context into smaller chunks
- Delegate sub-tasks to other agents
- Use a single agent to orchestrate the flow

## How does CopilotKit support this?

Each chat talks to one agent. Name that agent with the `agentId` prop on `<CopilotKitProvider>`. Every `<CopilotChat>` under the provider uses it:

```tsx
"use client";

import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    // [!code word:agentId]
    <CopilotKitProvider runtimeUrl="/api/copilotkit" agentId="<the-name-of-the-agent>">
      {children}
    </CopilotKitProvider>
  );
}
```

To use different agents in different areas of your app, give each chat its own `agentId`. The `agentId` of a chat overrides the `agentId` of the provider:

```tsx
"use client";

import { CopilotChat } from "@copilotkit/react-core";

export function Workspace() {
  return (
    <div>
      <CopilotChat agentId="research_agent" />
      <CopilotChat agentId="writing_agent" />
    </div>
  );
}
```

All requests from a chat stay with its agent, so you keep precise control over the workflow. To delegate sub-tasks from one agent to other agents, orchestrate them in your agent backend.

<Callout type="info">
  CopilotKit 2.0 has no Router Mode. In v1, Router Mode used an LLM adapter to pick an agent for each request. CopilotKit 2.0 removed the LLM adapters.
</Callout>
