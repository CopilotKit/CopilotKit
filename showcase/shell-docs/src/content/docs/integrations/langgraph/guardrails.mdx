Anything a user types reaches your model, and anything the model produces reaches your user. In LangGraph, you screen both with middleware. `AgentMiddleware` has hooks around the agent, the model call, and each tool call. `CopilotKitMiddleware` is also a middleware, so your checks sit next to it in the same list.

## Where the hooks sit

A run passes through these hooks in order:

| Hook | Runs | Use it for |
| --- | --- | --- |
| `before_agent` | Once, before the run starts | Rejecting a whole conversation (rate limits, a blocked tenant) |
| `before_model` | Before every model call | Input screening on the latest user message |
| `wrap_model_call` | Around every model call | Output screening; you see the request going in and the response coming back |
| `after_model` | After every model call, before any tool call | Post-hoc inspection that doesn't need to modify the response |
| `wrap_tool_call` | Around every tool call | Screening tool arguments and tool results |

`before_*` hooks return a state-update dict (or `None`). `wrap_*` hooks receive a `handler` they must call to continue the chain. This is what lets them inspect and rewrite the result.

## Start with the built-in PII middleware

Before writing anything custom, check whether `PIIMiddleware` already covers you. It ships with LangChain and handles the common DLP cases in both directions.

Install the packages in your agent project:

```bash
uv add "langchain>=1" langchain-openai copilotkit
```

Then build the agent with the middleware:

```python title="agent.py"
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware
from copilotkit import CopilotKitMiddleware

agent = create_agent(
    model=ChatOpenAI(model="gpt-6-luna", reasoning_effort="none"),
    tools=[get_weather],  # your tools
    middleware=[
        # Redact emails the user sends in.
        PIIMiddleware("email", strategy="redact"),
        # Mask card numbers wherever they appear, including in tool results.
        PIIMiddleware(
            "credit_card",
            strategy="mask",
            apply_to_output=True,
            apply_to_tool_results=True,
        ),
        # Refuse outright if an API key shows up.
        PIIMiddleware("api_key", detector=r"sk-[a-zA-Z0-9]{32}", strategy="block"),
        CopilotKitMiddleware(),
    ],
)
```

Serve this `agent` the way the [quickstart](/langgraph-python/quickstart) serves its graph: name it in `langgraph.json`, or pass it to `LangGraphAGUIAgent(graph=agent)` in your FastAPI endpoint. On the FastAPI path, also pass `checkpointer=MemorySaver()` to `create_agent`.

Built-in types are `email`, `credit_card`, `ip`, `mac_address`, and `url`. Any other name is a custom type that uses your `detector` (a regex or a callable).

Strategies:

- `block`: raises `PIIDetectionError`.
- `redact`: replaces the match with a placeholder, such as `[REDACTED_EMAIL]`.
- `mask`: hides the match except for its last characters. It uses `*` characters, which the chat renders as Markdown. Use `redact` or `hash` for text that the chat shows.
- `hash`: replaces the match with a hash.

To change the agent per request, see [agent configuration](/integrations/langgraph/configurable).

<Callout type="info" title="apply_to_output is off by default">
  `PIIMiddleware` screens **input** unless you say otherwise. Pass `apply_to_output=True` to
  screen model output and `apply_to_tool_results=True` to screen what tools return. Tool results are a
  frequent source of leaked data, since they come from your own systems.
</Callout>

## Input screening

For anything PII detection doesn't express (topic restrictions, prompt-injection heuristics, per-tenant policy), implement `before_model` and end the run when the check fails.

The examples below call `screen_input`, `redact_sensitive` and `tool_call_allowed`. These functions are your policy, so define them yourself.

```python title="guardrails.py"
from typing import Any

from langchain.agents.middleware import AgentMiddleware, AgentState, hook_config
from langchain_core.messages import AIMessage, HumanMessage
from langgraph.runtime import Runtime


class InputFirewall(AgentMiddleware):
    """Rejects user input that fails policy before it reaches the model."""

    def __init__(self, *, refusal: str = "I can't help with that request."):
        super().__init__()
        self.refusal = refusal

    # can_jump_to declares the edge; without it, "jump_to" is ignored.
    @hook_config(can_jump_to=["end"])
    def before_model(
        self, state: AgentState, runtime: Runtime[Any]
    ) -> dict[str, Any] | None:
        messages = state.get("messages", [])
        latest = next(
            (m for m in reversed(messages) if isinstance(m, HumanMessage)), None
        )
        if latest is None:
            return None

        verdict = screen_input(str(latest.content))  # your classifier or rules
        if not verdict.allowed:
            # Ending with an AIMessage means the user sees the refusal in chat
            # rather than an error toast.
            return {
                "jump_to": "end",
                "messages": [AIMessage(content=self.refusal)],
            }

        return None
```

Two things worth knowing:

- **`@hook_config(can_jump_to=["end"])` is required.** It declares the conditional edge at compile time. Returning `{"jump_to": "end"}` without it silently does nothing.
- **Returning an `AIMessage` is friendlier than raising.** A raised exception surfaces as a run error; an injected message renders as a normal assistant turn, so the user gets an explanation and the conversation stays usable.

<Callout type="warn" title="LangGraph Platform: the refusal also shows an error">
  With a LangGraph Platform deployment (`langgraph dev` or LangSmith, connected with `LangGraphAgent`), the refusal shows in chat, but the run then ends with the error `Cannot send 'RUN_FINISHED' while text messages are still active`, and the chat shows an "Agent run failed" message. An agent that you serve with FastAPI (`ag-ui-langgraph`) shows the refusal with no error.
</Callout>

## Output and DLP screening

Output screening belongs in `wrap_model_call`, because that's the only hook that can rewrite what the model produced before anything downstream sees it. Call `handler(request)`, inspect the result, and return either the original response or a replacement.

```python title="guardrails.py"
from dataclasses import replace
from typing import Awaitable, Callable

from langchain.agents.middleware import (
    AgentMiddleware,
    ModelRequest,
    ModelResponse,
)
from langchain_core.messages import AIMessage


def scrub_content(content):
    # Content is a string, or a list of blocks (for example from the OpenAI Responses API).
    if isinstance(content, str):
        return redact_sensitive(content)  # your DLP pass
    return [
        {**block, "text": redact_sensitive(block["text"])}
        if isinstance(block, dict) and block.get("type") == "text"
        else block
        for block in content
    ]


def scrub(response: ModelResponse) -> ModelResponse:
    scrubbed = []
    for message in response.result:
        if isinstance(message, AIMessage):
            clean = scrub_content(message.content)
            if clean != message.content:
                message = message.model_copy(update={"content": clean})
        scrubbed.append(message)
    return replace(response, result=scrubbed)


class OutputFirewall(AgentMiddleware):
    """Scrubs or blocks model output before it leaves the agent."""

    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        return scrub(handler(request))

    # CopilotKit calls this async variant.
    async def awrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], Awaitable[ModelResponse]],
    ) -> ModelResponse:
        return scrub(await handler(request))
```

<Callout type="warn" title="Streaming bypasses a naive output filter">
  `wrap_model_call` sees the completed response. When the model streams, tokens have already
  reached the browser by then, so a scrub applied here fixes the stored message while the
  user may have briefly seen the original. The same is true for `PIIMiddleware` with
  `apply_to_output=True`: its stream transformer covers only LangGraph's v3 event stream, and
  the CopilotKit AG-UI adapters stream model tokens before the middleware masks them. The
  browser can receive the raw value in streamed text, and only the final message is masked.
  The raw model output also travels in AG-UI `RAW` events, which `ag-ui-langgraph` sends by default.

  If a rule must keep a value out of the browser, do both:

  - Do not stream the screened model: `ChatOpenAI(..., disable_streaming=True)`.
  - On a FastAPI endpoint, turn off `RAW` events: `LangGraphAGUIAgent(..., emit_raw_events=False)`.
</Callout>

CopilotKit runs your agent on the async path. For every `wrap_*` hook, implement the `a`-prefixed variant (`awrap_model_call`, `awrap_tool_call`). A `wrap_*` hook with only the sync method raises `NotImplementedError` on the async path. Node hooks such as `before_model` run on both paths.

## Screening tool calls

Tools are the other boundary worth guarding: arguments carry user-influenced data outward, results carry system data back.

```python
from typing import Awaitable, Callable

from langgraph.types import Command
from langchain_core.messages import ToolMessage
from langchain.agents.middleware import AgentMiddleware, ToolCallRequest


class ToolFirewall(AgentMiddleware):
    def wrap_tool_call(
        self,
        request: ToolCallRequest,
        handler: Callable[[ToolCallRequest], ToolMessage | Command],
    ) -> ToolMessage | Command:
        if not tool_call_allowed(request):  # your policy
            return ToolMessage(
                content="This action is not permitted.",
                tool_call_id=request.tool_call["id"],
            )
        return handler(request)

    async def awrap_tool_call(
        self,
        request: ToolCallRequest,
        handler: Callable[[ToolCallRequest], Awaitable[ToolMessage | Command]],
    ) -> ToolMessage | Command:
        if not tool_call_allowed(request):  # your policy
            return ToolMessage(
                content="This action is not permitted.",
                tool_call_id=request.tool_call["id"],
            )
        return await handler(request)
```

Returning a `ToolMessage` without calling `handler` blocks execution while keeping the conversation coherent: the model sees a refusal it can respond to.

## Ordering against `CopilotKitMiddleware`

Middleware compose with **the first entry as the outermost layer**. For `wrap_*` hooks that means the first-listed middleware sees the request earliest and the response latest.

`CopilotKitMiddleware` merges frontend tools into the request and intercepts frontend tool calls on the way back. Put your guardrails **before** it in the list:

```python
middleware=[
    InputFirewall(),        # outermost: screens before anything else runs
    OutputFirewall(),       # sees the final response last
    CopilotKitMiddleware(), # innermost: frontend tools, state exposure
]
```

That ordering matters because `CopilotKitMiddleware` adds the browser's frontend tools to the model request:

- A guardrail after it sees a request that already holds frontend tools your policy did not approve.
- An output filter after it runs before CopilotKit builds the response that the frontend receives.

<Callout type="info">
  The list order is the only ordering control. There is no priority field, and a middleware
  cannot declare that it must run before another.
</Callout>

## Try it

Send `My email is jane@example.com` in the chat. With `PIIMiddleware("email", strategy="redact")`, the model sees `[REDACTED_EMAIL]`, not the address.

## What this doesn't cover

Middleware guards the agent. It does not guard the runtime around it. Authenticating the caller, rate-limiting by user, or rejecting a request outright before an agent run starts belongs at the runtime layer instead:

- [Authentication](/auth): `onRequest` and `onBeforeHandler` hooks on the runtime handler
- [Thread authorization](/auth#thread-authorization): stopping one user reaching another's conversation

And for actions that should require a human rather than a policy check, [Human in the loop](/human-in-the-loop) is the better tool: surface the action for approval rather than silently blocking it.
