## What you'll build

A writing agent whose `write_document` tool streams its `document` argument into agent state. The document panel grows token by token while the model generates the tool call. Without streaming, the document would appear all at once when the tool finishes.

A LangGraph agent's state normally changes only across node transitions, and a single node can run for many seconds. State streaming, also called predictive state updates, shows the user what the agent is doing while the node runs. Use it to keep users engaged during long steps, to show what the agent is working on, and to let users correct the agent early.

## Prerequisites

- A LangGraph agent served through the CopilotKit runtime. If you don't have one yet, start with the [quickstart](/quickstart).
- `@copilotkit/react-core` in your frontend. The hooks on this page come from `@copilotkit/react-core/v2`.

<Callout type="warn" title="The node's returned state is the source of truth">
  When a node in your LangGraph finishes executing, its returned state becomes the single source of truth. Streamed values are previews. Include every value you want to keep in the node's final returned state, or it is overwritten when the node completes. In the demo, `write_document` returns the finished `document` in its `Command` update.
</Callout>

## Implementation

  <Step>
    ### Install the CopilotKit SDK

  <Step>
    ### Map the tool argument to a state key

    Tell CopilotKit which tool argument to forward and which state key receives it. A `create_agent` agent does this with `StateStreamingMiddleware` and a `StateItem`. A custom graph passes an `emitIntermediateState` mapping to `copilotkitCustomizeConfig` and calls the model with the returned config. Both take the same three values: the state key, the tool name, and the tool argument.

    <Snippet region="state-streaming-middleware" />

    - The state key must exist in your agent state. The demo uses `document`.
    - The tool name and the argument name must match the tool call that the model makes. The demo uses `write_document` and `document`.
    - The tool still returns the finished value, which replaces the streamed preview when the tool call completes.
  </Step>
  <Step>
    ### Subscribe to the streamed state in the UI

    Call [useAgent](/reference/hooks/useAgent) with `UseAgentUpdate.OnStateChanged` so the component re-renders on every streamed update. Add `UseAgentUpdate.OnRunStatusChanged` to show a live indicator while `agent.isRunning` is true. Then render `agent.state.document` like any other string.

## Other ways to emit intermediate state

The Showcase demonstrates one agent shape per language. The patterns below cover the other shapes and manual emission. They aren't taken from the Showcase, so rename the state key, tool, and argument to match your agent. Each example writes an `observed_steps` list into agent state. Read it in the UI with the same `useAgent` subscription through `agent.state.observed_steps`.

### Tool-based streaming in a custom graph

In a custom `StateGraph`, pass an `emit_intermediate_state` mapping to `copilotkit_customize_config` and call the model with the returned config. The tool returns a `Command` so that the final `observed_steps` value persists when the node completes.

```python title="agent.py"
import uuid

from copilotkit import CopilotKitState
from copilotkit.langgraph import copilotkit_customize_config
from langchain.tools import ToolRuntime, tool
from langchain_core.messages import AIMessage, SystemMessage, ToolMessage
from langchain_core.runnables import RunnableConfig
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import END, START, StateGraph
from langgraph.prebuilt import ToolNode
from langgraph.types import Command

class AgentState(CopilotKitState):
    observed_steps: list[str]

@tool
def step_progress_tool(steps: list[str], runtime: ToolRuntime) -> Command:
    """Report the current steps being executed."""
    return Command(
        update={
            "observed_steps": steps,
            "messages": [
                ToolMessage(
                    content="Steps recorded to shared state.",
                    name="step_progress_tool",
                    id=str(uuid.uuid4()),
                    tool_call_id=runtime.tool_call_id,
                )
            ],
        }
    )

tools = [step_progress_tool]
model = ChatOpenAI(model="gpt-5.4")

async def chat_node(state: AgentState, config: RunnableConfig):
    streaming_config = copilotkit_customize_config(
        config,
        emit_intermediate_state=[
            {
                "state_key": "observed_steps",
                "tool": "step_progress_tool",
                "tool_argument": "steps",
            },
        ]
    )

    model_with_tools = model.bind_tools(
        [
            *state["copilotkit"]["actions"],
            *tools,
        ],
        parallel_tool_calls=False,
    )

    response = await model_with_tools.ainvoke(
        [
            SystemMessage(
                content="You are a task performer. Report your steps "
                "using step_progress_tool."
            ),
            *state["messages"],
        ],
        streaming_config,
    )
    return {"messages": [response]}

def route_after_chat(state: AgentState):
    last_message = state["messages"][-1]
    if not isinstance(last_message, AIMessage) or not last_message.tool_calls:
        return END

    frontend_action_names = {
        action["name"] for action in state["copilotkit"]["actions"]
    }
    if any(
        call["name"] not in frontend_action_names
        for call in last_message.tool_calls
    ):
        return "tool_node"

    # Frontend action calls are returned to CopilotKit for execution in the UI.
    return END

workflow = (
    StateGraph(AgentState)
    .add_node("chat_node", chat_node)
    .add_node("tool_node", ToolNode(tools))
    .add_edge(START, "chat_node")
    .add_edge("tool_node", "chat_node")
    .add_conditional_edges(
        "chat_node",
        route_after_chat,
        ["tool_node", END],
    )
)

graph = workflow.compile(checkpointer=MemorySaver())
```

### Emit state manually

For long-running work that isn't a tool call, emit state updates yourself with `copilotkit_emit_state`. This example simulates four steps with a one-second delay between updates, then returns the final list so it persists.

```python title="agent.py"
import asyncio

from copilotkit import CopilotKitState
from copilotkit.langgraph import copilotkit_emit_state
from langchain_core.runnables import RunnableConfig

class AgentState(CopilotKitState):
    observed_steps: list[str]

async def chat_node(state: AgentState, config: RunnableConfig):
    # Simulate executing steps one by one
    steps = [
        "Analyzing input data...",
        "Identifying key patterns...",
        "Generating recommendations...",
        "Formatting final output..."
    ]

    for step in steps:
        state["observed_steps"] = state.get("observed_steps", []) + [step]
        await copilotkit_emit_state(config, state)
        await asyncio.sleep(1)

    # ...call the model, then return every value you want to keep
    return {"observed_steps": state["observed_steps"]}
```

### Middleware on a prebuilt agent

With `createAgent`, add `stateStreamingMiddleware` to the `middleware` list. Each `stateItem` maps a tool argument to a state key, just like the `emitIntermediateState` mapping in a custom graph.

```ts title="agent-js/src/agent.ts"
import { createAgent } from "langchain";
import { StateSchema } from "@langchain/langgraph";
import { copilotkitMiddleware, CopilotKitStateSchema } from "@copilotkit/sdk-js/langgraph";
import { stateStreamingMiddleware, stateItem } from "@copilotkit/sdk-js/langgraph-middlewares";
import { tool } from "@langchain/core/tools";
import { z } from "zod";

export const AgentStateSchema = new StateSchema({
    observed_steps: z.array(z.string()).default(() => []),
    ...CopilotKitStateSchema.fields,
});
export type AgentState = typeof AgentStateSchema.State;

const stepProgressTool = tool(
    async (args) => args,
    {
        name: "step_progress_tool",
        description: "Reports the current steps being executed",
        schema: z.object({ steps: z.array(z.string()) }),
    }
);

export const graph = createAgent({
    model: "openai:gpt-5.4",
    tools: [stepProgressTool],
    middleware: [
        copilotkitMiddleware,
        stateStreamingMiddleware(
            stateItem({ stateKey: "observed_steps", tool: "step_progress_tool", toolArgument: "steps" })
        ),
    ],
    stateSchema: AgentStateSchema,
    systemPrompt: "You are a task performer. Report your steps using step_progress_tool.",
});
```

### Emit state manually

For long-running work that isn't a tool call, emit state updates yourself with `copilotkitEmitState`. This example simulates four steps with a one-second delay between updates, then returns the final list so it persists.

```ts title="agent-js/src/agent.ts"
import { Annotation } from "@langchain/langgraph";
import type { RunnableConfig } from "@langchain/core/runnables";
import {
  copilotkitEmitState,
  CopilotKitStateAnnotation,
} from "@copilotkit/sdk-js/langgraph";

const AgentStateAnnotation = Annotation.Root({
  ...CopilotKitStateAnnotation.spec,
  observed_steps: Annotation<string[]>,
});
type AgentState = typeof AgentStateAnnotation.State;

async function chat_node(state: AgentState, config: RunnableConfig) {
  // Simulate executing steps one by one
  const steps = [
    "Analyzing input data...",
    "Identifying key patterns...",
    "Generating recommendations...",
    "Formatting final output...",
  ];

  for (const step of steps) {
    state.observed_steps = [...(state.observed_steps ?? []), step];
    await copilotkitEmitState(config, state);
    await new Promise((resolve) => setTimeout(resolve, 1000));
  }

  // ...call the model, then return every value you want to keep
  return { observed_steps: state.observed_steps };
}
```
