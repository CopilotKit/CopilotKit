A user who reloads the page or opens an old conversation expects to see its earlier messages. Set `threadId` on `<CopilotKit>` to load a thread.

This guide assumes you have already gone through the [quickstart](/langgraph/quickstart) guide.

## Loading an Existing Thread

To load an existing thread in CopilotKit, you can set the `threadId` property on `<CopilotKit>` like so.

<Callout>When using LangGraph platform, the `threadId` must be a UUID.</Callout>

```tsx
{/* [!code highlight:1] */}
<CopilotKit threadId="37aa68d0-d15b-45ae-afc1-0ba6c3e11353">
  <YourApp />
</CopilotKit>
```

## Dynamically Switching Threads

You can also make the `threadId` dynamic. When it changes, CopilotKit loads the messages that the runtime's agent runner kept for that thread. The default `InMemoryAgentRunner` keeps them only in server memory, so a server restart loses them. To keep threads across restarts, use a persistent runner such as `SqliteAgentRunner` from `@copilotkit/sqlite-runner`.

```tsx
"use client";

import { useState } from "react";
import { CopilotKit } from "@copilotkit/react-core/v2";

const Page = () => {
  const [threadId, setThreadId] = useState("af2fa5a4-36bd-4e02-9b55-2580ab584f89"); // [!code highlight]
  return (
    {/* [!code highlight:3] */}
    <CopilotKit threadId={threadId}>
      <YourApp setThreadId={setThreadId} />
    </CopilotKit>
  )
}

const YourApp = ({ setThreadId }) => {
  return (
    {/* [!code highlight:1] */}
    <button onClick={() => setThreadId("679e8da5-ee9b-41b1-941b-80e0cc73a008")}>
      Change Thread
    </button>
  )
}
```

Click **Change Thread**. The chat shows the messages that the runtime kept for the new thread.
