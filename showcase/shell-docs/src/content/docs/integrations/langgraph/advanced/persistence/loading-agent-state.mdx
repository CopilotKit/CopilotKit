title: Loading Agent State
description: Use threadId to load previous agent states.

When a user comes back to a conversation, CopilotKit starts a new thread unless you name the old one.

### Setting the threadId

Set `threadId` on `<CopilotKit>` to load the agent state of that thread:

```tsx
<CopilotKit threadId="2140b272-7180-410d-9526-f66210918b13">
  <YourApp />
</CopilotKit>
```

<Callout>When using LangGraph platform, the `threadId` must be a UUID.</Callout>

CopilotKit will restore the messages and agent state that the runtime's agent runner kept for this thread. The default `InMemoryAgentRunner` keeps them only in server memory, so a server restart loses them. To keep threads across restarts, use a persistent runner such as `SqliteAgentRunner` from `@copilotkit/sqlite-runner`. (See [Message Persistence](/langgraph/advanced/persistence/message-persistence) for more details.)

### Loading Agent State

This means that the state of any agent will also be restored. For example:

```tsx
import { useAgent } from "@copilotkit/react-core/v2";

const { agent } = useAgent({ agentId: "research_agent" });

// agent.state will now be the state of research_agent in the thread id given above
```

To read and change this state in your UI, see [Reading agent state](/langgraph/shared-state/in-app-agent-read).
