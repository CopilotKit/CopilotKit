CopilotKit provides error handling tools to help you debug issues and monitor your application's behavior. In development, the Inspector shows errors in your UI. In production, the `onError` callback sends errors to your monitoring services.

## Quick Start

<Steps>

<Step>
### Local Development with the Inspector

The Inspector is on by default in development builds. `enableInspector` controls it:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";

export default function App({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      enableInspector={true} // [!code highlight]
    >
      {children}
    </CopilotKitProvider>
  );
}
```

<Callout type="tip">
  The Inspector shows errors directly in your UI, making it easy to spot
  issues during development. **No API key required** for this feature. It never
  loads in production builds.
</Callout>

</Step>

<Step>
### Production Error Observability

For production applications, use the `onError` callback to send errors to monitoring services. No `publicApiKey` is required:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";
import { analytics } from "./analytics";

export default function App({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        // [!code highlight]
        // Send to your monitoring service
        console.error("CopilotKit Error:", event.error);

        // Example: Send to analytics
        analytics.track("copilotkit_error", {
          code: event.code,
          message: event.error.message,
          agentId: event.context.agentId,
        });
      }} // [!code highlight]
    >
      {children}
    </CopilotKitProvider>
  );
}
```

</Step>

</Steps>

## Error Handling Options

### Inspector (`enableInspector`)

The Inspector provides immediate visual feedback during development:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" enableInspector={true}>
      {children}
    </CopilotKitProvider>
  );
}
```

**Features:**

- ✅ **No API key required** - works with any setup
- ✅ **Visual error display** - the launcher turns red and names the failure
- ✅ **Real-time feedback** - see errors immediately as they occur
- ✅ **Development-focused** - detailed event and error information for debugging

**Best for:**

- Local development
- Testing and debugging
- Understanding error flows

<Callout type="info">
  The Inspector is always disabled in production builds, on remote hosts, and
  during server rendering, so it does not show error details to end users. See
  [Inspector and dev console](/troubleshooting/inspector-dev-console).
</Callout>

### Error Observability (`onError`)

The `onError` callback gives you programmatic access to every error CopilotKit encounters. Switch on `event.code` to handle each error type:

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";
import { logToService } from "./logging";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        // Send error data to monitoring services
        switch (event.code) {
          case "runtime_info_fetch_failed":
            logToService("Runtime unreachable", event);
            break;
          case "agent_run_failed":
          case "agent_run_error_event":
            logToService("Agent run failed", event);
            break;
          case "tool_handler_failed":
            logToService("Frontend tool failed", event);
            break;
          default:
            logToService("CopilotKit error", event);
        }
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

`CopilotChat` also takes an `onError` prop. It is scoped to that chat's agent and fires **in addition to** the provider-level handler.

## Error Event Structure

The `onError` handler receives an event with three fields:

```typescript
import type { CopilotKitProviderProps } from "@copilotkit/react-core";

type CopilotKitErrorEvent = Parameters<
  NonNullable<CopilotKitProviderProps["onError"]>
>[0];
// {
//   error: Error;                    // the Error object
//   code: CopilotKitCoreErrorCode;   // the error type, e.g. "agent_run_failed"
//   context: Record<string, any>;    // additional context (agentId, toolName, etc.)
// }
```

| Code | Description |
|------|-------------|
| `runtime_info_fetch_failed` | Could not reach the runtime's `/info` endpoint |
| `agent_connect_failed` | Agent connection (thread setup) failed |
| `agent_run_failed` | Agent run rejected (e.g. network error) |
| `agent_run_failed_event` | The agent's `onRunFailed` subscriber fired |
| `agent_run_error_event` | Agent emitted a `RUN_ERROR` event |
| `tool_argument_parse_failed` | Tool call arguments were not valid JSON |
| `tool_handler_failed` | A frontend tool handler threw |
| `tool_not_found` | The agent called a tool that is not registered |
| `agent_not_found` | The requested agent is not registered on the runtime |
| `agent_thread_locked` | Another active run holds the thread |

## Common Error Observability Patterns

### Basic Error Logging

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        console.error("[CopilotKit Error]", {
          code: event.code,
          timestamp: new Date().toISOString(),
          context: event.context,
          error: event.error,
        });
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

### Integration with Monitoring Services

```tsx
// Example with Sentry
import * as Sentry from "@sentry/nextjs";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        Sentry.captureException(event.error, {
          tags: {
            code: event.code,
            agentId: event.context.agentId,
          },
          extra: {
            context: event.context,
          },
        });
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

### Custom Error Analytics

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";
import { analytics } from "./analytics";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={(event) => {
        // Track different error types
        analytics.track("copilotkit_event", {
          code: event.code,
          agent_id: event.context.agentId,
          tool_name: event.context.toolName,
          error_message: event.error.message,
          timestamp: Date.now(),
        });
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

## Development vs Production Setup

### Development Environment

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="http://localhost:3000/api/copilotkit"
      enableInspector={true} // Show visual errors
      onError={(event) => {
        // Simple console logging for development
        console.log("CopilotKit Event:", event);
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

### Production Environment

```tsx
import { CopilotKitProvider } from "@copilotkit/react-core";
import { logger, monitoring } from "./observability";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="https://your-app.com/api/copilotkit"
      onError={(event) => {
        // Log critical errors
        logger.error("CopilotKit Error", {
          code: event.code,
          error: event.error,
          context: event.context,
        });

        // Send to monitoring service
        monitoring.captureError(event.error, {
          extra: event.context,
        });
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

## Best Practices

### ✅ Do

- **Keep the Inspector on during development** for immediate feedback
- **Implement proper error observability** with the `onError` hook for monitoring
- **Monitor error patterns** to identify and fix issues proactively
- **Use structured logging** to make error analysis easier

### ❌ Don't

- **Don't expose detailed errors to end users** in production
- **Don't ignore error events** - they provide valuable debugging information
- **Don't log sensitive data** in error observability hooks
- **Don't block the UI** with error handling logic

## Troubleshooting

### Error Observability Not Working

If your `onError` hook isn't being called:

1. **Check where you set it** - put it on `CopilotKitProvider` to catch every error, or on `CopilotChat` for one chat's agent
2. **Check the agent IDs** - the IDs in your components must match the agents registered on your runtime
3. **Test with the Inspector** - open it to see if errors are occurring

### Inspector Not Showing

If the Inspector isn't displaying errors:

1. **Check `enableInspector`** - ensure it is not set to `false`
2. **Check the build** - the Inspector only loads in development builds on localhost
3. **Look for console errors** - check browser dev tools for JavaScript errors
