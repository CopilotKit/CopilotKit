## What is this?

LangGraph agents can receive runtime configuration from your frontend, such as user preferences, session metadata, or authentication tokens. CopilotKit provides two distinct channels for this depending on whether the values are **model-visible** or not:

| Channel | Mechanism | Visible to LLM? | Use for |
|---|---|---|---|
| `useAgentContext` | `state["copilotkit"]["context"]` | **Yes** — injected as a system message | User preferences, UI metadata, non-secret config |
| Custom `x-*` headers | `config["configurable"]` | **No** — never touches state or prompt | Auth tokens, API keys, secrets |

<Callout type="warning" title="Auth tokens belong in x-* headers, not useAgentContext">
  **`useAgentContext` is the model-visible channel.**  Every value published via
  `useAgentContext` is serialized into a `SystemMessage` sent to the LLM on every
  turn — it appears in LLM provider logs and the LLM can read and reference those
  values in its responses.

  **Do NOT put auth tokens, API keys, or secrets in `useAgentContext`.**

  For authentication and secrets, use the `x-*` header path instead.
  See the [Authentication guide](/langgraph/auth) for the full pattern.
</Callout>

<Callout type="warning" title="LangGraph 0.6.0+ Compatibility">
  LangGraph 0.6.0 deprecated the older `configurable` pattern for frontend→agent
  config (it rejected requests with both `configurable` and `context` set).
  For **non-secret** frontend config (preferences, metadata), use **`useAgentContext`**
  as shown below.  For **auth credentials**, use the `x-*` header path regardless
  of LangGraph version.
</Callout>

If you wish to read further, you can refer to [the configuration guide by LangGraph](https://docs.langchain.com/oss/python/langgraph/use-graph-api#add-runtime-configuration)

## When should I use this?

- **`useAgentContext` (model-visible)**: Use when you want the LLM to adapt its behavior based on frontend config — tone, expertise level, response length, UI state. The LLM reads these values naturally from the injected system message.

- **`x-*` headers (non-model-visible)**: Use when you need to pass a credential or secret the graph node reads programmatically, without ever sending it to the LLM. See the [Authentication guide](/langgraph/auth).

<Callout type="info" title="Looking for authentication?">
  If you need to pass authentication tokens, see the dedicated [Authentication guide](/langgraph/auth)
  which covers the `x-copilotkit-auth` configurable-header path (non-model-visible) and LangGraph
  Platform built-in auth.
</Callout>

## Non-secret Runtime Config with useAgentContext (v2 — Recommended)

Use `useAgentContext` from `@copilotkit/react-core/v2` to publish **non-secret** runtime configuration. This works seamlessly with LangGraph 0.6.0+ and `CopilotKitMiddleware`.

<Steps>
<Step>
### Publish context from the frontend

Use the `useAgentContext` hook to publish configuration values that your agent can access:

```tsx title="app/page.tsx"
import { useAgentContext } from "@copilotkit/react-core/v2"; // [!code highlight]

function YourMainContent() {
  // Publish NON-SECRET configuration the LLM is meant to see
  // [!code highlight:7]
  useAgentContext({
    description: "User response preferences",
    value: {
      tone: "professional",
      expertise: "expert",
      responseLength: "concise",
    },
  });

  return (... your component UI)
}
```

<Callout type="tip" title="Dynamic configuration">
  The context value updates automatically when your state changes. For example, if configuration values come from React state variables, the agent receives updated values on subsequent runs.
</Callout>
</Step>
<Step>
### Set up the middleware in your agent

Add `CopilotKitMiddleware` to your LangGraph agent. The middleware automatically injects the context into the LLM's system message:

```python title="agent.py"
from langgraph.prebuilt import create_agent
from langchain_openai import ChatOpenAI
from copilotkit import CopilotKitMiddleware  # [!code highlight]

graph = create_agent(
    model=ChatOpenAI(model="gpt-4"),
    tools=[],
    middleware=[CopilotKitMiddleware()],  # [!code highlight]
)
```
</Step>
<Step>
### Access context in your agent nodes

The context published via `useAgentContext` is accessible through the agent `state` parameter. The middleware stores it at `state["copilotkit"]["context"]` and also automatically injects it into the conversation as a `SystemMessage` for the LLM to read.

**For programmatic access** (e.g., to branch logic based on preferences):

```python title="agent_node.py"
from typing import Any

async def agent_node(state: dict[str, Any]) -> dict[str, Any]:
    # Access the context published from useAgentContext.
    # These values were also sent to the LLM — that is intentional here.
    copilotkit_state = state.get("copilotkit", {})
    context_entries = copilotkit_state.get("context", [])

    tone = "professional"
    expertise = "intermediate"
    response_length = "concise"

    for entry in context_entries:
        value = entry.get("value", {})
        if isinstance(value, dict):
            tone = value.get("tone") or tone
            expertise = value.get("expertise") or expertise
            response_length = value.get("responseLength") or response_length

    # Use the values in Python logic (in addition to the automatic LLM injection).
    return state
```

**For LLM-accessible context** (e.g., user preferences, instructions):

The `CopilotKitMiddleware` automatically injects context as a `SystemMessage`, so the LLM can read and respond to it naturally without explicit extraction code. This is ideal for configuration that affects how the LLM responds (tone, style, expertise level, etc.).

<Callout type="tip" title="When to use each approach">
  - Use **state access** when you need to programmatically use non-sensitive values in Python code
  - Use **LLM injection** (automatic via middleware) when you want the model to adapt its responses
  - For **auth tokens and secrets**: use `x-*` configurable headers — see the [Authentication guide](/langgraph/auth)
</Callout>
</Step>
</Steps>

## Verification

**State structure verification:** [`sdk-python/tests/test_context_integration.py`](https://github.com/CopilotKit/CopilotKit/tree/main/sdk-python/tests/test_context_integration.py) verifies the documented non-secret access pattern:

- Context values are readable from `state["copilotkit"]["context"]`
- Values persist across simulated agent turns
- The pattern handles missing or empty context gracefully
- Sensitive key names (tokens, passwords, secrets) must not appear in this channel

**Auth credential verification:** [`sdk-python/tests/test_configurable_auth_header.py`](https://github.com/CopilotKit/CopilotKit/tree/main/sdk-python/tests/test_configurable_auth_header.py) verifies the `x-*` configurable-header auth path:

- `x-copilotkit-auth` is accessible via `config["configurable"]` on repeated runs
- The token does NOT appear in `state["copilotkit"]["context"]` (non-model-visible)
- `config["configurable"]` values do not bleed into LangGraph state

## Legacy Pattern (LangGraph <0.6.0)

<details>
<summary>Click to expand legacy pattern for LangGraph versions before 0.6.0</summary>

<Callout type="warning" title="Deprecated for LangGraph 0.6.0+">
  This pattern is **not compatible** with LangGraph 0.6.0 and later. LangGraph 0.6.0 introduced runtime `context` and explicitly rejects requests with both `configurable` and `context` set. Use the v2 `useAgentContext` pattern above for non-secret config, and the `x-*` header path for credentials.
</Callout>

### Legacy: Pass via forwardedProps.config

```tsx title="app/page.tsx (legacy)"
import { useAgent } from "@copilotkit/react-core/v2";
import { useEffect } from "react";

function YourMainContent() {
  const { agent } = useAgent({
    agentId: "sample_agent",
  });

  useEffect(() => {
    agent.runAgent({
      forwardedProps: {
        config: {
          configurable: {
            userPreference: 'detailed'
          },
        }
      }
    });
  }, []);

  return (...);
}
```

### Legacy: Access in agent node

```python title="agent_node.py (legacy)"
from typing import Any
from langchain_core.runnables import RunnableConfig

async def agent_node(state: dict[str, Any], config: RunnableConfig):
    user_preference = config['configurable'].get('userPreference', None)
    return state
```

**Known issues with this pattern:**
- Does not work with LangGraph 0.6.0+ (HTTP 400 error: "Cannot specify both configurable and context")
- Configuration may become `None` on subsequent agent runs in the same session
- Not compatible with `@ag-ui/langgraph` 0.0.31+

</details>
