The Python agent lives in `examples/v1/travel/agent`. The app runs it as
an AG-UI server, so the browser and agent can exchange messages, state, tool
calls, and approval results through one protocol.

## Agent structure

The source is split by responsibility:

- `agent/src/state.py` defines the shared `AgentState`.
- `agent/src/agent.py` builds and compiles the LangGraph graph.
- `agent/src/chat.py` prompts the model and routes its tool calls.
- `agent/src/search.py` searches Places API (New) and streams progress.
- `agent/src/trips.py` applies approved trip changes.
- `agent/main.py` serves the graph at `http://localhost:8000/copilotkit`.

The graph has four nodes:

1. `chat_node` asks the model what to do next.
2. `search_node` searches for places and sends progress to the UI.
3. `trips_node` pauses a proposed trip change for user review.
4. `perform_trips_node` applies an approved change or handles a rejection.

You can inspect the graph in `agent/static/agent-diagram.png`.

## Run the agent by itself

From `examples/v1/travel`, run:

```shell
pnpm dev:agent
```

`agent/main.py` loads `agent/.env`, wraps the compiled graph in
`LangGraphAGUIAgent`, and mounts it at `/copilotkit`. Keep this process running
while you start the UI with `pnpm dev:ui` in another terminal.
