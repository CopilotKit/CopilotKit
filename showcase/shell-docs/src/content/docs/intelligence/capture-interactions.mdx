## Overview

Trajectories capture browser interactions as AG-UI `CUSTOM` events in CopilotKit Intelligence. This feature is in early access.

This guide connects an existing React app to Intelligence. To start the local environment, use [Try Trajectories with Docker](/intelligence/trajectories-docker).

Capture includes URLs, page titles, referrers, element text, attributes, form values, browser-visible headers, and bounded body snapshots. Recognized credential fields are redacted in the browser. Redaction has limits. Read [Captured data](/intelligence/captured-data) before you enable capture.

## Turn on capture

<Steps>
  <Step>
    ### Connect your Runtime to Intelligence

    Complete the [Docker guide](/intelligence/trajectories-docker) or the [Intelligence quickstart](/intelligence/quickstart).

    The TypeScript Runtime needs `intelligence` and `identifyUser`, with Trajectories enabled for its project. `identifyUser` must return the user from your verified application session. Keep the project API key on the server.

  </Step>
  <Step>
    ### Pass `learning` to the provider

    A Trajectory groups captured interactions. Add `learning` to your existing provider:

    ```tsx title="app/providers.tsx"
    "use client";

    import { CopilotKitProvider } from "@copilotkit/react-core/v2";

    export function Providers({ children }: { children: React.ReactNode }) {
      return (
        <CopilotKitProvider runtimeUrl="/api/copilotkit" learning>
          {children}
        </CopilotKitProvider>
      );
    }
    ```

    Keep your existing Runtime URL and application authentication configuration. Capture starts after the provider mounts, authenticates through Runtime, and joins the connection to Intelligence. A chat is not required. Capture excludes requests to the configured Runtime endpoint.

    The provider generates a Trajectory UUID. It stays the same across rerenders and reconnects while capture is on. Set `learning={false}` to stop capture. Turning capture on again generates a new ID. Unmounting the provider also stops capture.

    To connect capture to an application consent control, pass `learning={hasConsent}`. Read the active ID from `copilotkit.trajectoryId`.

  </Step>
  <Step>
    ### Name the actions that matter

    Click events include element details and a short control name in `target.label`, such as `Approve`. See [Click labels](/intelligence/captured-data#click-labels) for the sources and redaction rules.

    Add `data-copilotkit-action` for a stable, explicit action name:

    ```tsx
    <button data-copilotkit-action="deal.approve" onClick={approve}>
      Approve
    </button>
    ```

  </Step>
  <Step>
    ### Open the saved Trajectory

    Click an action in your app. Wait at least two seconds for the next batch.

    Open **Trajectories** in the same Intelligence project. Open the new Trajectory and find the click in its AG-UI Stream. Refresh the page and check that the event remains.

    To add a Thread link, start an agent conversation while capture is active. Core sends `thread.linked` after Runtime starts a run in that Thread.

  </Step>
</Steps>

Connected capture links each Thread once. It does not add Thread, message, or tool fields to individual clicks. A Trajectory can contain interactions without any Thread.

## Record outcomes

A click shows what a person did. It does not show whether the work succeeded. After your application operation succeeds, emit the outcome:

```tsx
import { useCopilotKit } from "@copilotkit/react-core/v2";

function ApproveButton({
  dealId,
  approveDeal,
}: {
  dealId: string;
  approveDeal: (id: string) => Promise<void>;
}) {
  const { copilotkit } = useCopilotKit();

  async function approve() {
    await approveDeal(dealId);
    copilotkit.emitTrajectoryEvent("deal.approved", { dealId });
  }

  return (
    <button onClick={approve}>
      Approve
    </button>
  );
}
```

The event belongs to the active Trajectory. Built-in names such as `click` are reserved. Your application controls the event payload. Automatic credential redaction does not inspect developer events.

## Start and stop a Trajectory yourself

Set `autoStart: false` on the prop. The provider then waits for your app to start capture:

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  learning={{ autoStart: false }}
>
  {children}
</CopilotKitProvider>
```

Call Core when your app decides a session starts:

```tsx
import { useCopilotKit } from "@copilotkit/react-core/v2";

function StartCaptureButton() {
  const { copilotkit } = useCopilotKit();

  async function startCapture() {
    const result = await copilotkit.startTrajectory();
    if (result.status === "error") {
      console.warn("Trajectory capture:", result.code);
    }
  }

  return (
    <button onClick={startCapture}>Start capture</button>
  );
}
```

`startTrajectory()` generates a UUID. To supply a UUID, call `startTrajectory({ trajectoryId: crypto.randomUUID() })`. With `autoStart: false`, the provider ignores `learning.trajectoryId` and logs a warning.

One Trajectory runs at a time. A start with the same ID reuses the current start. `copilotkit.stopTrajectory()` removes capture listeners and attempts a final batch. It does not wait for delivery or guarantee that the last events are saved.

## Capture errors

By default, Core logs setup errors with a code and a configuration hint. Pass `onError` to handle them in your app:

```tsx
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  learning={{
    onError: ({ code }) => console.warn("Trajectory capture:", code),
  }}
>
  {children}
</CopilotKitProvider>
```

Capture pauses during a connection loss and reconnects with fresh credentials. It does not buffer developer events during recovery or resend failed batches. See [Batches](/intelligence/captured-data#batches) for delivery limits.

## Advanced: send events to your own sink

A custom sink receives batches through an endpoint that you own. It replaces the connection to Intelligence. A sink endpoint does not automatically import events into Intelligence.

Install the collector package:

```bash
npm install @copilotkit/learning
```

Add your receiving endpoint as `sink`:

```tsx
import { httpSink } from "@copilotkit/learning";
import { CopilotKitProvider } from "@copilotkit/react-core/v2";

const sink = httpSink("/api/learning-events");

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" learning={{ sink }}>
      {children}
    </CopilotKitProvider>
  );
}
```

The endpoint receives `{ trajectoryId, learningContainerIds, events, dropped }`. `learningContainerIds` is optional. Implement storage and authentication for your endpoint.

The custom-sink integration also captures agent messages and tool events. It adds Thread context to clicks inside chat messages. Outside a message, it uses the single open Thread. With multiple open Threads, it returns `threadId: null` and lists the candidates in `threadAmbiguity`.

These chat fields belong to custom sinks. See [Captured data](/intelligence/captured-data#events) for the fields available in each integration.

Need capture in an app without CopilotKit? Use the [standalone collector](/intelligence/standalone-collector).
