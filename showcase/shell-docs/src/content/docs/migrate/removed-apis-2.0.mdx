---
title: Removed deprecated APIs in 2.0
description: Find the 2.0 replacement for each API that CopilotKit 1.x marked as deprecated.
---

CopilotKit 1.x marked some APIs as deprecated, and 2.0 removes them. If your app still uses one, the 2.0 build fails with a missing export or an unknown prop.

Most fixes are a rename or a deleted prop. A codemod does those for you.

## Update your code

1. Run the codemod:

   ```bash
   npx copilotkit@latest migrate
   ```

2. Search your code for `TODO(copilotkit-2.0)`. The codemod adds this comment where you must change the code yourself.
3. Find each marked API on this page, and apply the change.
4. Run your type check. TypeScript shows the removed options that the codemod does not change.

The codemod makes these changes:

| Your code | Codemod change |
| --- | --- |
| `BasicAgent`, `BasicAgentConfiguration`, `createNodeFetchHandler`, `useA2UIStore` | Renames the import and every use in the file |
| `showDevConsole` on `CopilotKitProvider`, `registry` on `A2UIRenderer` | Deletes the prop |
| The other removed imports, and `disclaimer` on `CopilotChatView` | Adds a `TODO(copilotkit-2.0)` comment |

## `CopilotKitRemovedApiError`

If your code still uses a 1.x export that 2.0 removed, it throws a `CopilotKitRemovedApiError`. The error happens when the code calls, constructs, or renders the export. The import itself does not throw. The message names the 2.0 replacement and links to the section about it:

```text
"useCopilotAction" was removed in CopilotKit 2.0. Use useFrontendTool from @copilotkit/react-core (parameters are now a Zod 4 / Standard Schema), or useHumanInTheLoop when the action waits for the user. Run `npx copilotkit@latest migrate` to update your code. See https://docs.copilotkit.ai/migrate/v2#hook-mapping
```

TypeScript shows the same message as a type error where the code uses the export, and your editor marks the import as deprecated. Do what the message says, or run the codemod.

The error has the code `REMOVED_API`, and its `docsUrl` property links the section about the API. It extends `Error`, not `CopilotKitError`, so `error instanceof CopilotKitError` does not match it. A removed constant, object, or React context has no stand-in, because code reads it without a call. An import of one fails the build.

## 1.x props, options, and arguments

Some 2.0 APIs keep the name of a 1.x API, but take other props, options, or arguments. If your code passes a 1.x one that cannot work in 2.0, it throws a `CopilotKitRemovedApiError`. If 2.0 only ignores it, a warning shows one time in development. TypeScript rejects a value for each removed option, and your editor marks it as deprecated.

### Provider props

In React and Vue, `CopilotKit` is an alias of `CopilotKitProvider`. These 1.x props are removed:

| Prop | In 2.0 | What to do |
| --- | --- | --- |
| `threadId` | Throws | Pass `threadId` to `<CopilotChat>`, or to `<CopilotChatConfigurationProvider>` around the chat. |
| `agent` | Throws | Rename it to `agentId`. |
| `guardrails_c`, `cloudRestrictToTopic` | Throws | Restrict the topics in your agent, for example in its prompt. |
| `authConfig_c` | Throws | Show your own sign-in screen before you render the provider. |
| `forwardedParameters` | Warns | Set the model parameters on the agent, for example `modelOptions` on a `BuiltInAgent`. |
| `transcribeAudioUrl`, `textToSpeechUrl` | Warns | Delete them. Voice input goes through the transcription service of the runtime. |
| `showDevConsole` | Warns | Delete it. See [`showDevConsole`](#showdevconsole). |

### Tool parameters as a list

`useFrontendTool` and `useHumanInTheLoop` take a Standard Schema for `parameters`, such as `z.object(...)`, in React and in Vue. A 1.x `Parameter[]` list throws. Write the list as a schema:

```tsx ignore title="Before"
useFrontendTool({
  name: "sayHello",
  parameters: [{ name: "name", type: "string", required: true }],
  handler: async ({ name }) => `Hello, ${name}!`,
});
```

```tsx title="After"
import { useFrontendTool } from "@copilotkit/react-core";
import { z } from "zod";

export function Greeter() {
  useFrontendTool({
    name: "sayHello",
    parameters: z.object({ name: z.string() }),
    handler: async ({ name }) => `Hello, ${name}!`,
  });
  return null;
}
```

### `useRenderToolCall` with arguments

In 1.x, `useRenderToolCall(tool, deps)` registered a renderer for a tool. In 2.0, `useRenderToolCall()` takes no arguments and returns a function that renders a tool call. A call with arguments throws. To register a renderer, use `useRenderTool`:

```tsx
import { useRenderTool } from "@copilotkit/react-core";
import { z } from "zod";

export function WeatherCard() {
  useRenderTool({
    name: "showWeather",
    parameters: z.object({ city: z.string() }),
    render: ({ parameters }) => <p>Weather in {parameters.city}</p>,
  });
  return null;
}
```

### `useThreads`

In 1.x, `useThreads()` returned the current thread. In 2.0, `useThreads({ agentId })` lists the threads of an agent. A call without arguments throws, and so does a read of `threadId`, `setThreadId`, or `isThreadIdExplicit` on its result. Read the current thread from `useCopilotChatConfiguration()`:

| 1.x `useThreads()` | 2.0 `useCopilotChatConfiguration()` |
| --- | --- |
| `threadId` | `threadId` |
| `setThreadId(id)` | `setActiveThreadId(id)` |
| `isThreadIdExplicit` | `hasExplicitThreadId` |

```tsx
import { useCopilotChatConfiguration } from "@copilotkit/react-core";

export function ThreadPicker({ threadIds }: { threadIds: string[] }) {
  const configuration = useCopilotChatConfiguration();
  return (
    <select
      value={configuration?.threadId}
      onChange={(event) => configuration?.setActiveThreadId(event.target.value)}
    >
      {threadIds.map((id) => (
        <option key={id}>{id}</option>
      ))}
    </select>
  );
}
```

### Runtime options

`CopilotKitRuntime` throws for these 1.x options, and so does the deprecated `CopilotRuntime` alias of `@copilotkit/runtime/v2`:

| Option | What to do |
| --- | --- |
| `serviceAdapter`, `delegateAgentProcessingToServiceAdapter` | Run the model in a `BuiltInAgent`. See [Update the runtime](/migrate/v2#update-the-runtime). |
| `remoteEndpoints`, `remoteActions`, `langserve` | Register each agent in `agents`. See [Agents and server-side actions in 2.0](/migrate/agents-2.0#langgraph-platform). |
| `actions` | Give the tools to the agent. See [Server-side actions](/migrate/agents-2.0#server-side-actions). |
| `mcpServers`, `createMCPClient` | Give the MCP clients to a `BuiltInAgent` as `mcp`. See [Replace `mcpServers` with `mcp`](/migrate/runtime-2.0#4-replace-mcpservers-with-mcp). |
| `middleware` | Use `beforeRequestMiddleware` and `afterRequestMiddleware`, or the `hooks` option of `createCopilotKitRuntimeHandler`. |

It warns one time in development for `observability_c`, `onError`, and `onStopGeneration`, which it ignores. To handle errors, pass `hooks: { onError }` to `createCopilotKitRuntimeHandler`.

### `_setOverride` in Angular

`CopilotChatConfiguration` has no `_setOverride` in 2.0. A call of `_setOverride` throws. If a subclass overrides it, a warning shows one time in development, because 2.0 does not call it. Move the code into overrides of `setActiveThreadId` and `startNewThread`. See [Chat configuration](/migrate/chat-2.0#chat-configuration).

## Runtime

| Removed | Use |
| --- | --- |
| `BasicAgent` | `BuiltInAgent` from `@copilotkit/runtime/agent` |
| `BasicAgentConfiguration` | `BuiltInAgentClassicConfig` from `@copilotkit/runtime/agent` |
| `createNodeFetchHandler` from `@copilotkit/runtime/node` | `createCopilotKitNodeHandler` |
| `CopilotKitRequestHandler` | `CopilotKitRuntimeFetchHandler` |

`createCopilotKitNodeHandler` takes the same arguments as `createNodeFetchHandler`. For the `BuiltInAgent` options, see [Runtime HTTP handlers in 2.0](/migrate/runtime-2.0).

`CopilotKitRuntimeFetchHandler` takes the `Request` directly. Remove the `{ request }` object from each call:

```ts ignore title="Before"
import type { CopilotKitRequestHandler } from "@copilotkit/runtime";

export function forward(handler: CopilotKitRequestHandler, request: Request) {
  return handler({ request });
}
```

```ts title="After"
import type { CopilotKitRuntimeFetchHandler } from "@copilotkit/runtime";

export function forward(handler: CopilotKitRuntimeFetchHandler, request: Request) {
  return handler(request);
}
```

## React and Vue

### `showDevConsole`

The `showDevConsole` prop on `CopilotKitProvider` had no effect. Delete it. The codemod deletes it in React files. In Vue templates, delete it yourself.

To turn the Inspector on or off, set `enableInspector`:

```tsx
"use client";
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" enableInspector={false}>
      {children}
    </CopilotKitProvider>
  );
}
```

### `disclaimer` on `CopilotChatView`

Move `disclaimer` into the `input` slot:

```tsx ignore title="Before"
<CopilotChatView disclaimer={MyDisclaimer} />
```

```tsx title="After"
import { CopilotChatView } from "@copilotkit/react-core";

function MyDisclaimer() {
  return <p>Answers can contain mistakes.</p>;
}

export function Chat() {
  return <CopilotChatView input={{ disclaimer: MyDisclaimer }} />;
}
```

### `routes` in learning options

The `routes` option had no effect, because capture keeps the raw URLs. Delete it from the `learning` prop and from `createCollector` options:

```tsx ignore title="Before"
<CopilotKitProvider
  runtimeUrl="/api/copilotkit"
  learning={{ routes: ["/deals/:id"], ignoreUrls: ["/health"] }}
>
```

```tsx title="After"
"use client";
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" learning={{ ignoreUrls: ["/health"] }}>
      {children}
    </CopilotKitProvider>
  );
}
```

## A2UI renderer

2.0 does not publish `@copilotkit/a2ui-renderer`, so all of its exports are removed, for example `useA2UIStore`, `useA2UIContext`, `createA2UICatalog`, `createCatalog` and `A2UIRenderer`. The provider renders A2UI with [components and surfaces](/generative-ui/components). Move each catalog to `createGenerativeUI`:

{/* kiira: ignore, the before code of a migration: @copilotkit/a2ui-renderer is not published for 2.0 */}
```tsx ignore title="Before"
import { createA2UICatalog } from "@copilotkit/a2ui-renderer";
import { z } from "zod";

export const catalog = createA2UICatalog(
  {
    StatusBadge: {
      description: "A small pill that shows a status.",
      props: z.object({ text: z.string() }),
      render: ({ props }) => <span>{props.text}</span>,
    },
  },
  { includeBasicCatalog: true },
);
```

```tsx title="After"
import { z } from "zod";
import {
  createGenerativeUI,
  standardUI,
} from "@copilotkit/react-core/generative-ui";

export const appUI = createGenerativeUI({
  id: "acme/app@1",
  extends: [standardUI],
  components: {
    StatusBadge: {
      component: ({ text }: { text: string }) => <span>{text}</span>,
      description: "A small pill that shows a status.",
      props: z.object({ text: z.string() }),
    },
  },
});
```

Pass it to the provider with `generativeUI={{ ui: appUI }}`. See [Adopt from A2UI](/generative-ui/components/from-a2ui) for the provider, the runtime, and agents that write A2UI v0.9.

## Message types from `@copilotkit/shared`

`ImageData` is removed. To send an image to the agent, put an `ImageInputPart` in the `content` of the user message:

```ts ignore title="Before"
import type { ImageData } from "@copilotkit/shared";

const image: ImageData = { format: "png", bytes: base64 };
```

```ts title="After"
import type { ImageInputPart } from "@copilotkit/shared";

export function pngPart(base64: string): ImageInputPart {
  return {
    type: "image",
    source: { type: "data", value: base64, mimeType: "image/png" },
  };
}
```

The `image` field on `AIMessage` is also removed. An assistant message carries text in `content`. To let users attach images in the chat, see [multimodal attachments](/multimodal-attachments).

## Web inspector

The `headers` property of the `cpk-thread-inspector` element is removed. Set `resolveHeaders` instead. The inspector calls it before each request, so a refreshed token is always used:

```ts
import { THREAD_INSPECTOR_TAG, type CpkThreadInspector } from "@copilotkit/web-inspector";

export function setInspectorToken(getToken: () => string) {
  const inspector = document.querySelector<CpkThreadInspector>(THREAD_INSPECTOR_TAG);
  if (inspector) {
    inspector.resolveHeaders = () => ({ Authorization: `Bearer ${getToken()}` });
  }
}
```
