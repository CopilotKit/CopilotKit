---
title: Chat UI in 2.0
description: Replace removed chat exports, update full label objects and repeated tool registrations, and check the default text and behavior that changed in the chat input, the audio recorder, the sidebar, and attachment previews.
---

In 2.0, an import from `@copilotkit/react-core`, `@copilotkit/vue`, or `@copilotkit/core` can fail, or a type check can fail. The Vue and Angular chat can also show different text or act differently. The cause is one of these changes:

- Some chat exports and icon packages are removed.
- The `CopilotChatLabels` type has more keys.
- `CopilotKitCore.addTool` lets a newer tool replace an older tool with the same name.
- Vue and Angular use the same default text and chat rules as React.
- React, Vue, and Angular share one chat input, audio recorder, docked sidebar, and attachment preview.

The codemod changes only the Angular text box subclass in [Angular text box](#angular-text-box). For the other changes, use the sections below.

## Removed exports

| Removed | Package | Use instead |
| --- | --- | --- |
| `BasicMarkdownRenderer` | `@copilotkit/react-core` | `StreamingMarkdownDefaultRenderer` |
| `BasicMarkdown` | `@copilotkit/vue` | `StreamingMarkdownDefault` |
| `parseMarkdown`, `MarkdownToken`, `MarkdownTokenList`, `ParseMarkdownOptions`, `Tokens` | `@copilotkit/core` and `@copilotkit/react-core` | [`@copilotkit/markdown`](/reference/packages/markdown) |
| `useLearningContainers`, `useLearningContainersInCurrentThread` | `@copilotkit/react-core` | `getLearningContainerId` on `CopilotKitIntelligence` |

The streaming renderers take the same `content` prop as the removed renderers:

```tsx ignore title="Before"
import { BasicMarkdownRenderer } from "@copilotkit/react-core";

export function Draft({ text }: { text: string }) {
  return <BasicMarkdownRenderer content={text} />;
}
```

```tsx title="After"
import { StreamingMarkdownDefaultRenderer } from "@copilotkit/react-core";

export function Draft({ text }: { text: string }) {
  return <StreamingMarkdownDefaultRenderer content={text} />;
}
```

## Icon packages

The chat draws its icons from inline SVG data. As a result, CopilotKit no longer installs `lucide-react` or `lucide-vue-next` for your app.

If your app imports one of these packages, add it to your own dependencies:

```bash
npm install lucide-react
```

## Label type

`CopilotChatLabels` has more keys in 2.0. React, Vue, and Angular now share one label set, and the text that the chat used to hard-code is now a label.

A partial override still works. Code that builds a complete `CopilotChatLabels` object fails to type-check until the object has the new keys. To fix this, start from the default labels and override only the keys that you need:

```ts title="After"
import { CopilotChatDefaultLabels } from "@copilotkit/core";
import type { CopilotChatLabels } from "@copilotkit/core";

export const labels: CopilotChatLabels = {
  ...CopilotChatDefaultLabels,
  chatInputPlaceholder: "Ask me anything...",
};
```

In Vue, the values of `CopilotChatDefaultLabels` now have the type `string`, not literal string types.

All label keys are in [CopilotChatLabels](/reference/hooks/useCopilotChatConfiguration#copilotchatlabels).

## Tool registration

`CopilotKitCore.addTool` now returns a function that removes this registration. If a tool with the same name and `agentId` is already registered, the newer tool is active. In 1.x, the second call did nothing. When you call the returned function, the earlier tool is active again.

If your code calls `addTool` twice with the same name and expects the first tool to stay active, remove the second call. To remove one registration, call the function that `addTool` returns:

```ts title="After"
import { CopilotKitCore } from "@copilotkit/core";
import { z } from "zod";

const copilotkit = new CopilotKitCore({ runtimeUrl: "/api/copilotkit" });

const removeSearch = copilotkit.addTool({
  name: "search",
  description: "Search the docs",
  parameters: z.object({ query: z.string() }),
  handler: async ({ query }) => `Results for ${query}`,
});

// Later, remove only this registration:
removeSearch();
```

`useFrontendTool` in React and Vue uses this function. When a component that replaces a provider tool unmounts, the provider tool is active again.

## Default text in Vue and Angular

Vue and Angular now show the same default text as React. These defaults changed:

| Label key | New default | Changed in |
| --- | --- | --- |
| `chatInputToolbarAddButtonLabel` | `"Add attachments"` | Vue, Angular |
| `userMessageToolbarPreviousBranchLabel` | `"Previous branch"` | Angular |
| `userMessageToolbarNextBranchLabel` | `"Next branch"` | Angular |
| `modalHeaderTitle` | `"CopilotKit Chat"` | Angular popup and sidebar |
| `chatToggleOpenLabel`, `chatToggleCloseLabel` | `"Open chat"`, `"Close chat"` | Angular popup and sidebar |

To keep the earlier text, set the label. For example, in Angular:

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotChatLabels } from "@copilotkit/angular";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotChatLabels({
      chatInputToolbarAddButtonLabel: "Add photos or files",
      modalHeaderTitle: "Copilot",
    }),
  ],
};
```

All label keys are in [CopilotChatLabels](/reference/hooks/useCopilotChatConfiguration#copilotchatlabels).

## Chat behavior in Vue and Angular

Vue and Angular now follow the same chat rules as React.

In Vue:

- **Enter during a run:** Enter with text in the input sends the message. Enter in an empty input stops the run.
- **Activity renderers:** A renderer with `activityType: "*"` draws every activity that has no renderer of its own.
- **Custom message renderers:** The chat tries each renderer in turn. The first renderer that returns content is used.

In Angular:

- **Stop button:** While the agent runs, the send button becomes a stop button.
- **Tool-call renderers:** The chat uses a renderer from another agent when no renderer for the current agent matches. A `"*"` renderer applies to all agents. A frontend tool for the current agent comes before a global renderer with the same name.
- **Removing a renderer:** When a component that called `registerRenderToolCall` is destroyed, only its renderer is removed. Tools with the same name stay registered.

If a test or a screenshot depends on the earlier behavior, update it to the behavior above.

## Angular text box

`CopilotChatTextarea` no longer has an `ngAfterViewInit()` method. The text box measures its height after each render. It also measures again when `inputMaxRows` changes.

If your component extends `CopilotChatTextarea`, a call to `super.ngAfterViewInit()` fails to type-check. The codemod deletes the call and removes `override` from your method:

```ts ignore title="Before"
import { Component } from "@angular/core";
import { CopilotChatTextarea } from "@copilotkit/angular";

@Component({ selector: "textarea[appTextarea]", template: "" })
export class AppTextarea extends CopilotChatTextarea {
  override ngAfterViewInit(): void {
    super.ngAfterViewInit();
    console.log("ready");
  }
}
```

```ts title="After"
import { Component } from "@angular/core";
import { CopilotChatTextarea } from "@copilotkit/angular";

@Component({ selector: "textarea[appTextarea]", template: "" })
export class AppTextarea extends CopilotChatTextarea {
  ngAfterViewInit(): void {
    console.log("ready");
  }
}
```

## Audio recorder

All three packages use one recorder. `AudioRecorderError` is the same class in `@copilotkit/react-core`, `@copilotkit/vue`, and `@copilotkit/angular`, so `instanceof` works for an error from any of them.

These rules changed:

- **A second `start()` rejects.** While the recorder starts or records, `start()` rejects with an `AudioRecorderError` that has the message `"Recorder is already active"`. In Angular, `start()` returned without an error. In React and Vue, a second call during the microphone prompt opened a second stream.
- **Angular `error` output:** It now emits for every failure of `start()` and `stop()`. This includes `"No active recording"` when you call `stop()` and nothing records.

If your Angular code calls `start()` on a recorder that can already record, do one of these:

1. Call `start()` only when `getState()` returns `"idle"`.
2. Catch the rejection.

```ts title="After"
import type { CopilotChatAudioRecorder } from "@copilotkit/angular";

export async function startRecording(recorder: CopilotChatAudioRecorder) {
  if (recorder.getState() !== "idle") return;
  await recorder.start();
}
```

## Docked sidebar

The docked sidebar adds an inline margin to `document.body` on its side. In 2.0, React and Vue use the same rules as Angular:

- **One owner:** Only one open docked sidebar on a page adds the margin. A second one logs a warning and adds no margin.
- **Margins come back:** When the sidebar closes or unmounts, the body gets back the margins that it had before. React set them to `""`.
- **Viewport changes:** The margin goes away when the viewport becomes 767px or narrower, and comes back when it becomes wider. If the browser has no `matchMedia`, the sidebar docks. React did not dock without `matchMedia`, for example in jsdom tests.
- **Vue server rendering:** Vue sets the margin when the sidebar mounts. The server-rendered HTML has no margin and no `<style>` element for it.

In Angular, the sidebar becomes a modal at `(max-width: 767px)`. Before, the breakpoint was `47.999rem`, which moved with the root font size.

If a test expects no body margin in jsdom, or reads the margin from a `<style>` element, update it to read `document.body.style`.

## Slash commands in React

The slash menu lists only menu items that have an `action`. A group with no items, such as `{ label: "Tools", items: [] }`, is not listed. Vue already worked this way.

## Attachment previews

In React, the preview that opens from an attachment is now a modal dialog, as in Vue and Angular:

- The dialog has the file name as its accessible name.
- Focus moves to the close button when the preview opens.
- Tab and Shift+Tab stay inside the preview.
- Focus goes back to the element that opened the preview when it closes.

In React and Vue, a text attachment shows its base64 data decoded as UTF-8. Before, characters outside ASCII showed incorrectly.

If a test reads `document.activeElement` after it opens a preview, update it to expect the close button.

## Scroll to bottom in Angular

`StickToBottom` and `ScrollPosition` now count 12px or less from the end as the bottom. Before, the default was 10px. Vue uses 12px.

To keep 10px, set the threshold:

```html title="chat.component.html"
<div copilotStickToBottom [threshold]="10">
  <!-- messages -->
</div>
```
