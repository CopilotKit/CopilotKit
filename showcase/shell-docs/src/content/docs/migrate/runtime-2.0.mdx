---
title: Runtime HTTP handlers in 2.0
description: Replace the Express and Hono runtime adapters with Fetch and Node handlers in CopilotKit 2.0, move the Built-in Agent to TanStack AI, and update license checks and the Node.js version.
---

CopilotKit 2.0 removes the runtime's Express and Hono adapters, their deprecated
aliases, and the `/express` and `/hono` entry points. The runtime accepts standard
Fetch requests or Node HTTP requests. Applications can still use Express or Hono
as their host framework.

This guide applies to **2.0**. Apps pinned to CopilotKit 1.x can keep their existing
adapters until they upgrade. Run `npx codemod @copilotkit/v2-migration` before the
upgrade. The codemod migrates common Express mounts, Hono mounts, and Next.js
`handle(endpoint)` wrappers automatically. It preserves aliases, single-route
mode, explicit CORS defaults, and request URLs. Express mounts receive an
app-owned router around the Node listener so unmatched requests still reach later
middleware. Hono mounts call the Fetch handler directly.

Cases requiring application knowledge receive a `TODO(copilotkit-2.0)`: router
customization, exported app objects, dynamic options, and custom CORS callbacks.
Express CORS configurations that implicitly reflect requested headers also require
manual migration. The codemod leaves the application's framework dependencies in
place because other routes may use them.

## Fetch and Next.js

Replace `createCopilotHonoHandler` or `createCopilotEndpoint` with
`createCopilotKitRuntimeHandler`. It returns a function, not a Hono app. Remove
`handle(app)` from `hono/vercel` and calls to `app.fetch(request)`.

```ts
import { CopilotKitRuntime, createCopilotKitRuntimeHandler } from "@copilotkit/runtime";

const runtime = new CopilotKitRuntime({ agents: {} }); // Supply your agents.
const handler = createCopilotKitRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
export const OPTIONS = handler;
```

For Bun, use `Bun.serve({ fetch: handler })`. For an existing Hono application,
mount a route that passes the raw request to the handler:

```ts
import { Hono } from "hono";
import { CopilotKitRuntime, createCopilotKitRuntimeHandler } from "@copilotkit/runtime";

const runtime = new CopilotKitRuntime({ agents: {} }); // Supply your agents.
const handler = createCopilotKitRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});

const app = new Hono();
app.all("/api/copilotkit/*", (c) => handler(c.req.raw));
```

## Node and Express

Replace `createCopilotExpressHandler` or `createCopilotEndpointExpress` with
`createCopilotKitNodeListener` from `@copilotkit/runtime/node`.

```ts
import { createServer } from "node:http";
import { CopilotKitRuntime } from "@copilotkit/runtime";
import { createCopilotKitNodeListener } from "@copilotkit/runtime/node";

const runtime = new CopilotKitRuntime({ agents: {} }); // Supply your agents.
const listener = createCopilotKitNodeListener({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});
createServer(listener).listen(4000);
```

In an Express app, mount it under the desired prefix and use a base path relative
to that mount. Express strips the mount prefix from `req.url`:

```ts
import express from "express";
import { CopilotKitRuntime } from "@copilotkit/runtime";
import { createCopilotKitNodeListener } from "@copilotkit/runtime/node";

const runtime = new CopilotKitRuntime({ agents: {} }); // Supply your agents.
const app = express();

app.use(
  "/api/copilotkit",
  createCopilotKitNodeListener({
    runtime,
    basePath: "/",
    cors: true,
  }),
);
app.listen(4000);
```

The listener is not an Express router: move `.use()`, `.get()`, and other router
configuration to the application's own router. Mount it only on the runtime
path; unmatched requests return a runtime 404 rather than calling `next()`.
Existing `express.json()` body parsing is supported.

## Single-route endpoints

For `createCopilotEndpointSingleRoute`, use `createCopilotKitRuntimeHandler` with
`mode: "single-route"`. For `createCopilotEndpointSingleRouteExpress`, use
`createCopilotKitNodeListener` with the same option. Keep the frontend's
`useSingleEndpoint` setting and the existing endpoint URL.

The generated Hono wildcard mount covers the base path and its descendants;
the Fetch handler validates the endpoint path and single-route envelope.

## Renamed runtime exports

The 2.0 release candidates named some runtime exports without "Kit". The old
names still work, but they are deprecated. The codemod renames them.

| Deprecated name               | Name to use                      |
| ----------------------------- | -------------------------------- |
| `CopilotRuntime`              | `CopilotKitRuntime`              |
| `createCopilotRuntimeHandler` | `createCopilotKitRuntimeHandler` |
| `createCopilotNodeListener`   | `createCopilotKitNodeListener`   |
| `createCopilotNodeHandler`    | `createCopilotKitNodeHandler`    |
| `CopilotSseRuntime`           | `CopilotKitSseRuntime`           |

The same rule applies to the other runtime exports named `Copilot...`, for
example `CopilotRuntimeOptions` (`CopilotKitRuntimeOptions`),
`CopilotRuntimeFetchHandler` (`CopilotKitRuntimeFetchHandler`), and
`NodeCopilotListener` (`NodeCopilotKitListener`).

## CORS and lifecycle

The generic handlers default to no CORS. Pass `cors: true` to retain the old
adapters' permissive default, or provide a `CopilotKitCorsConfig`. Express `cors`
options are not accepted: `methods`, `allowedHeaders`, and `exposedHeaders` become
`allowMethods`, `allowHeaders`, and `exposeHeaders`. Origin callbacks return a
string or `null` synchronously; they do not receive an Express callback or Hono
context. Use an explicit allowed origin when sending credentials.

The Fetch handler creates its channel controls lazily and opens no connection at
creation. On a long-running host, call `await handler.channels?.ready()` at startup
if the runtime declares channels. Do not start persistent channels in a
serverless route. The Node listener starts declared channels automatically;
`listener.channels?.ready()` waits for that startup.

## License checker

`runtime.licenseChecker` is removed. Call `await runtime.getLicenseChecker()`
instead. The runtime now verifies the license on first use, not when you create
the runtime. As a result, license warnings print on the first `/info` request,
not at startup.

```ts
import { CopilotKitRuntime } from "@copilotkit/runtime";

const runtime = new CopilotKitRuntime({ agents: {} }); // Supply your agents.

export async function licenseStatus() {
  const checker = await runtime.getLicenseChecker?.();
  return checker?.getStatus();
}
```

`getLicenseChecker()` returns `undefined` when the runtime does not use
Intelligence. The codemod adds a `TODO(copilotkit-2.0)` to each read of
`licenseChecker`. It does not rewrite the read, because the new method is async.

## Node.js version

`@copilotkit/runtime` requires Node.js `^20.19.3` or `>=22.13.0`. Node.js 21 is
not supported. If your server or CI uses an earlier version, upgrade Node.js
before you upgrade CopilotKit.

## Debug logs

With `debug: true`, the runtime writes its debug logs as JSON lines. In 1.x it
formatted them with `pino-pretty`, which needs Node streams and does not run on
edge runtimes. To read the logs formatted, pipe your server output through
`npx pino-pretty`.

If your code calls `runtime.debugLogger` (type `CopilotKitRuntimeLogger`), it has
only these methods in 2.0:

- `debug`, `info`, `warn`, and `error`. Each one takes `(msg)` or `(obj, msg)`.
- `child(bindings)`. It returns a logger that adds `bindings` to each line. It
  is optional on the type, because a logger that you pass as `logger` may not
  have it.

Other pino `Logger` methods and fields are not available, for example `trace`,
`fatal`, `level`, and `flush`. If your code uses them, change it to use the
methods above. The `LOG_LEVEL` environment variable still sets the log level.

In 2.0 you can also pass your own logger, for example pino, as `logger`. See
[Sending logs to your own logger](/backend/copilot-runtime#sending-logs-to-your-own-logger).

## Built-in Agent

In 2.0, `BuiltInAgent` imports from `@copilotkit/runtime/agent`, and it calls the
model with [TanStack AI](https://tanstack.com/ai). `model` takes a TanStack AI
text adapter, such as `openaiText("gpt-5")`. The adapter holds the API key and
the base URL. The runtime does not install the model packages, so your app
installs the ones it uses.

The codemod (`npx codemod @copilotkit/v2-migration`) does this for you:

- It moves `BuiltInAgent`, `defineTool`, and the other agent exports from
  `@copilotkit/runtime` and `@copilotkit/runtime/v2` to
  `@copilotkit/runtime/agent`.
- It moves the AI SDK helpers, such as `convertMessagesToVercelAISDKMessages`, to
  `@copilotkit/runtime/agent/ai-sdk`.
- It changes each `model` string for `openai`, `anthropic`, `google`, `gemini`,
  `google-gemini`, and `vertex` to its adapter, and it adds the adapter import.
- It changes `maxRetries: 3` to `retry: { maxRetries: 3 }`.

1.x:

```typescript ignore
import { BuiltInAgent } from "@copilotkit/runtime";

const agent = new BuiltInAgent({ model: "openai/gpt-5" });
```

2.0, after the codemod:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({ model: openaiText("gpt-5") });
```

The codemod does not install packages. It adds a `TODO(copilotkit-2.0)` comment
with a docs link for each item that needs your decision:

- A `model` that it cannot change: a MiniMax string, a value from a variable,
  or an AI SDK model.
- `apiKey` and `urlDownload`.
- The sampling options and `providerOptions`. The comment tells you to use
  `modelOptions`.
- `mcpServers` and imports of `MCPClientConfig`. The comment tells you to create
  each client with `createMCPClient` and pass it in `mcp: { clients: [client] }`.
- Imports of the removed `resolveModel`, `classifyModelSpec`,
  `BuiltInAgentModel`, `ModelSpecifier`, `MCPClient`, and `MCPTransport`.

Do these steps:

1. Install the packages.
2. Replace the models that the codemod did not change.
3. Move API keys and base URLs to the adapter.
4. Replace `mcpServers` with `mcp`.
5. Move provider options to `modelOptions` and `reasoning`.

### 1. Install the packages

The runtime installs `@tanstack/ai`. Install the adapter package for each provider that you use:

```npm
npm install @tanstack/ai-openai
```

| Adapter                                         | Package                          |
| ----------------------------------------------- | -------------------------------- |
| `openaiText`, `createOpenaiChat`                | `@tanstack/ai-openai`            |
| `openaiCompatibleText` (MiniMax, OpenRouter)    | `@tanstack/ai-openai/compatible` |
| `anthropicText`, `createAnthropicChat`          | `@tanstack/ai-anthropic`         |
| `geminiText`, `createGeminiChat`                | `@tanstack/ai-gemini`            |
| `vertexText`                                    | `@tanstack/ai-vertex`            |

`@tanstack/ai-openai/compatible` is part of the `@tanstack/ai-openai` package.

Also install these packages if your code needs them:

- `@tanstack/ai-mcp`: if an agent connects to MCP servers.
- `ai`: if your code imports from `@copilotkit/runtime/agent/ai-sdk`.

Remove the `@ai-sdk/*` packages that your code no longer imports.

### 2. Replace the remaining models

A model string throws when you create the agent. Replace each `model` that has
a TODO with an adapter.

For a model name from a variable, pick the adapter in your code:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { anthropicText } from "@tanstack/ai-anthropic";

const model =
  process.env.MODEL_PROVIDER === "anthropic"
    ? anthropicText("claude-sonnet-4-6")
    : openaiText("gpt-5");

const agent = new BuiltInAgent({ model });
```

For MiniMax, use `openaiCompatibleText`. The next step shows it.

An AI SDK model, such as `openai("gpt-5")` from `@ai-sdk/openai`, also throws.
Replace it with the TanStack AI adapter for the same model, such as
`openaiText("gpt-5")`. To keep the AI SDK model, write the `streamText()` call
in a `type: "aisdk"` factory:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { convertMessagesToVercelAISDKMessages } from "@copilotkit/runtime/agent/ai-sdk";
import { openai } from "@ai-sdk/openai";
import { streamText } from "ai";

const agent = new BuiltInAgent({
  type: "aisdk",
  factory: ({ input, abortSignal }) =>
    streamText({
      model: openai("gpt-5"),
      messages: convertMessagesToVercelAISDKMessages(input.messages),
      abortSignal,
    }),
});
```

In a factory, you add the tools yourself. See [Use any model router](/backend/custom-agent).

### 3. Move API keys and base URLs to the adapter

The agent has no `apiKey` option. Each adapter reads its own key from the
environment: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GOOGLE_API_KEY`. If the
key is in the environment, delete `apiKey`.

To pass the key yourself, use the `create*` helper of the adapter package:

1.x:

```typescript ignore
import { BuiltInAgent } from "@copilotkit/runtime";

const agent = new BuiltInAgent({
  model: "openai/gpt-5",
  apiKey: process.env.MY_OPENAI_KEY,
});
```

2.0:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { createOpenaiChat } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({
  model: createOpenaiChat("gpt-5", process.env.MY_OPENAI_KEY!),
});
```

CopilotKit no longer reads the base URL variables. Pass each value to the
adapter:

| 1.x                                         | 2.0                                                    |
| ------------------------------------------- | ------------------------------------------------------ |
| `OPENAI_BASE_URL`, OpenAI or Azure host     | `openaiText(model, { baseURL })`                       |
| `OPENAI_BASE_URL`, any other host           | `openaiCompatibleText(model, { baseURL, apiKey })`     |
| `COPILOTKIT_OPENAI_API=chat`                | `openaiChatCompletions(model, { baseURL })`            |
| `ANTHROPIC_BASE_URL`                        | `anthropicText(model, { baseURL })`                    |
| `GOOGLE_GENERATIVE_AI_BASE_URL`             | `geminiText(model, { baseURL, apiVersion: "" })`       |

Two of these values change:

- Anthropic: remove the `/v1` at the end of the URL. The adapter adds
  `/v1/messages`.
- Gemini: keep the API version at the end of the URL. `apiVersion: ""` stops the
  adapter from adding a second version segment.

MiniMax used `MINIMAX_API_KEY` and `MINIMAX_BASE_URL`. Pass both to
`openaiCompatibleText`:

1.x:

```typescript ignore
import { BuiltInAgent } from "@copilotkit/runtime";

const agent = new BuiltInAgent({ model: "minimax/MiniMax-M3" });
```

2.0:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiCompatibleText } from "@tanstack/ai-openai/compatible";

const agent = new BuiltInAgent({
  model: openaiCompatibleText("MiniMax-M3", {
    baseURL: process.env.MINIMAX_BASE_URL ?? "https://api.minimax.io/v1",
    apiKey: process.env.MINIMAX_API_KEY!,
  }),
});
```

See [Configure the provider](/model-selection#configure-the-provider) for the
other adapter options.

### 4. Replace `mcpServers` with `mcp`

The agent no longer opens MCP connections. Create a client for each server with
`createMCPClient` from `@tanstack/ai-mcp` (you installed it in step 1). Pass the
clients in `mcp: { clients: [client] }`:

1.x:

```typescript ignore
import { BuiltInAgent } from "@copilotkit/runtime";

const agent = new BuiltInAgent({
  model: "openai/gpt-5",
  mcpServers: [{ type: "http", url: "https://mcp.example.com/mcp" }],
});
```

2.0:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";
import { createMCPClient } from "@tanstack/ai-mcp";

const client = await createMCPClient({
  transport: { type: "http", url: "https://mcp.example.com/mcp" },
});

const agent = new BuiltInAgent({
  model: openaiText("gpt-5"),
  mcp: { clients: [client] },
});
```

Make these changes too:

- The agent keeps the client open between runs (`connection` is
  `"keep-alive"` by default). The agent does not close it, so call
  `await client.close()` when your server shuts down.
- `headers` and `fetch` move into `transport`.
- `name` is gone. If two tools have the same name, the run fails. This applies
  to tools from two clients, and to a client tool and a tool in `tools`.
  To give every tool of a client a prefix, set `prefix` on `createMCPClient`.
- `MCPClientConfig`, `MCPClient`, and `MCPTransport` are no longer exported. If
  you need the MCP types, import them from `@tanstack/ai-mcp`.

See [MCP Servers](/mcp-servers).

### 5. Move provider options to `modelOptions` and `reasoning`

These options are removed: `temperature`, `maxOutputTokens`, `topP`, `topK`,
`presencePenalty`, `frequencyPenalty`, `stopSequences`, `seed`, and
`providerOptions`. Put the provider's own option names in `modelOptions`. Put
the reasoning effort in `reasoning`:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({
  model: openaiText("gpt-5"),
  // Was: maxOutputTokens: 1000, providerOptions: { openai: { reasoningEffort: "low" } }
  modelOptions: { max_output_tokens: 1000 },
  reasoning: { level: "low" },
});
```

The adapter in `model` gives the types. `modelOptions` takes only the options
of that provider. `reasoning.level` takes only the levels of that model.

Make these changes too:

- `maxRetries`: write `retry: { maxRetries: 3 }`. The codemod does this for
  you.
- `overridableProperties`: you can list `model`, `toolChoice`, `prompt`, and
  `modelOptions`. Replace a removed option name with `modelOptions`.
- `toolChoice`: write `{ type: "tool", name: "searchDocs" }`, not `toolName`.
- `urlDownload`: delete it. The server no longer downloads attachment URLs. The
  agent sends each URL to the provider.

In an AI SDK factory, you can still let the AI SDK download URLs. Pass
`createSafeUrlDownload({ signal: ctx.abortSignal })` from
`@copilotkit/runtime/agent/ai-sdk` as `experimental_download`.

The agent also takes other TanStack AI `chat()` options, such as `promptCache`,
`middleware`, `systemPrompts`, and `agentLoopStrategy`. See
[Advanced Configuration](/advanced-configuration).

### If you used `resolveModel` or `classifyModelSpec`

Both exports are removed, because the agent no longer reads model strings.

- To build a model, call the adapter directly, for example
  `anthropicText("claude-sonnet-4-6")`.
- To let the frontend switch the model, use the `resolveModel` option of the
  agent. It turns a model name from the frontend into an adapter:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const agent = new BuiltInAgent({
  model: openaiText("gpt-5"),
  overridableProperties: ["model"],
  resolveModel: (name) => (name === "fast" ? openaiText("gpt-5-mini") : undefined),
});
```

If `resolveModel` returns `undefined`, or the agent has no `resolveModel`, the
run uses `model` and logs one warning. See
[Switch models from the frontend](/model-selection#switch-models-from-the-frontend).

### Other changes to check

Model providers:

- A missing API key fails when you create the adapter, at server start. The
  error names the environment variable to set.
- `openaiText` always uses the Responses API.

Messages:

- With `forwardSystemMessages` or `forwardDeveloperMessages`, the forwarded
  messages become system prompts after the agent's `prompt`.
- If `overridableProperties` lists `prompt`, a `prompt` in `forwardedProps`
  replaces the agent's prompt for that run.

Tools:

- `defineTool` takes the same arguments as in 1.x. It returns a TanStack AI
  server tool, so the tool also works in your own `chat()` call.
- `tools` also takes TanStack AI tools and provider tools. See
  [Server Tools](/server-tools).
- In a factory, `ctx.learnedSkills.tools` is an array of TanStack AI tools. For
  `streamText()`, convert it with `toAISDKTools` from
  `@copilotkit/runtime/agent/ai-sdk`. See [Skill delivery](/intelligence/learned-skills#factory-mode).

## Dependency cleanup

Remove `hono`, `@hono/node-server`, `express`, and `cors` from your app only if your
own host code no longer uses them. CopilotKit no longer directly depends on these
framework adapters, but the MCP SDK and MCP middleware can still install Express
and Hono transitively.
