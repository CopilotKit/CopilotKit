---
title: Runtime HTTP handlers in 2.0
description: Replace the Express and Hono runtime adapters with Fetch and Node handlers in CopilotKit 2.0, move classic BuiltInAgent configs to tanstackAIAgent or aiSdkAgent, and update license checks and the Node.js version.
---

CopilotKit 2.0 removes the runtime's Express and Hono adapters, their deprecated
aliases, and the `/express` and `/hono` entry points. The runtime accepts standard
Fetch requests or Node HTTP requests. Applications can still use Express or Hono
as their host framework.

This guide applies to **2.0**. Apps pinned to CopilotKit 1.x can keep their existing
adapters until they upgrade. Run `npx codemod @copilotkit/v2-migration` before the
upgrade. The codemod migrates common Express mounts, Hono mounts, and Next.js
`handle(endpoint)` wrappers automatically. It preserves aliases, single-route
mode, explicit CORS defaults, and request URLs. Express mounts receive an
app-owned router around the Node listener so unmatched requests still reach later
middleware. Hono mounts call the Fetch handler directly.

Cases requiring application knowledge receive a `TODO(copilotkit-2.0)`: router
customization, exported app objects, dynamic options, and custom CORS callbacks.
Express CORS configurations that implicitly reflect requested headers also require
manual migration. The codemod leaves the application's framework dependencies in
place because other routes may use them.

## Fetch and Next.js

Replace `createCopilotHonoHandler` or `createCopilotEndpoint` with
`createCopilotRuntimeHandler`. It returns a function, not a Hono app. Remove
`handle(app)` from `hono/vercel` and calls to `app.fetch(request)`.

```ts
import { CopilotRuntime, createCopilotRuntimeHandler } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
export const OPTIONS = handler;
```

For Bun, use `Bun.serve({ fetch: handler })`. For an existing Hono application,
mount a route that passes the raw request to the handler:

```ts
import { Hono } from "hono";
import { CopilotRuntime, createCopilotRuntimeHandler } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});

const app = new Hono();
app.all("/api/copilotkit/*", (c) => handler(c.req.raw));
```

## Node and Express

Replace `createCopilotExpressHandler` or `createCopilotEndpointExpress` with
`createCopilotNodeListener` from `@copilotkit/runtime/node`.

```ts
import { createServer } from "node:http";
import { CopilotRuntime } from "@copilotkit/runtime";
import { createCopilotNodeListener } from "@copilotkit/runtime/node";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const listener = createCopilotNodeListener({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});
createServer(listener).listen(4000);
```

In an Express app, mount it under the desired prefix and use a base path relative
to that mount. Express strips the mount prefix from `req.url`:

```ts
import express from "express";
import { CopilotRuntime } from "@copilotkit/runtime";
import { createCopilotNodeListener } from "@copilotkit/runtime/node";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const app = express();

app.use(
  "/api/copilotkit",
  createCopilotNodeListener({
    runtime,
    basePath: "/",
    cors: true,
  }),
);
app.listen(4000);
```

The listener is not an Express router: move `.use()`, `.get()`, and other router
configuration to the application's own router. Mount it only on the runtime
path; unmatched requests return a runtime 404 rather than calling `next()`.
Existing `express.json()` body parsing is supported.

## Single-route endpoints

For `createCopilotEndpointSingleRoute`, use `createCopilotRuntimeHandler` with
`mode: "single-route"`. For `createCopilotEndpointSingleRouteExpress`, use
`createCopilotNodeListener` with the same option. Keep the frontend's
`useSingleEndpoint` setting and the existing endpoint URL.

The generated Hono wildcard mount covers the base path and its descendants;
the Fetch handler validates the endpoint path and single-route envelope.

## CORS and lifecycle

The generic handlers default to no CORS. Pass `cors: true` to retain the old
adapters' permissive default, or provide a `CopilotCorsConfig`. Express `cors`
options are not accepted: `methods`, `allowedHeaders`, and `exposedHeaders` become
`allowMethods`, `allowHeaders`, and `exposeHeaders`. Origin callbacks return a
string or `null` synchronously; they do not receive an Express callback or Hono
context. Use an explicit allowed origin when sending credentials.

The Fetch handler creates its channel controls lazily and opens no connection at
creation. On a long-running host, call `await handler.channels?.ready()` at startup
if the runtime declares channels. Do not start persistent channels in a
serverless route. The Node listener starts declared channels automatically;
`listener.channels?.ready()` waits for that startup.

## License checker

`runtime.licenseChecker` is removed. Call `await runtime.getLicenseChecker()`
instead. The runtime now verifies the license on first use, not when you create
the runtime. As a result, license warnings print on the first `/info` request,
not at startup.

```ts
import { CopilotRuntime } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.

export async function licenseStatus() {
  const checker = await runtime.getLicenseChecker?.();
  return checker?.getStatus();
}
```

`getLicenseChecker()` returns `undefined` when the runtime does not use
Intelligence. The codemod adds a `TODO(copilotkit-2.0)` to each read of
`licenseChecker`. It does not rewrite the read, because the new method is async.

## Classic `BuiltInAgent`

In 2.0, `new BuiltInAgent({ model: "openai/gpt-5.5" })` throws when you create
the agent. `BuiltInAgent` takes only a `factory`. For an agent that you
configure with options, use `tanstackAIAgent` from
`@copilotkit/runtime/tanstack-ai`. To stay on the AI SDK, use `aiSdkAgent` from
`@copilotkit/runtime/ai-sdk`.

1. Before you upgrade, run the codemod. It rewrites each classic call to
   `tanstackAIAgent` and adds the imports:

   ```bash
   npx codemod @copilotkit/v2-migration
   ```

2. Install TanStack AI and the adapter for your provider:

   ```npm
   npm install @tanstack/ai @tanstack/ai-openai
   ```

   For Anthropic, install `@tanstack/ai-anthropic`. For Gemini, install
   `@tanstack/ai-gemini`.

3. Search for `TODO(copilotkit-2.0)`. Fix each one with the
   [option mapping](#option-mapping).
4. Run your type check. The adapter accepts only the model ids in its own list.

`@copilotkit/runtime` does not install `ai`, `@ai-sdk/*`, or `@tanstack/ai`.
Your app installs the SDK that it uses.

### Before and after

```ts ignore title="Before"
import { BuiltInAgent, defineTool } from "@copilotkit/runtime";
import { z } from "zod";

const getWeather = defineTool({
  name: "getWeather",
  description: "Get the current weather for a city.",
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ city, forecast: "sunny" }),
});

export const agent = new BuiltInAgent({
  model: "openai/gpt-5.5",
  prompt: "You are a helpful assistant.",
  tools: [getWeather],
  maxSteps: 5,
  maxOutputTokens: 1024,
});
```

```ts title="After"
import { defineTool } from "@copilotkit/runtime";
import { tanstackAIAgent } from "@copilotkit/runtime/tanstack-ai";
import { openaiText } from "@tanstack/ai-openai";
import { z } from "zod";

const getWeather = defineTool({
  name: "getWeather",
  description: "Get the current weather for a city.",
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ city, forecast: "sunny" }),
});

export const agent = tanstackAIAgent({
  adapter: () => openaiText("gpt-5.5"),
  prompt: "You are a helpful assistant.",
  tools: [getWeather],
  maxIterations: 5,
  modelOptions: { max_output_tokens: 1024 },
});
```

- The adapter reads `OPENAI_API_KEY` when you create it. The function form
  creates the adapter on the first run, so a missing key fails the run and not
  the import.
- `adapter` also accepts the adapter itself: `adapter: openaiText("gpt-5.5")`.
  This form reads the key when the file loads.
- `defineTool` tools, including tools with `interrupt: true`, do not change.
- If you do not set `maxIterations`, a run takes up to 5 model turns, or 10
  with learned skills.

### Stay on the AI SDK

`aiSdkAgent` keeps the classic option names. Replace the model string with a
model from an AI SDK provider package:

```npm
npm install ai @ai-sdk/openai
```

```ts title="AI SDK"
import { openai } from "@ai-sdk/openai";
import { defineTool } from "@copilotkit/runtime";
import { aiSdkAgent } from "@copilotkit/runtime/ai-sdk";
import { z } from "zod";

const getWeather = defineTool({
  name: "getWeather",
  description: "Get the current weather for a city.",
  parameters: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ city, forecast: "sunny" }),
});

export const agent = aiSdkAgent({
  model: openai("gpt-5.5"),
  prompt: "You are a helpful assistant.",
  tools: [getWeather],
  maxSteps: 5,
  maxOutputTokens: 1024,
});
```

`aiSdkAgent` works with `ai` 6 and `ai` 7.

### Option mapping

| Classic option | `tanstackAIAgent` | `aiSdkAgent` |
| --- | --- | --- |
| `model: "openai/gpt-5.5"` | `adapter: () => openaiText("gpt-5.5")` from `@tanstack/ai-openai` | `model: openai("gpt-5.5")` from `@ai-sdk/openai` |
| `model: "anthropic/claude-sonnet-4-6"` | `adapter: () => anthropicText("claude-sonnet-4-6")` from `@tanstack/ai-anthropic` | `model: anthropic("claude-sonnet-4-6")` from `@ai-sdk/anthropic` |
| `model: "google/gemini-3.5-flash"` | `adapter: () => geminiText("gemini-3.5-flash")` from `@tanstack/ai-gemini` | `model: google("gemini-3.5-flash")` from `@ai-sdk/google` |
| `maxSteps` | `maxIterations` | No change |
| `temperature`, `topP`, `maxOutputTokens`, and the other sampling options | `modelOptions`, with the names that the adapter uses (OpenAI: `top_p`, `max_output_tokens`) | No change |
| `apiKey` | An environment variable (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`), or the create function of the adapter: `createOpenaiChat("gpt-5.5", apiKey)` | `createOpenAI({ apiKey })("gpt-5.5")` |
| `prompt`, `tools`, `mcpServers`, `learnedSkills` | No change | No change |

Less common options:

| Classic option | `tanstackAIAgent` | `aiSdkAgent` |
| --- | --- | --- |
| `providerOptions` | `modelOptions`, without the provider key | No change |
| `toolChoice` | `toolChoice`. A named tool is `{ type: "tool", name }`. | No change |
| `maxRetries` | `retry: { maxRetries }` | No change |
| `mcpClients` | List the servers in `mcpServers`, or pass a TanStack AI MCP client in `mcp` | Return `client.tools()` from `tools: () => ...` |
| `"model"` in `overridableProperties` | Also list the adapters: `adapters: { fast: () => openaiText("gpt-5.4-mini") }` | Also list the models: `models: { fast: openai("gpt-5.4-mini") }` |
| Sampling options in `overridableProperties` | `"modelOptions"` | No change |
| `"prompt"` in `overridableProperties` | No replacement | No replacement |
| `urlDownload` | No option. Use `aiSdkAgent`. | No change |
| `forwardSystemMessages`, `forwardDeveloperMessages` | No change | No change |

With a model override, the client sends a name from `adapters` or `models`, for
example `forwardedProps: { model: "fast" }`. A name that is not in the list
keeps the default model.

### What the codemod leaves to you

The codemod adds a `TODO(copilotkit-2.0)` comment above:

- `apiKey`, `mcpClients`, and `urlDownload`.
- Sampling options, `providerOptions`, `toolChoice`, and `maxRetries`.
- `"model"` in `overridableProperties`.
- The `BasicAgentConfiguration` and `BuiltInAgentClassicConfig` types. Type the
  config with `Parameters<typeof tanstackAIAgent>[0]`.

For these calls, the codemod adds a TODO and keeps the `new BuiltInAgent` call:

- A model from a provider that has no TanStack AI adapter, such as `vertex/` or
  `minimax/`. Use `aiSdkAgent` with an AI SDK provider, for example
  `@ai-sdk/google-vertex`.
- A model that is not a string, for example a variable.

The codemod changes `gpt-5.4` to `gpt-5.5`, because the OpenAI adapter does not
list `gpt-5.4`.

### Factory agents

A `BuiltInAgent` with a `factory` keeps working. Make these changes:

- Import the AI SDK helpers, such as `convertMessagesToVercelAISDKMessages`,
  from `@copilotkit/runtime/ai-sdk`.
- Read `ctx.learnedSkills.definitions`, not `ctx.learnedSkills.tools`. Each
  definition is an SDK-neutral spec: `name`, `description`, `parameters`, and
  `execute`.
- Install `ai` and your provider package in your app.

To let CopilotKit build the messages, the tools, and the system prompt, call
`aiSdk(ctx)` in the factory. For TanStack AI, call `tanstackAI(ctx)`. Both
include the learned skills:

```ts
import { openai } from "@ai-sdk/openai";
import { BuiltInAgent } from "@copilotkit/runtime";
import { aiSdk } from "@copilotkit/runtime/ai-sdk";
import { stepCountIs, streamText } from "ai";

export const agent = new BuiltInAgent({
  type: "aisdk",
  factory: async (ctx) => {
    const base = await aiSdk(ctx, { prompt: "You are a helpful assistant." });
    return streamText({ ...base, model: openai("gpt-5.5"), stopWhen: stepCountIs(10) });
  },
});
```

The full list of removed and moved exports is in
[Removed deprecated APIs in 2.0](/migrate/removed-apis-2.0#classic-builtinagent).

## Node.js version

`@copilotkit/runtime` requires Node.js `^20.19.3` or `>=22.13.0`. Node.js 21 is
not supported. If your server or CI uses an earlier version, upgrade Node.js
before you upgrade CopilotKit.

## Dependency cleanup

Remove `hono`, `@hono/node-server`, `express`, and `cors` from your app only if your
own host code no longer uses them. CopilotKit no longer directly depends on these
framework adapters, but the MCP SDK and MCP middleware can still install Express
and Hono transitively.
