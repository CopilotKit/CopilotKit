---
title: Runtime HTTP handlers in 2.0
description: Replace the Express and Hono runtime adapters with Fetch and Node handlers in CopilotKit 2.0, move the Built-in Agent to TanStack AI, and update license checks and the Node.js version.
---

CopilotKit 2.0 removes the runtime's Express and Hono adapters, their deprecated
aliases, and the `/express` and `/hono` entry points. The runtime accepts standard
Fetch requests or Node HTTP requests. Applications can still use Express or Hono
as their host framework.

This guide applies to **2.0**. Apps pinned to CopilotKit 1.x can keep their existing
adapters until they upgrade. Run `npx codemod @copilotkit/v2-migration` before the
upgrade. The codemod migrates common Express mounts, Hono mounts, and Next.js
`handle(endpoint)` wrappers automatically. It preserves aliases, single-route
mode, explicit CORS defaults, and request URLs. Express mounts receive an
app-owned router around the Node listener so unmatched requests still reach later
middleware. Hono mounts call the Fetch handler directly.

Cases requiring application knowledge receive a `TODO(copilotkit-2.0)`: router
customization, exported app objects, dynamic options, and custom CORS callbacks.
Express CORS configurations that implicitly reflect requested headers also require
manual migration. The codemod leaves the application's framework dependencies in
place because other routes may use them.

## Fetch and Next.js

Replace `createCopilotHonoHandler` or `createCopilotEndpoint` with
`createCopilotRuntimeHandler`. It returns a function, not a Hono app. Remove
`handle(app)` from `hono/vercel` and calls to `app.fetch(request)`.

```ts
import { CopilotRuntime, createCopilotRuntimeHandler } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});

export const GET = handler;
export const POST = handler;
export const PATCH = handler;
export const DELETE = handler;
export const OPTIONS = handler;
```

For Bun, use `Bun.serve({ fetch: handler })`. For an existing Hono application,
mount a route that passes the raw request to the handler:

```ts
import { Hono } from "hono";
import { CopilotRuntime, createCopilotRuntimeHandler } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});

const app = new Hono();
app.all("/api/copilotkit/*", (c) => handler(c.req.raw));
```

## Node and Express

Replace `createCopilotExpressHandler` or `createCopilotEndpointExpress` with
`createCopilotNodeListener` from `@copilotkit/runtime/node`.

```ts
import { createServer } from "node:http";
import { CopilotRuntime } from "@copilotkit/runtime";
import { createCopilotNodeListener } from "@copilotkit/runtime/node";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const listener = createCopilotNodeListener({
  runtime,
  basePath: "/api/copilotkit",
  cors: true,
});
createServer(listener).listen(4000);
```

In an Express app, mount it under the desired prefix and use a base path relative
to that mount. Express strips the mount prefix from `req.url`:

```ts
import express from "express";
import { CopilotRuntime } from "@copilotkit/runtime";
import { createCopilotNodeListener } from "@copilotkit/runtime/node";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.
const app = express();

app.use(
  "/api/copilotkit",
  createCopilotNodeListener({
    runtime,
    basePath: "/",
    cors: true,
  }),
);
app.listen(4000);
```

The listener is not an Express router: move `.use()`, `.get()`, and other router
configuration to the application's own router. Mount it only on the runtime
path; unmatched requests return a runtime 404 rather than calling `next()`.
Existing `express.json()` body parsing is supported.

## Single-route endpoints

For `createCopilotEndpointSingleRoute`, use `createCopilotRuntimeHandler` with
`mode: "single-route"`. For `createCopilotEndpointSingleRouteExpress`, use
`createCopilotNodeListener` with the same option. Keep the frontend's
`useSingleEndpoint` setting and the existing endpoint URL.

The generated Hono wildcard mount covers the base path and its descendants;
the Fetch handler validates the endpoint path and single-route envelope.

## CORS and lifecycle

The generic handlers default to no CORS. Pass `cors: true` to retain the old
adapters' permissive default, or provide a `CopilotCorsConfig`. Express `cors`
options are not accepted: `methods`, `allowedHeaders`, and `exposedHeaders` become
`allowMethods`, `allowHeaders`, and `exposeHeaders`. Origin callbacks return a
string or `null` synchronously; they do not receive an Express callback or Hono
context. Use an explicit allowed origin when sending credentials.

The Fetch handler creates its channel controls lazily and opens no connection at
creation. On a long-running host, call `await handler.channels?.ready()` at startup
if the runtime declares channels. Do not start persistent channels in a
serverless route. The Node listener starts declared channels automatically;
`listener.channels?.ready()` waits for that startup.

## License checker

`runtime.licenseChecker` is removed. Call `await runtime.getLicenseChecker()`
instead. The runtime now verifies the license on first use, not when you create
the runtime. As a result, license warnings print on the first `/info` request,
not at startup.

```ts
import { CopilotRuntime } from "@copilotkit/runtime";

const runtime = new CopilotRuntime({ agents: {} }); // Supply your agents.

export async function licenseStatus() {
  const checker = await runtime.getLicenseChecker?.();
  return checker?.getStatus();
}
```

`getLicenseChecker()` returns `undefined` when the runtime does not use
Intelligence. The codemod adds a `TODO(copilotkit-2.0)` to each read of
`licenseChecker`. It does not rewrite the read, because the new method is async.

## Node.js version

`@copilotkit/runtime` requires Node.js `^20.19.3` or `>=22.13.0`. Node.js 21 is
not supported. If your server or CI uses an earlier version, upgrade Node.js
before you upgrade CopilotKit.

## Debug logs

With `debug: true`, the runtime writes its debug logs as JSON lines. In 1.x it
formatted them with `pino-pretty`, which needs Node streams and does not run on
edge runtimes. To read the logs formatted, pipe your server output through
`npx pino-pretty`.

If your code calls `runtime.debugLogger` (type `CopilotRuntimeLogger`), it has
only these methods in 2.0:

- `debug`, `info`, `warn`, and `error`. Each one takes `(msg)` or `(obj, msg)`.
- `child(bindings)`. It returns a logger that adds `bindings` to each line.

Other pino `Logger` methods and fields are not available, for example `trace`,
`fatal`, `level`, and `flush`. If your code uses them, change it to use the
methods above. The `LOG_LEVEL` environment variable still sets the log level.

## Built-in Agent

In 2.0, `BuiltInAgent` imports from `@copilotkit/runtime/agent`, and it calls the
model with [TanStack AI](https://tanstack.com/ai). The runtime does not install
the model packages, so your app installs the ones it uses.

The codemod (`npx codemod @copilotkit/v2-migration`) does this for you:

- It moves `BuiltInAgent`, `defineTool`, `resolveModel`, and the other agent
  exports from `@copilotkit/runtime` and `@copilotkit/runtime/v2` to
  `@copilotkit/runtime/agent`.
- It moves the AI SDK helpers, such as `convertMessagesToVercelAISDKMessages`, to
  `@copilotkit/runtime/agent/ai-sdk`.

It does not install packages. It adds a `TODO(copilotkit-2.0)` comment that links
here for each item that needs your decision. Do these steps:

1. Install the packages.
2. Replace AI SDK models.
3. Move provider options to `modelOptions`.
4. Remove `urlDownload`.
5. Await `resolveModel`.

### 1. Install the packages

Install `@tanstack/ai` and the adapter for each provider in your model strings:

```npm
npm install @tanstack/ai @tanstack/ai-openai
```

| Model string prefix                 | Package                  |
| ----------------------------------- | ------------------------ |
| `openai`, `minimax`                 | `@tanstack/ai-openai`    |
| `anthropic`                         | `@tanstack/ai-anthropic` |
| `google`, `gemini`, `google-gemini` | `@tanstack/ai-gemini`    |
| `vertex`                            | `@tanstack/ai-vertex`    |

Also install these packages if your code needs them:

- `@tanstack/ai-mcp`: if an agent sets `mcpServers`.
- `ai`: if your code imports from `@copilotkit/runtime/agent/ai-sdk`.

If a package is missing, the run fails with an error that names the package to
install. Remove the `@ai-sdk/*` packages that your code no longer imports.

### 2. Replace AI SDK models

`model` takes a model string or a TanStack AI adapter. An AI SDK model, such as
`openai("gpt-5.4")` from `@ai-sdk/openai`, throws when you create the agent.
Use a model string:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";

const agent = new BuiltInAgent({
  model: "openai:gpt-5.4",
});
```

If you configured the provider yourself, for example with a custom base URL,
use a TanStack AI adapter. See
[Configure the provider yourself](/model-selection#configure-the-provider-yourself).

To keep the AI SDK model, write the `streamText()` call in a `type: "aisdk"`
factory:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { convertMessagesToVercelAISDKMessages } from "@copilotkit/runtime/agent/ai-sdk";
import { openai } from "@ai-sdk/openai";
import { streamText } from "ai";

const agent = new BuiltInAgent({
  type: "aisdk",
  factory: ({ input, abortSignal }) =>
    streamText({
      model: openai("gpt-5.4"),
      messages: convertMessagesToVercelAISDKMessages(input.messages),
      abortSignal,
    }),
});
```

In a factory, you add the tools yourself. See [Use any model router](/backend/custom-agent).

### 3. Move provider options to `modelOptions`

These options are removed: `temperature`, `maxOutputTokens`, `topP`, `topK`,
`presencePenalty`, `frequencyPenalty`, `stopSequences`, `seed`, and
`providerOptions`. Put the provider's own option names in `modelOptions`. The
agent sends them to the provider unchanged:

```typescript
import { BuiltInAgent } from "@copilotkit/runtime/agent";

const agent = new BuiltInAgent({
  model: "openai:gpt-5.4",
  // Was: maxOutputTokens: 1000, providerOptions: { openai: { reasoningEffort: "low" } }
  modelOptions: {
    max_output_tokens: 1000,
    reasoning: { effort: "low" },
  },
});
```

Make these changes too:

- `maxRetries`: it is a setting of the provider client. Pass it to an adapter,
  for example `createOpenaiChat("gpt-5.4", apiKey, { maxRetries: 3 })` from
  `@tanstack/ai-openai`.
- `overridableProperties`: you can list `model`, `toolChoice`, `prompt`, and
  `modelOptions`. Replace a removed option name with `modelOptions`.
- `toolChoice`: write `{ type: "tool", name: "searchDocs" }`, not `toolName`.

### 4. Remove `urlDownload`

The server no longer downloads attachment URLs. The agent sends each URL to the
provider. Delete the `urlDownload` key.

In an AI SDK factory, you can still let the AI SDK download URLs. Pass
`createSafeUrlDownload({ signal: ctx.abortSignal })` from
`@copilotkit/runtime/agent/ai-sdk` as `experimental_download`.

### 5. Await `resolveModel`

`resolveModel` is async, and it returns a TanStack AI adapter. Add `await`:

```typescript
import { resolveModel } from "@copilotkit/runtime/agent";

const adapter = await resolveModel("anthropic:claude-sonnet-4-6");
```

### Other changes to check

Model providers:

- A missing API key fails when the agent resolves the model, at the start of a
  run. The error names the environment variable to set.
- `ANTHROPIC_BASE_URL`: requests go to `{base}/v1/messages`. A trailing `/v1` in
  the value is removed first. If your proxy serves `/messages` without `/v1`,
  change the proxy route.
- MiniMax uses the Chat Completions API. It needs `MINIMAX_API_KEY` and does not
  use `OPENAI_API_KEY`.

Messages:

- With `forwardSystemMessages` or `forwardDeveloperMessages`, the forwarded
  messages become system prompts after the agent's `prompt`.
- If `overridableProperties` lists `prompt`, a `prompt` in `forwardedProps`
  replaces the agent's prompt for that run.

Tools:

- `MCPClient` and `MCPTransport` are TanStack AI MCP types. Import them from
  `@copilotkit/runtime/agent` or `@tanstack/ai-mcp`.
- For `mcpClients`, create the client with `createMCPClient` from
  `@tanstack/ai-mcp`. A custom provider's `tools()` must return TanStack AI tools.
  See [MCP Servers](/mcp-servers#user-managed-mcp-clients).
- In a factory, `ctx.learnedSkills.tools` is an array of TanStack AI tools. For
  `streamText()`, convert it with `toAISDKTools` from
  `@copilotkit/runtime/agent/ai-sdk`. See [Skill delivery](/intelligence/learned-skills#factory-mode).

## Dependency cleanup

Remove `hono`, `@hono/node-server`, `express`, and `cors` from your app only if your
own host code no longer uses them. CopilotKit no longer directly depends on these
framework adapters, but the MCP SDK and MCP middleware can still install Express
and Hono transitively.
