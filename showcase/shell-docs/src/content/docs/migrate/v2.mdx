## Overview

CopilotKit 2.0 removes the v1 React and Runtime APIs. The React hooks and the
chat components are exported from `@copilotkit/react-core`, and the runtime
serves AG-UI agents from `@copilotkit/runtime`. The `@copilotkit/react-ui` and
`@copilotkit/react-textarea` packages are deleted.

If your app already used the `/v2` subpaths that CopilotKit 1.x shipped
(`@copilotkit/react-core/v2`, `@copilotkit/runtime/v2`), the same APIs now
import from the package root. 2.0 has no `/v2` subpaths for React or the runtime.

This migration is not a global string replacement. Some exports kept their
names, some were renamed, and some have no 1:1 replacement because 2.0 uses a
different model. Start with the codemod, then use the steps below for what it
cannot migrate:

```bash
npx codemod @copilotkit/v2-migration
```

**What's changing:**

| Before (v1)                              | After (2.0)                           |
| ---------------------------------------- | ------------------------------------- |
| v1 hooks from `@copilotkit/react-core`   | 2.0 hooks from `@copilotkit/react-core` |
| `<CopilotKit>`                           | `<CopilotKitProvider>`                |
| `@copilotkit/react-ui`                   | `@copilotkit/react-core`              |
| `@copilotkit/react-ui/styles.css`        | No stylesheet import                  |
| `@copilotkit/react-core/v2`              | `@copilotkit/react-core`              |
| `@copilotkit/runtime` service adapters   | `BuiltInAgent` and `createCopilotRuntimeHandler` from `@copilotkit/runtime` |
| `@copilotkit/runtime/v2`                 | `@copilotkit/runtime`                 |
| `@copilotkit/vue`                        | `@copilotkit/vue/v2`                  |
| `CopilotTextarea` (`@copilotkit/react-textarea`) | Removed. 2.0 has no equivalent. |

## Migration Steps

<Steps>
<Step>
### Update the provider and hook imports

Replace the v1 hooks with their 2.0 equivalents, and replace the `<CopilotKit>`
provider with `<CopilotKitProvider>`. The provider's `agent` prop is `agentId`
in 2.0.

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import { CopilotKit } from "@copilotkit/react-core";
import { useCopilotReadable, useCopilotAction } from "@copilotkit/react-core";
```

#### After

```tsx
import {
  CopilotKitProvider,
  useAgentContext,
  useFrontendTool,
} from "@copilotkit/react-core";
```

#### Hook mapping

Use this table to find the 2.0 replacement for each v1 hook:

| v1 hook                            | 2.0 hook                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------- |
| `useCopilotAction`                 | [`useFrontendTool`](/reference/hooks/useFrontendTool), or [`useHumanInTheLoop`](/reference/hooks/useHumanInTheLoop) when the action waits for the user |
| `useCopilotReadable`               | [`useAgentContext`](/reference/hooks/useAgentContext)                      |
| `useCopilotAdditionalInstructions` | [`useAgentContext`](/reference/hooks/useAgentContext)                      |
| `useCoAgent`                       | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCoAgentStateRender`            | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCopilotChat`                   | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCopilotChatHeadless_c`         | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCopilotChatSuggestions`        | [`useConfigureSuggestions`](/reference/hooks/useConfigureSuggestions)      |
| `useLangGraphInterrupt`            | [`useInterrupt`](/reference/hooks/useInterrupt)                            |
| `useRenderToolCall` (v1)           | [`useRenderTool`](/reference/hooks/useRenderTool)                          |
| `useDefaultTool`                   | [`useDefaultRenderTool`](/reference/hooks/useDefaultRenderTool)            |

The tool hooks take a Standard Schema such as `z.object(...)` for `parameters`,
not the v1 `Parameter[]` list:

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import { useCopilotAction } from "@copilotkit/react-core";

function Greeter() {
  useCopilotAction({
    name: "sayHello",
    description: "Greet the user by name",
    parameters: [{ name: "name", type: "string", required: true }],
    handler: async ({ name }) => `Hello, ${name}!`,
  });
  return null;
}
```

```tsx
import { useFrontendTool } from "@copilotkit/react-core";
import { z } from "zod";

function Greeter() {
  useFrontendTool({
    name: "sayHello",
    description: "Greet the user by name",
    parameters: z.object({ name: z.string() }),
    handler: async ({ name }) => `Hello, ${name}!`,
  });
  return null;
}
```

Chat-UI customization props were also renamed in 2.0:

| v1 (component prop)    | 2.0 (slot / prop)                                  |
| ---------------------- | -------------------------------------------------- |
| `AssistantMessage`     | `assistantMessage` slot (under `messageView`)      |
| `markdownTagRenderers` | `markdownRenderer` slot (under `assistantMessage`) |

See [Slots](/custom-look-and-feel/slots) for how the slot system replaces the
v1 component-override props.

</Step>
<Step>
### Upgrade to Zod 4.2 or later

CopilotKit 2.0 sends every tool schema to the agent as JSON Schema. It reads
that JSON Schema from the schema itself, through the
[Standard JSON Schema](https://standardschema.dev) interface. Zod 4.2 and
later implement this interface. Zod 3 does not, and 2.0 no longer converts
Zod 3 schemas for you.

**What breaks:** a Zod 3 schema in `parameters` (`useFrontendTool`,
`useHumanInTheLoop`, `useComponent`), in the `args` of a tool renderer, or in
an Open Generative UI sandbox function. CopilotKit throws
`Cannot convert schema to JSON Schema` when it sends the tool to the agent.

**How to fix it:** install Zod 4.2 or later. Your `z.object(...)` code does
not change.

```bash
npm install zod@^4.2.0
```

Do not use `import { z } from "zod/v4"` to stay on Zod 3. The `zod/v4`
subpath in Zod 3.25 does not implement Standard JSON Schema. Import from
`zod`, not `zod/mini`, for the same reason.

**Alternatives:** any library that implements Standard JSON Schema works in
the same places:

- [Valibot](https://valibot.dev) v1, with each schema wrapped in
  `toStandardJsonSchema()` from `@valibot/to-json-schema`.
- [ArkType](https://arktype.io) 2.1.28 or later.

**A2UI catalogs stay on Zod 3.** The component schemas that you give to
`createCatalog` go to `@a2ui/web_core`, which reads Zod 3 schema internals.
If your app installs Zod 4, install Zod 3 next to it under an alias, and use
the alias only in your catalog definitions:

```bash
npm install zod-v3@npm:zod@^3.25.76
```

{/* kiira: ignore, `zod-v3` is an npm alias that the reader installs */}
```tsx ignore
import { z } from "zod-v3";

const definitions = {
  StatusBadge: { props: z.object({ text: z.string() }) },
};
```

</Step>
<Step>
### Replace React UI imports

UI components like `CopilotChat`, `CopilotSidebar`, and `CopilotPopup` are now exported from `@copilotkit/react-core`.

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import { CopilotPopup } from "@copilotkit/react-ui";
import { CopilotSidebar } from "@copilotkit/react-ui";
import { CopilotChat } from "@copilotkit/react-ui";
```

#### After

```tsx
import { CopilotPopup } from "@copilotkit/react-core";
import { CopilotSidebar } from "@copilotkit/react-core";
import { CopilotChat } from "@copilotkit/react-core";
```

</Step>
<Step>
### Update the runtime

2.0 has no service adapters (`OpenAIAdapter`, `AnthropicAdapter`, ...) and no
GraphQL endpoint. A model runs in a `BuiltInAgent`, and
`createCopilotRuntimeHandler` serves the runtime. Read
[Runtime HTTP handlers in 2.0](/migrate/runtime-2.0) for Express, Hono, and
Node, and [Deploy to any runtime](/runtime-server-adapter) for other hosts. If
your agent uses a model string, read
[Classic `BuiltInAgent`](/migrate/runtime-2.0#classic-builtinagent).

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```ts ignore
import {
  CopilotRuntime,
  OpenAIAdapter,
  copilotRuntimeNextJSAppRouterEndpoint,
} from "@copilotkit/runtime";
import type { NextRequest } from "next/server";

const runtime = new CopilotRuntime();
const serviceAdapter = new OpenAIAdapter();

export const POST = async (req: NextRequest) => {
  const { handleRequest } = copilotRuntimeNextJSAppRouterEndpoint({
    runtime,
    serviceAdapter,
    endpoint: "/api/copilotkit",
  });
  return handleRequest(req);
};
```

#### After

Install TanStack AI and an adapter for your provider:

```bash
npm install @tanstack/ai @tanstack/ai-openai
```

In `app/api/copilotkit/[[...slug]]/route.ts`:

```ts
import { CopilotRuntime, createCopilotRuntimeHandler } from "@copilotkit/runtime";
import { tanstackAIAgent } from "@copilotkit/runtime/tanstack-ai";
import { openaiText } from "@tanstack/ai-openai";

const runtime = new CopilotRuntime({
  agents: {
    default: tanstackAIAgent({ adapter: () => openaiText("gpt-5.5") }),
  },
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
```

</Step>
<Step>
### Update Vue imports

The Vue 2.0 API lives at the `@copilotkit/vue/v2` subpath. The v1 `CopilotKit`
component becomes `CopilotKitProvider`; most exports otherwise retain their
public names.

#### Before

```ts
import { CopilotKit, useCopilotAction } from "@copilotkit/vue";
```

#### After

```ts
import { CopilotKitProvider, useFrontendTool } from "@copilotkit/vue/v2";
```

</Step>
<Step>
### Remove the stylesheet import

CopilotKit 2.0 components include their own styles, so you don't import a stylesheet.
Remove this line when no v1 `@copilotkit/react-ui` components are left in your app:

```tsx
import "@copilotkit/react-ui/styles.css"; // [!code --]
```

If your app imports a v2 stylesheet (`@copilotkit/react-core/v2/styles.css`,
`@copilotkit/vue/styles.css`, or `@copilotkit/angular/styles.css`), this codemod
removes the import from your JS, TS, CSS, and Vue files and from `angular.json`:

```bash
npx jscodeshift --parser=tsx --extensions=tsx,ts,jsx,js,css,scss,vue,json \
  -t https://raw.githubusercontent.com/CopilotKit/CopilotKit/main/codemods/remove-stylesheet-import.ts \
  ./src
```

In an Angular app, add `angular.json` after `./src` so the codemod also updates its `styles` arrays.

</Step>
<Step>
### Upgrade AG-UI client if using it directly

If you import from `@ag-ui/client` directly, install the version that `@copilotkit/runtime` depends on:

```bash
npm install @ag-ui/client@1.0.2
```

A different version installs a second copy of the package, with its own `HttpAgent` class. Run `npm ls @ag-ui/client` to make sure that only one version is installed.

Note: If you only use CopilotKit's React packages, `@ag-ui/client` types are already re-exported from `@copilotkit/react-core` and you don't need a separate install.

</Step>
<Step>
### Check your Node.js and LangChain versions

Every 2.0 package declares the Node.js versions that it supports:

| Packages | Node.js |
| --- | --- |
| `@copilotkit/runtime` and the `@copilotkit/channels-*` packages | `^20.19.3` or `>=22.13.0` |
| All other packages | `>=20` |

If you build or render on Node.js 18, upgrade to Node.js 20 or later. The
runtime has more details in the [runtime migration guide](/migrate/runtime-2.0).

If your LangGraph JS agent uses `@copilotkit/sdk-js`, install LangChain 1.x.
`@copilotkit/sdk-js` 2.0 needs these versions:

| Package | Version |
| --- | --- |
| `@langchain/core` | `>=1.1.41 <2` |
| `@langchain/langgraph` | `>=1.2.9 <2` |
| `langchain` | `>=1.3.4 <2` |
| `zod` | `^4.2.0` |

```bash
npm install @langchain/core@^1.1.41 @langchain/langgraph@^1.2.9 langchain@^1.3.4 zod@^4.2.0
```

</Step>
</Steps>

## Gotchas

- **Tool rendering is not frontend tool execution.** Replace the v1
  `useRenderToolCall` registration hook with `useRenderTool`. The 2.0 hook named
  `useRenderToolCall` is a different low-level consumer API.
- **Schemas changed.** The 2.0 tool and interaction hooks use Standard Schema
  objects such as `z.object(...)`, not the v1 `Parameter[]` shape. Zod
  schemas must come from Zod 4.2 or later.
- **Names can move packages.** React UI components move from
  `@copilotkit/react-ui` to `@copilotkit/react-core`.
- **`CopilotTextarea` has no replacement.** 2.0 deleted
  `@copilotkit/react-textarea`. Remove the component, or build the behavior
  with your own textarea and the [2.0 hooks](/reference).
- **No 1:1 replacement is intentional.** Where a v1 export has no 2.0
  equivalent, migrate the surrounding pattern using the linked 2.0 reference
  instead of selecting a similarly named symbol.

## Full Example

### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import type { ReactNode } from "react";
import { CopilotKit } from "@copilotkit/react-core";
import { CopilotPopup } from "@copilotkit/react-ui";
import "@copilotkit/react-ui/styles.css";

export function App({ children }: { children: ReactNode }) {
  return (
    <CopilotKit runtimeUrl="/api/copilotkit">
      {children}
      <CopilotPopup />
    </CopilotKit>
  );
}
```

### After

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider, CopilotPopup } from "@copilotkit/react-core";

export function App({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">
      {children}
      <CopilotPopup />
    </CopilotKitProvider>
  );
}
```
