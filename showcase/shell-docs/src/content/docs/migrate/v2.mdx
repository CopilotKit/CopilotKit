## Overview

CopilotKit 2.0 removes the v1 React, Vue, and Runtime APIs. The React hooks and the
chat components are exported from `@copilotkit/react-core`, and the runtime
serves AG-UI agents from `@copilotkit/runtime`. Angular apps move from
`@copilotkit/angular` 0.x to 2.0. For a summary of the changes, read
[What's new in 2.0](/whats-new-2.0).

2.0 deletes two packages:

- `@copilotkit/react-ui`: its components moved to `@copilotkit/react-core`.
- `@copilotkit/react-textarea`: discontinued. 2.0 has no successor for
  `CopilotTextarea`.

If your app already used the `/v2` subpaths that CopilotKit 1.x shipped
(`@copilotkit/react-core/v2`, `@copilotkit/runtime/v2`, `@copilotkit/vue/v2`),
the same APIs now import from the package root. In 2.0, these `/v2` subpaths
are deprecated aliases of the package roots. Your imports still work, and your
editor marks them as deprecated. Move each import to the package root. `@copilotkit/react-core/v2/styles.css` is empty, because the 2.0
components add their own styles. Delete that import.

This migration is not a global string replacement. Some exports kept their
names, some were renamed, and some have no 1:1 replacement because 2.0 uses a
different model. Start with the codemod. Before you upgrade the packages, run
it in the root of your app:

```bash
npx copilotkit@latest migrate
```

Then use the steps below for the code that it cannot migrate.

**What's changing:**

| Before (v1)                              | After (2.0)                           |
| ---------------------------------------- | ------------------------------------- |
| v1 hooks from `@copilotkit/react-core`   | 2.0 hooks from `@copilotkit/react-core` |
| `<CopilotKit>`                           | `<CopilotKitProvider>`                |
| `@copilotkit/react-ui`                   | `@copilotkit/react-core`              |
| `@copilotkit/react-ui/styles.css`        | No stylesheet import                  |
| `@copilotkit/react-core/v2`              | `@copilotkit/react-core`              |
| `@copilotkit/runtime` service adapters   | `BuiltInAgent` and `createCopilotKitRuntimeHandler` from `@copilotkit/runtime` |
| `@copilotkit/runtime/v2`                 | `@copilotkit/runtime`                 |
| `CopilotRuntime`                         | `CopilotKitRuntime`                   |
| v1 hooks from `@copilotkit/vue`          | 2.0 hooks from `@copilotkit/vue`      |
| `@copilotkit/vue/v2`                     | `@copilotkit/vue`                     |
| `@copilotkit/angular/styles.css`         | No stylesheet import                  |
| `@copilotkit/angular/a2ui`               | `@copilotkit/angular/generative-ui`   |
| `CopilotTextarea` (`@copilotkit/react-textarea`) | Discontinued. 2.0 has no successor. |

## Minimum versions

CopilotKit 2.0 removes the v1 APIs, so v1 and 2.0 code cannot run side by
side in one app. Upgrade every `@copilotkit/*` package to 2.0 at the same time.

2.0 needs:

- Node.js `^20.19.3` or `>=22.13.0` for `@copilotkit/runtime`, and Node.js 20
  or later for the other packages. See
  [Check your Node.js and LangChain versions](#check-your-nodejs-and-langchain-versions).
- React 18 or 19.
- Angular 22 for `@copilotkit/angular`.
- Zod 4.2 or later for your tool schemas. See
  [Upgrade to Zod 4.2 or later](#upgrade-to-zod-42-or-later).

## Migration Steps

<Steps>
<Step>
### Update the provider and hook imports

Replace the v1 hooks with their 2.0 equivalents, and replace the `<CopilotKit>`
provider with `<CopilotKitProvider>`. The provider's `agent` prop is `agentId`
in 2.0.

`CopilotKit` and `CopilotKitProps` still work in 2.0. They are aliases of
`CopilotKitProvider` and `CopilotKitProviderProps`, so an existing import does
not break. Use `CopilotKitProvider` in new code. The alias takes the 2.0 props,
so you must still rename `agent` to `agentId`.

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import { CopilotKit } from "@copilotkit/react-core";
import { useCopilotReadable, useCopilotAction } from "@copilotkit/react-core";
```

#### After

```tsx
import {
  CopilotKitProvider,
  useAgentContext,
  useFrontendTool,
} from "@copilotkit/react-core";
```

#### Provider props

Some props of the v1 `<CopilotKit>` changed or are not in 2.0. The codemod
renames `agent`. It marks each of the other props with a
`TODO(copilotkit-2.0)` comment.

| v1 prop | 2.0 |
| --- | --- |
| `agent` | `agentId` |
| `threadId` | `threadId` on `<CopilotChat>`, or on a `<CopilotChatConfigurationProvider>` around the chat |
| `onError` | Same prop. The handler gets `{ error, code, context }`. Read `code` where you read `type`. |
| `transcribeAudioUrl` | Removed. For voice input, give the runtime a `transcriptionService`. See [Voice](/voice). |
| `forwardedParameters` | Removed. Set the model options on the agent, for example `modelOptions` on `BuiltInAgent`. |
| `textToSpeechUrl`, `guardrails_c`, `cloudRestrictToTopic`, `authConfig_c` | Removed. 2.0 has no equivalent. |

#### Hook mapping

Use this table to find the 2.0 replacement for each v1 hook:

| v1 hook                            | 2.0 hook                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------- |
| `useCopilotAction`                 | [`useFrontendTool`](/reference/hooks/useFrontendTool), or [`useHumanInTheLoop`](/reference/hooks/useHumanInTheLoop) when the action waits for the user |
| `useCopilotReadable`               | [`useAgentContext`](/reference/hooks/useAgentContext)                      |
| `useCopilotAdditionalInstructions` | [`useAgentContext`](/reference/hooks/useAgentContext)                      |
| `useCoAgent`                       | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCoAgentStateRender`            | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCopilotChat`                   | [`useAgent`](/reference/hooks/useAgent) (custom chat UI: [Headless UI](/custom-look-and-feel/headless-ui)) |
| `useCopilotChatHeadless_c`         | [`useAgent`](/reference/hooks/useAgent)                                    |
| `useCopilotChatSuggestions`        | [`useConfigureSuggestions`](/reference/hooks/useConfigureSuggestions)      |
| `useLangGraphInterrupt`            | [`useInterrupt`](/reference/hooks/useInterrupt)                            |
| `useRenderToolCall` (v1)           | [`useRenderTool`](/reference/hooks/useRenderTool)                          |
| `useThreads` (v1)                  | [`useCopilotChatConfiguration`](/reference/hooks/useCopilotChatConfiguration) for the current thread. See [Same import, new API](#same-import-new-api). |
| `useDefaultTool`                   | [`useDefaultRenderTool`](/reference/hooks/useDefaultRenderTool)            |

The tool hooks take a Standard Schema such as `z.object(...)` for `parameters`,
not the v1 `Parameter[]` list:

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import { useCopilotAction } from "@copilotkit/react-core";

function Greeter() {
  useCopilotAction({
    name: "sayHello",
    description: "Greet the user by name",
    parameters: [{ name: "name", type: "string", required: true }],
    handler: async ({ name }) => `Hello, ${name}!`,
  });
  return null;
}
```

```tsx
import { useFrontendTool } from "@copilotkit/react-core";
import { z } from "zod";

function Greeter() {
  useFrontendTool({
    name: "sayHello",
    description: "Greet the user by name",
    parameters: z.object({ name: z.string() }),
    handler: async ({ name }) => `Hello, ${name}!`,
  });
  return null;
}
```

Chat-UI customization props were also renamed in 2.0:

| v1 (component prop)    | 2.0 (slot / prop)                                  |
| ---------------------- | -------------------------------------------------- |
| `AssistantMessage`     | `assistantMessage` slot (under `messageView`)      |
| `markdownTagRenderers` | `markdownRenderer` slot (under `assistantMessage`) |

See [Slots](/custom-look-and-feel/slots) for how the slot system replaces the
v1 component-override props.

<Step>
### Upgrade to Zod 4.2 or later

CopilotKit 2.0 sends every tool schema to the agent as JSON Schema. It reads
that JSON Schema from the schema itself, through the
[Standard JSON Schema](https://standardschema.dev) interface. Zod 4.2 and
later implement this interface. Zod 3 does not, and 2.0 no longer converts
Zod 3 schemas for you.

**What breaks:** a Zod 3 schema in `parameters` (`useFrontendTool`,
`useHumanInTheLoop`, `useComponent`), in the `args` of a tool renderer, or in
an Open Generative UI sandbox function. CopilotKit throws
`Cannot convert schema to JSON Schema` when it sends the tool to the agent.

**How to fix it:** install Zod 4.2 or later. Your `z.object(...)` code does
not change.

```bash
npm install zod@^4.2.0
```

Do not use `import { z } from "zod/v4"` to stay on Zod 3. The `zod/v4`
subpath in Zod 3.25 does not implement Standard JSON Schema. Import from
`zod`, not `zod/mini`, for the same reason.

**Alternatives:** any library that implements Standard JSON Schema works in
the same places:

- [Valibot](https://valibot.dev) v1, with each schema wrapped in
  `toStandardJsonSchema()` from `@valibot/to-json-schema`.
- [ArkType](https://arktype.io) 2.1.28 or later.

</Step>

### Replace React UI imports

UI components like `CopilotChat`, `CopilotSidebar`, and `CopilotPopup` are now exported from `@copilotkit/react-core`.

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import { CopilotPopup } from "@copilotkit/react-ui";
import { CopilotSidebar } from "@copilotkit/react-ui";
import { CopilotChat } from "@copilotkit/react-ui";
```

#### After

```tsx
import { CopilotPopup } from "@copilotkit/react-core";
import { CopilotSidebar } from "@copilotkit/react-core";
import { CopilotChat } from "@copilotkit/react-core";
```

<Step>
### Update the runtime

2.0 has no service adapters (`OpenAIAdapter`, `AnthropicAdapter`, ...) and no
GraphQL endpoint. A model runs in a `BuiltInAgent`, and
`createCopilotKitRuntimeHandler` serves the runtime. Read
[Runtime HTTP handlers in 2.0](/migrate/runtime-2.0) for Express, Hono, and
Node, and [Deploy to any runtime](/runtime-server-adapter) for other hosts.

For LangGraph agents, remote endpoints, and server-side actions, see [Agents and server-side actions in 2.0](/migrate/agents-2.0).

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```ts ignore
import {
  CopilotRuntime,
  OpenAIAdapter,
  copilotRuntimeNextJSAppRouterEndpoint,
} from "@copilotkit/runtime";
import type { NextRequest } from "next/server";

const runtime = new CopilotRuntime();
const serviceAdapter = new OpenAIAdapter();

export const POST = async (req: NextRequest) => {
  const { handleRequest } = copilotRuntimeNextJSAppRouterEndpoint({
    runtime,
    serviceAdapter,
    endpoint: "/api/copilotkit",
  });
  return handleRequest(req);
};
```

#### After

In `app/api/copilotkit/[[...slug]]/route.ts`:

```ts
import {
  CopilotKitRuntime,
  createCopilotKitRuntimeHandler,
} from "@copilotkit/runtime";
import { BuiltInAgent } from "@copilotkit/runtime/agent";
import { openaiText } from "@tanstack/ai-openai";

const runtime = new CopilotKitRuntime({
  agents: { default: new BuiltInAgent({ model: openaiText("gpt-6-luna") }) },
});

const handler = createCopilotKitRuntimeHandler({
  runtime,
  basePath: "/api/copilotkit",
});

export const GET = handler;
export const POST = handler;
```

</Step>
<Step>
### If you use Vue, update Vue imports

The 2.0 API is at the package root, `@copilotkit/vue`, as in React. The `/v2`
subpaths, such as `@copilotkit/vue/v2` and `@copilotkit/vue/v2/generative-ui`,
are deprecated aliases of the package root. Imports from them still work, and
your editor marks them as deprecated. Imports of `useCopilotAction` and
`useCopilotReadable` from `@copilotkit/vue` fail, because 2.0 removes the v1
hooks.

The codemod (`npx copilotkit@latest migrate`) migrates these imports and
hooks. It changes `.ts` files and the `<script>` and `<script setup>` blocks of
`.vue` files. It does not change templates. If it cannot convert some code, it adds a `TODO(copilotkit-2.0)`
comment.

To migrate by hand:

1. Remove `/v2` from each `@copilotkit/vue` import path. For example,
   `@copilotkit/vue/v2/generative-ui` becomes `@copilotkit/vue/generative-ui`.
2. Replace `useCopilotAction` and `useCopilotReadable` with their 2.0 hooks.
   The [hook mapping](#hook-mapping) table above applies to Vue too. A
   `useCopilotAction` call that only renders becomes `useRenderTool`.
3. If a `useFrontendTool` call has a `Parameter[]` list, replace the list with
   a Standard Schema such as `z.object(...)`. A Zod schema needs
   [Zod 4.2 or later](#upgrade-to-zod-42-or-later).

`CopilotKit` and `CopilotKitProps` still work. They are aliases of
`CopilotKitProvider` and `CopilotKitProviderProps`, so `<CopilotKit>` in a
template does not break. Use `CopilotKitProvider` in new code.

#### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```ts ignore
// Inside <script setup lang="ts">
import { useCopilotAction } from "@copilotkit/vue";
import { useAgentContext } from "@copilotkit/vue/v2";

useAgentContext({ description: "The name of the user", value: "Ada" });

useCopilotAction({
  name: "sayHello",
  description: "Greet the user by name",
  parameters: [{ name: "name", type: "string", required: true }],
  handler: async ({ name }) => `Hello, ${name}!`,
});
```

#### After

```ts
// Inside <script setup lang="ts">
import { useAgentContext, useFrontendTool } from "@copilotkit/vue";
import { z } from "zod";

useAgentContext({ description: "The name of the user", value: "Ada" });

useFrontendTool({
  name: "sayHello",
  description: "Greet the user by name",
  parameters: z.object({ name: z.string() }),
  handler: async ({ name }) => `Hello, ${name}!`,
});
```

</Step>
<Step>
### If you use Angular, update Angular code

`@copilotkit/angular` goes from 0.x to 2.0. Most of the 0.x API stays the same
in 2.0. These changes can break the build or the app:

- `@copilotkit/angular/styles.css` is removed. The components add their own
  styles.
- `@copilotkit/angular/a2ui` is removed. A2UI renders with generative UI from
  `@copilotkit/angular/generative-ui`.
- The A2UI exports of `@copilotkit/angular` are removed, for example
  `CopilotA2UIRecovery` and `readA2UILifecycleContent`.
- `provideCopilotKit` throws in production when it has no runtime.

The codemod (`npx copilotkit@latest migrate`) changes your `.ts` files.
It does not change templates, stylesheets, or `angular.json`. If it cannot
convert some code, it adds a `TODO(copilotkit-2.0)` comment.

To migrate:

1. Run the codemod. Then install `@copilotkit/angular@next`.
2. Remove `@copilotkit/angular/styles.css` from `angular.json` and from your
   stylesheets. See [Remove the stylesheet import](#remove-the-stylesheet-import).
3. Give each `provideCopilotKit` call a `runtimeUrl`, `licenseKey`, `agents`,
   or `selfManagedAgents`. The codemod marks each call that has none of them.
4. Move your A2UI catalogs to generative UI. The codemod converts
   `createAngularCatalog` to `createGenerativeUI`, and `a2ui: { catalog }` to
   `provideGenerativeUI({ ui: catalog })`. Rewrite each component that it
   marks. See [Adopt from A2UI](/generative-ui/components/from-a2ui).
5. Fix the other `TODO(copilotkit-2.0)` comments. Each comment names the 2.0
   API to use, for example `handleCopy()` for a write to the `copied` signal
   of a copy button.

#### Before

{/* kiira: ignore, shows the 0.x code this guide migrates away from */}
```ts ignore title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { appCatalog } from "./app-catalog";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({
      runtimeUrl: "/api/copilotkit",
      a2ui: { catalog: appCatalog },
    }),
  ],
};
```

#### After

```ts title="src/app/app.config.ts"
import { ApplicationConfig } from "@angular/core";
import { provideCopilotKit } from "@copilotkit/angular";
import { provideGenerativeUI } from "@copilotkit/angular/generative-ui";
import { appCatalog } from "./app-catalog";

export const appConfig: ApplicationConfig = {
  providers: [
    provideCopilotKit({ runtimeUrl: "/api/copilotkit" }),
    provideGenerativeUI({ ui: appCatalog }),
  ],
};
```

Some Angular behavior also changed: error logs, the runtime connection, the
chat text, and the markdown output. Read the Angular sections of these pages:

- [Providers in 2.0](/migrate/providers-2.0)
- [Chat UI in 2.0](/migrate/chat-2.0)
- [Generative UI in 2.0](/migrate/generative-ui-2.0)
- [Migrate the Markdown Renderer](/migrate/markdown-renderer#angular)

</Step>

### Remove the stylesheet import

CopilotKit 2.0 components include their own styles, so you do not import a
stylesheet.

The codemod deletes the CopilotKit stylesheet imports from your JavaScript and
TypeScript files, and from the `<script>` blocks of `.vue` files. It does not
read CSS files, the `<style>` blocks of `.vue` files, or `angular.json`.

To find the imports that are left, search your project:

```bash
git grep -n "@copilotkit/.*\.css"
```

Delete each import that it finds, for example:

```css title="src/styles.css"
@import "@copilotkit/angular/styles.css"; /* [!code --] */
```

In `angular.json`, delete the CopilotKit entry from each `styles` array.

Keep `@copilotkit/core/styles.css`. It is the 2.0 stylesheet for an app that
sets `injectStyles` to `false`.

</Step>

## Same import, new API

These names import from the same package in v1 and 2.0, but the 2.0 API is
different. After the upgrade, your type check fails at each v1 use. JavaScript
has no type check, so there the v1 code fails at run time or does nothing.

| v1 name | What you see in 2.0 | What to do |
| --- | --- | --- |
| `CopilotKit`, `CopilotKitProps` | Type errors on v1 props, such as `threadId`. `CopilotKit` is an alias of `CopilotKitProvider`, and it takes the 2.0 props. | Change each prop as the [provider props](#provider-props) table shows. |
| `useFrontendTool` | A type error on `parameters`. The v1 hook took a `Parameter[]` list. | Write `parameters` as a Standard Schema, such as `z.object(...)`. See the [example](#hook-mapping). |
| `useHumanInTheLoop` | A type error on `parameters`, for the same reason. | Write `parameters` as a Standard Schema. The `render` component still gets `respond`. |
| `useRenderToolCall` | A type error, because the 2.0 hook takes no arguments. It returns a function that renders one tool call. | Register your renderer with [`useRenderTool`](/reference/hooks/useRenderTool). |
| `useThreads` | A type error, because `agentId` is missing. The 2.0 hook lists the threads of an agent from CopilotKit Intelligence. It does not return `threadId` or `setThreadId`. | Pass `threadId` to `<CopilotChat>`. To read or change the thread, use `threadId` and `setActiveThreadId` from [`useCopilotChatConfiguration`](/reference/hooks/useCopilotChatConfiguration). |
| `CopilotRuntime` | The 2.0 runtime class is `CopilotKitRuntime`. It takes `agents`, not `serviceAdapter`, `remoteEndpoints`, or `actions`. | Follow [Update the runtime](#update-the-runtime). |

In Vue, `useFrontendTool` changes in the same way. See
[If you use Vue, update Vue imports](#if-you-use-vue-update-vue-imports).

The codemod renames or marks most of these uses. It does not change
`useThreads` calls, so search your code for `useThreads` and change each call
by hand.

## Gotchas

- **Schemas changed.** The 2.0 tool and interaction hooks use Standard Schema
  objects such as `z.object(...)`, not the v1 `Parameter[]` shape. Zod
  schemas must come from Zod 4.2 or later.
- **Names can move packages.** React UI components move from
  `@copilotkit/react-ui` to `@copilotkit/react-core`.
- **The `a2ui` option is deprecated.** `@copilotkit/a2ui-renderer` is gone,
  and the provider renders A2UI with
  [components and surfaces](/generative-ui/components). The `a2ui` provider
  prop (React and Vue) and the `a2ui` option of Angular's `provideCopilotKit`
  still work: they pass `catalog` and `theme` on to generative UI, so
  `catalog` must be a UI from `createGenerativeUI`. The runtime option `a2ui`
  still works as `generativeUI: { a2uiVersion: "0.9" }`, which an agent that
  writes A2UI v0.9 needs. Move both to `generativeUI`. See
  [Adopt from A2UI](/generative-ui/components/from-a2ui).
- **`CopilotTextarea` has no successor.** `@copilotkit/react-textarea` is
  discontinued, and 2.0 deletes it. Remove the component, or build the
  behavior with your own textarea and the [2.0 hooks](/reference).
- **No 1:1 replacement is intentional.** Where a v1 export has no 2.0
  equivalent, migrate the surrounding pattern using the linked 2.0 reference
  instead of selecting a similarly named symbol.
- **The provider logs errors and ends its core.** Without an `onError`
  handler, CopilotKit logs each error. The React provider disposes its core
  when it unmounts. See [Providers in 2.0](/migrate/providers-2.0).

## Full Example

### Before

{/* kiira: ignore, shows the v1 code this guide migrates away from */}
```tsx ignore
import type { ReactNode } from "react";
import { CopilotKit } from "@copilotkit/react-core";
import { CopilotPopup } from "@copilotkit/react-ui";
import "@copilotkit/react-ui/styles.css";

export function App({ children }: { children: ReactNode }) {
  return (
    <CopilotKit runtimeUrl="/api/copilotkit">
      {children}
      <CopilotPopup />
    </CopilotKit>
  );
}
```

### After

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider, CopilotPopup } from "@copilotkit/react-core";

export function App({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">
      {children}
      <CopilotPopup />
    </CopilotKitProvider>
  );
}
```

Run your type check. It must pass. When it passes and no import from a v1 API or a `/v2` subpath is left, the migration is complete.
