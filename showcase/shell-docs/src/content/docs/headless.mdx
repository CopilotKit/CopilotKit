## Full rendering control via hooks

CopilotKit's headless hooks give you complete control over the chat
experience: you compose messages, streaming, and tool-call surfaces
yourself with zero UI opinions. Bring your own design system and render
everything your way.

There are two live cells on this page. Start with
[**Minimal**](#minimal-headless-simple) for the smallest possible custom
chat on `useAgent` + `useCopilotKit`, then jump to
[**Complete**](#complete-headless-complete) to see the full generative-UI
composition (tool calls and activity messages) rebuilt by hand from the
low-level hooks.

## When should I use this?

Use headless UI when you want to:

- Build a completely custom chat interface with your own design system
- Integrate agent chat into existing UI patterns
- Have full control over message rendering and interaction
- Drop generative UI primitives (`useRenderToolCall`,
  `useRenderActivityMessage`, `useRenderCustomMessages`) into a layout
  that isn't a chat at all

## Minimal (`headless-simple`)

<FrameworkSetup concept="programmatic-control-setup" />

Build the smallest custom chat in three steps:

1. Get the agent with `useAgent({ agentId })` and the core with `useCopilotKit()`. Import both hooks from `@copilotkit/react-core/v2`:

   ```tsx
   import { useAgent, useCopilotKit } from "@copilotkit/react-core/v2";
   ```

2. On send, add the user message with `agent.addMessage(...)`. Then call `copilotkit.runAgent({ agent })`:

   <Snippet region="use-agent-simple" cell="headless-simple" title="frontend/src/app/page.tsx: useAgent + useCopilotKit" />

3. Map the user and assistant text messages in `agent.messages` to your own bubbles. `UserBubble` and `AssistantBubble` are your own components that take a `content` string:

   <Snippet region="message-list-simple" cell="headless-simple" title="frontend/src/app/page.tsx — message list" />

That's it: no `<CopilotChat />`, no `<CopilotChatMessageView>`, no
slots. The downside: you only get text. Tool calls and activity messages
(A2UI, MCP Apps) do not show unless you wire them in yourself. The next
section shows how.

## Complete (`headless-complete`)

The Complete demo renders tool calls and activity messages in a custom list.
It uses the low-level hooks only, without `CopilotChatMessageView` or
`CopilotChatAssistantMessage`.

To render tool calls and activity messages in your own list:

1. Get the renderers, and index tool results by `toolCallId`.
2. Map each message by its role.
3. Render each tool call with its result.
4. Put the text and the tool-call cards in your own bubbles.

### The renderer hooks

Call `useRenderToolCall()` and `useRenderActivityMessage()` at the top of
your message list, and index tool results by `toolCallId`:

<Snippet region="use-rendered-messages-hook" title="frontend/src/app/chat/message-list.tsx: renderer hooks" />

What each hook does:

- `useRenderToolCall()`: returns the renderer for any registered tool
  call (per-tool via `useRenderTool` / `useComponent`, plus the
  wildcard from `useDefaultRenderTool`).
- `useRenderActivityMessage()`: renders A2UI + MCP Apps activity
  messages for the current agent scope.

### Per-role dispatch

The message list switches on `role`. User messages render their text.
Assistant messages render their text and tool calls. Activity messages go
through `renderActivityMessage`. Other roles, such as `reasoning`, render
nothing. `ActivityWrapper` is a styled `div` in the demo, so use any container:

### Bubble chrome

The `UserBubble` and `AssistantBubble` components are **pure chrome**:
they receive the message text (and, for the assistant, the tool-call
nodes) from the message list and drop them into a styled container. No
chat primitives are imported here. The demo bubbles use the shadcn/ui
`Avatar`, `react-markdown`, and the demo helpers `cn`, `AttachmentChip`, and
`splitContent`. Replace them with your own markup:

Ask the agent a question that calls a tool with a renderer, such as the
weather in the demo. Your assistant bubble shows the reply text and the
tool-call card.
