## Overview

`useComponent` is a convenience hook built on top of `useFrontendTool`.
It registers a tool and renders a React component in chat using the tool call parameters.

This is part of the v2 tool rendering hook set with [`useRenderTool`](/reference/hooks/useRenderTool), [`useDefaultRenderTool`](/reference/hooks/useDefaultRenderTool), and [`useRenderToolCall`](/reference/hooks/useRenderToolCall).

Use this when you want a visual component renderer without writing a full frontend tool config manually.

## Signature

```tsx
import { z } from "zod";
import type { ComponentType } from "react";
import { useComponent } from "@copilotkit/react-core/v2";

function useComponent<TSchema extends z.ZodTypeAny | undefined = undefined>(
  config: {
    name: string;
    description?: string;
    parameters?: TSchema;
    // When parameters is provided, props are inferred via z.infer.
    // When omitted, render accepts any props.
    render: ComponentType<InferRenderProps<TSchema> & ComponentToolCallProps>;
    agentId?: string;
    followUp?: boolean;
  },
  deps?: ReadonlyArray<unknown>,
): void;
```

## Parameters

- `config.name`: tool name used by the agent to invoke this component tool.
- `config.description`: optional extra description for model guidance.
- `config.parameters`: optional Zod schema for the tool's parameters. When provided, `render` props are inferred from the schema. When omitted, the tool is advertised with an empty parameter schema (`{ "type": "object", "properties": {} }`), so the agent invokes it with no arguments.
- `config.render`: React component rendered with the tool call's arguments as props, plus a `toolCallStatus` prop. While the call streams, the props are the partially parsed JSON of the arguments, not a schema-parsed result, so fields can be missing (see Behavior). Accepts any props when `parameters` is omitted.
- `config.agentId`: optional agent scope for the registration.
- `config.followUp`: whether the agent should continue after rendering the component. Defaults to `true`; set it to `false` to stop after the tool call.
- `deps`: optional dependency array for refreshing registration.

## Render props

Your component receives every tool call argument as a prop, plus:

- `toolCallStatus`: `"inProgress"`, `"executing"` or `"complete"`.
  - `"inProgress"`: the agent is still streaming the arguments. The props are partial.
  - `"executing"`: all arguments have arrived.
  - `"complete"`: the tool call has finished.

If one of your tool parameters is also named `toolCallStatus`, the parameter's value wins, so the prop keeps its existing meaning.

## Behavior

- Prepends a default instruction to the description: _"Use this tool to display the \"&lt;name&gt;\" component in the chat..."_.
- Calls `useFrontendTool` internally with a render function that spreads the tool parameters as component props and adds `toolCallStatus`.
- **Props arrive partial while the tool call streams.** The component renders as soon as the agent starts the tool call, and again as each argument streams in. While `toolCallStatus` is `"inProgress"`, any field can be missing, nested fields included. The props are the arguments the agent sent, not a parsed schema result, so schema defaults such as `.default("c")` are not filled in. The `render` type shows the complete parameters, so TypeScript does not warn you. Check `toolCallStatus` before you read nested fields, or treat every prop as optional and render a placeholder for missing fields.
- **A render error does not crash the app.** If the component throws, CopilotKit renders nothing in its place and reports the error to the console. It tries again when more arguments arrive or the status changes, so the component appears once its props are complete.
- Inherits `useFrontendTool` lifecycle behavior: duplicate-name override warning, tool removal on unmount, and renderer retention for chat history.
- Tracks updates by `config.name` plus `deps` (include any changing captured values in `deps`).
- **`deps` comparison**: compares plain data (strings, numbers, booleans, `null`, dates, and plain objects and arrays of those) by value, so an inline literal such as `[{ status }]` re-registers only when its contents change. A function never counts as changed, as before, so keep a changing callback in a ref. Class instances and other objects compare by identity, so a circular value such as the `agent` from `useAgent` is safe to pass. Adding or removing an entry counts as a change.

## Usage

```tsx
import { z } from "zod";
import { useComponent } from "@copilotkit/react-core/v2";
import type { ComponentToolCallProps } from "@copilotkit/react-core/v2";

const weatherCardSchema = z.object({
  city: z.string().describe("City name"),
  unit: z.enum(["c", "f"]).default("c"),
});

type WeatherCardProps = z.infer<typeof weatherCardSchema>;

// Props are partial while the tool call streams, so read each field as optional.
function WeatherCard({
  city,
  unit,
  toolCallStatus,
}: Partial<WeatherCardProps> & ComponentToolCallProps) {
  if (toolCallStatus === "inProgress") {
    return <div className="rounded border p-3">Loading weather…</div>;
  }
  return (
    <div className="rounded border p-3">
      <div className="text-sm text-zinc-500">Weather request</div>
      <div className="font-medium">
        {city ?? "…"} ({(unit ?? "c").toUpperCase()})
      </div>
    </div>
  );
}

function App() {
  useComponent(
    {
      name: "showWeatherCard",
      description: "Render a weather card in chat for the requested city.",
      parameters: weatherCardSchema,
      render: WeatherCard,
    },
    [],
  );

  return null;
}
```
