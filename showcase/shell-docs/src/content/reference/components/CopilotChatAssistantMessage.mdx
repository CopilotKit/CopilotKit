## Overview

`CopilotChatAssistantMessage` displays assistant messages with Markdown support, tool call rendering, and an action toolbar. By default the Markdown renderer is CopilotKit's **streaming markdown renderer** ([`@copilotkit/markdown-renderer`](/reference/packages/markdown-renderer)) — a zero-dependency, streaming-safe renderer with incremental rendering, per-token fade-in animation, GFM, tables, autolinks, and citations. It does **not** do syntax highlighting, math, or diagrams by default. To add those, plug in your own renderer: globally via `CopilotKitProvider`'s `markdownRenderer` prop, or per-message via the `markdownRenderer` slot below. `BasicMarkdownRenderer` (marked-based) remains available as a lighter alternative. The toolbar provides copy, rating (thumbs up/down), read aloud, and regenerate buttons with localized tooltips sourced from `CopilotChatConfigurationProvider`.

<Callout type="info">
  Upgrading from a version that bundled Streamdown? See [Migrate the Markdown Renderer](/migrate/markdown-renderer) to restore rich rendering.
</Callout>

## Import

```tsx
import { CopilotChatAssistantMessage } from "@copilotkit/react-core/v2";
import "@copilotkit/react-core/v2/styles.css";
```

## Props

<PropertyReference name="message" type="AssistantMessage" required>
  The assistant message object to render. Contains the message `content`, `id`,
  `role`, and any associated tool calls.
</PropertyReference>

<PropertyReference name="messages" type="Message[]">
  The full array of conversation messages. Passed through to the `toolCallsView`
  slot for context-aware tool call rendering.
</PropertyReference>

<PropertyReference name="isRunning" type="boolean" default="false">
  Whether the agent is currently executing. Can be used by slot components to
  adjust their behavior during streaming.
</PropertyReference>

<PropertyReference name="isLatest" type="boolean">
  Whether this is the last message the chat renders. While `isRunning` is
  `true`, the latest message hides its toolbar. `CopilotChatMessageView` passes
  it, because its rendered list can differ from `messages` when
  `transformMessages` drops, replaces or reorders messages. When omitted, the
  component compares `message.id` with the last entry of `messages`.
</PropertyReference>

<PropertyReference name="onThumbsUp" type="(message: AssistantMessage) => void">
  Callback invoked when the user clicks the thumbs-up button; while ratings are
  recorded, only when the click gives a rating. When not provided,
  the thumbs-up button is hidden from the toolbar, unless `thumbsUpButton` is
  set or, inside `CopilotChatMessageView` under a `CopilotChatConfigurationProvider`, Automatic Learning capture has started
  (see [Reply ratings](#reply-ratings)). When this component is used
  as the assistant slot of `CopilotChatMessageView`, the callback can receive a
  callback-only `rawEvent` value for a live direct AG-UI `TEXT_MESSAGE_START`.
  Direct use of this component receives the canonical assistant message.
</PropertyReference>

<PropertyReference
  name="onThumbsDown"
  type="(message: AssistantMessage) => void"
>
  Callback invoked when the user clicks the thumbs-down button; while ratings
  are recorded, only when the click gives a rating. When not
  provided, the thumbs-down button is hidden from the toolbar, unless
  `thumbsDownButton` is set or, inside `CopilotChatMessageView` under a
  `CopilotChatConfigurationProvider`, Automatic Learning capture has started. The
  `CopilotChatMessageView` callback-only `rawEvent` behavior applies only when
  this component is used through that parent path.
</PropertyReference>

<PropertyReference
  name="onReadAloud"
  type="(message: AssistantMessage) => void"
>
  Callback invoked when the user clicks the read-aloud button. When not
  provided, the read-aloud button is hidden from the toolbar.
</PropertyReference>

<PropertyReference
  name="onRegenerate"
  type="(message: AssistantMessage) => void"
>
  Callback invoked when the user clicks the regenerate button. When not
  provided, the regenerate button is hidden from the toolbar.
</PropertyReference>

<PropertyReference name="additionalToolbarItems" type="React.ReactNode">
  Additional React elements appended to the toolbar alongside the default action
  buttons.
</PropertyReference>

<PropertyReference name="toolbarVisible" type="boolean">
  Controls whether the action toolbar is visible. When set to `false`, the
  toolbar is hidden entirely regardless of which callback props are provided.
</PropertyReference>

## Slots

All slot props follow the CopilotKit slot system: each accepts a replacement React component, a `className` string that is merged into the default component's classes, or a partial props object that extends the default component.

<PropertyReference name="markdownRenderer" type="SlotProp<typeof CopilotChatAssistantMessage.MarkdownRenderer>">
  Slot for the Markdown rendering engine. Defaults to the built-in streaming renderer (`StreamingMarkdownDefaultRenderer` from `@copilotkit/react-core/v2`, a thin adapter over [`@copilotkit/markdown-renderer`](/reference/packages/markdown-renderer)'s `StreamingMarkdownRenderer`) — streaming-safe incremental rendering with per-token animation, GFM, tables, autolinks, and citations, with **no** syntax highlighting or math. A renderer is any component that accepts `MarkdownRendererProps` (`{ content: string; isStreaming?: boolean; className?: string }`, exported from `@copilotkit/react-core/v2`). `BasicMarkdownRenderer` (marked-based) is available as a lighter alternative. This per-message slot takes precedence over a `markdownRenderer` set on `CopilotKitProvider`. `markdownRenderer` also accepts a config object (`DefaultMarkdownRendererProps`) to configure the built-in renderer without writing a wrapper — e.g. `markdownRenderer={{ nodeRenderers: { codeBlock: Shiki } }}`.

  **As a replacement component** (here, restoring Streamdown — install `streamdown` first):
  ```tsx
  import { Streamdown } from "streamdown";

  <CopilotChatAssistantMessage
    message={msg}
    markdownRenderer={({ content }) => <Streamdown>{content}</Streamdown>}
  />
  ```

  To apply a renderer to every message at once, set it on the provider instead (define it outside render so its identity is stable):
  ```tsx
  import { StreamdownRenderer } from "./markdown-renderer";

  <CopilotKitProvider markdownRenderer={StreamdownRenderer}>
    {/* ... */}
  </CopilotKitProvider>
  ```

  For a full walkthrough of all three approaches (keep the default, configure it, or replace it) across React, Vue, and React Native, see the [Markdown Rendering](/markdown-rendering) guide.

</PropertyReference>

<PropertyReference name="toolbar" type="SlotProp<typeof CopilotChatAssistantMessage.Toolbar>">
  Slot for the action toolbar container. Defaults to `CopilotChatAssistantMessage.Toolbar`, which renders a horizontal row of action buttons below the message content.

**As a className:**

```tsx
<CopilotChatAssistantMessage message={msg} toolbar="border-t pt-2 mt-2" />
```

</PropertyReference>

<PropertyReference
  name="copyButton"
  type="SlotProp<typeof CopilotChatAssistantMessage.CopyButton>"
>
  Slot for the copy-to-clipboard button in the toolbar. Defaults to
  `CopilotChatAssistantMessage.CopyButton`. The tooltip label is sourced from

<PropertyReference

## CopilotChatToolCallsView

A companion component that renders the tool calls contained in an assistant message. Each call is drawn by the closest registered tool renderer (registered via `useFrontendTool`, `useHumanInTheLoop`, `useRenderTool` or `renderToolCalls` on the provider).

Calls the agent makes in a row are collapsed into one group, drawn by the `group` slot, when their renderer opts into grouping. The built-in card from `useDefaultRenderTool()` does; a custom renderer opts in with `group: true`. Any other call always shows on its own. Inside a [`CopilotChatMessageView`](/reference/components/CopilotChatMessageView), groups span messages and follow the view's `toolCallDisplay`; used on its own, this component groups the calls of `message`.

### Import

```tsx
import { CopilotChatToolCallsView } from "@copilotkit/react-core/v2";
```

### Props

<PropertyReference name="message" type="AssistantMessage" required>
  The assistant message whose tool calls should be rendered.
</PropertyReference>

<PropertyReference name="messages" type="Message[]">
  The full conversation message array. Provides context for tool call renderers
  that need to reference other messages (e.g., to find the corresponding tool
  result message).
</PropertyReference>

<PropertyReference
  name="display"
  type='"grouped" | "line" | "stacked" | "turn" | "separate"'
>
  How to show the calls. Inside a message view it defaults to the view's
  [`toolCallDisplay`](/reference/components/CopilotChatMessageView#toolcalldisplay);
  on its own it defaults to `"grouped"`. `"separate"` renders every call on its
  own, without a group.
</PropertyReference>

### Slots

<PropertyReference name="group" type="SlotProp<typeof CopilotChatToolCallGroup>">
  Draws a group of calls made in a row in the `"grouped"`, `"line"` and
  `"stacked"` displays. The `"turn"` display draws its calls as rows inside the
  reply and doesn't use it. Defaults to
  [`CopilotChatToolCallGroup`](/reference/components/CopilotChatToolCallGroup).
  Like every slot, it accepts a className, props for the default, or a
  replacement component, which receives the group's `calls` and a
  `renderCall` function.

**Through `CopilotChat`:**

```tsx
<CopilotChat
  messageView={{
    assistantMessage: {
      toolCallsView: { group: "rounded-2xl shadow-sm" },
    },
  }}
/>
```

**As props for the default group:**

```tsx
<CopilotChatToolCallsView
  message={message}
  messages={messages}
  group={{ appearance: "line" }}
/>
```

**As a replacement component:**

```tsx
<CopilotChatToolCallsView
  message={message}
  messages={messages}
  group={({ calls, renderCall }) => (
    <details>
      <summary>Ran {calls.length} tools</summary>
      {calls.map((call) => (
        <div key={call.toolCall.id}>{renderCall(call)}</div>
      ))}
    </details>
  )}
/>
```

</PropertyReference>

## Usage

### Basic Assistant Message

```tsx
function AssistantBubble({ message }) {
  return (
    <CopilotChatAssistantMessage
      message={message}
      onThumbsUp={(msg) => console.log("Thumbs up:", msg.id)}
      onThumbsDown={(msg) => console.log("Thumbs down:", msg.id)}
    />
  );
}
```

### Customizing the Toolbar

```tsx
function CustomToolbarMessage({ message }) {
  return (
    <CopilotChatAssistantMessage
      message={message}
      onRegenerate={(msg) => handleRegenerate(msg)}
      onReadAloud={(msg) => speak(msg.content)}
      additionalToolbarItems={
        <button onClick={() => shareMessage(message)}>Share</button>
      }
      toolbar="border-t border-gray-200 pt-2"
    />
  );
}
```

### Hiding the Toolbar

```tsx
function MinimalMessage({ message }) {
  return (
    <CopilotChatAssistantMessage message={message} toolbarVisible={false} />
  );
}
```

### Custom Markdown Renderer

```tsx
function CustomRendererMessage({ message }) {
  return (
    <CopilotChatAssistantMessage
      message={message}
      markdownRenderer={({ content }) => (
        <ReactMarkdown>{content}</ReactMarkdown>
      )}
    />
  );
}
```

### Standalone Tool Calls View

```tsx
function ToolCallsList({ message, allMessages }) {
  return (
    <div className="tool-calls">
      <CopilotChatToolCallsView message={message} messages={allMessages} />
    </div>
  );
}
```

## Behavior

- **Markdown Support**: The built-in renderer is [`@copilotkit/markdown-renderer`](/reference/packages/markdown-renderer) — a zero-dependency streaming renderer that supports GFM (headings, bold/italic/strikethrough, lists, links, inline and fenced code, tables, blockquotes, images), autolinks, citations, and per-token fade-in animation. It escapes raw HTML and sanitizes link/image URLs. Syntax highlighting, math (KaTeX), and diagrams are **not** included by default; plug in a custom `markdownRenderer` to add them (see [Migrate the Markdown Renderer](/migrate/markdown-renderer)).
- **Toolbar Visibility**: The toolbar appears on hover or focus by default, except on the latest message while `isRunning` is `true`. Individual buttons are only rendered when their corresponding callback prop (`onThumbsUp`, `onThumbsDown`, `onReadAloud`, `onRegenerate`) is provided. The thumbs also render when their slot is set or, inside `CopilotChatMessageView` under a `CopilotChatConfigurationProvider`, once Automatic Learning capture has started. The copy button is always visible when the toolbar is shown.
- **Localized Labels**: All toolbar button tooltips are sourced from the nearest `CopilotChatConfigurationProvider`. See [`useCopilotChatConfiguration`](/reference/hooks/useCopilotChatConfiguration) for the full list of label keys.
- **Tool Call Rendering**: Tool calls embedded in the assistant message are rendered by the `toolCallsView` slot. Each tool call is resolved using the `useRenderToolCall` hook, which looks up registered renderers by tool name.
- **Slot System**: Each slot prop accepts three forms -- a replacement component, a className string merged into the default, or a partial props object that extends the default component's props.

## Reply ratings

When this component renders inside `CopilotChatMessageView` under a `CopilotChatConfigurationProvider` and Automatic Learning capture has started, the thumbs record ratings, also while capture reconnects or is stopped:

- A click rates the reply and opens a field for an optional comment next to the thumb.
- Pointing at or keyboard-focusing the chosen thumb opens its comment again. On a touch screen, tapping the chosen thumb removes the rating instead.
- Clicking the chosen thumb again removes the rating.
- The rating shows while the page is open and is sent to the active Trajectory as a `message.feedback` event. Like any Trajectory event, a rating given while no Trajectory captures is not sent.

`onThumbsUp` and `onThumbsDown` run when a rating is given, not when it is removed. The comment field is the `feedbackComment` slot, `CopilotChatAssistantMessage.FeedbackComment` by default; its placeholder and send button use the `assistantMessageFeedbackCommentPlaceholder` and `assistantMessageFeedbackCommentSubmitLabel` labels. See [Collect reply ratings](/intelligence/capture-interactions#collect-reply-ratings) for the event and how ratings reach Intelligence.
