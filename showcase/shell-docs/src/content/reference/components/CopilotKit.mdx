---
title: "CopilotKitProvider"
description: "The CopilotKit provider component, wrapping your application."
---

`<CopilotKitProvider>` is the CopilotKit provider. It will typically wrap your entire application (or a sub-tree of your application where you want to have a copilot). It provides the copilot context to all other components and hooks.

<Callout type="info" title="Upgrading from v1?">
  The v1 `<CopilotKit>` provider was removed in 2.0. Use `<CopilotKitProvider>`
  instead, and rename its `agent` prop to `agentId`. See the
  [migration guide](/migrate/v2).
</Callout>

You can also name the agent per chat with `<CopilotChat agentId="my_agent">`, or
for a subtree with `<CopilotChatConfigurationProvider agentId="my_agent">`. Both
of those override the provider-level default. See [Provider and handler
pairs](/backend/runtime-endpoints#provider-and-handler-pairs).

When `useSingleEndpoint` is omitted, the transport is negotiated from the
Runtime info response.

## Example

You can find more information about self-hosting CopilotKit [here](/direct-to-llm/guides/self-hosting).

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";
import "@copilotkit/react-core/styles.css";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit">{children}</CopilotKitProvider>
  );
}
```

## Properties

<PropertyReference name="children" type="ReactNode" required>
  The children to be rendered within the provider.
</PropertyReference>

<PropertyReference name="runtimeUrl" type="string">
  The endpoint for the Copilot Runtime instance. See the Copilot Runtime API
  documentation.
</PropertyReference>

<PropertyReference name="agentId" type="string" default='"default"'>
  The agent every `<CopilotChat>` under this provider talks to, unless a chat
  names its own with the `agentId` prop. The agent is named by its **key in the
  runtime's `agents` map**, not the agent's own `name` or `id`. See [Which name
  identifies an agent](/backend/copilot-runtime#which-name-identifies-an-agent).
</PropertyReference>

<PropertyReference name="publicApiKey" type="string"  >
Your Copilot Cloud API key.

Don't have it yet? Go to https://dashboard.operations.copilotkit.ai and get one for free.

</PropertyReference>

<PropertyReference name="publicLicenseKey" type="string"  >
Your public license key for accessing CopilotKit Intelligence features.

Don't have it yet? Go to https://dashboard.operations.copilotkit.ai and get one for free.

</PropertyReference>

<PropertyReference name="licenseToken" type="string">
  Signed license token for offline verification of CopilotKit Intelligence features.
</PropertyReference>

<PropertyReference name="headers" type="Record<string, string> | (() => Record<string, string>) | (() => Promise<Record<string, string>>)"  >
Additional headers to be sent with runtime requests. Pass an object for static
headers, or a function (sync or async) that builds them fresh. The function
runs when each request is sent, so a refreshed token is always used.

Cache inside the builder. Clerk's and Auth0's `getToken()` already cache. A
builder that calls the network every time adds one call per request.

If the builder throws or rejects, that request is not sent and `onError` gets
`header_resolution_failed`.

Core headers are also sent to any `selfManagedAgents` /
`agents__unsafe_dev_only` agent, including ones on other origins. Don't put a
bearer token in core headers if those agents point at a third party.

For example:

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";
import { useAuth } from "./auth";

export function Providers({ children }: { children: ReactNode }) {
  const { getToken } = useAuth();

  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      headers={async () => ({ Authorization: `Bearer ${await getToken()}` })}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

</PropertyReference>

<PropertyReference name="properties" type="Record<string, unknown>"  >
Custom properties to be sent with the request.
  Can include threadMetadata for thread creation and authorization for LangGraph Platform authentication.
  For example:

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      properties={{
        user_id: "users_id",
        authorization: "your-auth-token", // For LangGraph Platform authentication
        threadMetadata: {
          account_id: "123",
          user_type: "premium",
        },
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

Note: The `authorization` property is automatically forwarded to LangGraph agents. See the LangGraph Agent Authentication Guide (see code examples above) for details.

</PropertyReference>

<PropertyReference name="credentials" type="RequestCredentials"  >
Indicates whether the user agent should send or receive cookies from the other domain
  in the case of cross-origin requests.

To enable HTTP-only cookie authentication, set `credentials="include"` on the
frontend (`https://myapp.com`):

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="https://api.myapp.com/copilotkit"
      credentials="include"
    >
      {children}
    </CopilotKitProvider>
  );
}
```

Then configure CORS on your runtime endpoint (`https://api.myapp.com`):

```ts
import {
  BuiltInAgent,
  CopilotRuntime,
  createCopilotRuntimeHandler,
} from "@copilotkit/runtime";

const runtime = new CopilotRuntime({
  agents: { default: new BuiltInAgent({ model: "openai/gpt-5.4" }) },
});

const handler = createCopilotRuntimeHandler({
  runtime,
  basePath: "/copilotkit",
  cors: {
    origin: "https://myapp.com",
    credentials: true,
  },
});
```

</PropertyReference>

<PropertyReference name="useSingleEndpoint" type="boolean">
  Forces the single-route transport (`true`) or the multi-route transport
  (`false`). When omitted, the transport is negotiated from the Runtime info
  response.
</PropertyReference>

<PropertyReference name="messageFilter" type="(messages: Message[]) => Message[]">
  Rewrites the message list sent to runtime agents on every run. CopilotKit
  sends the whole thread each time. When your agent already stores the
  conversation, return only the messages to send, for example
  `messageFilter={(messages) => messages.slice(-1)}`. The filter changes the
  request body only; the transcript the UI renders is untouched. Agents passed
  in directly (`selfManagedAgents`), Intelligence runs, and suggestion runs are
  not filtered. Prefer a stable reference (`useCallback`).
</PropertyReference>

<PropertyReference name="enableInspector" type="boolean">
  Enable or disable the CopilotKit Inspector, letting you inspect AG-UI events,
  view agent messages, check agent state, and visualize agent context. It is
  enabled by default in development browser builds on localhost or loopback
  hosts, and is always disabled on remote hosts, in production, and during
  server rendering. An explicit value takes priority over `CopilotChat`'s
  `inspectorTools` prop.
</PropertyReference>

<PropertyReference name="showIntelligenceIndicator" type="boolean">
Whether to automatically mount the built-in CopilotKit Intelligence indicator
in chat. Set to `false` when your application renders its own Intelligence
status UI. Defaults to `true`.

</PropertyReference>

<PropertyReference name="selfManagedAgents" type="Record<string, AbstractAgent>">
  AG-UI agents managed by your app and registered directly with CopilotKit.
  Use this when you connect to agents without routing through a Copilot Runtime.
</PropertyReference>

<PropertyReference name="agents__unsafe_dev_only" type="Record<string, AbstractAgent>">
  Preconfigured local agents for development and tests. Use `selfManagedAgents`
  for production direct-agent setups.
</PropertyReference>

<PropertyReference name="frontendTools" type="ReactFrontendTool[]">
  Frontend tools registered for the whole app. Same shape as the argument of
  [`useFrontendTool`](/reference/hooks/useFrontendTool).
</PropertyReference>

<PropertyReference name="humanInTheLoop" type="ReactHumanInTheLoop[]">
  Human-in-the-loop tools registered for the whole app. Same shape as the
  argument of [`useHumanInTheLoop`](/reference/hooks/useHumanInTheLoop).
</PropertyReference>

<PropertyReference name="renderToolCalls" type="ReactToolCallRenderer[]">
  Tool call renderers registered for the whole app. See
  [`useRenderTool`](/reference/hooks/useRenderTool) for the component-scoped
  form.
</PropertyReference>

<PropertyReference name="renderActivityMessages" type="ReactActivityMessageRenderer[]">
  Renderers for AG-UI activity messages, registered for the whole app.
</PropertyReference>

<PropertyReference name="renderCustomMessages" type="ReactCustomMessageRenderer[]">
  Renderers for custom messages, registered for the whole app.
</PropertyReference>

<PropertyReference name="markdownRenderer" type="MarkdownRenderer">
  Global Markdown renderer for assistant and reasoning messages. Accepts a
  className string, a config object for the built-in renderer
  (`DefaultMarkdownRendererProps`), or a component that takes
  `MarkdownRendererProps`. A per-message `markdownRenderer` slot still wins over
  this. See [`CopilotChatAssistantMessage`](/reference/components/CopilotChatAssistantMessage).
</PropertyReference>

<PropertyReference name="a2ui" type="{ theme?: Theme; catalog?: any; loadingComponent?: React.ComponentType; includeSchema?: boolean; recovery?: A2UIRecoveryRendererOptions }">
Configuration for the A2UI (Agent-to-UI) renderer.

The built-in A2UI renderer is activated automatically when the runtime reports
that `a2ui` is configured in `CopilotRuntime`. This prop is optional and only
needed to override the theme, supply a custom component `catalog`, set a
`loadingComponent`, toggle whether the schema is included (`includeSchema`), or
tune the error-recovery status UI (`recovery`).

`includeSchema` defaults to `true`, which sends the catalog's component schemas
and the A2UI generation and design guidelines to the agent as context. With
`includeSchema: false`, the agent still receives the catalog ID and the names of
the catalog's custom components, without their JSON schemas or the guidelines.
A LangGraph agent that uses the CopilotKit middleware's injected A2UI tool then
gives its A2UI subagent the component names only. To give the subagent more
detail, pass a composition guide through the middleware's A2UI guidelines:
`a2uiParams.guidelines.compositionGuide` in TypeScript, or
`a2ui_params["guidelines"]["composition_guide"]` in Python.

```tsx
import type { ReactNode } from "react";
import {
  CopilotKitProvider,
  a2uiDefaultTheme,
  type A2UITheme,
} from "@copilotkit/react-core";

// Start from the default theme and override what you need.
const myCustomTheme: A2UITheme = { ...a2uiDefaultTheme };

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider runtimeUrl="/api/copilotkit" a2ui={{ theme: myCustomTheme }}>
      {children}
    </CopilotKitProvider>
  );
}
```

</PropertyReference>

<PropertyReference name="mcpApps" type="{ allowSameOriginFallback?: boolean }">
Configuration for the built-in MCP Apps renderer.

`allowSameOriginFallback` restores `allow-same-origin` on the MCP App sandbox.
By default widgets get an opaque origin. **Unsafe:** with it set, a widget runs
with your page's origin and can read your cookies, storage and DOM. Only use it
for widgets you trust that need `localStorage`, `IndexedDB` or cookies. See
[Sandbox and widget storage](/generative-ui/mcp-apps#sandbox-and-widget-storage).

</PropertyReference>

<PropertyReference name="openGenerativeUI" type="{ sandboxFunctions?: SandboxFunction[]; designSkill?: string }">
  Configuration for Open Generative UI. Use `sandboxFunctions` to expose host
  functions to generated sandboxed iframes, and `designSkill` to override the
  design guidance injected as agent context for `generateSandboxedUi`.
</PropertyReference>

<PropertyReference name="generativeUI" type="GenerativeUIConfig">
  Experimental. Native generative UI: `generativeUI={{ ui }}`, where `ui` comes
  from `createGenerativeUI`. The agent renders your React components into chat
  or into `<GenerativeUISurface id>` mounts.
</PropertyReference>

<PropertyReference name="defaultThrottleMs" type="number">
  Default throttle interval, in milliseconds, for `useAgent` re-renders caused
  by message and state updates. Individual `useAgent` calls and prebuilt chat
  components can override it with their own `throttleMs`.
</PropertyReference>

<PropertyReference name="learning" type="boolean | LearningConfig">
  Turns on interaction capture (`@copilotkit/learning`). `learning` (short for
  `learning={true}`) records with the default options; pass an object for
  options, including `autoStart`, `trajectoryId`, and `learningContainerIds`.
  `false` or omitting the prop turns capture off.
</PropertyReference>

<PropertyReference name="onError" type="(event: { error: Error; code: CopilotKitCoreErrorCode; context: Record<string, any> }) => void | Promise<void>"  >
Error handler called when CopilotKit encounters an error. Fires for all error
types: runtime connection failures, agent errors, and tool errors.

```tsx
import type { ReactNode } from "react";
import { CopilotKitProvider } from "@copilotkit/react-core";
import { debugDashboard } from "./debug-dashboard";

export function Providers({ children }: { children: ReactNode }) {
  return (
    <CopilotKitProvider
      runtimeUrl="/api/copilotkit"
      onError={({ error, code, context }) => {
        debugDashboard.capture({ error, code, context });
      }}
    >
      {children}
    </CopilotKitProvider>
  );
}
```

</PropertyReference>

<PropertyReference name="debug" type="DebugConfig">
  Enable client-side debug logging for the AG-UI transport and event pipeline.
  Pass `true` for event and lifecycle summaries, or a config object with
  `verbose: true` to include full event payloads.
</PropertyReference>
